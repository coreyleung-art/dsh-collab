# 任务结果验收清单模板 v1（task-verify 基础）

> 属主：QA 验收员 session-ffb7c3ab · 2026-08-17 · 协作流水线 B 路线（forum → bus-bridge → 设备执行 → 结果回传 → QA 验收）
> 用途：智能体提交任务结果（PR 语义）后，QA 按本清单验收；task-verify 工具化后同构自动化
> 验收机制：交付物 → 验收报告 → 返工跟踪（与 15 项验收同闭环）

## 1. 任务元信息

| 字段 | 值 |
|------|-----|
| task-id | <forum 任务 id> |
| 任务定义 | <forum 帖/任务描述> |
| 提交方 | <会话 id / 角色> |
| 执行设备 | <mac-mini / MBP / PC-i9 等> |
| 执行通道 | <bus-bridge> |
| 提交时间 | <ts> |
| 期望交付项 | <清单> |

## 2. 验收清单（QA 六条标准）

| # | 标准 | 检查项 | 结果 | 证据 |
|---|------|--------|------|------|
| 1 | **正确性** | 任务定义要求 vs 结果逐项对照 | ✅/❌ | <对照记录> |
| 2 | **完整性** | 全部交付项在位（产物/日志/证据文件）| ✅/❌ | <文件清单> |
| 3 | **格式** | 结构化输出符合约定（JSON 契约/报告模板）| ✅/❌ | <schema 对照> |
| 4 | **证据链** | 结果附来源可溯（执行记录/数据引用/时间戳）| ✅/❌ | <引用> |
| 5 | **判定+返工** | PASS/FAIL + 缺陷列表 → 返工跟踪 | ✅/❌ | <缺陷表> |
| 6 | **回归** | 涉及既有功能时挂回归基线对照 | ✅/❌ | <基线对照> |

## 3. 判定结论

```
task-id: <id>
判定: PASS / FAIL
通过项: n/6
缺陷列表: <# 缺陷 | 证据 | 严重度 | 处置>
返工跟踪: <已回报提交方 / 复验触发条件>
报告: ~/dsh-collab/qa/acceptance-<YYYYMMDD>-task-<id>.md
```

## 4. task-verify 工具化映射（高频验收自动化）

```text
task-verify <task-id>
  1. 读任务定义（forum API）→ 生成期望清单
  2. 对照提交结果（正确性/完整性/格式逐项）
  3. 证据链检查（来源可溯字段）
  4. 输出 PASS/FAIL 结论 + 报告落盘
  5. FAIL → 缺陷列表回报提交方（返工跟踪）
```

## 5. 边界与纪律

- 验收只读：不修改任务结果（只报告缺陷）
- 判定用宿主 API 工具权威（curl/PID 仅参考）
- 报告落 ~/dsh-collab/qa/（file:qa 红绿灯锁）
- 高频重复验收 → task-verify 自动化（tool 化后并入验收工具面）
