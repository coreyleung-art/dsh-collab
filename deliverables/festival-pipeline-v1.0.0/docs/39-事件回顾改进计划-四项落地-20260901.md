## P1：verify-all selfcheck 接入定时（launchd 每日，与词表闭环同步）

### 目标
- verify-all selfcheck 每日自动运行，恒 true 类缺陷实时暴露（无需人工触发）
- 与现有词表闭环（每日 06:30）同步，形成「词表+验证」双每日巡检

### 方案
```xml
<!-- ~/Library/LaunchAgents/com.dsh.verify-registry.plist -->
<!-- 每日 06:40（词表 06:30 之后 10 分钟，错峰） -->
<key>StartCalendarInterval</key>
<dict>
  <key>Hour</key><integer>6</integer>
  <key>Minute</key><integer>40</integer>
</dict>
<key>ProgramArguments</key>
<array>
  <string>/opt/homebrew/bin/node</string>
  <string>/Users/coreyleung/meituan-multi/scripts/verify-all.js</string>
  <string>selfcheck</string>
</array>
```

### 执行步骤
1. [ ] 创建 plist（含日志重定向 ~/.dsh/verify-registry.log）
2. [ ] launchctl load 注册
3. [ ] 手动触发验证一次（selfcheck 全通过）
4. [ ] 失败通知机制：selfcheck 非 0 退出 → 黑板 data/alerts/verify-failed 落链
5. [ ] 与词表闭环（06:30）时间协调确认

### 验收标准
- launchctl list 显示正常
- 每日 06:40 自动运行，日志留痕
- 失败时黑板告警

## P2：老登执行通道同步接入 verify-registry（批量/改价原语判定器移交时带验证）

### 目标
- 学习侧已移交老登的 4 原语（批量上架/下架/改库存/商品导入）在**老登执行通道**中也带权威验证
- 老登侧所有写操作同样遵循 R030（无验证的成功=未成功）

### 方案
| 原语 | verify-registry 判定器 | 老登接入点 |
|------|------------------------|-----------|
| product_batch_upshelf | 全部 SKU sellStatus=0 | 批量 API 调用后复查 searchListPageNew |
| product_batch_downshelf | 全部 SKU sellStatus=1 | 同上 |
| product_batch_stock | 全部 SKU stock=target | 复查库存字段 |
| import_products | afterCount > beforeCount | 导入后查商品总数 |
| change_price | price = targetPrice | 改价后查商品价格字段 |
| edit_discount | discount = targetDiscount | 活动查询复查 |

### 执行步骤
1. [ ] 知了提供 verify-registry 模块 + 判定器用法文档给老登
2. [ ] 老登执行通道（waimai_action/批量原语）接入 verify 复查
3. [ ] 双向联调：守白测试店验证（老登侧执行+判定器验证）
4. [ ] 老登原语注册表补 verify_cases 反向用例

### 验收标准
- 老登侧批量/改价操作后有验证字段（verify 证据）
- 无验证的操作返回「未验证」状态（不默认成功）

## P4：「结果真实性」月度审计项（HR 台账）

### 目标
- 每月例行抽查自动化操作的结果真实性（防止「无验证的成功」死灰复燃）
- 与 HR 审批台账衔接，形成「授权→执行→验证→审计」闭环

### 方案
| 项 | 内容 |
|----|------|
| 审计频率 | 每月一次（建议每月 5 日前） |
| 审计对象 | 上月全部写操作（accept/reject/上下架/改价/折扣/开店关店/im_send/批量） |
| 审计方法 | 抽 5 条执行记录，核对 verify 证据（API 响应/状态字段快照） |
| 判定标准 | R030：有 verify 证据 = 合格；无验证 = 不合格（记为审计问题） |
| 工具支持 | verify-all.js report + 执行日志（store.logAction 已有审计） |
| 输出 | 审计结果入 HR 审批台账（audit.jsonl append-only） |

### 执行步骤
1. [ ] 司库-HR 将「结果真实性月度审计」纳入台账制度（已承诺登记 M4/M5）
2. [ ] 知了提供审计数据源：执行日志 + verify-all report + verify_cases 反向用例
3. [ ] 每月审计执行（HR 主导，知了支持）
4. [ ] 审计发现问题 → 黑板 data/alerts/ 预警 → 整改

### 验收标准
- 每月有审计记录（含合格/不合格明细）
- 不合格项有整改闭环
