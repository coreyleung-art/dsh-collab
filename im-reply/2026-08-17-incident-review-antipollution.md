## 二、根因链（层层叠加，非单一失误）

### 1. 测试与生产环境未隔离（最根本）
- 联调直接在**真实客户会话**上执行（s6 8.13#13单 L**、s3 x**），无测试店铺/测试会话隔离
- de7b29de 与我都在真实会话上做「管道验证」「按钮测试」「scrollIntoView 验证」
- → 测试内容天然落入生产会话

### 2. 验证口径不可靠（假阳性陷阱）
- 管道自报 `verified:true` / `preview 更新` = 假阳性（读窗口残留/当前激活会话展示，非目标会话真实状态）
- 联调多轮依赖管道自报推进，直到我坚持「watcher status 变化」才暴露真相
- → 管道自报成功 ≠ 真发成功，无独立验收环节

### 3. 用户确认护栏被稀释（流程失守）
- 用户设「提交前必须确认」护栏，但我把「话术定稿」误当「发送授权」
- 第一批 4 条（id 29/31/32/33）在话术定稿后未经逐条批准即 yes=true 真发
- 后续复测持续 yes=true（用户批准的是「4 条复测草稿」，但被扩展为反复真发）
- → 护栏存在但执行走样

### 4. 重试无上限（骚扰叠加）
- 同一会话 s3 x** 真发 9 次（id 36/40/48/49/50/52/53/57/69/70），即使失败也反复试
- 无「同会话重试次数上限」「失败冷却」机制
- → 即使未落区，也是高频骚扰客户会话

### 5. 测试消息无标记拦截
- 【系统测试】【管道验证】类消息直接发送，无「测试内容禁止真发」校验
- 管道只查长度/会话存在，不查内容性质
- → 测试消息与正常话术无差别流入

### 6. 污染识别滞后
- 无「发送后立即核对落区内容」环节，直到用户审查才发现
- 若 watcher 验收实时化，可第一时间发现

## 三、防污染机制设计（六道闸门）

### 闸门 1：测试/生产环境隔离（Sandbox 优先）
- **联调专用测试店铺**（如新建沙箱店）或**测试会话白名单**（前缀 `[TEST]` 会话）
- 生产会话发送仅允许「审批通过的话术队列」
- 规则：**联调/验证一律在测试环境；生产发送必须来自审批队列**

### 闸门 2：内容白名单校验（发送前）
- 发送内容必须命中「已审批话术库」条目（hash 匹配或 ID 引用）
- **禁止词拦截**：`【】` `测试` `验证` `管道` `忽略` `按钮点击` 等 → 拒绝发送
- 规则：**内容不在白名单 → 直接拒绝，不进入管道**

### 闸门 3：用户逐条确认（发送授权）
- 每条生产发送前生成 `approval_token`（会话ID+内容hash+时间戳）
- 用户/审批流确认后才带 token 调用发送 API
- 规则：**无有效 approval_token → 管道拒绝执行**（服务端强制，不依赖调用方自觉）

### 闸门 4：独立验收（watcher 权威）
- 发送后 15-30s，以 watcher 采集的 `im_sessions.status=replied` + `timeline 含发送内容` 为准
- 管道自报仅作参考，**验收结果独立写入审计**
- 规则：**watcher 未确认 → 标记 PENDING_VERIFY / FAILED，不视为成功**

### 闸门 5：重试/频率限制
- 同会话：失败重试 ≤2 次，间隔 ≥60s（管道已有 60s 防重复，需加次数上限）
- 同会话发送频率：24h 内 ≤3 条
- 规则：**超限自动锁定该会话，人工解锁**

### 闸门 6：实时审计与污染警报
- actions 表增强：`verified`（watcher 验收结果）、`verify_ts`、`content_class`（test/customer）
- 发送后自动核对：内容含测试词 → 立即告警（即使管道 ok）
- 规则：**任何测试类内容落区 → 触发 P1 告警 + 通知用户**

## 四、排错工作流（Debug SOP，替代裸调）

```
问题报告 → 分级
├─ L1 dry-run 失败 → 检查注入/聚焦（读 taValue 实证）
├─ L2 verified 假阳性 → 用 watcher status 独立验收（禁止信管道自报）
├─ L3 落区失败 → 检查模态框/窗口态/会话匹配（读 activeElement）
└─ L4 消息污染 → 立即止损（用户已定）→ 核对落区清单 → 人工补救

排错环境：一律测试店铺/测试会话 → dry-run → 沙箱真发 → 灰度 1 条（用户确认）→ 批量（逐条确认）
```

**禁止事项**：
- ❌ 禁止在真实客户会话上做任何「测试/验证」类发送
- ❌ 禁止在管道未闭环（watcher 未验收）时批量发送
- ❌ 禁止把「话术定稿」当作「发送授权」
- ❌ 禁止无 approval_token 生产发送
