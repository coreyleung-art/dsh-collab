# 超时兜底提审流程设计（v1）

> 作者：智能客服 session-b193c782 · 2026-08-17
> 依据：用户确认——未回复超过 1 分钟的具体信息 → 提取门店账号+客户消息 → 自动起草 → 推企微确认
> 状态：草稿待确认；数据源需与 de7b29de 核对

## 一、流程总览

```
[检测] pending 消息未回复 >1min
  → [提取] 门店账号 + 客户消息 + 上下文
  → [拟稿] 范本库/场景规则匹配 + 敏感/上下文自审
  → [推送] 企微确认卡 (channel.send, level=P1)
  → [确认] 用户在企微确认 / 回 IM 处理
```

## 二、超时检测（步骤1）

- **触发条件**：**当日活跃** pending 消息未回复 > 1 分钟（用户确认阈值）
- **当日过滤（关键）**：只提审当日新客户消息（sessionKey 含「今日」或 last_client_at 在当日）——**历史积压不逐条推送企微**（实测当前 178 条全为历史积压，最短 45h，批量推=刷屏），历史积压走批量人工/归档
- **数据源**：app.db im_sessions（只读）+ /api/im/timeout?minutes=1（unreplied_min 字段，de7b29de 已上线）
- **轮询**：每 60s 检查一次（与采集节奏对齐）
- **去重**：同会话同内容已提审过（10min 内）不重复推送

## 三、提取字段（步骤2）

| 字段 | 来源 | 说明 |
|------|------|------|
| 门店账号 | im_sessions.store_id → stores.name | 如「天河3号店-初蘅天河」 |
| 会话 key | im_sessions.session_key | 如「今日#33单 我**」 |
| 客户消息 | im_sessions.last_client_msg / detail.timeline 最后 client | 具体问题内容 |
| 上下文 | detail.timeline 近 3 条 | 客户历史诉求（如「明天早上记得送花」） |
| 订单状态 | /api/im/order-status（可选） | 如已下单/配送中 |

## 四、拟稿（步骤3）

- 场景规则匹配（19 类）+ 范本库话术（manuals/21 + 各店范本）
- 自审（审核规则 v3）：白名单/禁止词/敏感转人工/上下文相关/频率
- 敏感类（退款/投诉/发票/骑手失联）→ **不拟稿，标记转人工**

## 五、企微推送确认卡（步骤4）

- **通道**：channel.send（外链通讯员 92623479）
- **级别**：P1（超时兜底属业务关键；对齐外链分级策略）
- **卡片内容**：
  ```
  [IM 超时提审] 门店：天河3号-初蘅天河
  会话：今日#33单 我**
  客户：多久送达？
  上下文：已下单，催时效
  ── 拟回复 ──
  您好！可以的哦，我们会尽快安排配送～
  ── 操作 ──
  确认发送 / 修改 / 忽略（回复数字或文字）
  ```

## 六、确认与回执（步骤5）

- 用户在企微回复「确认」→ 走预填待发（de7b29de 弹 IM 框预填）或直接发送（若用户授权）
- 用户回复「修改 + 新文案」→ 采纳后重推
- 用户回复「忽略/转人工」→ 标记 handled
- 回执写 actions 审计（im_review 类型）

## 七、与值守窗口衔接

- **营业常规时段**：仅此超时兜底流程（模式 B）
- **非营业/高峰**：值守增强（模式 A，可主动拟稿预填）
- 超时兜底是全时段安全网（营业时段唯一介入点）
