# IM 回复发送前内容审核规则（v1 草稿）

> 作者：智能客服 session-b193c782 · 2026-08-17
> 依据：用户决策「可控自动化 + 总线 agent 自审」——拟稿方自审 → 生成 approval_token → 仅在带 token 时发送
> 状态：草稿 v3（token 统一为 HMAC-SHA256 格式，与 de7b29de auto-controlled-send-design.md 对齐）· 停止令下设计，恢复后启用

## 一、审核职责

智能客服（内容拟稿方）承担**发送前内容审核**：
1. 拟稿（范本库匹配 + 场景规则）
2. 自审（本规则清单）
3. 通过 → 生成带 approval_token 的待发条目（会话ID+内容hash+ts+审核结论）
4. 仅带有效 token 的条目允许进入发送管道（de7b29de 侧校验）

## 二、审核清单（逐条通过才发）

### A. 来源与授权（G1/G2）
- [ ] 目标会话在审批队列（approval-queue.json）
- [ ] 内容命中已批准话术白名单 或 与队列 draft 一致（80% 前缀匹配）
- [ ] 已获用户确认（逐条确认 or 审批流 token）

### B. 内容安全（G3）
- [ ] 无测试/系统类关键词（测试/验证/管道/忽略/【】/TEST 等 → 拒绝）
- [ ] 无违规引流词（微信→绿泡泡替代；不加外部联系方式）
- [ ] 无敏感承诺（不承诺具体送达时间/百分百还原——只用「尽快」「按时间安排」「相似度80%」）
- [ ] 无不当措辞（不指责客户/不推责/不用「系统」背锅式生硬表述）

### C. 会话与上下文（G4/G5）
- [ ] 会话未在敏感清单——**权威来源 = approval-queue.json 的 risk 标记（引用非复制）**（退款/投诉/发票/骑手失联/广告 → 转人工，不自动发）
- [ ] 内容与客户最后消息相关（不答非所问）
- [ ] 回复前查订单状态（若可查）：订单已完成的催单类 → 收尾话术；未完成 → 正常话术
- [ ] 同会话 24h 发送 ≤3 条（频率限制）

### D. 技术前置（G6）
- [ ] agent_light(im_window:N) 绿灯
- [ ] /api/im/collecting 该店 false
- [ ] 持短锁（发送时）

## 三、拒绝条件（任一命中即拒绝，转人工或标记）

1. 内容含禁止词（测试/验证/管道/【】等）
2. 内容未命中白名单且非队列 draft
3. 目标会话未确认（无用户批准）
4. 会话属敏感类（退款/投诉/发票/骑手/广告）
5. 内容承诺具体时间或百分百还原
6. 含违规引流词（微信等外部联系方式）
7. 同会话超频（24h >3 条）
8. 会话与内容上下文不符（答非所问）
9. 审核 token 缺失/过期/不匹配（会话+内容 hash 校验）

## 四、approval_token 格式（v3 · HMAC 统一）

```
token = HMAC-SHA256(secret, storeId + "|" + sessionKey + "|" + text + "|" + ts)
```
- 密钥化 HMAC（非明文拼接），与 de7b29de auto-controlled-send-design.md 一致
- 含会话+内容绑定（防跨会话复用）
- **有效期 10 分钟**（防重放；超时需重新审核）

## 五、审核记录（审计）

- 每次审核写 actions/审核日志：{会话, 内容hash, 审核结论(pass/reject), 拒绝原因, token, ts}
- 周度抽查：审核通过内容的实际落区/客户反馈（联动用户洞察 24h 差评度量）

## 六、与 SOP 衔接

本规则 = im-reply-debug-sop.md 红线 5 条的**制度化实现**：
- 红线2（管道自报不作数）→ 审核后 watcher 独立验收仍保留
- 红线3（逐条确认）→ 审核 + 用户确认 + token
- 红线4（测试内容拦截）→ 审核拒绝条件 1
- 红线5（重试有界）→ 拒绝条件 7
