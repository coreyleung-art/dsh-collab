# 需求确认 · 审批分级机制（用户掌握开关 + 智能体初审 + 黑板登记）

> 建立：2026-08-20 · HR · J42 延伸设计（用户提出思路 → 梳理方案 → 确认后落地）

## 用户原话（提炼）

> 「J42 每个需求都生成文档确认……是不是有些审批判断可以挂黑板给你或适合的智能体去审核？按重要性和严重性分级，不需要我介入的直接审批。或者让我掌握开关：自动/宽松/正常/严格，类似标准？」

## J42 现状（如实回答）

- 当前 J42 规则：**所有需求**（无论大小）→ 先写 .md 梳理 → 用户确认 → 才干活。**无分级**，全部走人工确认
- 实际执行观察：大任务（放行/论文拉取）确认合理；但**例行/低风险**（如接单回复、例行改价、监察运行）也走确认流程=过重

## 方案 · 审批分级四档 + 用户开关（待确认）

### 分级矩阵（按 重要性 × 风险）

| 档位 | 名称 | 适用（示例） | 审批方式 |
|---|---|---|---|
| L0 | **自动** | 例行/查询/已定流程内（接单回复/每日日报/监察审计/检索） | 智能体直接执行，黑板登记 |
| L1 | **宽松** | 常规低风险变更（改价/上下架/回复模板/常规文档沉淀） | 智能体初审直接批，黑板登记+每日汇总可查 |
| L2 | **正常**（默认） | 常规新任务/迭代/新功能（现有 J42 行为） | 写 .md 确认文档，智能体初审+用户一键确认 |
| L3 | **严格** | 高危/大方向/架构变更/成本超限/外部承诺/删除数据/合规 | 必须用户明确确认（现有全量确认行为） |

### 用户开关（全局可调，随时改）

| 开关档 | 效果 |
|---|---|
| 自动 | 全 L0（所有审批下沉，仅 L3 强升必须用户） |
| 宽松 | L0/L1 下沉，L2 起需确认 |
| 正常（默认） | L0/L1 下沉，L2/L3 需确认（=本方案默认） |
| 严格 | L0-L2 全需确认（=现 J42 全量确认行为，兜底） |

### 硬性升级（任何档位都不可绕过）

1. 成本触发：单任务预计/实际 >¥X（阈值可配，默认沿用熔断 100/200）
2. 外部承诺：对外承诺/发布/金钱往来
3. 数据/资产：删除、覆盖、破坏性变更
4. 合规/敏感：隐私、平台规则边界
5. 跨域影响：影响其他角色/资源的架构变更

→ 命中任一 → 强制升 L3（用户确认）

### 黑板登记（审批台账）

- 所有 L0/L1 直接审批动作 → 写审批台账（registry 或 pending-work-plan 增列），格式：时间/动作/审批档位/决策依据/执行结果
- 用户随时可查台账，可一键回滚/追责（监察体系已可回放）
- 每日本来就有 waimai-audit 09:20 + registry 版本递增=天然台账

## 落地动作（确认后）
