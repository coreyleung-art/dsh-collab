## 核心设计（对官方 #4416 open question #6 正面回答）
1. **写端纯函数埋点**：appendLines 的 before size=帧偏移 + events 首尾 seq 天然可得 → sidecar 条目是日志追加的纯函数，O(1) 增量，无额外 IO
2. **免跨文件事务一致性**：日志权威 + sidecar 可落后 + logSize 校验自愈（读时只补落后帧，非全量）
3. **.idx 格式**：magic+version+headerEndByte+logSizeSnapshot + 定长 24B/帧记录(startByte/endByte/firstSeq/lastSeq)，torn 检测靠定长取模
4. **两档惰性构建**：轻档(帧级,只扫帧头~1.5ms,服务尾部页) / 全档(seq级,解每帧~500ms 一次性,任意 fromSeq)
5. **loadStoredFrom 对接**：coordinator hook 现成；部分读 readFileRange 替代整文件 readFile；无 idx 优雅降级全量
6. **四层实施** L1 轻档读→L2 写端埋点→L3 loadStoredFrom→L4 inspect bounded(后续)

## 端到端验证（真实副本 14.1MB/27608帧/59686事件）
- 尾部窗口 fromSeq=711500：二分 62μs → 部分读 0.98ms(12帧) vs 全量 497ms = **~500x**，事件集与全量 filter 完全一致 PASS
- 中部 700000：14.5ms(366帧) PASS；近头部 100：自然退化全量成本 PASS
- 机制无正确性缺陷，可安全落地
