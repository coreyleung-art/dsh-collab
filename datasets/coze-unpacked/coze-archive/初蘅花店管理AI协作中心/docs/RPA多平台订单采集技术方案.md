# RPA自动化采集多平台订单数据技术方案

## 一、需求背景与现状分析

### 1.1 用户基本情况
- **门店规模**：4家鲜花门店
- **使用平台**：美团外卖、饿了么、京东到家、麦芽田（配送）、花集通（补单）
- **核心诉求**：将线上订单数据拉取到自研ERP系统，用于销售BOM模块和销售预测
- **当前痛点**：各平台数据分散，人工汇总效率低

### 1.2 各平台对接条件评估

| 平台 | API对接门槛 | 麦芽田/花集通 | 后台手动导出 | RPA可行性 |
|------|------------|--------------|-------------|-----------|
| 美团外卖 | ≥30家门店 | 麦芽田仅配送推送，无订单拉取 | ✅ 支持 | ⚠️ 风险较高 |
| 饿了么 | 无明确门槛，需认证 | 同上 | ✅ 支持 | ✅ 可行 |
| 京东到家 | 无明确门槛 | 同上 | ✅ 支持 | ✅ 可行 |

## 二、各平台数据导出能力调研

### 2.1 美团外卖商家后台

#### 数据导出功能
- **入口**：`美团外卖商家中心 → 财务管理 → 下载专区 → 门店账单`
- **导出内容**：
  - 账单数据（含订单明细、金额、优惠、结算信息）
  - 支持按日期范围筛选
  - 支持全部门店账单打包下载
- **导出格式**：Excel/CSV
- **时间跨度**：最长60天
- **权限要求**：
  - 主账号：默认拥有订单导出权限
  - 子账号：需主账号在「账号管理→员工管理→补充权限」中授权

#### 登录方式
- 手机号 + 短信验证码
- 账号密码登录
- 手机APP扫码登录
- **安全机制**：
  - 连续3次密码错误，账号锁定15分钟
  - 频繁登录触发验证码/滑块
  - 设备指纹检测

#### 反爬机制（2026年最新）
根据搜索结果，美团已部署多维度风控：
- IP频率限制（单IP每秒≤5次，超10次触发1小时封禁）
- 设备指纹识别（dfpid/xid双重验证）
- WASM加密Token（动态失效）
- 滑块验证码/点选验证码拦截
- 行为分析（鼠标轨迹、点击节奏）

### 2.2 饿了么商家后台

#### 数据导出功能
- **入口**：`饿了么商家版 → 财务管理 → 财务下载 → 导出账单`
- **导出内容**：账单明细、订单明细、优惠信息
- **导出格式**：Excel
- **权限要求**：需完成企业实名认证

#### API能力（开放平台）
- **接口**：`eleme.order.getOrder`、`eleme.order.mgetOrders`、`eleme.order.getAllOrders`
- **数据范围**：支持查询近90天订单
- **授权方式**：OAuth 2.0
- **申请路径**：开放平台控制台 → 创建应用 → 申请L3授权

### 2.3 京东到家/京东秒送商家后台

#### 数据导出功能
- **入口**：`京东外卖商家中心 → 财务管理 → 账单下载 → 餐饮专用 → 账单导出`
- **导出内容**：订单明细、结算账单
- **导出格式**：Excel（加密文件，密码短信发送）
- **时间跨度**：最长31天
- **每日限制**：同一导出类型每天最多10次

#### API能力（开放平台）
- **接口**：`https://openapi.jddj.com/djapi/order/es/query`
- **授权方式**：OAuth
- **数据范围**：近一年订单（未完成订单不受限制）

### 2.4 麦芽田平台

根据麦芽田开放平台官网（maiyatian.com），其定位为**聚合配送平台**：
- **订单管理开放平台**：将订单推送至麦芽田管理、打印、配送
- **聚合配送开放平台**：提供配送能力接口
- **关键限制**：麦芽田是接收方（接收来自美团等平台的订单推送），不是数据源方
- **结论**：麦芽田**不能作为订单数据来源**，无法导出第三方平台订单

### 2.5 花集通

作为鲜花行业聚合配送平台，与麦芽田类似：
- 接收各平台订单推送
- 不提供订单导出API
- 定位是配送履约，非数据管理

## 三、技术方案选型

### 3.1 RPA技术方案对比

| 技术方案 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| **Playwright** | 性能最优（比Selenium快46%）、自动等待机制、内置调试工具 | 需编程能力 | 开发者自建RPA |
| **Selenium** | 生态成熟、多浏览器支持 | 配置复杂、性能较低 | 复杂跨浏览器场景 |
| **Puppeteer** | Chrome原生支持、API简洁 | 仅限Chromium | 快速原型开发 |
| **八爪鱼RPA** | 云端执行、电商模板丰富、定时任务 | 订阅制收费 | 企业级电商数据采集 |
| **影刀RPA** | 多系统集成强、BI对接完善 | 学习成本 | 数据整合场景 |
| **实在智能** | RPA+AI结合、非侵入式采集 | 收费较高 | 大型电商企业 |

#### 方案B：商业RPA工具（八爪鱼RPA）

**适用场景**：团队无开发能力，追求快速上线

**优势**：
- 内置电商平台采集模板
- 云端7×24小时执行
- 支持定时任务和数据推送
- 监控看板和异常告警

**配置要点**：
1. 创建美团、饿了么、京东到家采集流程
2. 配置定时任务（T+1日9:00执行）
3. 设置数据推送至数据库或Excel

## 四、增量同步策略设计

### 4.1 数据采集频率

| 业务场景 | 推荐频率 | 说明 |
|---------|---------|------|
| 订单数据同步 | 每小时或每日 | 订单完成后再采集，避免状态未最终确定 |
| 对账数据同步 | T+1日 | 次日采集前一日完整账单 |
| 实时监控（可选） | 每15分钟 | 高峰期可缩短间隔 |

### 4.2 增量同步机制

```
┌─────────────────────────────────────────────────────────┐
│                    增量同步流程                           │
│                                                          │
│  1. 记录上次同步时间点（last_sync_time）                  │
│  2. 采集时只拉取 last_sync_time → now 的订单             │
│  3. 对比订单号（order_id）去重                            │
│  4. 更新同步时间戳                                        │
│  5. 异常时回退至上一成功节点                              │
└─────────────────────────────────────────────────────────┘
```

### 4.3 断点续传设计

- 记录每次采集的订单ID范围
- 失败后从断点恢复
- 保留7天采集日志
- 人工确认机制（重要订单）

## 六、风险评估与应对

### 6.1 风险矩阵

| 风险类型 | 概率 | 影响 | 等级 | 应对措施 |
|---------|-----|-----|------|---------|
| 账号封禁 | 中 | 高 | 🔴高 | 低频采集、使用主账号、备用账号 |
| IP被封 | 低 | 中 | 🟡中 | 代理IP池、控制请求频率 |
| 验证码拦截 | 高 | 中 | 🟡中 | 人工介入机制、滑块识别 |
| 数据缺失 | 低 | 高 | 🟡中 | 校验机制、补采逻辑 |
| 合规风险 | 中 | 高 | 🔴高 | 仅采集自有账号数据、不传播 |

### 6.2 账号安全策略

**合规要点**：
1. **仅采集自有账号**：使用本人/本店注册的商家账号
2. **遵守平台规则**：《美团平台服务协议》明确禁止未经授权的自动化抓取
3. **控制采集频率**：
   - 单IP请求≤5次/秒
   - 单次任务间隔≥10分钟
   - 每日采集≤10次
4. **账号隔离**：RPA账号与日常运营账号分离

**美团规则要点**（据美团规则中心）：
- 未经美团事先书面许可，不应自行或授权、协助任何第三方非法抓取
- 违规抓取可导致账号封禁、API权限永久取消
- 严重违规可能追究法律责任

### 6.3 技术层面风险控制

```python
class SafeCrawler:
    """安全爬虫基类"""
    
    def __init__(self):
        self.request_interval = 3  # 请求间隔3秒
        self.daily_limit = 8       # 每日最多8次
        self.retry_count = 3       # 重试3次
        
    async def safe_request(self, url):
        """带频率控制的请求"""
        await asyncio.sleep(self.request_interval)
        # 检测验证码
        if await self.detect_captcha():
            raise CaptchaException("验证码拦截，需要人工处理")
        return await self.request(url)
```

### 6.4 应急响应

| 触发条件 | 响应动作 |
|---------|---------|
| 账号登录失败 | 发送告警通知，暂停采集 |
| 连续验证码 | 人工介入，输入验证码后继续 |
| IP被封 | 自动切换代理IP，继续任务 |
| 数据异常 | 记录日志，次日人工核对 |

## 八、替代方案建议

### 8.1 聚合订单管理系统

考虑使用成熟的多平台订单管理系统（如**风吹 MSP**、**巨客云**等），这类系统：
- 已与各平台完成API对接
- 提供统一的订单管理界面
- 支持导出和API对接

### 8.2 寻找合规数据接口

- **美团商家版API**：联系美团BD，4家门店可申请测试权限
- **饿了么开放平台**：完成企业认证后可直接申请
- **京东到家开放平台**：无门店数量限制

### 8.3 线下数据同步

对于核心数据，可采用半自动化方案：
- 每日人工导出 → Excel → 导入ERP
- 降低RPA使用频率，减少账号风险

## 九、总结与建议

### 9.1 方案推荐

| 优先级 | 方案 | 理由 |
|-------|------|------|
| ⭐⭐⭐ | 饿了么/京东API对接 | 合规、稳定、无门槛 |
| ⭐⭐ | 商业RPA（八爪鱼） | 快速上线、维护省心 |
| ⭐ | 自建Playwright RPA | 完全可控、但有合规风险 |

### 9.2 关键决策点

1. **美团数据**：建议使用「每日手动导出+导入ERP」的保守方案
2. **饿了么/京东**：可尝试API对接或RPA自动化
3. **RPA频率**：每日≤3次，间隔≥2小时
