# 麦芽田对接自研ERP — 技术实现方案

## 结论先行

**麦芽田可以通过API对接到自研ERP，且已有第三方ERP跑通先例。**

核心架构：

```
美团/饿了么/淘宝闪购/抖音
        │
        ▼
   麦芽田（订单聚合+配送调度）
    │           │
    │ ①开放平台API│ ②Webhook回调
    ▼           ▼
   自研ERP ←────┘
```

## 一、麦芽田开放平台能力确认

据[麦芽田开放平台](http://www.maiyatian.com/open.html)，提供**三类开放接口**：

| 开放平台 | 方向 | 核心能力 | 与你的需求关系 |
|---------|------|---------|--------------|
| **订单管理开放平台** | 外部→麦芽田 | 将订单推送至麦芽田，实现一站式管理/打印/配送，**数据安全、数据回传、无缝衔接、全自动化** | ⭐ 最核心——美团订单流入麦芽田 |
| **聚合配送开放平台** | 麦芽田→外部 | 以接口形式提供聚合配送能力（配送绑定、配送设置），数据实时回传 | ⭐ 核心——配送数据可回传到你的系统 |
| **配送开放平台** | 双向 | 标准接口对接，获取上游外卖订单，**订单数据推送、配送数据回传** | ⭐ 核心——订单+配送双向流转 |

**关键确认**：麦芽田官方明确写了"数据回传"和"订单数据推送、配送数据回传"，这意味着数据可以回流到你的ERP。

## 二、已有ERP对接先例：139ERP（博远ERP）

据[139ERP麦芽田接口文档](https://help.139erp.com/docs/mindoc/mindoc-1hbbojhm5kmh5)（2026年5月更新），博远ERP已完整跑通与麦芽田的对接：

### 2.1 对接流程

```
1. 麦芽田分配接口地址 + 密钥（AppKey/AppSecret）
2. ERP配置接口状态（开启/关闭）、启用时间
3. ERP同步仓库/门店信息到麦芽田（城市编码、地址、经纬度、物品类别等）
4. 麦芽田审核门店资质
5. 开始派单 → 麦芽田配送 → 配送状态自动回传到ERP
```

### 2.2 已实现的功能

| 功能 | 实现方式 | 说明 |
|------|---------|------|
| **门店同步** | ERP→麦芽田推送 | 仓库ID、城市编码、地址、经纬度、物品类别、指定配送方 |
| **自动派单** | ERP触发→麦芽田执行 | 勾选出库单→派单→麦芽田调度骑手 |
| **配送状态追踪** | 麦芽田→ERP回传 | 派送单号、骑手信息、轨迹状态、取消原因 |
| **取消订单** | ERP→麦芽田 | 预取消试算违约金→确认取消→麦芽田执行 |
| **门店信息更新** | ERP保存时自动同步 | 已同步门店修改后保存即自动更新到麦芽田 |

### 2.3 关键技术细节

**接口配置字段**：
- 接口状态（开启/关闭）
- 启用时间
- **接口地址**（由麦芽田分配）
- **密钥**（AppKey/AppSecret，由麦芽田分配）

**门店同步必填字段**：
- 城市编码、手机号码、门店地址、门店经度、门店纬度、物品类别、坐标类别

**配送状态回传字段**：
- 派送单号、骑手姓名、骑手电话、配送轨迹状态、取消原因

### 3.2 三种数据获取方式

| 方式 | 实时性 | 实现难度 | 数据完整性 | 推荐度 |
|------|--------|---------|-----------|--------|
| **① 开放平台API拉取** | 高（准实时） | 中 | 全量 | ⭐⭐⭐⭐⭐ |

### 3.3 方式一：开放平台API拉取

**申请流程**：

```
Step 1: 准备信息
  - 应用名称、应用图标（SVG 128x128）
  - 公司名称、公司地址
  - 技术负责人及联系方式
  - 邮箱（接收重要信息）
  - 正式回调地址域名
  - 测试回调地址域名
  - 授权回调地址
  - 麦芽田账号
  - 三方店铺名称

Step 2: 联系麦芽田客服/商务，提交上述信息
  → 审核通过后，麦芽田官方发送AppKey/AppSecret到邮箱

Step 3: 配置对接
  - 在ERP中配置接口地址 + AppKey/AppSecret
  - 同步4家门店信息到麦芽田（禅城/华师/越秀/天河）
  - 等待门店资质审核通过

Step 4: 测试验证
  - 下单测试推送至麦芽田
  - 验证配送状态回传
  - 验证数据完整性
```

**鉴权方式**：

据[看云-麦芽田聚合配送对接](https://www.kancloud.cn/w509778577/xinbanwaimaijiaocheng/3149157)和[CSDN开发者经验](https://ask.csdn.net/questions/8978978)：

```python
# 麦芽田采用 OAuth 2.0 + API Key 混合鉴权
# 对外开放接口：API Key（AppKey + AppSecret）
# 涉及用户数据：OAuth 2.0 授权流程

import hmac
import hashlib
import time

def generate_sign(params, app_secret):
    """签名生成：按key升序排序 → 拼接 → HMAC-SHA256"""
    sorted_params = sorted(params.items(), key=lambda x: x[0])
    param_str = "&".join([f"{k}={v}" for k, v in sorted_params])
    sign = hmac.new(
        app_secret.encode('utf-8'),
        param_str.encode('utf-8'),
        hashlib.sha256
    ).hexdigest()
    return sign

# 请求头
headers = {
    "Authorization": f"Bearer {access_token}",  # 或 ApiKey模式
    "X-Timestamp": str(int(time.time())),
    "X-Nonce": "unique_request_id",
    "Content-Type": "application/json"
}
```

**Token生命周期管理**：
- access_token有效期：约2小时
- 需实现自动刷新机制（过期前3分钟主动刷新）
- 建议封装统一AuthClient，OkHttp拦截器自动注入凭证

### 3.4 方式二：Webhook回调推送

**回调地址配置**（据看云文档）：

| 回调类型 | 用途 | 配置要求 |
|---------|------|---------|
| 正式回调地址 | 生产环境回调接口域名 | HTTPS，支持POST |
| 测试回调地址 | 测试阶段回调接口域名 | HTTPS，支持POST |
| 授权回调地址 | OAuth授权流程回调 | 完整URL |

**你的ERP需要实现的回调接口**：

```python
# 订单状态变更回调
@app.route('/webhook/maiyatian/order', methods=['POST'])
def order_callback():
    data = request.json
    order_id = data.get('order_id')
    status = data.get('status')  # 新单/已确认/配送中/已完成/已取消
    
    # 幂等处理
    if Order.exists(order_id):
        Order.update_status(order_id, status)
    else:
        Order.create(order_id, data)
    
    # 2秒内必须响应
    return {"data": "ok"}

# 配送状态变更回调
@app.route('/webhook/maiyatian/delivery', methods=['POST'])
def delivery_callback():
    data = request.json
    order_id = data.get('order_id')
    
    # 更新配送状态：骑手信息/轨迹/送达时间等
    Delivery.update(order_id, data)
    
    return {"data": "ok"}
```

**回调注意事项**：
- 必须在2秒内响应 `{"data":"ok"}`
- 推送失败会重试（间隔1分钟，共3次）
- 需实现幂等性（订单号作为唯一标识）
- 需验证签名（防止伪造请求）

### 3.5 方式三：报表定时导出（兜底方案）

## 五、关键风险与应对

| 风险 | 说明 | 应对 |
|------|------|------|
| API文档不公开 | 麦芽田API文档需商务审核后提供 | 联系商务时明确索要完整API文档 |
| 系统稳定性 | 有用户反馈偶尔出现系统故障 | 实现本地缓存+重试机制，关键数据不依赖单一源 |
| 数据延迟 | Webhook推送可能有秒级延迟 | 关键场景用API主动拉取作为补偿 |
| 门店审核 | 4家门店需逐一审核资质 | 提前准备好营业执照、门店地址、经纬度等 |
