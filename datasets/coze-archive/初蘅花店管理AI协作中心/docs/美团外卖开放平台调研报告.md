# 美团外卖开放平台完整调研报告

## 执行摘要

**核心结论：**
- 鲜花连锁门店（4家）自研接入美团外卖开放平台存在较高门槛，需要满足"门店量≥30家且日订单量≥1000单"的接入标准【来源：《平台接入标准》-美团技术服务合作中心】
- 对于4家门店的鲜花连锁品牌，目前无法直接申请自研接入，建议采用以下方案：
  1. **方案一（推荐）**：通过第三方服务商（ERP服务商）进行对接，选择支持美团外卖集成的成熟ERP系统
  2. **方案二**：通过美团商家后台手动导出数据，或使用RPA工具实现数据自动化采集
  3. **方案三**：扩大经营规模后（达到30家门店、日订单1000单）再申请自研接入

**关键信息：**
- 官方文档地址：美团技术服务合作中心 https://developer.waimai.meituan.com （餐饮类）/ 美团闪购合作中心 https://tscc.meituan.com （鲜花绿植等零售类）
- 鲜花品类属于闪购业务，应接入闪购合作中心
- API调用费用：基础类接口0.0015元/次，管理类接口0.003元/次（自2022年1月1日起收费）
- 接口频率限制：不同接口限流标准不同，一般在5-80次/秒范围

## 2. 商家自研接入流程

### 2.1 注册与资质要求

**接入标准（鲜花绿植等闪购品类）：**

根据《美团闪购医药好物集市技术服务合作中心》文档，闪购品牌商自研接入标准如下【来源：《美团闪购医药好物集市技术服务合作中心》】：

**一、自研开发者（连锁品牌商家）接入标准**

1. 入驻申请门店为闪购的品牌商，需要有品牌业务ID（需联系品牌经理获取）
2. 暂不提供营业执照为个体户的对接服务
3. 入驻品牌有自研开发能力可申请入驻，需提交以下材料：
   - 产品说明书
   - 软件著作权证书
   - 域名证书

**重要提示：**
- 软件著作权和域名证书的申请主体必须与入驻主体公司保持一致
- 如申请主体不一致，需提供转让证明或公司关联联系证明

**提交方式：**
- 邮件标题：营业执照名称（XXX）入驻闪购品牌商安全材料申请
- 收件人：mt.lingshou.open@meituan.com
- 邮件内容需注明申请对接的模块：商品管理、订单管理、门店管理、订单小票打印、财务管理、营销管理、IM等【来源：《美团闪购医药好物集市技术服务合作中心》】

**餐饮类品牌商接入标准（参考）：**

餐饮类品牌商需满足：
- 门店量≥30家且日订单量≥1000单
- 已与外卖建立长期的增值产品合作，或商家综合经营水平良好（市场口碑、用户满意度、市场覆盖度、服务履约等）【来源：《平台接入标准》】

**对4家鲜花门店的评估：**
❌ 不满足餐饮类接入标准（门店数量和订单量未达标）
⚠️ 闪购类未明确门店数量要求，但需通过品牌业务ID审核，建议联系美团品牌经理确认具体要求

### 2.2 申请步骤全流程

**闪购品牌商对接流程**【来源：《对接流程》】：

```
步骤1：了解对接方案
  ↓
步骤2：创建品牌商企业（需使用多级总账号登录）
  ↓
步骤3：创建品牌商应用
  ↓
步骤4：开发者账号管理
  ↓
步骤5：关联企业（如需）
```

**详细步骤说明：**

**步骤1：联系品牌经理**
- 与美团品牌经理联系，获取：
  - 客户多级总账号对应的客户ID
  - 或品牌多级总账号对应的业务品牌ID
- **重要：** 建议使用绑定门店数量最多的多级总账号，因为应用关联门店的范围由授权账号的门店范围决定

**步骤2：创建品牌商企业**
1. 登录美团闪购合作中心官网，选择"立即入驻"
2. 使用多级总账号（客户总账号或品牌总账号）登录商家端
3. 填写申请人基本信息：
   - 申请人类型（企业法人/企业代理人）
   - 申请人姓名、手机号、电子邮箱
   - 手持身份证照片（清晰拍出人物五官及身份证信息）
   - 身份证号
   - 若为代理人，需上传企业授权证明（加盖公章）
4. 填写企业基本信息：
   - 企业营业执照名称及照片（仅支持中国大陆工商局或市场监督管理局颁发的三合一证照）
   - 营业执照注册号（统一社会信用代码）
   - 营业执照地址、有效期
   - 法定代表人信息及证件照片
5. 提交审核（审核周期：1-5个工作日）

**步骤3：创建品牌商应用**
企业信息审核通过后，创建应用：
1. 填写应用名称（不超过20字）
2. 选择对接ID类型（服务商创建品牌应用，需品牌企业授权）
3. 填写客户ID或业务品牌ID（从品牌经理获取）
4. 上传应用LOGO（可选）
5. 关联开发者
6. 提交审核

**步骤4：品牌方授权**
1. 商家使用对应的手机号码或商家账号登录商家端
2. 进入"合作中心→我的应用"页面
3. 查看待审核应用，点击"去审核"
4. 选择门店授权方式：
   - **账号维度授权**：账号下关联的门店整体授权，新增门店自动授权
   - **门店维度授权**：手动选择需授权的门店，新增门店需手动授权
5. 提交审核

**步骤5：获取开发凭证**
审核通过后，在开发者中心查看：
- appid（应用ID）
- appsecret（应用密钥）

### 2.3 审核周期和注意事项

**审核周期：**
- 企业信息审核：1-5个工作日【来源：《对接流程》】
- 应用审核：1-5个工作日【来源：《对接流程》】
- 上线申请：1个工作日【来源：《平台接入标准》】

**重要注意事项：**

1. **营业执照要求**：
   - 必须使用品牌总部的营业资质进行申请
   - 申请执照需与美团签约的营业执照相符
   - 营业执照须在有效期内，信息清晰完整【来源：《对接流程》】

2. **一个营业执照限制**：
   - 一个营业执照只能以一种身份入驻
   - 且仅支持创建一个企业ID
   - 入驻成功无法更改【来源：《美团闪购医药好物集市技术服务合作中心》】

3. **门店绑定规则**：
   - 同一个品牌的多个美团外卖商家账号下的门店，可通过门店绑定授权工具绑定至同一个应用【来源：《平台接入标准》】
   - 每个单门店仅能绑定到一个应用【来源：《平台接入标准》】

4. **技术服务要求**：
   - 应用正式上线后，需保证有长期的技术支持人员协助维护
   - 日常运营中可能出现需要技术人员协助处理的临时问题【来源：《平台接入标准》】

5. **服务下线**：
   - 不再使用对接服务时，需在应用管理中将已绑定的门店全部解除绑定
   - 并将应用操作下线【来源：《平台接入标准》】

### 2.4 沙箱环境/测试环境说明

**预发单接口测试：**
- 支持模拟发单参数，确定美团是否可配送，并实现发单信息预览
- 测试门店的shop_id固定为 `test_0001`，仅用于对接时联调测试【来源：《预发单接口-美团技术服务合作中心》】

**注意：** 文档中未明确说明是否提供独立沙箱环境，建议在申请接入时向美团官方技术支持确认。

## 3. 核心API接口详解

### 3.1 订单类API

#### 3.1.1 推送已完成订单（status=8）

**接口说明：**
用于接收订单状态变更为"已完成"(status=8)的消息回调【来源：《推送已完成订单-美团技术服务合作中心》】

**请求方式：** POST（美团向商家推送）

**请求地址：** APP方URL（商家需在开发者中心配置回调地址）

**关键参数：**

| 参数名 | 类型 | 是否必填 | 描述 |
|-------|------|---------|------|
| order_id | long | 是 | 订单号，数据库用bigint(20)存储 |
| wm_order_id_view | long | 是 | 订单展示ID，与用户端、商家端订单详情展示一致 |
| app_poi_code | string | 是 | APP方门店id |
| wm_poi_name | string | 是 | 商家门店名称 |
| recipient_address | string | 是 | 订单收货人地址 |
| recipient_phone | string | 是 | 订单收货人联系电话（可能为隐私号） |
| logistics_code | string | 是 | 订单配送方式（需订阅字段"22 配送方式"） |

**订单状态参考值：**
- 1：用户已提交订单
- 2：向商家推送订单
- 4：商家已确认
- 8：订单已完成
- 9：订单已取消

**注意事项：**
- 商家系统收到推送消息后，需在2秒内响应
- 正确响应内容为 `{"data":"ok"}`
- 推送失败会每隔一分钟重试，共重试3次
- 订单脚印仅支持查询近30天内的订单记录

#### 3.1.2 获取未接单订单

**接口说明：**
获取某个app下最近8分钟内，超过2分钟没有完成接单的订单【来源：《获取未接单订单-美团技术服务合作中心》】

**请求方式：** POST

**请求地址：**
- 正式环境：`https://api-open-cater.meituan.com/waimai/ng/order/getUnConfirmedOrders`

**关键参数：**

| 参数名 | 类型 | 是否必填 | 描述 |
|-------|------|---------|------|
| pageNo | int | 是 | 分页页码，从1开始 |
| pageSize | int | 是 | 分页大小，不能超过1000 |

**调用频率限制：**
- 5次/分钟（或达到平台总限制）

**注意事项：**
- 此接口返回的数据为快照，非准实时状态
- 可能包含状态为非新订单的订单
- 开发者不应该存储接口返回的值作为后续统计等其他用途
- 应自行判断订单状态做幂等处理

#### 3.1.3 商家确认订单

**接口说明：**
商家收到新订单消息后，可操作接单【来源：《订单接口接入方式-美团闪购医药好物集市技术服务合作中心》】

**请求方式：** POST

**应用级参数：**
- 订单ID
- 确认操作

**注意事项：**
- 此接口为必接接口（美团配送模式）

### 4.4 回调验签机制

**签名生成方式：**

## 5. 鉴权与安全

### 5.1 OAuth2.0授权流程

**第三方业务授权流程（服务商模式）**【来源：《第三方业务授权-美团技术服务合作中心》】：

```
步骤1：入驻技术合作中心并申请业务权限
  获取developerId及SignKey、businessId及API权限
  ↓
步骤2：业务授权URL拼装
  https://open-erp.meituan.com/general/auth?developerId=xxx&businessId=xxx&...
  ↓
步骤3：美团商家授权流程
  商家登录→选择数据资源→选择授权主体→确认授权
  ↓
步骤4：获取authorization_code
  回调接口接收授权码（有效期10分钟）
  ↓
步骤5：使用authorization_code换取access_token
  POST https://api-open-cater.meituan.com/oauth/token
```

**授权URL示例：**
```
https://open-erp.meituan.com/general/auth?developerId=100602&timestamp=1577772770&charset=UTF-8&businessId=17&sign=acce9f196f609952b3194bd4e164c340247c39ee&state=test
```

**授权URL注意事项：**
- 有效时间：24小时
- 授权后需在24小时内发起获取access_token的请求【来源：《第三方业务授权-美团技术服务合作中心》】

### 5.2 API签名算法

**签名计算步骤（HMAC-SHA256）**【来源：《Java程序员如何对接美团接口-平易客配送系统》】：

```python
import hashlib
import hmac
import time

def generate_sign(params, app_secret):
    # 1. 按key升序排序
    sorted_params = sorted(params.items(), key=lambda x: x[0])
    # 2. 拼接字符串
    param_str = "&".join([f"{k}={v}" for k, v in sorted_params])
    # 3. HMAC-SHA256加密
    sign = hmac.new(app_secret.encode('utf-8'),
                   param_str.encode('utf-8'),
                   hashlib.sha256).hexdigest()
    return sign
```

**注意事项：**
- 所有参数必须URL编码
- 空值参数不可忽略
- 时间戳须精确到秒，与美团服务器时间偏差不得超过10分钟（部分文档说是15分钟）
- nonce需每次请求唯一【来源：《PHP实现美团点评团购券对接》】

### 5.3 Token管理

**关键概念**【来源：《美团闪购医药好物集市技术服务合作中心-商家自授权》】：

| 概念 | 作用 | 默认有效期 |
|-----|------|-----------|
| access_token | 访问资源接口的令牌，需附加到请求参数中 | 30天 |
| refresh_token | 刷新获取新的access_token | 180天 |
| authorize_code | 获取access_token的凭证 | 1小时 |
| sig签名 | 参数签名，使用appid和appsecrect进行MD5加密获得 | 不涉及 |

**Token获取方式：**

1. **快捷接口**：
   - 调用 `/api/v1/oauth/authorize`，参数response_type=token
   - 直接获取access_token

2. **标准接口**（OAuth2.0兼容）：
   - 步骤1：调用 `/api/v1/oauth/authorize`，参数response_type=code，获取授权码
   - 步骤2：调用 `/api/v1/oauth/token`，参数code为上一步获得的授权码，换取access_token

**Token刷新：**
- access_token过期时，使用refresh_token获取新的access_token
- 刷新后，旧的refresh_token失效，同时下发新的refresh_token

**注意事项：**
- 授权完成后，应用接入方需要在24小时内发起获取access_token的请求，超时将不能获取

## 6. 对接到自研ERP的技术方案

### 6.1 数据同步架构建议

**方案对比：**

| 同步方式 | 优点 | 缺点 | 适用场景 |
|---------|-----|------|---------|
| **实时推送（Webhook）** | 数据实时性高，延迟低 | 依赖网络稳定性，推送失败需重试 | 订单状态变更、配送状态变更 |
| **定时拉取** | 实现简单，可自主控制频率 | 实时性差，可能遗漏数据 | 历史订单查询、账单数据 |
| **混合模式（推荐）** | 兼顾实时性和可靠性 | 实现复杂度高 | 核心业务数据（订单、配送） |

**混合模式架构：**

```
美团平台
  ├─ Webhook推送（实时）
  │   ├─ 订单状态变更 → ERP接收 → 处理业务逻辑
  │   └─ 配送状态变更 → ERP接收 → 更新配送信息
  │
  └─ 定时拉取（补偿）
      └─ 定时任务（每30分钟） → 调用订单列表接口 → 对比本地数据 → 补充遗漏订单
```

**实现建议：**
- **主推备拉**：通过配置HTTPS回调地址接收美团推送的JSON格式订单数据，同时在服务端部署异步轮询程序，每30秒扫描增量订单【来源：《第三方如何接入美团外卖平台，零点校园系统一键无缝对接》】
- **幂等性设计**：通过订单编号作为唯一标识，将已处理的订单ID存储至Redis缓存中，重复请求直接返回成功响应【来源：《Java如何接入美团》】

3. **数据一致性保障**：
   - 使用数据库事务确保数据原子性
   - 实现幂等性，避免重复处理相同订单
   - 定期对账，对比美团平台数据和ERP数据

**监控与告警：**
- 接口调用成功率监控
- 接口响应时间监控
- 数据同步延迟监控
- 异常错误告警（短信、邮件）

- 订单数据：订单量、订单金额、平均客单价等
- 用户数据：新客数量、回头客比例、用户评价等
- 财务数据：收入、支出、结算详情等
- 运营数据：促销活动效果、商品销售排行等

**优点：**
- 无需编程，操作简单
- 适合数据需求量不大的商家
- 无需通过审核

**缺点：**
- 手动操作，效率低
- 无法实现实时同步
- 数据格式可能需要二次处理

**适用场景：**
- 临时数据分析需求
- 月度/季度财务对账
- 小规模商家

### 8.2 第三方SaaS对接

**优点：**

**缺点：**
- 需支付服务费用
- 数据存储在第三方平台
- 定制化能力有限

**适用场景：**
- 无自研团队或自研能力不足
- 希望快速上线
- 愿意支付服务费用

### 8.3 RPA自动化工具

**开源项目：**
- waimai-crawler：外卖订单自动化采集神器，支持美团、饿了么、百度外卖【来源：《外卖订单自动化采集神器:3步实现美团饿了么订单数据自动汇总-CSDN博客》】

**优点：**
- 无需通过官方审核
- 可定制化程度高

**缺点：**

**法律风险提示：**

**适用场景：**
- 仅作为临时解决方案
- 非商业化用途
- 研究学习目的

### 8.4 美团外卖开放平台 vs 美团企业版 vs 美团配送开放平台

| 对比维度 | 美团外卖开放平台 | 美团企业版 | 美团配送开放平台 |
|---------|----------------|-----------|----------------|
| **定位** | 商家对接外卖订单系统 | 企业消费管理平台 | 配送能力开放平台 |
| **目标用户** | 外卖商家 | 企业客户（B端） | 有配送需求的商家/企业 |
| **核心功能** | 订单管理、商品管理、门店管理、配送管理 | 用餐、差旅、用车、福利采购等一站式企业消费管理 | 配送下单、配送状态查询、骑手管理 |
| **数据范围** | 仅限自家门店的外卖订单数据 | 企业员工的消费数据 | 配送订单数据 |
| **费用** | API调用收费（基础类0.0015元/次） | 企业服务费，具体需咨询 | 配送费用+可能的API费用 |
| **适用场景** | 连锁品牌商家对接自研ERP系统 | 企业管理员工消费（餐补、差旅等） | 需要调用美团配送能力的商家 |

**美团企业版特点：**
- 面向企业端的消费管理平台，提供用餐、差旅、用车、福利采购等服务【来源：《助力企业消费数字化转型，美团企业服务"加速度"-新华网》】
- 支持与财务系统、HR系统对接，实现数字化报销【来源：《【公司动态】超过90%企业给餐饮供给打高分!上百位美团企业版用户深度调研》】
- 提供100%覆盖的配送能力和海量商家供给【来源：《美团企业版-企业餐补\|美团酒店\|美团打车\|商务差旅一站式管理平台》】

**结论：**
对于鲜花连锁门店对接美团外卖订单数据的需求，应选择**美团外卖开放平台**（具体为美团闪购合作中心），而非美团企业版或美团配送开放平台。

## 9. 核心结论与建议

### 9.1 核心结论

1. **接入门槛较高**
   - 餐饮类自研接入需满足：门店量≥30家且日订单量≥1000单【来源：《平台接入标准》】
   - 鲜花品类属于闪购业务，需通过品牌业务ID审核，需提供软件著作权证书和域名证书【来源：《美团闪购医药好物集市技术服务合作中心》】

2. **4家门店无法直接自研接入**
   - 无法满足餐饮类接入标准
   - 闪购类需联系品牌经理确认具体要求
   - 即便申请通过，接入周期较长（企业审核1-5工作日，应用审核1-5工作日，上线审核1工作日）

3. **API调用成本较低**
   - 基础类接口0.0015元/次，管理类接口0.003元/次
   - 小规模商家（4家门店）月费用预计20-40元

4. **技术实现复杂度适中**
   - 提供OAuth2.0标准授权流程
   - 需实现签名算法、Webhook回调、幂等性处理
   - 建议采用混合模式（实时推送+定时拉取）

### 9.2 针对鲜花连锁门店的建议方案

**方案一：第三方SaaS对接（推荐）**

**优点：**
- 无需自研，快速上线
- 无需通过美团审核
- 享受专业运维支持

**操作步骤：**
1. 调研市场上支持美团外卖集成的ERP服务商（如银豹等）
2. 选择符合需求的SaaS服务
3. 购买服务并完成配置
4. 通过SaaS系统同步数据到本地ERP

**预估成本：**
- SaaS服务费：具体需咨询服务商
- API调用费：按实际调用次数计算

**方案二：美团商家后台手动导出**

**优点：**
- 完全免费
- 无需任何技术对接
- 无审核门槛

**缺点：**
- 手动操作，效率低
- 无法实现实时同步

**适用场景：**
- 临时数据分析需求
- 月度/季度财务对账

**方案三：扩大规模后自研接入**

**前提条件：**
- 门店数量达到30家以上
- 日订单量达到1000单以上
- 具备自研团队和软件著作权

**预估周期：**
- 资质审核：1-5工作日
- 应用审核：1-5工作日
- 开发对接：2-4周（取决于团队经验）
- 上线审核：1工作日

**预估成本：**
- 开发成本：人力成本
- API调用费：按实际调用次数计算

### 9.3 准备工作清单（如选择自研接入）

**资质材料：**
- [ ] 营业执照（三合一，在有效期内）
- [ ] 法定代表人身份证（正反面）
- [ ] 软件著作权证书（申请主体需与营业执照主体一致）
- [ ] 域名证书（申请主体需与营业执照主体一致）
- [ ] 产品说明书
- [ ] 企业授权证明（如为代理人申请）
- [ ] 手持身份证照片（清晰拍出人物五官及身份证信息）

**技术准备：**
- [ ] 搭建HTTPS服务器（端口80或443）
- [ ] 开发签名算法（HMAC-SHA256或MD5）
- [ ] 实现OAuth2.0授权流程
- [ ] 开发Webhook回调接口
- [ ] 实现幂等性处理机制
- [ ] 配置数据库表结构（订单、商品、配送等）
- [ ] 开发异常处理和重试机制

**联络准备：**
- [ ] 联系美团品牌经理，获取品牌业务ID
- [ ] 获取客户多级总账号或品牌多级总账号
- [ ] 确认门店绑定方式（账号维度授权/门店维度授权）

**测试准备：**
- [ ] 准备测试门店shop_id（test_0001）
- [ ] 准备测试用例（订单创建、接单、配送、完成、取消等）
- [ ] 配置沙箱/测试环境（如需）

### 9.4 风险提示

1. **审核不通过风险**
   - 门店数量或订单量不达标
   - 资质材料不齐全或不符合要求
   - 软件著作权主体不一致

2. **技术风险**
   - 接口变更导致系统失效（平台年均3次重大升级）【来源：《第三方如何接入美团外卖平台》】
   - 频率限制导致请求失败
   - 网络波动导致数据丢失

3. **合规风险**
   - 使用非公开接口可能违反平台协议
   - 数据存储需符合《个人信息保护法》要求【来源：《平易客配送系统与主流外卖平台API对接技术要点》】
   - 不得将用户数据用于非法用途

4. **业务风险**
   - API故障导致订单同步失败
   - 数据不一致导致财务对账问题
   - 缺乏技术支持导致问题无法及时解决
