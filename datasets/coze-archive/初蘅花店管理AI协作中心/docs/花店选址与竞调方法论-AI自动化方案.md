# 花店选址与竞品调研方法论提炼 — 及AI自动化方案

> 日期：2026-06-02 | 基于禅城店/华师店/越秀店/天河店4门店竞调数据 + 行业调研

---

## 一、当前人工调研的现状分析

### 1.1 调研内容还原

从4张图片中提取，当前代运营人员的调研包含两个层级：

**层级1：店铺基础画像（表格化）**

| 维度 | 指标 | 数据来源 |
|------|------|----------|
| 销售规模 | 月售量 | 外卖平台前端 |
| 质量评价 | 前端评分 | 外卖平台前端 |
| 商品丰富度 | 商品数量 | 外卖平台前端 |
| 价格策略 | 满减活动（阶梯） | 外卖平台前端 |
| 获客策略 | 新客活动金额 | 外卖平台前端 |
| 配送能力 | 8km内配送费、3km配送时长 | 外卖平台前端 |
| 营业时长 | 实际营业时间 | 外卖平台前端 |
| 营销活动 | 有无神卷活动 | 外卖平台前端 |
| 竞争烈度 | 距离(km) | 外卖平台前端（仅华师店有） |
| 口碑质量 | 爆品好评数 | 外卖平台前端（仅天河店有） |
| 实时热度 | 近24小时单量 | 外卖平台前端（仅天河店有） |

**层级2：爆品深度分析（截图+手动记录）**

| 维度 | 指标 |
|------|------|
| 品名与主题 | 花束名称、场景标签（生日/毕业/送花上） |
| 销量 | 已售数量 |
| 规格 | 枝数/束数 |
| 定价 | 到手价 vs 原价（折扣率） |
| 服务保障 | 坏损包退、新客专享标识 |

### 1.2 当前做法的优缺点

**优点：**
- 覆盖了竞品分析的核心维度（价格、销量、活动、配送）
- 对爆品做了深度拆解，能看到定价策略
- 不同门店分别调研，保留了区域差异

**不足：**

| 问题 | 说明 |
|------|------|
| **指标不统一** | 4个门店的调研维度不一致（禅城/越秀缺"距离"，仅天河有"爆品好评数"和"24h单量"） |
| **无时间序列** | 只拍了一个时间点的快照，无法看趋势变化 |
| **缺乏量化分析** | 满减阶梯没有计算实际折扣力度，爆品折扣率没有自动算出 |
| **缺少自有门店对比** | 只有竞品数据，没有与自有门店的对比分析 |
| **无竞品分档** | 没有区分头部/腰部/尾部竞品，策略应对应有差异 |
| **跨店重复竞品未标记** | "花仙女"在5家门店周边都出现，明显是跨区连锁，但未做专项分析 |
| **效率低** | 人工截图+手动填表，4店×5竞品≈2-3小时/次 |

## 二、4门店竞调数据深度分析

### 2.1 门店竞争环境对比

| 门店 | 竞品数 | 合计月售 | 平均月售 | 平均评分 | 竞争烈度判断 |
|------|--------|---------|---------|---------|-------------|
| **越秀店** | 4家 | 24000+ | **6000+** | **4.65** | 🔴 极高 — 月售量级最大，评分最高 |
| **华师店** | 5家 | 19000+ | 3800+ | 4.44 | 🟡 高 — 月售量大，竞品多且近（最近4.4km） |
| **天河店** | 5家 | 14000+ | 2800+ | 4.48 | 🟡 中高 — 有精细化运营的对手（24h单量91） |
| **禅城店** | 5家 | 7000+ | 1400+ | 4.46 | 🟢 中等 — 月售量级最低，竞争相对温和 |

> **计算说明**：平均月售 = 各竞品月售之和 ÷ 竞品数。原始月售数据取平台展示下限（如"2000+"取2000）。

### 2.2 跨区域连锁竞品识别

**"花仙女鲜花店"** — 全域竞品，出现在4个门店周边（5次出现）：
- 禅城：月售2000+，评分4.4
- 华师：月售5000+/4000+（两家店），评分4.2/4.6
- 越秀：月售9000+，评分4.3
- 天河：月售4000+，评分4.6，24h单量91（最高）

**判断**：花仙女是跨区域鲜花连锁/加盟品牌，线上运营能力极强——商品数600-800+、满减阶梯精细、新客活动5元、神卷活动全开。其越秀店月售9000+是全区最高，天河店24h单量91也是竞品最高。

**"花花来了鲜花店"** — 出现在禅城/华师/天河3家门店周边，月售1000-3000+，评分4.2-4.5，运营能力中等偏上。

**"花花公主鲜花店"** — 出现在华师/天河2家门店周边，月售3000+，评分4.5。

### 2.3 爆品定价策略解码

| 定价特征 | 数据支撑 | 策略解读 |
|----------|---------|---------|
| **原价虚高，到手价极低** | 原价¥188-448，到手价¥53-75，折扣率15-45% | 外卖平台的"锚定效应"策略——高原价制造价值感，大折扣制造紧迫感 |
| **核心价格带集中** | 到手价¥53-75（11-33枝），集中在一个窄区间 | 消费者心理价位在50-80元，这是外卖鲜花的主力成交带 |
| **低枝数引流** | 3枝¥53、1束¥56 | 低价引流款，拉高店铺曝光和转化率 |
| **33枝客单提升** | 33枝¥63-73 | 中等枝数但价格仅比11枝高10-20元，推动消费者"加量不加价" |
| **满减阶梯设计** | 68减1→98减2→128减3→188减4 | 引导消费者凑单至下一阶梯，实际折扣约1.5-2% |

**关键洞察**：外卖鲜花的核心竞争不是"花材成本"，而是**平台算法规则下的定价博弈**——高原价+大折扣=平台算法倾斜+消费者冲动下单。

### 2.4 各门店策略建议（基于竞调数据）

| 门店 | 策略重点 |
|------|---------|
| **越秀店** | 竞品最强（月售9000+），需差异化——避开价格战，主打品质/服务（猪猪和时尚评分4.9是天花板） |
| **华师店** | 竞品距离近（4-6km），配送速度是关键——3km配送38-52分钟，争取38分钟内 |
| **天河店** | 花仙女24h单量91极强——需要分析其爆品结构，针对性设置引流款 |
| **禅城店** | 竞争温和——一号花店24小时营业是唯一威胁，可考虑延长营业时间对标 |

## 三、行业方法论框架

### 3.1 选址分析标准方法论

#### 第一层：宏观商圈评估（GIS + 数据驱动）

| 维度 | 指标 | 数据源 |
|------|------|--------|
| 人口密度 | 常住人口、工作人口 | 统计局/百度慧眼 |
| 消费力 | 人均收入、消费支出 | 统计局/大众点评消费数据 |
| 客流热力 | 日均客流、驻留时长 | 高德/百度热力图 |
| 交通可达性 | 地铁/公交站点密度 | 地图API |
| 业态分布 | 餐饮/零售/写字楼密度 | POI数据 |

#### 第二层：中观行业适配（鲜花零售特有）

| 维度 | 指标 | 说明 |
|------|------|------|
| 婚庆密度 | 周边婚庆公司/摄影工作室数量 | 鲜花大宗需求来源 |
| 商务需求 | 写字楼/酒店/会议中心密度 | 商务花篮/桌花需求 |
| 居住结构 | 小区户数、房价中位数 | 家庭日常消费潜力 |
| 节日敏感度 | 周边2km内学校/商圈密度 | 情人节/毕业季等脉冲需求 |
| 竞品饱和度 | 3km内鲜花店数量及月售量 | 直接竞争压力 |

#### 第三层：微观点位评估（具体选址决策）

| 维度 | 指标 | 说明 |
|------|------|------|
| 可见性 | 临街面宽、招牌可视距离 | 自然客流吸引力 |
| 配送半径 | 3km覆盖小区数/写字楼数 | 外卖订单覆盖能力 |
| 租金效率 | 月租/预估月营收 | 投资回报率 |
| 供应链距离 | 距花材批发市场/冷库距离 | 采购和保鲜成本 |

### 3.2 竞品调研标准方法论

#### 周期性竞调框架（PDCA循环）

```
┌─────────────────────────────────────────────────┐
│  竞调周期：月度为主 + 节日节点专项              │
│                                                  │
│  Plan  ─→ 确定调研范围、竞品名单、核心指标      │
│    ↓                                             │
│  Do    ─→ 数据采集（平台数据+实地暗访）          │
│    ↓                                             │
│  Check ─→ 结构化分析、趋势对比、异常预警         │
│    ↓                                             │
│  Act   ─→ 策略调整、定价优化、活动对标           │
└─────────────────────────────────────────────────┘
```

#### 竞品分析维度（五力模型 × 鲜花行业适配）

| 分析维度 | 鲜花行业指标 | 当前调研覆盖 |
|----------|-------------|-------------|
| **直接竞争** | 同平台同品类竞品的销量/评分/价格 | ✅ 已覆盖 |
| **替代威胁** | 超市鲜花/花艺工作室/直播卖花 | ❌ 未覆盖 |
| **买方议价** | 消费者价格敏感度（满减弹性） | ⚠️ 部分（有满减但无弹性分析） |
| **供应商议价** | 花材价格波动对竞品定价影响 | ❌ 未覆盖 |
| **新进入者** | 新开鲜花店/跨界进入者 | ❌ 未覆盖 |

#### 竞品分档与差异化应对

| 档位 | 判断标准 | 应对策略 | 当前调研是否区分 |
|------|---------|---------|----------------|
| **头部** | 月售5000+，评分4.5+ | 不打价格战，差异化品质/服务 | ❌ 未区分 |
| **腰部** | 月售1000-5000，评分4.3+ | 对标满减+爆品定价，逐步追赶 | ❌ 未区分 |
| **尾部** | 月售<1000，评分<4.3 | 监控但不作为主要对标对象 | ❌ 未区分 |

## 四、AI自动化方案

### 4.1 目标定义

| 维度 | 人工现状 | AI化目标 |
|------|---------|---------|
| 采集频率 | 月度1次，2-3小时/次 | 每日自动采集，5分钟/次 |
| 数据维度 | 10-13个指标，不统一 | 20+指标，全标准化 |
| 分析深度 | 描述性统计，无趋势 | 诊断性+预测性分析，含趋势预警 |
| 报告输出 | 截图+手填表格 | 自动生成结构化报告+可视化看板 |
| 策略联动 | 人工判断调整 | AI推荐定价/活动调整方案 |

### 4.3 各层技术方案详解

#### Layer 1: 数据采集层

| 数据源 | 采集方式 | 采集频率 | 可行性 |
|--------|---------|---------|--------|
| **美团/饿了么 - 竞品列表** | mobile_use 云手机自动化 | 每日 | ✅ 成熟，当前已有云手机 |
| **美团/饿了么 - 爆品详情** | mobile_use + OCR | 每周 | ✅ 可行 |
| **美团/饿了么 - 评价分析** | mobile_use 采集 | 每周 | ⚠️ 需解决翻页 |
| **高德/百度 - POI数据** | API直接调用 | 每月 | ✅ 成熟 |
| **大众点评 - 评价/评分** | fetch_web / browser skill | 每周 | ⚠️ 反爬较严 |
| **小红书/抖音 - 口碑** | mobile_use 搜索 | 每月 | ✅ 可行 |
| **花材批发价** | 内部采集系统（已有） | 每日 | ✅ 已有 |

**采集脚本核心逻辑（mobile_use）：**
```
1. 打开美团APP → 搜索"鲜花" → 切换到"商家"tab
2. 按距离排序 → 逐个进入竞品店铺
3. 采集：店名、月售、评分、商品数、满减、新客、配送费、时长、营业时间、神卷
4. 进入"热销"tab → 采集Top5爆品的品名、已售、规格、到手价、原价
5. 退出 → 下一个竞品 → 重复
6. 切换位置到各门店坐标 → 重复1-5
```

#### Layer 2: 结构化处理层

| 处理步骤 | 技术方案 | 输出 |
|----------|---------|------|
| OCR识别 | read_image / 第三方OCR | 图片→文字 |
| 字段抽取 | LLM结构化提取（JSON schema） | 文字→字段 |
| 标准化映射 | 品类映射表 + 命名归一 | 统一命名 |
| 折扣率计算 | (到手价/原价)×100% | 折扣率字段 |
| 满减弹性分析 | 每档实际折扣率 = 优惠额/消费额 | 满减力度指标 |
| 质量校验 | 跨期对比+异常值检测 | 数据质量标签 |

**关键标准化规则：**
- 月售量归一：`2000+` → `2000`（取下限），`9000+` → `9000`
- 竞品去重：同名店铺+同地址 → 去重；同名不同地址 → 标记为连锁分店
- 距离标准化：统一从"自有门店坐标"计算直线距离

#### Layer 3: 分析引擎层

| 分析模块 | 核心算法 | 输出 |
|----------|---------|------|
| **竞品分档** | K-means聚类（月售×评分） | 头部/腰部/尾部标签 |
| **定价策略分析** | 折扣率分布 + 价格带热力图 | 定价策略报告 |
| **满减弹性** | 每档折扣率 + 凑单引导点 | 满减优化建议 |
| **趋势预警** | 同比/环比变化 + 阈值告警 | 预警通知 |
| **节日预测** | 结合价格波动因子体系 | 节前备货/定价建议 |
| **市场份额估算** | 月售占比推算 | 市场格局图 |

#### Layer 4: 报告与决策层

**月度自动报告结构：**
```
1. 市场概览
   - 各门店竞品数量、平均月售、评分变化趋势
   - 竞品分档及变化
   
2. 重点竞品动态
   - 新增/消失竞品
   - 头部竞品月售/评分/活动变化
   - 跨区域连锁竞品（如花仙女）全域动态
   
3. 爆品追踪
   - 竞品Top5爆品变化
   - 定价策略调整（折扣率变化）
   - 新品上架监测
   
4. 策略建议
   - 满减阶梯优化
   - 引流款定价调整
   - 营业时间/配送覆盖优化
   - 节日备货建议（接入价格波动因子）
```

### 4.4 AI化实施路线

#### 阶段一：半自动化（1-2周，立即可做）

| 任务 | 方式 | 工具 |
|------|------|------|
| 统一调研模板 | 设计标准化表格（15个必填字段） | Excel/飞书表格 |
| mobile_use自动采集 | 云手机自动化抓取竞品列表 | mobile_use |
| read_image批量OCR | 截图→OCR→结构化 | read_image |
| 自动计算指标 | 折扣率、满减力度、竞品分档 | Python脚本 |

#### 阶段二：全自动化（1-2个月）

| 任务 | 方式 | 工具 |
|------|------|------|
| 定时自动采集 | 每日/每周定时触发 | Calendar + mobile_use |
| 结构化入库 | 自动OCR→字段抽取→标准化 | LLM + JSON schema |
| 趋势分析 | 同比/环比+异常检测 | Python + 阈值规则 |
| 自动报告生成 | 模板化+数据填充 | LLM生成Markdown报告 |

#### 阶段三：智能决策（3-6个月）

| 任务 | 方式 | 工具 |
