# 分布式节点通道稳定性评估（2026-08-26）

> 评估对象：黑板协议 v1.0 全通道（heartbeat/tasks/notes/outbox/inbox）
> 方法：中枢侧压测 + 跨节点压测 + 心跳监控

---

## 一、中枢侧压测（黑板 Rust 版）

| 并发 | 总写入 | 耗时 | 吞吐 | 错误 |
|---|---|---|---|---|
| 20 | 1000 | 0.5s | 2094 ops/s | 0 |
| 50 | 2500 | 1.4s | 1813 ops/s | 0 |
| 100 | 5000 | 2.7s | 1867 ops/s | 0 |

**结论**：100 并发 5000 写入 0 错误，稳定 1800-2100 ops/s。压测后黑板 CPU 0.3%、两侧心跳未断。

## 二、跨节点压测（MBP → i9 端到端）

### 链路
```
MBP 写 outbox（to:i9, topic: stab-v2-*）→ MBP node-bridge 转发
→ 黑板 notes/i9/stab-v2-* → i9 node-bridge 读到 → 落盘 i9 inbox
```

### 结果
- 20 条 MBP→i9 消息，抽样 5/5 单键确认全部送达（from=mbp to=i9）✅
- i9 端 inbox 落盘确认（stab-v2-1.json 含 from=mbp）✅
- 0 丢失 / 0 错误
- 批量 30 条 outbox 写入：MBP node-bridge 全部转发（日志 63 条 OUTBOX 200）✅

### 发现问题（非通道问题）
- **notes/ 列命名空间被 genebank 刷屏**（8000+ 键），`limit=80` 拿不到自己的消息——统计时应用单键 GET 或 timeline，不能用 list limit
- Windows 终端 GBK 显示中文乱码（数据本身 UTF-8 正确）

## 四、通道稳定性评级

| 通道 | 方向 | 稳定性 | 说明 |
|---|---|---|---|
| heartbeat | 节点→黑板 | 🟢 稳定 | 60s 标准，压测未断 |
| tasks/queue | 中枢→节点 | 🟢 稳定 | 执行回报全通 |
| notes/coordinator-* | 中枢→节点 | 🟢 稳定 | 订阅/轮询双通道 |
| outbox（to 跨节点）| 节点→节点 | 🟢 稳定 | 20 条全送达 0 丢失 |
| inbox 落盘 | 黑板→节点 | 🟢 稳定 | i9 完整收到 |

**总体评级：🟢 稳定**——全通道在压测下无丢失、无错误、心跳不中断。

## 五、优化建议
1. notes 列表查询：genebank 刷屏导致 limit 取不到自己消息——建议后续黑板支持「按前缀过滤列表」或客户端用单键 GET
2. i9 侧批量压测脚本待 i9 会话激活后补充（当前为中枢驱动）
