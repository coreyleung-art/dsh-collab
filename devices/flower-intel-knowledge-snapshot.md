## 二、核心内容摘要（已读文档要点）

### 110-技术架构：6 层解耦
```
L6 交互输出层   企微审批卡片 + Web后台 + Dify前端
L5 智能决策层   5 大 Dify Agent + Function Calling
L4 AI 编排层    Dify v1.13.2 + 知识库(RAG) + 人工节点
L3 数据整合层   MySQL 8.4(业务) + Obsidian(人工) + ChromaDB(运营RAG) + Milvus(SKU向量)
L2 执行引擎层   FastAPI + Celery + Playwright/mitmproxy
L1 基础设施层   Docker Compose 独立 Stack（零冲突）
```

### 120-对接ERP安全边界（三大铁律）
1. **绝不直连 ERP 数据库**（MySQL 或 PG 都不行）——违反项目永久停摆
2. **所有写操作必须人工审批**（企微卡片点确认才算）——禁止 Agent 自动改价
3. **所有 API 调用四要素**：Token + IP 白名单 + 幂等 Key + 审计日志——缺一拒绝 403
- 对接模式：只读 API（库存/商品/价格/门店）+ 有限写 API（只允许改价/上架商品，每次≤10 条、每日≤3 轮，走企微人工审批）

### 130-Dify Agent 清单（5 Agent + 备用 1）
**全局共享 Function Calling（9 个）**：query_competitor_price（FastAPI→MySQL+Milvus 语义对标）/ query_my_inventory（ERP 只读）/ query_my_sales（ERP 只读）/ run_pricing_formula（毛利率·物流·节日系数）/ send_wecom_approval_card（企微审批卡）/ query_approval_status / apply_erp_batch_price（安全写入）/ chromadb_qa（Obsidian RAG）/ write_decision_log（写决策日志）
- **Agent1 竞品采集分析师**：每 4 小时采集京东/美团/淘宝 TOP20 → 语义对标（Milvus）→ 重大异动推企微告警 → 记录 320-异动
- **Agent2 定价策略师**：Workflow 模式，run_pricing_formula + 竞品区间 → 出建议价 → 触发审批
- Agent3（促销方案/清仓）、Agent4（告警触发，见 620）、Agent5（审批流转）

### 210-基础定价规则（黄金引擎）
- **毛利率下限**：开业花篮 ≥55% / 花束礼盒 ≥60% / 精品高端 ≥65% / 绿植多肉 ≥50% / 清明祭祀 ≥45% / 企业定制 ≥40%
- **熔断底价**：成本 × 1.35~1.60（按品类），低于此价自动拦截需人工审批
- **物流加价**：同城自提 +0 / 3km 内 +15 或 10% / 3-10km +25 或 12% / 10-20km +40 或 15% / 跨城顺丰 +8 冰袋
- **节日系数 7 节 × 5 档**：情人节 ×1.10→×1.80（T-14 至当天）/ 母亲节 ×1.08→×1.70 / 520 ×1.10→×1.75 / 七夕 ×1.08→×1.65 / 清明 ×1.05→×1.45 / 教师节 ×1.05→×1.35 / 圣诞 ×1.08→×1.55（T+1 回落 ×1.00-1.10）
- **周末系数**：周一-四 ×1.00 / 周五 ×1.05 / 周六 ×1.08 / 周日 ×1.06
- **竞品联动**：建议价落「竞品 25-50 分位」区间；品牌连锁可比小店 +8-15%；绝不低于熔断底价；差异化允许 25-75 分位外定价（需决策日志写理由）
- **库存联动**：同款 ≤14 天销量 → 降价 5-15% 清仓（推 Agent3）/ 1-3 天 → 提价 3-8% + 补货提醒 / <1 天 → 自动 CRIT 告警 + 提价 10-20% / 鲜切 7 天内过期 → 立即促销清仓
- **定价公式**：`建议价 = max(熔断底价, min((成本/(1-目标毛利率) + 物流) × 节日系数 × 周末系数 × 对标调整, 竞品75分位×1.05), 竞品25分位×0.98)`（不高于行业最高太多、不低于最低太多）

### 610-改价审批流程（三级）
Agent2 生成建议价 → FastAPI 打包「改价审批单」（对比表+毛利率测算+熔断底价校验）→ 企微自建应用推审批卡片 → 1 级审批（门店经理/区域主管：≤10 条 & 单笔 ≤10%）→ 2 级审批（运营总监：>10 条或单笔 >10%）→ 3 级审批（总经理：单笔 >25% 或触熔断底价）→ APPROVED 后 FastAPI 构造幂等写请求（4 要素）→ ERP 执行

### 620-异常告警处理（分级 SLA）
- **CRIT**（核心节日 SKU 库存告警/竞品降 25%+/写 ERP 失败）：15 分钟首应，2 小时处理，30 分钟未 ACK 升级 2 号人
- **WARN**（降价 15-24%/采集连续失败 2 平台/毛利率异常）：30 分钟首应，当日内，2 小时未处理升级
- **INFO**（新店开业/常规库存预警/节日 T-14 提醒）：当日处理，3 日内，可不升级
- 通知链：@门店运营群 + @区域主管 → 15min 未 ACK → @运营总监 → 30min → @总经理 → 2h 未处理 → 自动拨打电话
- 采集失败分级：1 次重试静默 / 连续 3 次 WARN+暂停平台 / 连续 5 次（推测）→ 人工介入
