### 新增（实现）

- **形态判据**（先分形态，再谈有效性）：`action` / `record` / `feed` / `ack` / `unknown`
  —— 形态判不了必须报 `unknown`，**绝不并入任何一侧**。
- **五态判定**：`closed` / `stale` / `open` / `unknown` / `n/a`，每条附**所依赖的条件量**（`conditions`）与「缺的是什么 + 怎么补」。
- **回复可见性三通道**（本插件唯一的新判据）：
  - 通道 A 卡内指针（中强度）：另有一条条目的 `reply_to` / `in_reply_to` 指向本条；
  - 通道 B 线程记录（强强度）：本条 `thread` 下存在**本条之后**的、来自**非本条发件人**的消息（P0 只读 inbox，不接外部服务）；
  - 通道 C 指针形态（弱强度）：本条 `reply_to` 指向的键/文件仍存在 —— **只作参考，不得据此判 closed**。
  - **载体三分**：短 id / 黑板键 / **空串**（空串按「未提供」处理，不算命中也不报错）。
- **时效**：默认 7 天窗（`--max-age-days` 覆盖，**窗值必打印在输出与理由里**）；支持 ms 载体与 ISO 串载体；ISO 无时区按 **UTC** 解释并**在理由里写明该假设**。
- **四个工具**（名字过命名门，不得改）：`item_validity_check` / `item_validity_batch` / `item_validity_explain` / `item_validity_index_write`。
- **唯一写操作**：索引写 `~/dsh-collab/docs/item-validity-index.json`；`dryRun` 默认 `true`、须 `confirm:true`；写临时文件 → 原子改名 → **写后回读断言**。
- **R7 逐条日志**：`~/dsh-collab/logs/dsh-plugin-item-validity-review-check.log`，每次判一条一行 JSON `{ts,tool,source,shape,state,why,channel,elapsed_ms}`，**判不了（unknown）也写**。
- **R2 `--selfcheck` 三段**：① 能力清单（4 工具 + 只读/可写）② 不该发生路径 **9 条拒绝证明**（真去试，记录被谁拒、什么码）③ 依赖完整性（两级解析 + 符号 + 真挂载冒烟三态）。
- **R10 `--lean4-check` 六项 A–F**：A 真扫 `lib/*.js`（剥注释/字符串/正则后匹配 16 个危险原语 + 危险模块 import，并附正向对照证明扫描器非空判定）；B **14 条**负例；C **8 条**正例；D sha256 写前写后一致；E `Object.isFrozen` 实测 + 真改一次证明拒改；F **12 个**命令调用点，集合非空且 ⊆ `{node}`。
- **`--selftest` 自证矩阵**：**27 条**（16 负例 + 11 正例），含规范点名的 8 条负例。

### 移植纠错（Python 参考实现 v1.0 → v1.2.3 修过的三处缺陷，如实记录）

> 参考实现：`~/dsh-collab/scripts/inbox-validity-check.py`（v1.2.3，已 10 PASS）。
> 该脚本头部已声明「形态与五态判据**以本插件为准**」。以下三处是它在自演进中修掉的缺陷，
> 本插件是**带着修正**移植的，不是照抄初版。

1. **单一窗判记录体 ⇒ `stale 1111 > 动作项 433`**（v1.2.0 修）
   - 症状：一个时效窗同时装「回执」与「待办」，2624 条里 1111 条被判 `stale`，而动作项只有 433 条 —— 即**大部分「过期」根本不是待办**。
   - 根因：用「**会变的量**（年龄）」去判「**不该变的东西**（历史记录）」。
   - 修法：**先分形态**，时效只适用于动作项；记录体/回执/流水一律 `n/a`（其年龄不构成失效理由）。
   - 本插件：判定阶梯第 3 步先切 `n/a`，第 6/7 步才谈时效。实测 2642 条中 `n/a 2105`、`stale 2`。

2. **形态判不了被当成 `n/a`**（v1.2.1 修，**由 selftest 负例抓出**）
   - 症状：认不出形态的条目被并入「不适用」，于是「判不了」被读成「不用管」。
   - 根因：把「**不知道它适不适用**哪种判据」与「它**不适用**判据」当成同一个结论。
   - 修法：形态判不了 ⇒ `unknown`，并写明缺的是哪个形态字段。
   - 本插件：负例矩阵第 4 条（`{}` ⇒ `unknown`，**不得 n/a**）常驻自证；实测 `unknown 101` 条来自形态判不了。

3. **盲区声明与末行报数自相矛盾**（v1.2.x 修）
   - 症状：一边声明「本工具看不到它是否已在会话线程里被回复」，一边把 `open` 报成「仍有未决待办」。
   - 根因：声明的射程与报数的措辞不是同源。
   - 修法：把 `open` 的含义**固定为**【无关闭声明且无可见回复】，并在同一份输出的末尾固定带盲区声明。
   - 本插件：`BLIND_SPOT` 是**模块常量**，四个工具与 CLI 的每条分支都带它；`--selftest` 有一条专门断言它必带。

### 一处**如实标注的口径张力**（未擅自替规范裁决）

规范 §2 的 `open` 定义（动作项、窗内、无关闭声明、无可见回复）与 §3 的合成规则（A/B 都不命中 ⇒ `unknown`，不得报 `open`）在**同一条件**上给出不同结论。本实现按「回复通道是否**可观测**」切分：带 `thread` 的条目查过线程 ⇒ `unknown`；不带 `thread` 的条目无可观测通道 ⇒ `open`（由盲区声明兜底）。两种口径的计数都输出（`tally` / `strictTally`），切换只需 `ctx.strictNoReply = true` 一处。详见 `docs/README.md` 坑 11。
