# 运维硬约束：禁止「起服务绑定端口测试」类操作

> 日期：2026-08-27 · 起因：三次 CLD 崩溃（01:19 / 01:21 / 01:44），全部发生在「起服务绑定端口 + kill 循环」测试后

## 硬约束（违反 = 触发 CLD 崩溃）

**禁止在本机执行以下操作：**
1. ❌ `nohup python3 ... &` 起后台服务（即使 --agent 独立名）
2. ❌ 绑定新端口测试（curl 到 17898/17899 等临时端口）
3. ❌ `kill` launchd 管理域外的测试进程（进程组交互触发 Electron 崩溃）
4. ❌ 大量循环创建进程（for i in ...; do 起服务; done）

## 原因分析

三次崩溃共同点：
- 内存 free 骤降（正常 10万+ 页 → 1.5万 页 ≈ 256MB）
- 起服务绑定端口 → launchd/Electron 进程组交互
- CLD 是 Electron GUI，对进程组/信号/端口变化高度敏感

## 安全替代（以后用）

1. ✅ 编译验证：`cargo build --release`（纯编译无副作用）
2. ✅ 单元测试：`cargo test`（无端口绑定）
3. ✅ 静态审查：读源码/逻辑分析
4. ✅ 黑板只读查询：`curl GET 8792`（不绑定端口）
5. ✅ 文件级验证：写文件/读文件（不涉及进程）
6. ⚠️ 必须真测时：用 launchd 已托管的服务测（不新起），或等用户在场明确批准

## 生效范围

- 本会话 + 所有智能体：Rust/Node/Python 服务改造后**不得在本机起临时服务测试**
- 验证方式改为：编译 + 单测 + 静态审查 + 黑板只读
- 需要运行时验证的改造 → 部署到 i9（Windows 隔离环境）或等用户操作
