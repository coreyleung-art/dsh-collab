### 根因（代码级，一处）

```js
:1193   s.open?panel:null        // ★ 面板【条件渲染】——关着时把手不在 DOM 里
:997    },[s.open]);             // 修复前是 },[]);  ← ★ 依赖数组为空
```

**链路**：
```
首次渲染时 s.open=false
  ⇒ 面板（含把手）不在 DOM
  ⇒ resizeRef.current === null
  ⇒ effect 里 if(!el) return;  【提前返回】
  ⇒ 而 deps=[] ⇒ effect【永不重跑】
  ⇒ ★ 监听器从未注册 ⇒ 用户拖拽没反应
```

**★ 这是「条件渲染 + useEffect([]) + ref 需要元素存在」三者相撞的经典陷阱。**
**★ 语法检查、断言、回归**全都抓不到它** —— 只有真拖一下才知道。**

### 修法

1. **依赖数组 `[]` → `[s.open]`** —— 面板打开时重新绑定监听器
2. **并就地写明为什么**（防后人又改回 `[]`）
3. **加回归守卫**：断言 `},[s.open]);` 存在，且 `resizeRef` 之后不得出现 `},[]);`

**★ 作用域已验证**：`const s=useEng()` 在 `:971`，effect 在 `:972` ⇒ `s.open` 在作用域内（无 TDZ）。

## [0.8.0] - 2026-10-10

### 新增 · 首轮无音频 ⇒ 自动重连并回放（用户裁定的「加重连」）

**背景（当晚实测结论）**：下行音频失败呈【会话级二值】——同一会话要么整场出声、要么整场哑
（生产日志 32 会话 / 73 轮，混合场 = 0）。判别量在**服务端**：两场紧邻会话的客户端
`session.create` 参数逐字相同、结果却相反，且 `session.created` 全量载荷仅 3 字段
⇒ **无法预测**，只能「哑了就重开」。失败率（探针样本内）约 20%/会话。

**行为**：本轮结束若完全没收到下行音频 → **不立即重连**，先等 `FALLBACK_WAIT_MS`（3s）；
窗口内音频到达则取消（**桥的 TTS 兜底稍后才出声，误判会把正常回答变成多余重连**）；
窗口后仍无 → 关旧会话、开新会话、**回放本轮已说的音频**、自动补 commit。
最多重连 2 次（探针样本内覆盖约 96%）。用户无需重说。

### 修复 · 两个由本次开发暴露的缺陷（均已加回归断言）

1. **吞内容**：第一版在「无音频的 done」处直接 `return` 去重连，把正常轮次的内容也吞了
   —— 由 `test-draft-iterate.cjs` 5 项全败暴露。现改为**先落行、再判重连**。
2. **误判正常轮**：见上「兜底窗口」——这是第一版没有的设计。
3. **成功自愈显示成报错**：重连提示原用 `err` 字段，而 `err` 在界面上是**红色 + ⚠️**——
   一次**成功**的自动恢复看着像故障。现新增中性状态行 `note`（灰蓝、无警告图标），
   重连提示改走 `note`；`err` 只留真正的故障。

## 0.3.5 (2026-09-10) 【真·根因修复“没声音”】
- 根因: 每个 audio_delta 分片的 base64 各自带 '=' padding, 客户端**整段拼接后一次 atob** 抛 Invalid character
  - 症状: 面板诊断 收0KB/播0次; 后端+桥收到 400KB+ 音频但客户端解码即崩
  - 复现: `atob(拼接b64)` → Invalid character; `Buffer.from(b64,"base64")` 宽松解码只恢复 4096/412KB(在第一个 padding 停)
  - 实测: 15/15 分片**各自** base64 解码 100% OK(合计 303KB PCM)
- 修复: playAi 改为**逐片解码**累积 Float32(每片=一个独立 audio_delta 的合法 b64); flushAi 拼成整段再按 2s 分段播; 播放前 resume 兜底
- 同时: onBridgeMsg 错误上行到诊断面板(不再空 catch 吞错); playAi 守卫空/非字符串 audio
- 沙箱验证: apply+portal slot OK / 逐片解码(aiSamples.push) OK / flushAi 用 aiSamples OK / 诊断上屏 OK
