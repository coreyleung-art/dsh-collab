## 0.12.7 — 2026-10-10 · 不适用面 ≠ 压不动（判决 C 的问句查出来的第二处）

- **★ 问句**（星桥判决 C 逐字）：「『非单调 ⇒ 不抛出』会不会让已知事故从红变绿？
  **异常不可忽略、返回值可忽略** ⇒ 请自查有无调用方以『未抛异常 = 成功』为判据。」
- **自查结果一（调用方：无此模式）**：两处消费点都经 `accountWrite()`，按**显式字段**判定 ——
  `w.wrote === true` 才算写入；`WIRE_ACTION.CANNOT_SHRINK` / `NOT_APPLICABLE` / 其余各自分支。
  ⇒ **没有**「没抛异常就算成功」的调用方。（本条是**核过**的，不是声称。）
- **★ 自查结果二（查出真缺陷）**：非单调面原先返回 `action='cannot_shrink'`，而 `noticeFor()` 会据此产出一条
  **全零指标的 WARN**（`被遮 0 token · 检查点 0 token · 省 0 · 要求 0`）——**不适用面被冒充成「压不动」**，
  还会多记一次 `cannotShrink`。★ 这正是本线反复出现的「**两种成因同痕**」：模型不成立 与 模型成立但无解，落成同一种记录。
- **修法**：新增动作码 `WIRE_ACTION.NOT_APPLICABLE='not_applicable'`：
  · `decideWrite()` 对 `verdict==='surface_not_monotonic'` 单列该动作码；**一律不产通知**（`noticeFor()` 亦加防御）；
  · `accountWrite()` 单列计数 `notApplicable`（**不混入** `cannotShrink`）；`csx_status.guard.write` 暴露该字段。
- **纯断言 W 组 +2（总 263 → 265）**：动作码为 `not_applicable`（**不**并进 cannot_shrink）· `noticeFor()` 返回 `null`。
  摘要 `sha256=b30df6d414710cd43fc327cae30ac12fa7d42c912d5d6339061c8778f3c1398f`。
- **★ 判据层的对应更正（判决 B）**：`tools/incident-regression.py` 的输出顶部与 INC-07 行**显式声明**
  「**矩阵口径 = 盘面**（harness 均为新进程读盘），**不等于在役**；在役可能是旧版」并给出两条在役核对通道

## 0.12.5 — 2026-10-10 · 真缺陷修复：表面序 ≠ seq 序 ⇒ 原先**抛出**，现改为**不适用面 + 不抛出**

- **★ 缺陷来源**：短判决位（星桥第二任）在役实测 —— `csx_checkpoint` **3/3 报同一错**
  「`entries 必须按 seq 严格升序（2646318≤2646324）`」**字节一致**（⇒ 稳定、非竞态；报错前后 `guard` 全字段恒等 ⇒ **零变更**）。
  器材归本会话，故不待代修，自行定位。
- **机制（离线复现，一次命中）**：任何**表面替换**（官方压缩、工具结果剪枝、本插件将来的写入）都会把**新节点**
  （seq 最大，因为它是后 `append` 的）插到表面**中间位置** ⇒ 此后**表面顺序不再是 seq 升序**。
  复现输入 `nodes = [10, 11, 24, 18, 19]` ⇒ 原实现**抛出**
  `CheckpointError: entries 必须按 seq 严格升序（第 3 条 seq=18 ≤ 前一条 24）`，与在役所见**同一句话**。
- **两件独立的问题，本轮只修前者（后者须裁决）**：
  · **① 契约违反（本件修）**：观察器的契约是「**绝不抛出**」（`lib/replace.js` 文件头自己写的），
    而 `buildReplacement` 在非单调表面上**抛** ⇒ 在役表现就是工具报错。现改为 `ok:false` + 可定位诊断。
  · **② 模型不适用（记录待裁）**：本核按「**seq 升序的连续区间**」建模（handoff 写 `seq-range`、账本按 seq 召回），
    该模型在非单调表面上**不成立** ⇒ 如实判「**本步不动**」，**不硬算**（硬算出来的区间是错的）。
    ★ 支持非单调表面（按**位置**建模）属**设计变更**，须先裁决；本核不擅改。
- **修法**：`lib/replace.js` 新增前置判定 —— 返回冻结的
  `{ ok:false, verdict:'surface_not_monotonic', seqInversion:{index, prevSeq, curSeq}, reason }`，
  原因里点明「该会话发生过表面替换」「本核不适用」「**本步不动**（不是故障，是已知不适用面）」。
- **纯断言（W 组 +6，总 254 → 260）**：非单调 ⇒ **不抛出** · `ok:false` · `verdict` 正确 ·
  原因含「表面替换 / 本步不动」 · **带位置与两侧 seq**（可定位，不是一句人话）·
  ★ **负控**：单调表面**不**被这条拦下（避免误伤正常路径）。摘要 `sha256=ddbb1cd9b35e53cf…`。
- **★ 在役影响与前置（重要）**：活体仍跑 **0.12.4**（本修复要**下次重启**才在役生效）⇒
  在重启前，**发生过表面替换的会话**里调 `csx_checkpoint` 仍会**报那句错**；重启后同样是那个会话，会变成**干净的不适用面 skip**。
