# 中枢自主感知机制（解决「中枢未自主收到信息」）

> 日期：2026-08-27 · 起因：用户多次指出中枢未自主感知 MBP/i9 消息

## 问题根因

- bb-sub 订阅器把消息落盘 `~/.dsh/inbox/bb/coordinator.jsonl` ✅
- 但落盘 ≠ 唤醒中枢会话 → 中枢不自主感知（等用户提醒才查）

## 机制（已上线）

### 1. central-wake 守护（launchd 常驻）
- 每 60s 检查 coordinator.jsonl 新增
- 有新增 → 写触发标记 `data/central/wake-trigger`（含新消息 key/inbox 数）
- launchd: com.dsh.central-wake（KeepAlive）

### 2. 中枢会话行为规则（固化）
每次会话激活/用户发消息后：
1. 先查 `data/central/wake-trigger`
2. 有触发 → 扫 `~/.dsh/inbox/bb/coordinator.jsonl` 处理新消息
3. 处理完 → 清触发标记（写空或标记 processed）

### 3. 配套
- bb-sub coordinator 订阅器（落盘 notes/mac-mini/ + collab/ + central/queue/）
- agent-msg 跨设备消息（notes/<node>/agent-msg-* + data/threads/ 索引）

## 效果

- MBP/i9 发消息 → bb-sub 落盘 → central-wake 写触发 → 中枢下次激活即处理
- 不再等用户提醒「你没收到信息」

## 当前验证（2026-08-27 02:24）

- MBP dsh-tools v1.3.1 测试通过（bb-read/agent-msg 全绿 + bb-proxy 代理）
- i9 测试通过（bb-read/agent-msg 全绿）
- x-chain-test 线程 4 条跨设备消息（三设备双向 ✅）
- central-wake 检测到新消息 → 触发标记已写 ✅
