# CHANGELOG · dsh-plugin-reflect-synthesize

## v1.0.0 · 2026-09-10（首版 · 含跨设备层）

**性质**：每日反思流水线「提炼」（⑤）环节的工具化。把 harvested 的 clusters 提炼成
**待用户裁定的提案** `proposal-<date>.md`。

**定位**：本工具是全流水线里**唯一需要"判断"**的环节，因此纪律是
**规则能定的用规则；规则定不了的显式标 `unclear` 交人工/LLM 复核** ——
硬猜的代价不对称（一个被硬猜成"已有覆盖"的盲区会**连被看见的机会都没有**）。

### 交付
- 插件形态：`package.json` + `cordis.patch.yml` + `lib/index.js`（`inject:['tools']`）注册工具 `reflect_synthesize`
- 四步：① 对照现有库（5 值闭集判定）② 分类归档（7 值闭集）③ **按 `(cross_device, recurrence)` 二元组排序**（跨设备优先）④ 生成「看一眼就能裁」的提案
- ★ **跨设备增量**：排序键升级为二元组；每项显式标 `复现: mac-mini×3 + mbp×1（跨设备 ✅ 3 台）`；同步盘污染项单列且不计入复现
- ⑩ 结构门：**本工具没有写 RULES.md / governance-philosophy.json 的能力**
  （旗标集合运算证明 + 冻结 `WRITE_SPEC` + `guardWritePath` 四道判定 + `--lean4-check` A–F）

### ★ 开发中被自己的检查抓到的四个错误（错误模型复盘）

#### 1. 「必须由 agent 自填规则号」——工具在最该认出新条目的时候瞎了
- **错误模型**：`extends-existing` 要求 cluster 里有人填了规则号/哲学号去引用它。
- **后果**：一个与 `phi-reference-is-copy` 关键词重合 **17** 的 cluster，
  因为 agent 填的是「无」而掉进 `unclear`。而这恰恰是**最该被认出来的情形** ——
  条目是新入册的，agent 还不知道它存在，当然不会去引用它。
- **怎么发现的**：`--json` 里逐项打印判定的**中间量**（`best_match.overlap` / `novelty` / `coverage` / `decisive`），
  看到 `overlap 17` 却判 `unclear`。
- **修法**：去掉"必须自填引用"；改用**决定性**（最佳重合明显领先第二名 = `overlap ≥ max(4, 2×第二名)`）
  + 覆盖率 ≥ 60%（`already-application`）+ `novelty ≥ 4`（`extends-existing`）。
  → 上述 cluster 现在正确判为 `extends-existing`（补维）。

#### 2. bigram 列表直接给用户看 → 渲染层泄漏实现细节
- **后果**：提案里出现「补的是『证证、据要、要标、注采』这一维」—— 看着像乱码，反而让人不敢裁。
- **怎么发现的**：人眼看生成的 proposal 全文（这是"格式必须看一眼就能裁"的直接验证）。
- **修法**：回到**归一化原文**上取连续 fresh 片段 → 输出「注采集时点」「据要标注」这类真词。
  中途还踩了一次：初版从 bigram 反推、只拼 3 个字符丢了中间（实测「前集时」而非「前采集时」），
  于是改为**直接在原文字符串上取子串**。

#### 3. 冲突正则只允许紧邻 → `conflicts` 分支形同不存在
- **后果**：「与 R006 **直接**冲突」因为中间夹了 2 个字而**漏判**。
- **怎么发现的**：**判定分支覆盖自测** —— 造 5 条合成 cluster 逐条断言每个 judgment 分支能被走到。
  第一次跑就红：`conflicts→❌got:new-dimension`。
- **修法**：正则允许 ≤8 个非断句字符间隔；并把 5 分支自测**固化进 `--lean4-check` 的 C 项**
  （"分支从来没被执行过"和"分支写错了"一样危险）。

#### 4. 把合法输入错列进负例（与 harvest 侧同类的第二次）
- **后果**：制造了"永远修不掉的红"，或者诱使后来者去收紧一个**正确**的实现。
- **修法**：修正**我自己的测试期望**。这不是放宽门，是修错测试。

### 已登记的局限（不隐瞒）
- 哲学 vs 规则的取舍是**启发式**（信号词）+ 平手默认哲学；因此**每一项都强制把"选哲学还是选规则"作为用户的裁定项**，并用 `--lean4-check` C 项声明这一点。
- 关键词重合是**字面层**判据，不是语义蕴含。换述/蕴含判断仍需人工 —— 这正是 `unclear` 清单存在的原因。
- 冲突检测**只认显式措辞**；工具不猜语义冲突（猜错的代价是把"其实不冲突"的东西送进裁决）。
- 扫描器是**源码结构扫描，非完整 AST**；命名与输出均如实标注。
