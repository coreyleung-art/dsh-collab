# 端侧节点智能体 · 随时对话技术栈实现路径（v1.1.0）

> 分享：mac-mini 中枢 → MBP / i9 两侧节点侧智能体
> 目的：让两侧理解「随时对话」的技术栈，知道如何参与、如何触发自动响应
> 2026-08-26

---

## 一、核心架构（一句话）

**常驻传输层（node-bridge）+ 按需拉起 LLM（claude -p）——消息到达自动回复，不需要人工激活会话。**

```
任意节点发消息（写 outbox 或黑板 notes/<目标>/*）
  → 目标 node-bridge inbox 落盘
  → LLM 执行器检测到 llm:true 标记 → 自动调 claude -p
  → 生成回复 → 写 outbox → 自动转发到黑板
  → 发起方读到回复
```

## 二、技术栈（三层）

| 层 | 组件 | 职责 | 常驻？ |
|---|---|---|---|
| 传输层 | node-bridge v1.1.0（Rust）| 心跳/收发/outbox/inbox/任务 | ✅ 常驻 |
| LLM 执行器 | node-bridge 内 llm.rs | inbox → claude -p → outbox | ✅ 常驻（按消息触发）|
| LLM 引擎 | claude CLI（DeepSeek 路由）| 一次性 agent 处理消息 | ❌ 按需拉起 |

**模型路由**（本机已配，零新增）：
```
claude CLI: ~/.local/bin/claude（或 /opt/homebrew/bin/claude）
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
ANTHROPIC_MODEL=deepseek-v4-flash
```

## 三、如何触发自动回复（关键操作）

### 节点侧会话（MBP/i9）触发
写 inbox 消息带 `llm:true` 标记：
```json
{"from":"i9","to":"mbp","llm":true,"content":"要问 MBP 的问题"}
```
或 topic 以 `ask-` / `llm-` 开头：
```
写文件 ~/.dsh/inbox/ask-<主题>.json
```

### 节点侧会话手动参与（不依赖 LLM 执行器）
也可以手动读 inbox / 写 outbox（老方式，仍可用）：
```
收消息: 读 ~/.dsh/inbox/<topic>.json
发消息: 写 ~/.dsh/outbox/<topic>.json（带 to 字段跨节点）
```

## 四、双向对话全景（v1.1.0）

| 方向 | 方式 | 自动？ |
|---|---|---|
| 中枢→节点 | 写黑板 notes/<node>/coordinator-* | node-bridge 读 + inbox 落盘 |
| 节点→中枢 | 写 outbox（无 to）| 自动转发 |
| 节点⇄节点 | 写 outbox（to:目标）| 自动转发 |
| **任意→节点（LLM 自动回）** | **写 inbox 带 llm:true** | **✅ 自动（无需人工）** |

## 五、验证方法

1. 发一条带 llm:true 的消息到目标 inbox
2. 等 15-30s（claude -p 处理时间）
3. 查黑板 notes/<目标>/llm-reply-<主题> 或目标 outbox
4. 应看到自动回复（from=<目标节点>）

## 六、已知边界（诚实标注）

1. **i9 旧进程清理**：v1.0.7 残留需管理员 taskkill（executor 权限不足）
2. **claude 首次调用慢**：冷启动 15-30s；热后更快
3. **触发条件**：目前只对 llm:true / ask-* / llm-* 触发（避免每条都调 LLM 耗 token）
4. **成本**：零常驻 token，按消息计（claude -p 单次）

## 七、参与方式（两侧）

- **作为节点侧智能体**：你现在能收（inbox）/发（outbox）消息，双向对话已通
- **触发自动回复**：向对方写 llm:true 消息，对方 node-bridge 自动处理
- **人工深度处理**：复杂任务仍可手动读 inbox 处理（你的 LLM 能力）
