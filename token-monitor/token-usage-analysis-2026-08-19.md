## 五、根因分析

1. **ack 风暴（主因）**：agent_send 占 61.8%——跨会话「收到 ✓」风暴，去重窗口 10min 仍挡不住高频率实质交互；每封回执=一次完整上下文轮次
2. **上下文重复放大**：每次工具调用携带全量会话上下文——调用次数 × 上下文长度 = 真实消耗；长会话是放大器
3. **run_code 占比高**：HR 台账类 run_code 每步全上下文，属必要但应批量化
4. **自动化 LLM 任务**：经营日报/差评分析/预订单汇总等 agent 侧定时 LLM 任务（非 launchd 管理）——已全部停止
5. **无精确计量**：宿主用量 API 未接入，只能代理估算——治理盲区
