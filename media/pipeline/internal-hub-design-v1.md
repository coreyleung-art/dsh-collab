> 维护：媒体专员 session-54e809ed · 2026-08-17 · v1.1（+双轨架构：用户 2026-08-17 决策「专栏分两部分——一个给人看，一个给 AI 自己看」）
> 来源：用户 2026-08-17 决策「不要只留信息流，沉淀为有质量的内部知识资产：视觉内部专栏/智能体播客/论坛网页，记录每个角色的里程碑与报告文件」
> 定位：把碎片化的信息流（总线消息/迭代报告）沉淀为**可浏览、可检索、有质量**的内部知识阵地——角色档案墙 + 大事记时间线 + 报告索引 + 经验沉淀。

## 〇、双轨架构（v1.1 核心）

```
智能体网络内部专栏 hub/
├── human/   # 人类可读版（视觉网页，浏览器打开）
│   ├── index.html     网络概览+协作拓扑+今日大事
│   ├── roster.html    角色档案墙（卡片式）
│   ├── timeline.html  大事记时间线（垂直时间轴）
│   ├── reports.html   报告库（索引）
│   ├── lessons.html   经验沉淀（方法论/踩坑）
│   └── forum.html     论坛（预留）
└── ai/      # AI 可读版（结构化数据，供智能体检索/上下文注入）
    ├── roster.json    角色档案（机器可读：角色/能力/资源/状态）
    ├── timeline.json  事件流（日期/事件/来源/类型）
    ├── reports-index.json  报告索引（路径/属主/日期/摘要）
    ├── lessons.json   经验沉淀（方法论/踩坑/成功模式，结构化）
    └── README.md      AI 消费说明（如何用这些数据）
```

**为什么双轨**：
- **人类看**：需要视觉化、叙事化、一眼看懂网络结构——HTML 网页 + 图表 + 时间线
- **AI 看**：需要机器可读、精确、可检索——JSON 数据可直接被会话读取、注入上下文、做决策；不翻人类网页（网页是给眼睛看的，JSON 是给推理用的）
- **同源双写**：一份数据源 → 生成 human/ 网页 + ai/ JSON，保持一致

## 一、目标与原则

1. **信息流 → 知识资产**：总线消息是流水，本专栏是沉淀——每角色有档案页，每个里程碑有记录，每份报告有索引
2. **有质量的经验**：不止罗列事件，提炼「成就 / 经验 / 方法论 / 踩坑」——可复用的知识
3. **视觉化**：角色协作图（Mermaid）、里程碑时间线、成就统计——一眼看懂网络结构
4. **零维护成本**：静态 HTML（可本地打开/可托管 GitHub Pages），数据从 dsh-collab + agent_profiles 定期导出生成
5. **AI 可消费**：ai/ JSON 是结构化事实源——其他智能体直接读取，作为「网络全景」上下文

## 二、形态选型（三选一或组合）

| 形态 | 说明 | 技术 | 成本 | 适配 |
|---|---|---|---|---|
| **A 视觉内部专栏（网页）** | 角色档案墙+时间线+报告索引+协作图，浏览器打开 | 静态 HTML + Mermaid + 内联样式 | 低（一次搭建，定期更新） | ★★★★★ 首选 |
| B 内部播客（音频） | 每期音频：角色访谈/里程碑解读 | 需 TTS/录音，PC-i9 可渲染 | 中 | ★★★ 二期（视觉专栏稳定后） |
| C 论坛网页 | 按角色/主题分区，可评论 | 需后端（Dify/n8n 可搭） | 中高 | ★★★ 三期（需交互需求） |

**首期建议：方案 A（视觉内部专栏网页）**——零后端、低维护、立即见效；B/C 作为后续演进（播客=内容形态扩展，论坛=交互扩展）。

## 三、专栏结构（信息架构）

```
智能体网络内部专栏（index.html）
├── ① 网络概览（首页）
│   ├── 角色统计（总数/在岗/角色类型分布）
│   ├── 协作拓扑图（Mermaid：会话→资源/协作线）
│   ├── 今日/本周大事（滚动摘要）
│   └── 快速入口（角色档案/时间线/报告库）
├── ② 角色档案墙（roster.html）
│   ├── 每角色一张卡片：角色名/定位一句话/能力清单/资源归属/当前状态
│   ├── 里程碑时间线（该角色做了什么）
│   └── 交付物链接（报告/档案文件）
├── ③ 大事记时间线（timeline.html）
│   ├── 按日期倒序：事件/里程碑/新角色到岗/生产落地
│   ├── 每事件挂来源（迭代报告/广播 id）——可溯源
│   └── 按季度/月份分组
├── ④ 报告库（reports.html）
│   ├── 按角色/类别索引：qa/ research/ media/ devices/ im-reply/ cld-health…
│   ├── 每份报告：标题/日期/属主/一句话摘要/链接
│   └── 可检索（页面内搜索）
└── ⑤ 经验沉淀（lessons.html）
    ├── 方法论：各角色沉淀的 SOP/框架/机制（如外链分级/QA 验收/成长叙事）
    ├── 踩坑实录：事故复盘（如智能客服污染/写冲突/内存 OOM）
    └── 成功模式：可复制的协作模式
```

## 四、数据源与生成机制

| 数据 | 来源 | 更新 |
|---|---|---|
| 角色档案 | agent_profiles（30+ 档案）+ 角色 role 文档（6 份） | 角色变更时 |
| 交付物索引 | ~/dsh-collab/（67 顶层 md + 子目录 50+） | 每周导出 |
| 里程碑事件 | 本稿件库 topics/topic-backlog + 迭代报告 + 协调者广播 | 每日更新 |
| 经验沉淀 | 各角色方法论文档 + QA 验收报告 + 复盘文档 | 每周提炼 |

**生成方式**：媒体专员维护一个数据源（JSON 或 md 索引）→ 生成静态 HTML → 本地打开或托管。首版手工生成，后续可用脚本（n8n/Dify 定时）自动化。

## 五、视觉设计（暗色科技感）

- 配色：深色底 + 青色/紫色高亮（与 AI 主题一致）
- 卡片式布局：角色卡片/事件卡片/报告卡片
- Mermaid 协作图：会话→资源/协作线可视化
- 时间线：垂直时间轴 + 节点图标（角色🆕/里程碑🏆/落地🔧/踩坑⚠️）
- 响应式：桌面为主，移动可读

## 七、与稿件库的关系

- 内部专栏 = **内部知识资产**（不对外）
- 新闻稿件库 = **对外内容资产**（发布用）
- 两者同源（同一事件/报告），专栏是「原始沉淀层」，稿件是「对外输出层」
- 专栏素材可直接喂稿件生产（一鱼两吃）

## 八、Token 成本评估

- P1 骨架：一次生成约 1-2 次大上下文输出（中等 token）——需用户批准
- 后续更新：每周一次导出+生成（低 token，可错峰）
- 计入媒体台账（ROI：内部资产可复用，减少重复调研）
