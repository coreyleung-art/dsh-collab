## T1 · 会话列表空

**现象**：重开 CLD 后左侧会话列表为空 / 只剩新会话；但磁盘 session 文件都在。

**判定**（3 条命令锁定）：
```bash
# ① 磁盘数据是否健康（P6 工具，与 doctor healthy 同口径 191）
#    在 dsh 宿主内: 调 session_recovery_check 工具；命令行: 看 doctor 输出的 healthy 数
#    ⚠️ doctor 的 "sessions":[] 是缓存命中统计(healthy 行不 push) —— 与 UI 会话列表无关！看 healthy 即可

# ② 运行时解析是否指向 runtime（排除版本遮蔽）
node -e "console.log(require.resolve('@deepseek-ai/dsh-session/package.json'))"
#   必须指向 .../dsh-runtime/runtime/node_modules/@deepseek-ai/  (rc.2)
#   若指向 ~/.dsh/profiles/... → 遮蔽，走 T7

# ③ 文件首帧完整性（排除损坏; 191 应全 ok）
#   用 scan-first-frame 扫描: 首帧必须恰含一行 header
```

**根因（实证 v1.1，2026-09-04 深挖）**：分两层——
1. **版本遮蔽**（历史根因，已修）：profile 曾装 rc.6/7 的 dsh-session 系残留遮蔽 runtime rc.2 → 索引空。
2. **renderer 首查时序竞态**（当前偶发根因）：workspace 服务（`ctx.workspaceRegistry`）的 `sessionPersistence` 依赖是**强制**的——官方文档明确 "unavailable persistence peer leaves the plugin **pending** rather than being mistaken for an empty history"；web listen 先于 workspace init 完成时，**首窗 renderer 查询命中 pending → 空列表且不自动重试**；关窗重开（dsh 进程不变）时服务已 active → 正常。实测佐证：磁盘 191 文件首帧全健康、`list()` 全量仅 0.01s（性能非瓶颈）、workspace.json sessionIds=72 从不落盘更新（UI 读内存态）、doctor 的 `sessions:[]` 只是缓存命中统计**与 UI 无关**（勿再被误导）。

**处置**：
```
① 判定数据层健康: session_recovery_check（P6 工具）→ 191 可恢复 = 数据没事
② 判定是竞态而非损坏: 磁盘文件首帧扫描全 ok + workspace.json 正常
③ 【首选·零风险】关窗重开（Cmd+W 后 Dock 重开）或 Cmd+R —— 不重启 dsh
④ 若重启后仍空且数据健康 → 就是竞态复发，重复③
⑤ 勿在数据健康时 mv/删 session 文件 / 改 workspace.json（会真弄丢）
⑥ 根因修复方向（runtime restricted 区，需完整门禁）: 让 UI 会话查询失败自动重试 / workspace init 前置
```
**关键教训**：*会话文件在 ≠ 会话列表有*（数据层 vs 索引层）；*doctor sessions:[] ≠ 会话没了*（缓存统计，看 healthy 数即可）；*重启 ≠ 修复*（竞态下重启可能再踩中，关窗重开即可）。

## T2 · CLD 崩溃 SIGABRT / OOM

**现象**：CLD 无征兆退出；`~/Library/Logs/CLD/` 或 dsh 日志出现 `SIGABRT` / `Fatal process OOM` / `heap limit 4001MB`；exit-marker 显示 `cleanExit:false, reason:"dsh-crash"`。

**判定**：
```bash
cat ~/.cld/logs/*exit-marker* 2>/dev/null      # P0 看门狗产物（有则直接给原因）
ls ~/Library/Logs/CLD/ && tail -100 dsh-web.log # boot 段 / GC / exit-trace
vm_stat; ps aux | sort -rk4 | head -5            # 内存大头是谁
```

**根因（实证 ×6）**：Node/Electron JS 堆上限 **4001MB 硬顶**（`--max-old-space-size` 在打包 Electron 被白名单过滤，官方行为，改环境变量无效）。触发源：① 打开超大 session 全量 zstd 解压；② 启动 doctor 扫描全部 session；③ auto-index 深夜索引 4.2GB chunks。

**处置**：
```
① 查官方: guard-doc-check "electron memory limits node options"   # P0 —— 证明确认 NODE_OPTIONS 白名单
② 停内存大户: launchctl unload com.user.auto-index(保 plist) / kill 索引进程
③ 不重试 NODE_OPTIONS 改堆 —— 已证明无效(官方白名单只放行 2 项)
④ 若反复崩: 查是否全量解压大 session 触发 → 拆/归档超大 session
⑤ C1 boot / C2 web 200 / C4 会话在 / C6 renderer 无新错
```
**关键教训**：*改 Node 堆上限 = 无效路径，勿再试*（Electron fuse `EnableNodeOptionsEnvironmentVariable` 开了但 packaged whitelist 仍拦截 heap flag）。根治 = 减少单进程内存峰值，不是抬高天花板。

## T3 · 内存暴涨（启动/夜间）

**现象**：CLD 一开内存 4-13GB；或每天 04:30 前后内存飙高。

**判定**：`ps aux | grep -E "doctor|auto-index|chromadb"` + `launchctl list | grep auto-index` + `ls -la ~/.dsh/storages/chunks.jsonl*`。

**根因**：`com.user.auto-index` 每日 04:30 对 2.35M chunks / 4.2GB 做向量索引；doctor 启动扫描 189 个 session 全量读。

**处置**：
```
① 官方预查(P0) → ② 停 auto-index(plist 保留可恢复) → ③ 索引脚本改流式/限量(未做前不复启用)
④ C3 data_ok(doctor healthy 不降) / C2 web 200
```

## T4 · 插件报错

**现象细分**（对照症状选路）：
| 报错 | 根因 | 处置 |
|---|---|---|
| `ERR_MODULE_NOT_FOUND @deepseek-ai/dsh-tools` | 插件源码无 dsh-tools 依赖链接 | 源码建 `node_modules/@deepseek-ai/dsh-tools` → 指向 profile 内 rc.2（**WF-3**） |
| `Cannot read properties of undefined (reading 'render')` | defineTool 缺 `output: makeOutput()` | 每个 tool 补 `output`（schema json + render 序列化） |
| 装了不生效/无 UI | 协议不符：须 `__ModuleLoader__.load({factory})` + exports 用 `{default}` 条件对象 | 按 **WF-3** 重写 client 入口 |
| React error #31 / 侧边栏崩 | 手写 `{type,props}` 对象 | 改 `React.createElement`（见 T6） |
| 禁官方插件后显示 "DSH Local Build …" | 官方 plugin 被 disable → fallback 文案 | 改用 shadowing（priority:-1），勿 disable（**WF-3**） |

**通用处置**：
```
① guard-doc-check <插件机制关键词>        # P0：查 dsh-docs 插件协议
② 查 profile package.json deps/bundles 是否登记该插件
③ guard backup 相关 package.json/cordis.patch.yml（P1）
④ 沙箱验证语法（P4）→ 落真 → dump-config 验证配置合并 → 重启
⑤ C1 boot / C4 会话 / C6 renderer 无该插件 error
```

## T5 · web 起不来 / boot 不完整

**现象**：CLD 开了但界面空白/一直 loading；`dump-config` 报错；某插件 "waiting for xxx" 挂起。

**判定**：`dump-config` exit code；renderer 日志（`--enable-logging=stderr` 重启抓）；`cordis.patch.yml` 里最近禁用的插件（曾禁用 ui-reference 治 file-reference 挂起，但会留 boot 不完整）。

**处置**：
```
① 官方预查(P0) → ② guard backup package.json/cordis.patch.yml → ③ 逐个嫌疑插件: 查其依赖服务是否就绪
④ 禁用根治不了就恢复官方插件 + 修根因(file-reference 依赖 remote 服务)，勿长期靠 disable
⑤ C1-C7 全跑（boot 过 ≠ 全好，重点 C5 历史加载）
```

## T6 · React 崩溃（侧边栏/界面）

**现象**：控制台 `Element type is invalid … #31`；点了某品牌/hero 区域整块崩。

**根因**：client 插件返回 `{type:'div', props:{…}}` 字面对象。React 19 需要真实 element——必须 `React.createElement('div', null, …)`。

**处置**：
```
① guard-doc-check "react element type invalid"（P0，可查本地 electron-docs/react 段）
② 改 client.js: React.createElement 全量替换手写对象
③ 沙箱验证 → 重启 → C6 renderer 无 #31 → C4 会话正常
```

## T7 · 连环错 / 版本遮蔽（pnpm 事故）

**现象**：一次 `dsh plugin add` 后：schema.required 崩、history `.parse undefined`、`abbreviateHomePath is-not-a-function`、file-reference 挂起…… 一串不相关报错。

**根因**：pnpm 把 profile 依赖重写成 **65 个 @deepseek-ai 旧包（rc.6/7）**，遮蔽 runtime rc.2 → 各子系统拿到不兼容版本。

**判定**：
```bash
guard-check-deps        # 输出 profile vs runtime 遮蔽清单
ls ~/.dsh/profiles/web/node_modules/@deepseek-ai/ | grep -E "\.bak-|\.pnpmcopy"
```

**处置**：
```
① 官方预查(P0): guard-doc-check "pnpm workspace overrides shadowing"
② guard backup profile package.json
③ 对每个遮蔽包: mv 出 profile(保留 .bak-/或移 runtime 同级), 让解析回落 runtime
④ guard-check-deps 复查 → 遮蔽归零
⑤ 重启 → C5 历史加载(专治 .parse/undefined) → C7 无遮蔽
```
**关键教训**：*pnpm 是重写器不是安装器*——在 profile 里 add 包会连带重写全家。改依赖一律手改 package.json + 手动 symlink，并保留 .bak-。

## T8 · 崩溃无痕（壳无看门狗——P0 已补）

**现象**：以前 CLD 崩了完全没记录，只能猜。

**根因**：Electron 壳 spawn dsh 后无 child exit 监听 → 崩溃即静默。

**处置（已落地 P0 asar patch）**：
```
① 崩溃后先看: ~/.cld/logs/ 下 exit-marker(cleanExit:false + crash-reason.log)
② traceCrash 已写 reason/code/signal → 按 reason 分诊到 T2/T3/T5
③ 补做项(未落地): crashReporter.start + getHeapStatistics 周期采样(内存趋势)
```

## T9 · 未知问题先查官方（P0 门的前置习惯）

**原则**：凡诊断超过 15 分钟无定论，或要动底层，**先查本地官方镜像，再谈修**：
```bash
guard-doc-check "<主题>"            # 机械门: 自动在 tech-research/{dsh-docs,electron-docs,swift-docs} 检索
# 例: guard-doc-check "session persistence" / "electron node options whitelist" / "react 19 element"
```
本地镜像（174MB，MBP `~/tech-research/`）：
- `dsh-docs/`（245 md，含 postmortem）→ dsh 插件/会话/服务机制
- `electron-docs/`（297 md）→ 壳层/Node/打包/fuse
- `swift-docs/` → TSPL（壳若涉 Swift 侧）
镜像超过 14 天未更新时，guard-doc-check 会警告"镜像过期"，需 web 查官方最新再落证据。
