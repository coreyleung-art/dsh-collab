# CLD/DSH 界面层封装与模块机制

> 沉淀：2026-09-04 · 来自品牌套壳 + 界面修复实战
> 主题：client 插件如何封装、界面各模块如何组织、如何安全定制

---

## 一、界面层架构总览

```
BrowserWindow (CLD)
 └─ Vite shell (index-*.js)
     ├─ __ModuleLoader__（模块系统，boot wire 注入）
     ├─ client 插件们（/plugins/<id>/client.js，rev 缓存）
     │   ├─ 框架层: client-runtime / locale / slots / theme
     │   ├─ 结构层: layout / sidebar / conversation / renderer
     │   └─ 功能层: brand / settings / goal / plan / reference ...
     └─ React 渲染树（slot 系统组织）
```

**两条通道**：
- **host 通道**（Node，profile loader）：提供服务（ctx.sessions 等）
- **client 通道**（浏览器）：渲染 UI，通过 remote 访问 host 服务

## 二、client 插件的封装规范（关键契约）

### 2.1 包结构
```
~/dsh-plugin-<name>/
├── package.json         # 必须含 dsh.bundle.patch + dsh.client
├── cordis.patch.yml     # bundle patch: insert 自己的 loader 行
└── lib/
    ├── index.js         # host 半区（空 apply 即可，export {apply}）
    └── client.js        # client 半区（核心）
```

### 2.2 package.json 关键字段
```json
{
  "main": "lib/index.js",
  "exports": {
    ".": { "default": "./lib/index.js" },
    "./client": { "default": "./lib/client.js" },
    "./cordis.patch.yml": "./cordis.patch.yml",
    "./package.json": "./package.json"
  },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "inject": ["@deepseek-ai/dsh-client-runtime", "@deepseek-ai/dsh-client-locale", "..."],
      "platform": "web"
    }
  }
}
```
**要点**：
- exports 用 `{default: ...}` 条件对象（非裸字符串）——否则 client-modules 解析失败
- `dsh.client.inject` 声明依赖的服务（须真实存在，否则 guard 拒绝）

### 2.3 client.js 格式（铁律）
```js
window.__ModuleLoader__.load({
  id: "dsh-plugin-my-brand",          // 必须与包名一致
  factory: (require) => {
    var module = { exports: {} };
    var exports = module.exports;
    Object.defineProperty(exports, Symbol.toStringTag, { value: "Module" });
    // require("react") 可用
    exports.name = "...";
    exports.inject = ["slots"];
    exports.apply = function(ctx) { ... };
    return module.exports;            // 必须 return
  },
});
```
⚠️ 非 ESM `export`——那是 host 格式，client 必须 `__ModuleLoader__.load`

### 2.4 组件返回（铁律）
```js
// ✅ 正确：React.createElement
return React.createElement("span", {style:{...}}, "内容");
// ❌ 错误：手写 {type, props} —— React error #31，slot 崩连带整个界面崩
return { type: "span", props: {...} };
```

### 2.5 接入 profile
```
1. package.json deps 加 "dsh-plugin-x": "link:/path/to/x"
2. bundles 数组追加 "dsh-plugin-x"
3. node_modules 建 symlink → 源目录
4. 重启 CLD（不要依赖热重载——31888 reload 有 bug 会崩壳）
```

## 三、Slot 系统（界面模块组织核心）

### 3.1 slot 是 React 渲染的"插槽"
各 UI 模块（sidebar/conversation 等）在 JSX 里声明 `renderSlot("slot.name", props, {fallback})`——第三方插件往同名 slot 注册组件即"插入"界面。

### 3.2 slot kind（类型决定注册规则）
| kind | 规则 | 例 |
|---|---|---|
| single | 同 priority 只一个注册者，冲突抛错 | sidebar.brand.mark |
| keyed | 需 options.key，同 key 冲突 | settings.plugin.item |
| list | 需 options.id | conversation.input.dock |
| chain | 需 options.select | — |

### 3.3 shadowing（覆盖官方组件）
```
single slot 已有官方注册（priority 0）→ 我们用 priority:-1 注册
"register at a different priority to shadow it (lowest renders)"
```
**不要禁用官方插件**——slot 空 → renderSlot 走 fallback（如品牌区显示 "DSH Local Build"）

### 3.4 slot 声明位置
- slot 由 **使用它的组件**在 children 表声明（kind/scope）
- 注册方只需 register，不重复声明（重复声明报错）

## 四、界面模块机制

### 4.1 Sidebar（左栏）
```
sidebar
├── sidebar.brand.mark    品牌图标 slot（官方 FishLogo / 我们替换）
├── sidebar.brand.name    品牌名 slot（官方 wordmark）
├── sidebar.workspaces    工作区列表 slot（读 ctx.sessions）
├── sidebar.<功能区>      各功能模块 slot
└── sidebar.settingsArea  底部设置
```
渲染代码结构（dsh-client-ui-sidebar）：css-module 类名（哈希化）+ React 树。

### 4.2 Conversation（对话区）
```
conversation
├── conversation.hero.brand.mark   hero 区大 logo slot（size 34）
├── conversation.hero.*            hero 区（headline/preview 是 locale key）
├── conversation.composer          输入区
└── conversation.* 消息流
```
- **hero 文案是 locale key**（conversation NS 的 hero.headline/hero.preview），非 slot
- locale 二次注册同 NS 抛错 → 改文案走 CSS 或 patch 源

### 4.3 品牌区（dsh-client-ui-brand-official）
```
注册 3 个 single slot：sidebar.brand.mark / sidebar.brand.name / conversation.hero.brand.mark
渲染 FishLogo（鲸鱼）+ BrandWordmark（DeepSeek 文字）
```
**定制**：自写插件 priority:-1 替换 3 slot（尺寸契约：sidebar 传 24、hero 传 34，SVG viewBox 自适应）

### 4.4 其他模块（不深挖，列结构供参考）
- **settings**：settings.section / settings.plugin.item（keyed!）等
- **goal/plan**：goal 相关 slot
- **renderer**：dsh-client-ui-renderer 实际渲染 slot 树，slot 崩溃在此被捕获（"slot entry crashed in ..."）

## 五、CSS / 样式机制

### 5.1 CSS-module 哈希类名
- 各模块样式编译为哈希类（如 `.hHd-Xa_brand`）——**不稳定**，勿硬编码选择器
- 类名含义见 css 定义（可 grep 模块名找）

### 5.2 注入自定义 CSS（client 插件内）
```js
// 仿 skin-center 范式
const tag = document.createElement("style");
tag.dataset.pluginCss = tagId;   // 去重
tag.textContent = css;
document.head.appendChild(tag);
document.body?.setAttribute("data-<name>", "1");  // 作用域
```
- 选择器用 `[data-<name>]` 前缀作用域
- 若需隐藏结构元素，优先 `[class*="xxx"]` 子串（较稳）或结构定位

### 5.3 主题变量
```
--dsw-alias-* (brand-primary/label-primary/sidebar-* 等)
```
在 `[data-<name>]` 作用域覆盖可改品牌色。

## 六、client 模块加载链路（排查用）

```
HTML script: client-modules + client-runtime（仅这 2 个 parser preload）
→ __DSH_BOOT__ wire 注入全部插件清单（id/url/rev/inject）
→ Vite shell 启动 → __ModuleLoader__ 逐个 fetch client.js
→ __ModuleLoader__.load 注册 → runner 激活 apply（等 inject 服务）
→ slot 注册 → React 渲染
```
**排查要点**：
- 插件在 wire 不在 preload = 正常（都是动态）
- rev 变 = 文件变了；界面没更新先硬刷新
- "did not activate / pending waiting for X" = X 服务未提供（host 侧缺失/版本错）

## 七、版本一致性（界面崩溃高危）

**client 端崩溃常因版本遮蔽**：
| 症状 | 根因 | 修 |
|---|---|---|
| abbreviateHomePath is not a function | profile client-runtime rc.6 vs runtime rc.2 | 移除 profile 旧包 |
| history .parse undefined | profile dsh-session rc.7 | 移除回落 runtime |
| slot entry crashed (keyed slot ...) | 插件与 rc.2 slot API 不兼容 | 版本对齐/升级插件 |

**铁律**：@deepseek-ai 包统一用 runtime 版本；profile 出现旧版即遮蔽源。

## 八、安全定制清单（界面层）

| 想做什么 | 正路 | 别 |
|---|---|---|
| 换品牌 logo/文字 | priority:-1 shadowing 3 slot | 禁官方插件（fallback） |
| 改 hero 文案 | CSS 隐藏 或 patch locale | 二次 register locale（抛错） |
| 加侧边栏项 | 注册 sidebar slot（list 用 id） | — |
| 改主题色 | CSS 变量覆盖 | 硬编码哈希类 |
| 加整个 UI 插件 | 完整 client 插件（§2） | — |
