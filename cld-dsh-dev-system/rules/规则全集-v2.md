## 一、五道闸（一切底层改动）

```
① 备份闸   操作前备份「最后两个可正常加载状态」→ guard backup
② 校对闸   版本/上游核对 → guard version-check
③ 门禁闸   不可写清单检查 → guard check-writable
④ 沙箱闸   隔离副本验证 → guard sandbox
⑤ 审查闸   物理审查（语法/权限/加载/实测）→ guard review
```

## 二、版本铁律（pnpm 事故核心教训）

1. **@deepseek-ai 包版本以 runtime 为准**（0.1.1-rc.2），profile 不应自装遮蔽版本
2. profile 出现旧版（rc.6/7）@deepseek-ai = 遮蔽源，应移除回落 runtime
3. 改依赖前：`guard version-check`；改后：dump-config + 重启 + 会话/历史实测
4. pnpm 操作会**全量重写依赖树**——理解后果，先备份

## 四、client 插件契约（界面定制铁律）

1. **格式**：`window.__ModuleLoader__.load({id, factory})`，非 ESM export
2. **组件**：返回 React.createElement 结果，勿手写 {type,props}（React error #31）
3. **slot 替换**：priority:-1 shadowing（禁用会触发 fallback）
4. **hero 文案**：locale key 非 slot → CSS 处理
5. **先最小探针**（改 document）验证 apply 执行，再上完整逻辑

## 五、备份纪律

1. 数量：保留最后 2 个 good 态（.bak-good-N 滚动）
2. 时机：任何写操作**之前**（不是之后）
3. 验证：备份后校验可解析
4. 覆盖：package.json / cordis.patch.yml / pnpm-lock / node_modules 清单 / 插件源码

## 六、验证清单（改动后必测）

```
□ dump-config EXIT 0
□ web HTTP 200
□ doctor 会话数正常（191）
□ 点会话 → 历史可加载
□ renderer console 无新错误（--enable-logging）
□ 版本一致性（profile vs runtime）
```

## 七、报告纪律

- 每次实质改动 → send-repair-report.py 报告（黑板+归档）
- 事故 → 24h 内补 postmortem（按 DSH 官方格式：Status/Summary/Root cause/Guardrails/Lessons）

## 十、GC/内存治理逻辑门（2026-09-06 新增）

> 工具: guard-gc-gate · 对应 Lean 定理 safe_gc_timer
> 任何 GC 类操作(定时GC/手动GC/内存治理变更)前必跑: guard-gc-gate check

六前提(全满足才允许实施):
- G1 会话已落盘(appendLines 含 fsync + rollback)
- G2 无 GC 误删回调(dsh-session FinalizationRegistry = 0)
- G3 活跃会话强引用(coordinator sessions Map)
- G4 GC 阻塞有界(方案 max_block_ms ≤ 300ms)
- G5 仅空闲触发(不撞推理/流式)
- G6 RSS 阈值触发(默认 3.0GB, 非高频)

证据: 代码级核查(2026-09-06) G1-G3 通过; 实测 GC 阻塞 39-332ms(大小堆);
GC 不丢会话(落盘+强引用+无回调三保障)
