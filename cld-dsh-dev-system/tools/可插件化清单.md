## 🧩 可插件化（DSH 工具面，agent 可直接调用）

| # | 插件工具名 | 功能 | 基于 |
|---|---|---|---|
| P1 | `guard_check_writable(path)` | 门禁检查（agent 操作前自动拦） | guard CLI |
| P2 | `guard_backup(path)` | 自动备份 | guard CLI |
| P3 | `guard_version_check(pkg)` | 版本校对 | guard CLI |
| P4 | `deps_consistency_scan()` | profile/runtime 版本一致性扫描 | T1 |
| P5 | `cld_health_check()` | 一键健康检查 | T3 |
| P6 | `session_recovery_check()` | 会话/历史可读性验证 | T2 |
| P7 | `brand_plugin_scaffold(name)` | 生成品牌插件骨架 | dsh-plugin-my-brand 模板 |
| P8 | `repair_report(title, json)` | 报告生成+投递 | send-repair-report.py |

**插件化方式**：参考 dsh-plugin-agent-way（defineTool 注册 host 工具）+ guard CLI 逻辑，做一个 `dsh-plugin-guard` host 插件，暴露 P1-P8。工具 schema 用当前 runtime dsh-tools 的 value schema DSL（勿用 required 内联——见 gov 教训）。

---

## 集成点（hook 到 agent 工作流）

1. **写操作前**：agent 调用 P1/P2（门禁+备份）——做成工具后可在系统提示词里要求
2. **依赖改动**：P4（一致性扫描）前后各跑
3. **每次重启**：P5（健康检查）
4. **每次修复**：P8（报告）
