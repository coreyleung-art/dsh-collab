# 分布式协作底层哲学 + 规则 R031（2026-09-03 用户定案）

> 触发：2026-09-03 MBP 通讯教训（agent_send 跨设备死信/绕路代理执行/本地 GUI 签名更优）
> 一句话哲学：沟通合作远大于自己解决问题；团结一切可以团结的力量；通讯永续大于其他一切任务。

## 一、哲学层（三原则）

### P1 · 协作优先原则
**沟通合作远大于自己解决问题。** 问题出现先想「谁能帮、谁最适合做」——广播/分派/借助他方力量，而非独自绕路硬做。团结一切可以团结的力量。

### P2 · 本地执行优先原则
分布式智能体网络下，**跨设备协作任务优先让设备侧所在的本地智能体（cld/dsh）完成**。
本地智能体拥有：本地资源（文件/服务/进程）、本地权限（钥匙串/证书/凭据）、低延迟（无跨网络）。
协调者/发起方不做「代理执行」——除非确认目标设备无本地执行者。

### P3 · 通讯永续原则
**通讯永续大于其他一切任务；通讯大于自己直接介入完成任务。**
通讯是分布式网络的命脉——通道断了，一切协作归零。
发现通道异常（消息 queued 死信 / SSE 断连 / 心跳陈旧）→ **立即修复通道，优先级高于手头任何任务**。

## 二、规则层（R031 · 可执行）

## R031 ✅ 分布式协作优先（本地执行+通讯永续+协作优先）
- 分类: 协作 | 范围: all-bus-devices | 状态: enforced
- 摘要: 跨设备任务本地执行优先；通讯通道健康 > 一切任务；协作分派 > 自己绕路代理执行
- 详情: 见哲学层 P1-P3 + 门 G1-G2

## 三、门层（可检查）

### G1 · 任务分派门（协作/本地执行）
收到跨设备任务或遇到跨设备问题时，先问：
1. 目标设备是否有本地智能体（cld/dsh/executor）？→ 有：分派给它（黑板 notes/<node>/ 通道）
2. 该智能体是否有本地资源/权限（钥匙串/证书/本地服务）？→ 有：必须本地执行，协调者不做代理
3. 无本地执行者 → 协调者才介入（且优先用黑板通道，不用 agent_send 跨设备）

**分派通道规范**：跨设备 → 黑板 notes/<node>/ + SSE 订阅消费端；agent_send 仅本机进程内（跨设备必死信）

### G2 · 通讯健康门（通讯永续）
每次协作动作前/中发现：
1. agent_send 消息 queued 超过 1 轮未送达 → 判定通道异常 → 切黑板通道 + 通知目标
2. 心跳陈旧（节点 /heartbeat 超时）→ 报节点离线 → 走节点唤醒/恢复
3. SSE/事件桥断连 → 重启订阅器（bootout+bootstrap）
4. 通讯异常处理期间 → 暂停非紧急任务，优先恢复通道

## 四、实践映射（本次教训的具体化）
| 场景 | 旧做法（错） | 新做法（R031） |
|------|------------|--------------|
| MBP iOS 签名构建 | 协调者 ssh 直构建（errSecInternalComponent）或 agent_send 催（死信） | 黑板 notes/mac-mini/ 通知 mbp-bus → MBP 本地 GUI 签名（一次成功） |
| MBP 联系 | agent_send（本机机制跨设备死信） | 黑板 SSE 通道（mbp-bus central-inbox 订阅，心跳一直活） |
| 星台桥问题 | 协调者逐个排查 | 先想设备本地（MBP 有 GUI 环境）+ 通讯永续（通道对了问题自解） |

## 五、执行检查（可落地）
1. 协调者收到跨设备请求 → 过 G1（分派 or 介入）
2. 任何 agent_send 跨设备尝试 → 自查 G2（改黑板）
3. 通道异常 → 通讯优先级 > 当前任务（P3）
