# CLD / DSH 品牌套壳解决方案

> 方案：mbp-ops · 2026-09-04 · v1.0
> 现状：骨架插件 dsh-plugin-my-brand 已上线 Mac mini（占位蓝点验证 shadowing 生效）
> 目标：把 DSH 界面默认品牌（DSH 鲸鱼/DeepSeek 文字/hero 标语）替换为用户自己的品牌，可回滚

---

## 一、方案总览

**一句话**：写一个 client 品牌插件，用 DSH 官方 slot 机制（priority shadowing）替换品牌元素 + CSS 注入处理文案——不动官方插件源码、不 hack runtime、全程可回滚。

### 可替换面 vs 不可替换面（先明确边界）

| 界面元素 | 机制 | 可替换？ | 方法 |
|---|---|---|---|
| 左栏顶部鲸鱼图标 | slot `sidebar.brand.mark` | ✅ | priority:-1 shadowing |
| 左栏品牌文字 | slot `sidebar.brand.name` | ✅ | 同上 |
| 对话区大鲸鱼 | slot `conversation.hero.brand.mark` | ✅ | 同上 |
| "探索未至之境" 标语 | locale key `hero.headline` | ⚠️ | CSS 隐藏/改写 |
| "预览版" 徽章 | locale key `hero.preview` | ⚠️ | CSS 隐藏 |
| 窗口标题/网页 title | HTML title | ✅ | CLD main.js title |
| Dock/应用图标 | icon.icns | ✅ | 换资源文件 |
| 主题色/强调色 | CSS 变量 --dsw-alias-* | ✅ | CSS 覆盖 |

### 为什么用 slot shadowing（而非禁用官方插件）
- 禁用 `ui-brand-official` → slot 空 → sidebar 走 **fallback**（显示 "DSH Local Build 29b22c5"，已实测踩坑）
- shadowing（priority:-1 < 官方 0，lowest renders）→ slot 有 occupant → **不触发 fallback**，我们的组件胜出

## 二、架构与机制详解

### 2.1 插件形态
```
~/dsh-plugin-my-brand/
├── package.json        # dsh.bundle.patch + dsh.client（inject sidebar/conversation）
├── cordis.patch.yml    # insert: id=my-brand, name=dsh-plugin-my-brand
└── lib/
    ├── index.js        # host 入口（空 apply，占位满足 bundle 要求）
    └── client.js       # ★ 核心：slot shadowing + CSS 注入
```
接入方式：profile package.json 的 `dependencies` 加 `link:` + `bundles` 追加 → node_modules 建 symlink（与其他用户插件一致）→ 重启/热重载生效。

### 2.2 Slot shadowing 核心代码
```js
// priority:-1（官方为 0，lowest renders → 我们胜出）
ctx.slots.inject("sidebar.brand.mark", () =>
  ctx.slots.register({ name: "sidebar.brand.mark", priority: -1 }, MyBrandMark)
);
// name 与 hero.mark 同理
```

### 2.3 CSS 注入核心代码（仿 skin-center 范式）
```js
const tag = document.createElement("style");
tag.dataset.pluginCss = tagId;      // 去重
tag.textContent = css;
document.head.appendChild(tag);
document.body?.setAttribute("data-my-brand", "1");  // 作用域标记
```

### 2.4 尺寸契约（你的组件如何自适应）
| 位置 | 宿主传入 | 建议 |
|---|---|---|
| sidebar.brand.mark | `size: 24` | SVG 用 viewBox 等比 → 自动适配 |
| hero.brand.mark | `size: 34` | 同上 |
| sidebar.brand.name | 无 size | 文字按容器自适应 |

**结论**：用 **SVG + viewBox** 做 logo，宿主传 24/34 都完美缩放；`size` 是 prop 非硬限，你的组件也可忽略它自定尺寸。

## 三、定制内容填写指南（骨架 → 正式品牌）

### 3.1 替换占位 mark（核心动作）
在 `client.js` 的 `MyBrandMark` 里，把占位 `<span>` 换成你的设计。三种形态：

**A. SVG logo（推荐）**——等比自适应两个尺寸位：
```js
function MyBrandMark({ size = 24 }) {
  return {
    type: "svg",
    props: {
      width: size, height: size, viewBox: "0 0 100 100",
      children: [/* 你的 SVG path/elements */],
    },
  };
}
```

**B. 图片 logo**：
```js
function MyBrandMark({ size = 24 }) {
  return { type: "img", props: { src: "/your-logo.png", width: size, height: size, style: { objectFit: "contain" } } };
}
```

**C. 文字标识**：
```js
function MyBrandMark({ size = 24 }) {
  return { type: "span", props: { style: { fontWeight: 800, fontSize: Math.round(size*0.6) }, children: "★" } };
}
```

### 3.2 品牌名文字（左栏）
`MyBrandName` 渲染你的品牌文字（如 "FlowerNet" / 自定义字标）。**留空 = 只留图标**；也可渲染图片 wordmark。

### 3.3 hero 文案处理（CSS 方案）
注入 CSS 隐藏/改写 "探索未至之境" 与 "预览版"。因 CSS-module 哈希类名不稳定，用 **body[data-my-brand] 作用域 + 结构定位**或对话区容器选择。隐藏示例：
```css
[data-my-brand] [class*="headlineText"] { display: none; }
[data-my-brand] [class*="previewBadge"] { display: none; }
```
> ⚠️ `[class*=]` 依赖哈希子串稳定性，验证后定稿；更稳的做法是注入完整自定义 hero 替换（需另评估）。

### 3.4 主题色覆盖（可选）
CSS 变量覆盖品牌强调色：
```css
[data-my-brand] {
  --dsw-alias-brand-primary: #你的色;
  --dsw-alias-label-primary: #你的色;
  /* ... 需查完整变量清单 */
}
```

## 五、边界与注意事项

1. **slot shadowing 是官方支持机制**（"register at a different priority to shadow, lowest renders"）——非 hack，版本升级大概率兼容
2. **hero 文案 locale 不可二次注册**（同 NS 抛错）→ 走 CSS；若官方改文案 key 需同步更新
3. **client 插件无服务端逻辑**（index.js 空 apply）——不碰会话/存储，无 OOM/崩溃风险面
4. **哈希类名稳定性**：CSS 选择器避免硬编码哈希，用 `[data-my-brand]` 作用域 + 语义定位
5. **升级影响**：CLD/dsh 升级若改动 brand slot 声明或 hero 结构，需回归验证
6. **占用 slot 需在官方之后注册**：bundle 顺序放最后（当前 my-brand 是第 32 层）——若官方调整加载顺序需复查
