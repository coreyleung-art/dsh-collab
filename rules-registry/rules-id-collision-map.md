> 起因：与 mac-mini 做规则库双向 diff 发现——**同一编号在两端指向不同规则**（两端各自独立分配编号所致）。
> 取证：ssh 直连取回对端 `~/dsh-collab/rules-registry/rules.json`（version 2.21.1，62 条）与我侧逐 id 对齐。
> ★ 判据更正：**不能按 `summary`/`name` 文本比对**（会把"措辞不同但语义一致"误判为撞车）⇒ 判据是 **id→语义** 人工确认。

**范围界定**：两端共有的 id 中，`name` **完全相同**的有 48 条（R001–R031 等，同源共享历史）；
`name` 不同者共 14 条，全部落在 R032–R045 区间，进一步按**语义**分类如下。

## 3. 处置约定（建议，待对端确认）

1. **交叉引用一律带命名空间**：`mbp:R040` / `xq:R040`（章程 §8 已有此意，建议升级为强制）；
2. **编号冻结不重编**（重编会破坏 `retiredEntries` 与外挂表 `ruleId` 溯源）⇒ 以本表消歧；
3. 今后新规则用命名空间 id 或按节点分带，避免再撞；
4. 建议双方各持本表，并发板 `data/registry/rules-id-collision-map`。

## 4. 教训（方法论）

- 双向 diff **只比文本会得出错误结论**：对端初判「多为措辞差异」，实测 **10/14 是同号不同义**；
- 此前"跨端引用规则号"看似无问题，是因为**实际上没有人真正交叉引用过这些编号**。
