# bus 唤醒语义改造规格（方案 A · 待用户裁定后实施）

> 2026-10-03 星桥起草 · 依据：死锁机制链复盘 + 7 天流量基线（日均 205、常态 50-100、设门时代 ~8652/天）
> 状态：**规格冻结，待用户选择 A/B/A+B 后执行**。本文件只描述方案 A；B 见文末。

## 1. 要解决的问题

实测机制链：定向卡未带 reply_required ⇒ 指针形态 ⇒ central-inbox inject（**不唤醒**）⇒ 收方静默挂起 ⇒ 只有用户消息才开回合 ⇒ 双方互相等（11.5h 空档实证）。根因 = 「成本治理」放在了「激活路径」上。

## 2. 方案 A：唤醒语义反转

### A-1 默认唤醒（收端）
- agent-way `deliver()`：指定 `to` 的定向消息**默认 followup（唤醒）**；`inject`（不唤醒）只用于显式 `notify_only=true` 的信封。
- central-inbox：卡片无 `notify_only` 字段时注入即唤醒（reply_required 字段保留为「更强提示」语义，不再承担唤醒开关）。
- 例外保留：广播（broadcast）默认不逐人唤醒（维持现状，防 N 倍成本）；@提及维持唤醒。

### A-2 防风暴改到发端（成本治理归位）
- agent-way `sendMessage`：同 from→to 对，10 分钟窗口超过 N=10 条 ⇒ 第 11 条起降级为 inject 并在返回中标注 `rate_limited: true`。
- 去重（内容指纹）与自回声守卫不变（它们不伤激活，继续兜底）。

### A-3 全文门禁阈值重校准
- 阈值 50 → 200 字（依据：日均 205、常态 50-100；峰值 537 出现在 10-02 异常日，非自然流量）。
- 保留：看黑板指针豁免、urgent 豁免。

### A-4 送达回执语义（已在进行，并入本规格验收）
- boarded（已写板）≠ 已读；跨机回复指引写卡；球权字段 awaiting 必填（已入 portal）。

## 3. 验收判据（可复跑）

| 判据 | 方法 |
|---|---|
| 定向消息唤醒 | 同机：A→B 发卡（无 reply_required）⇒ B 的 agent/status 由 idle→running（观察事件） |
| notify_only 不唤醒 | 显式 notify_only ⇒ 不产生回合，仅入上下文 |
| 发端限速 | 同 from→to 连发 12 条 ⇒ 第 11/12 条返回 rate_limited:true |
| 阈值 200 | 150 字直发通过；250 字无指针拒绝 |
| 回归 | selftest 全绿 + 既有去重/自回声用例不变 |
