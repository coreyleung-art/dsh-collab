## 一、公约审查结论(权威流程)

公约 §3.2 跨设备角色沟通 = **任何角色可直接走服务器 bus 信封**:
`角色 → 信封(from=<dev>:<role> target=<对端>) → 服务器 bus → 对端守护 → 黑板 → central-inbox 唤醒`

- 角色**可以直接** bus/send(不需经星桥中转)——星桥是总线协调者非转发代理
- 但**通道必须是 bus 信封**(R033/公约), 不得用 agent-msg 黑板通道发跨设备

## 二、我的错误(承认)

1. 我近期采集 i9 能力用了 **agent-msg(notes/i9/ 黑板通道)** 而非 bus/send——违反 R033/公约 §3.2
2. 根因: ①便利性偏差(agent-msg 本地工具顺手) ②**更深: bus 通道 token 未配(401), 正确通道不可用→退回老路**
3. 这证明: 公约发布 ≠ 工具就绪——缺「工具层强制」, 靠自觉必复发(我自己就是反例)

## 三、Lean4 门方案(防复发, 工具层强制)

### 门 1: G-C42 · 跨设备通道门(行为断言, 校验器加)
- 断言: cross-device-bus-only
- 校验: 扫描发送记录, 发现跨设备(i9/mbp)消息走了 agent-msg 黑板键(notes/i9/agent-msg-* 或 notes/mbp/agent-msg-* 由本机 dsh-tools 写入) → FAIL
- 意义: 静态检查"近期是否有违规发送", 周期性跑(锁审计同周期)

### 门 2: agent-msg 工具层拦截(源头堵, 最有效)
- dsh-tools agent-msg: 若 --to i9|mbp → 直接拒绝, 提示「跨设备须走服务器 bus/send(公约 §3.2), 本工具仅限设备内(mac-mini 内角色)」
- 意义: 从工具源头让违规不可能发生(便利性偏差无法触发)

### 门 3: bus 通道可用性(补正确通道)
- mac-mini 侧配 X-Webhook-Token(读取 ~/.dsh/bus-bridge-token 0600)
- 提供 bus-send 便捷封装(角色可调用), 或确认守护已有入口
- 意义: 让正确通道成为顺手通道(消除走老路的理由)

## 四、执行步骤
1. 本方案 + 公约审查结论 → 发星桥(他管校验器/守护)
2. 星桥实施: 校验器加 G-C42 + agent-msg 拦截 + token 配置确认
3. 我登记 + 广播全员(含自我检讨示例)
4. 周期性: 校验器含 G-C42 后, 违规即 FAIL 可见
