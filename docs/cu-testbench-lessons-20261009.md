# CU 实验台 · 可迁移教训（2026-10-09）

> **来源**：`~/systemone-lab/cu/**`（computer-use × System One 本地实验台）建造过程中**实测踩出来**的坑。
> **为什么单列**：这些**不是** CU 专有——任何做本地模型实验 / 回归 / 自建审查的线都会再踩一遍。
> **相关**：`cu/OPERATIONS.md`（逐条操作账本，含更正）· `data/registry/cu-lab`（登记卡）· `cu/STATUS.md`（交接档）。

## 0. 一句话

本台最贵的一课：**"绿了"和"验过了"是两件事。** 下面十条都是这条的具体形态。

## 1. 回归键名会被**子串**静默跳过（本项目踩过两次）

`systemone-lab/compare.py:64` 跳过任何**含** `recorded_at / env / run / name / generated_at / elapsed`
**子串**的键（是子串，不是前缀）。`truncated_step_rate` 含 **t-**run**-cated** ⇒ 被静默排除
⇒ 回归报"全绿"，其实那个指标**根本没比**。

**纪律**：指标名定下来后立刻 `is_metric(key)` 断言一遍，并把这条断言**钉成回归**（日后加键踩雷马上红）。

## 2. `skip ≠ pass`；**空集通过是假绿**

一条规则、一个 checker，当它的靶集为**空**时（glob 写错、目录不存在）会"扫到 0 个文件 ⇒ 0 命中 ⇒ 通过"。
而**规则因自身配置错误而静默降级的表现，恰好就是"全绿"**——与"规规矩矩全过"长得一模一样。

**纪律**：任何"扫描型"判据，靶集为空必须判 `skip`（或红），**不许判 pass**；报告里 skip 与 pass 分列。

## 3. MPS 上 RSS 量错了对象（差 ~27×）

macOS 统一内存在 RSS 里**不可见**：一个 4B bf16 模型，`ps rss` 报 0.35 GiB，`/usr/bin/footprint -p <pid>`
的 `phys_footprint` 报 **9.52 GiB**。若信 RSS，**本轮头条结论（"B 贵 5.8 GiB 内存"）会正好反过来**。

**纪律**：Apple Silicon 上一律用 `phys_footprint` 作内存指标；RSS 只作"错误仪表读数"留档。

## 4. 模型的真实输入上限 ≠ 你以为的那个数字

本机实测：瓶颈**不是** `MAX_STATE_CHARS=200_000`，**不是** tokenizer 的 8192，**不是** config 的 7999，
而是 **nano torch 后端的硬上限 `max_len=2048` tokens**。超出的部分**静默截掉状态尾部**——而被截的
正是投影**末尾的 `ELEMENTS` 行**。⇒ 决策是在"读残了的 state"上做的，而归因会把它记成"决策错"。

**纪律**：投影预算按 **token** 标定，不按字符（坐标/id 很吃 token，实测 ~0.51 tok/char；中文 ~0.86）。
截断必须**显式上报**（进 `truncated` 字段），不许静默。

## 5. 审查器管回归，独立审查管发现——**两者不可互替**

自建审查器（15 条规则）在真树上全绿，**却一条都没查出它本该抓的 6 个真缺陷**。原因：审查器与受审代码
**同一作者** ⇒ 规则只覆盖**已踩过的坑**（"同源盲点"）。
那 6 个缺陷全部来自**另起一个无上下文、只读、只质疑的独立审查**。

**纪律**：把"已量到的差异"做成会红的判据（回归），把"我没想到的形态"交给**没有我上下文**的独立审查。
缺任一条，绿灯就不代表安全。

## 6. 存档的 state 键集必须与 live 一致（否则静默换答案）

一份冻结 state 存下来时**漏了 `focus` 键** ⇒ 投影成 `FOCUS none` ⇒ **路线问从 `act` 翻成 `abstain`**，
元素头根本没跑。消融一度看起来"强判据反而升档"——其实是夹具缺陷。

**纪律**：冻结/回放前**验键集与 live 相等**；缺键 ≡ `None` 的语义要显式写死（本台用 `.get()`，
使"缺键"与"空值"**逐位相同**，可回归）。

## 7. "只读证成"必须**出声**

`--prove-readonly` 在证明成立时**什么都不打印**。一个只在失败时才说话的检查，与"从来没跑过"**无法区分**。

**纪律**：证成/未证/被破坏**三态都要输出**，包括"未证（未开此开关）"。

## 8. payload 只放"本该稳定"的字段

把"延迟"记进回归 payload ⇒ 每次都在动 ⇒ **每次给自己判红**（本项目踩过两次）。
反例：双稳定门"等出来的时间"**是被测对象**，理应留在 payload。
**判据**：问一句"这个量是**被测对象**还是**机器抖动**"。

## 9. 冻结时钟要覆盖**所有**未声明的文件

只冻结显式设过 `mtime` 的几个文件，其余文件落盘拿**墙上时钟** ⇒ 同一天两次"清单逐位相同"是
**假通过**，隔天再跑就不等了。
**纪律**：冻结时钟覆盖**全部**未声明项（文件 + 目录），并把"被改写的路径"打印出来，别让它悄悄发生。

## 10. 账本的更正要**追加**，不要改写

错就错在账上：`OPERATIONS.md` 的 OPS-4 曾引用一份**与基线逐字节相同**的"修复前原件"（= 归档时抄错文件
⇒ 该条承诺的"凭留档可逐键还原"是空的）。处置：追加 OPS-5 记录**新旧 sha256 + 差异键**，
**让错误本身仍可审计**，而不是把旧条目改掉。

**纪律**：更正走**追加**；被替换的物留 sha256；账本只增不删。

## 附：这批坑为什么值得记——本台唯一原创的切入点

按 §7.0 的文献调研（OSWorld / WebArena / MacArena / PACE 等已核原文）：

本台正是冲这两处去的（`cu/suite/attribution.py` 的 `classify()→none|grounding|planning|execution`）。
上面十条，是让这个切入点**站得住**的前提——**没有一个数字是"没验证却敢说的"**（R030）。
