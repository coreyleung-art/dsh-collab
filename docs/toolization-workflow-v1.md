# 工具化工作流 · 两次法则落地 (Φ8 · 重复即工具化)

> 作者: 明鉴 v2 · 2026-09-05 · 配套 Φ8 治理哲学 + R006 九标准
> 一句话: 凡出现过两次以上的 → 按九大标准工具化·插件化; 九标准自身可演化; 本流程是落地路径

## 一、为什么是"两次"而非"一次"或"三次"

| 次数 | 语义 | 行动 |
|------|------|------|
| 第 1 次 | 必要尝试(validate)——确认这事值得做 | 手工做, 记录"可能是模式" |
| 第 2 次 | 模式确认(pattern confirm)——同样的事再出现 | 警觉: 标记为「待工具化候选」 |
| 第 3 次之前 | 重复成为负债 | **必须工具化**(不可拖到第三次) |

> 呼应 Φ6(理论先行·最小化): 第 1 次 = 最小验证; 验证通过 + 重复出现 = 值得抽象的信号。

## 二、九大标准(R006)能否持续迭代? —— 能, 且应然

**结论: R006 九标准是「元标准」, 自身可演化(全开放随实践加), 但有演化纪律。**

### 为什么能/应演化
每次工具化实践会暴露新的**共性约束**(工具在不同场景被复用后, 会撞到九条没覆盖的新要求)。例:
- 我们现在新增工具(bb-gallery-audit/bb-asset-relations/bb-plan-scanner)反复用到**幂等可复跑**、**增量更新**、**建议-确认门控**——这些是九条之外的实践共性, 若多次出现应升为正式标准
- 候选演进方向(实践未达标不并): "幂等可复跑" / "dry-run 建议模式" / "结构化产物可落链" / "多场景泛化验证"

### 演化纪律(防标准膨胀)
1. **实践驱动**: 新共性必须在 ≥2 个工具里实证出现, 才够格成为候选(Φ8 对自身生效)
2. **用户确认**: 并入九标准需用户拍板(呼应 Φ1 用户主权)
3. **向后兼容**: 新增标准不破坏既有工具达标(九条是底线, 新条是更高要求)
4. **可操作性**: 每条标准须有 mark(检查标记)与 example, 否则不收

### 迭代入口
```bash
python3 ~/dsh-collab/scripts/bb-toolize.py --suggest   # 扫候选: 重复工具/重复模式/可并标准
# → 人工确认 → 升入 R006 或建新工具
```

## 三、工具化工作流(8 步)

```
触发(两次法则)                        可工具化候选登记(黑板 todo/plan-archive)
   ↓                                    ↑
1️⃣ 确认抽象边界(这事稳定吗?会再变吗)   └── 5️⃣ 实现(按九标准清单逐项过)
   ↓
2️⃣ 起名 + 定位(工具名/属哪个域)         6️⃣ TCC 验收(--selfcheck 绿 + 实测证据)
   ↓
3️⃣ 设计接口(CLI/参数/产物)             7️⃣ 三件套落档(文档/代码/数据 + 黑板登记)
   ↓
4️⃣ 干跑验证(最小可用先手工对拍)         8️⃣ 登记 + 审查防复发(纳入流程/审计器)

九标准清单(实现时逐项打勾):
□1 插件形态   □2 --selfcheck(TCC)  □3 CLD自适应   □4 --tool-version
□5 文档化     □6 版本管理           □7 统一日志     □8 自动落链    □9 CLI治理
```

## 四、各步骤要点(来自本次审查工具化实践)

| 步 | 要点 | 本次实例 |
|----|------|---------|
| 1 抽象确认 | 只工具化"稳定重复"的; 一次性的不工具化 | 蓝图重复是真模式 → 抽象; 单次页面调整不工具化 |
| 2 定位 | 名字说清"做什么" | bb-gallery-audit(审查管理器结构) |
| 3 接口 | CLI 与产物都幂等可复跑 | --scan/--selfcheck/--json |
| 4 干跑 | 手工先做一遍验证工具逻辑 | 先人工发现 H6 再写检查 |
| 5 九标准 | 逐项过, 缺哪补哪 | --selfcheck/--tool-version 补上 |
| 6 验收 | 真数据实测非纸面 | 审查出 3 真实问题 |
| 7 落档 | 三件套 + 黑板 | docs/gallery-audit-tool-and-report |
| 8 防复发 | 工具纳入流程, 不再手工 | 每次加 Tab 跑审计器 |

## 五、防复发机制(工具化的闭环)
- 工具化后, 把"运行检查"挂到**常规入口**(发布流程/新功能清单), 让工具持续把关
- bb-gallery-audit.py 已入 sysgraph-version release 前检查
- 工具自身也可被审查(元工具化: 审查器审查审查器)
