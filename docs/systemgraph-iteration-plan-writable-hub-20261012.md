## §0 用户原话与目标翻译

> 「允许任何一个经过授权接入的 ai，操作所有页面的更新和内容添加以及连线工作。变成了相当于蓝图和架构图管理器根据我们最新变动能实时更新。也能反向指导 ai 继续服务各自原本的蓝图和制定新的目标。」

拆成四条可验收的目标：

| # | 目标 | 一句话判据 |
|---|---|---|
| **G1** | **授权 AI 可写** | 任意经授权的会话可对任意页面/蓝图/关系执行**增改**，且**改动可追溯、可回滚** |
| **G2** | **实时双向** | 写入后 **≤10s** 全体订阅端可见（读向已由 A 组达成；**写向与推送待建**） |
| **G3** | **管理器即真值** | 管理器里的内容 = 各 AI 的最新产出，**不再需要人工搬运** |
| **G4** | **反向指导** | 管理器能**主动向 AI 派发**：某蓝图缺什么、该谁补、新目标是什么 |

★ **G4 是本规划里最新、也最需要先定清楚的一条** —— 它把管理器从「被动被写」变成「**主动发指令**」，涉及唤醒与 token 成本，须单独裁决。

## §2 需求分解（八件）

### R1 · 写端点与动词层（**基座，其余全部依赖它**）
- `POST/PUT/DELETE /api/blueprints/<id>` · `/api/relations/edges` · `/api/assets/<id>` · `/api/pages/<id>`
- ★ **必须有独立的 HTTP 动词层**（现状写语义藏在 GET 里，**审计与鉴权无处挂**）
- 判据：动词层存在 + 每个写端点有 `author` 留痕 + 非授权请求 401/403

### R2 · 授权模型（**G1 的核心，也是最需要先定的**）
- **主体**：会话 id（非角色名 —— 角色名会漂移，见「别名属角色不属会话」的既有教训）
- **粒度**：`域/资源/动作` 三元（如 `blueprint:flowernet` × `write`）
- **载体**：写权限表（黑板 `data/registry/systemgraph-write-acl`），**可读、可审、可回滚**
- **令牌**：复用黑板 `Bearer`（`~/.dsh/blackboard-token`）+ 调用者身份声明
- ★ **不可自我授权**：申请权限须由**属主或用户**批（防「AI 给自己发权限」）
- 判据：未授权写被拒且**留痕**（含被拒原因）；授权变更本身有台账

### R3 · 页面级内容寻址（让「所有页面」成为可写对象）
- 每个 tab / 章节有**稳定 id**（如 `page:systemgraph/agents`），内容与页面解耦
- 写入 = 对 `page:<id>` 的 patch，而非改 HTML
- 判据：任一页面可被单独读写；改一页不影响他页

### R4 · 连线编辑（关系图可写）
- `relations.edges` 增删改；**关系类型枚举**受约束（现状 9 类：contains/depends_on/requires/consumes/manages/references/consumed_by/child_of/distinct_from）
- ★ **必须防环**：`child_of`/`depends_on` 写入前做环检测（21 蓝图 / 53 边规模下很廉价）
- 判据：写入合法边后图与 `/api/relations` 均反映；写入**成环边**被拒并给理由

### R5 · 实时推送（读向已完成；**写向与推送待建**）
- A 组已给：模型 + 版本号 + SSE 订阅
- 待建：**写后广播**（版本号自增 → 前端 SSE/轮询看到 → 局部重渲）
- 判据：A 席写入 → B 席 **≤10s** 可见（跨机也测）

### R6 · 版本与回滚（**不可逆操作的底线**）
- 一版一文件（B 组已定基准）：`data/blueprint/<id>/blueprint-<id>-v<X.Y>.md`
- 每次写 = 新版本；**软删 `retired`** 而非真删
- 判据：任一写入可回滚到前一版；版本台账**自 09-07 复写**

### R7 · 反向指导通道（**G4，须单独裁决**）
- 管理器**检测缺口**（如：某蓝图无 `stages` ／ 某边悬空 ／ 某能力无属主）
- 按**属主映射**派发到对应会话（复用 `agent_send` + 黑板卡；**≤200 字指针 + 卡**，遵守 v2.4 门）
- ★ **成本闸**：派发=唤醒=token。须有**频次上限 + 去重 + 合并**，否则会变成 awake 风暴
- ★ **不可自动升级为「AI 自己给自己派活」** —— 派发目标与内容须可审
- 判据：缺口能被检出并派发；**重复派发被去重**；有频次上限且可熔断

### R8 · 并发与同源互斥（多 AI 同时写）
- **同源互斥**：同一资源段的写走 R001 红绿灯（`agent_light`/`agent_lock`）
- **冲突策略**：乐观锁（版本号 CAS）—— 版本不匹配则拒，返回最新版让调用方重试
- 判据：两席同时写同一资源 ⇒ **一成一败**（不得双写覆盖），败方拿到可重试信息

## §3 分期建议（依赖序，每期可独立验收）

| 期 | 内容 | 为什么这个顺序 | 可独立验收的产物 |
|---|---|---|---|
| **P1** | **R1 写端点 + R2 授权** | 没有它，其余七件全是空谈；且**鉴权必须在写存在之前就位**，否则会先长出无鉴权的写 | 动词层 + ACL 表 + 未授权被拒的实测 |
| **P2** | **R3 页面寻址 + R6 版本回滚** | 「能写」之后立刻要「写坏能退」——**回滚是写功能的一部分**，不是后置项 | 页面可写 + 任一写可回滚 |
| **P3** | **R4 连线编辑 + R5 实时推送** | 图能改 + 改了立刻看见（A 组已铺好底座） | 增删边 + 跨席 ≤10s 可见 |
| **P4** | **R8 并发互斥** | 多人/多 AI 真开始写之后，冲突才会真实发生；**但协议要先定，不能等出事再补** | 双写一成一败的实测 |
| **P5** | **R7 反向指导** | 最新、最贵、最需要先想清成本与控制 | 缺口检出 + 派发 + 去重 + 熔断 |

★ **不建议并行开工 P1 与 P3** —— 没有授权模型的写端点等于给全网开了无门通道。

## §4 必须先定的三件事（**请你裁决，我不代裁**）

| # | 议题 | 为什么必须你定 |
|---|---|---|
| **D1** | **授权范围**：是所有在线 AI 默认可写，还是**逐个授权**？写到什么粒度（整页 / 章节 / 单字段）？ | 这是**谁能改你的中枢**的问题，属权限决策 |
| **D2** | **反向指导的边界**：允许管理器**自动唤醒** AI 吗？还是只**产出待办卡**、由人决定发不发？ | 自动唤醒 = **token 成本 + 打扰**，且可能形成 AI 互派活的循环 |
| **D3** | **写失败的可见性**：写坏了是**静默拒绝**还是**大声报错并留痕**？ | 决定故障是「被发现」还是「被掩盖」——本晚已多次栽在「静默」上 |

★ **我的建议**（供你否掉）：
- D1 → **逐个授权**，粒度到「资源 × 动作」；先用**小范围**（我 + 星桥）跑通再放开
- D2 → **先只产出待办卡，不自动唤醒**；跑稳后再评估开关式自动派发
- D3 → **大声报错 + 留痕**；且把「写被拒」也计入审计

## §5 风险（不美化）

| 风险 | 说明 | 缓解 |
|---|---|---|
| **无鉴权的写 = 全网可改中枢** | 一旦 P1 只做写不做授权，任何会话都能改蓝图与关系 | **把 R2 与 R1 绑在同一期**，不可拆 |
| **AI 互派活形成循环** | 管理器派给 AI → AI 改内容 → 触发新缺口 → 再派 | 频次上限 + 去重 + **派发链深度上限** |
| **反向下游不可控** | 派发是「叫醒别人干活」，叫醒本身有成本与打扰 | 默认产出待办卡；自动唤醒须显式开启 |
| **同源写冲突致数据损坏** | 两个 AI 同时写同一蓝图 | P4 的乐观锁 + R001 红绿灯；**这两条要在 P3 之前就把协议定下来** |
| **本晚已发生的那一类**：改了契约没核调用点 | 我刚因改 `fetch()` 返回契约导致**全端点空载荷**，且**只查状态码的冒烟没拦住** | 已加**内容闸**；后续每期验收**必须同时查载荷与状态码** |
