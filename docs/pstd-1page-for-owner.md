# PSTD 一页纸 · 插件命名与合规审查工具

> **这份是给「用工具的人」看的。** 给「审查员角色」看的作业手册在 `~/dsh-collab/docs/audit-reviewer-handover-v1.md`。
> 档案（证据与复现命令）在 `~/dsh-collab/audits/20261008/handover-v1-repro-archive.md` —— **那份不用读**。
> 版本：工具包 v1.0.4 · 本页 2026-10-08

## 一句话

**它把「插件合不合规」从靠人肉眼看，变成跑一次就出结果** —— 出「哪一条不过、证据是什么、该怎么改」。

## 它能回答的四个问题

| 你想问 | 用哪个 | 它给你什么 |
|---|---|---|
| 「这个名字能用吗？」 | `plugin_name_gate action=check` | 合不合规 + 规范形式（目录名/包名/插件行/工具名/日志路径/登记卡键） |
| 「我想要个新插件，叫什么好？」 | `plugin_name_gate action=allocate` | 从用途推荐一套规范标识 + 是否被占用 |
| 「本机插件现在有多少不合规？」 | `plugin_name_gate action=audit` | 全量扫描 + 违规清单（**注意：只审 N1–N4**） |
| 「这个插件符不符合 R006 十项？」 | `plugin_review target=<插件名>` | 十项逐项判据 + 证据 + 整改动作；`deep=true` 会真跑一次挂载冒烟 |

## 怎么用

**最省事**：直接在会话里说一句话，比如
- 「看看 `dsh-plugin-xxx` 符不符合标准」
- 「帮我起个插件名，用来做花店库存告警」
- 「本机有多少插件命名不合规」

**或者直接点名工具**（共 5 个，宿主级、任何会话可调）：

| 工具 | 一句话 |
|---|---|
| `plugin_standard` | 规范台：查看 N1–N8 / R006 十项 / P1–P5 模式 / 门型 |
| `plugin_name_gate` | 命名门：check 查名 / allocate 派名 / audit 普查 / explain 讲规范 |
| `plugin_review` | R006 十项审查（单个或全量、可选真冒烟） |
| `plugin_pattern_list` | 已有哪几种「模式化交付」模板 |
| `plugin_pattern_scaffold` | 按模板生成新插件骨架（**默认只演练不落盘**） |

## 它输出什么

- **判定三态**：`pass`（全过）· `partial`（**有待证项 —— 不是失败，也不等于通过**）· `fail`
- **每条都带证据**，并要求**能复现**（而不是只给结论）
- **附整改动作**：哪一条不过、应该改成什么
- 命令行侧退出码：`0` 成功 · `1` 失败/门失效 · `2` 用法或 IO 错误

## 边界（它不做的）

- **不代改、不自裁**：它出判据与证据，**改与裁定由人/其它角色做**（三方分离）
- **`audit` 只审 N1–N4**（目录名/包名/插件行/工具名）；N5–N8 需读正文或运行时，**它明确声明未测**（不假装通过）
- **R8「自动落链」没有自动核验实现**：它会给人工核验清单，**不代表已通过**
- 真冒烟有**四态**：`pass` / `fail` / `skipped`（该次执行的环境问题）/ `timeout` —— **`skipped` 不算通过**
