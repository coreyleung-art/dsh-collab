## 一、结论先说（TL;DR）

1. **技术上很简单**：SystemGraph 有**自包含静态导出**（3.7MB，22 个 JSON + 77 个 SVG + d3，无需后端）。放上服务器 = 传一份静态目录 + 起一个静态服务。
2. **真正的约束不是技术，是两件已经存在的事**：
   - **① 它现在就已经在公网上、且无需鉴权**：`https://tm.meetfunbp.com/systemgraph/` → manifest/index/api **全部 200，无凭据**，且是**旧版本**（`exported=2026-09-10T14:11:32`，本地为 `23:05:16`，**落后约 9 小时**）。
     · **敏感度实测（不推断）**：抽查 `bp/map.html`(32KB) 命中 `股权×3 / 融资×1`；`api/blueprints.json` 命中 `股权×1`；**`bp/capital.html`(153KB) 未命中** 估值/出让/融资/轮次/万元 → 故准确表述是「**公网无鉴权可读，且部分文件含股权/融资表述**」，**并非**"资本计划数字全暴露"。**最终敏感判定应由属主（明鉴）给口径**——她最清楚各文件承载什么。
   - **② 通讯服务器的安全组是白名单**：实测只有 `22 / 8791 / 8792 / 8803` 对外可达（临时在服务器监听 8899 → 本机探测 `000`）。**新开端口必须你在腾讯云控制台放行**；80/443 当前**关闭**。
3. **所以这不是"能不能放"的问题，是"用哪种访问模型放"的问题**（见第四节五选项）。我的推荐见第五节。

## 四、五个部署方案（含需求与代价）

**A. 由现有黑板进程托管静态目录**（复用已开端口 8792）
- 做法：给 `rust-blackboard` 加静态路由（如 `GET /sg/*` 从指定目录读文件）。
- 需：改我的 Rust 二进制（可控）+ 一个**鉴权决定**（黑板对非回环请求默认要求 token；浏览器导航无法带自定义头 → 只能用 URL 参数或对该路径免鉴权）。
- 优：**零新端口、零新服务、零控制台操作**；与数据同机，日后可接实时数据。
- 劣：把可视化塞进**通讯关键路径**（大量静态请求会与消息处理抢同一进程）；token 走 URL 会进历史/日志。

**B. 新起一个 node 静态服务 + 新端口**
- 做法：`/opt/systemgraph` + systemd 单元 + `node` 最小静态服务。
- 需：**你在控制台放行一个端口**（建议 8790 或 8080）；或用 80/443。
- 优：与通讯解耦、干净、易重启；systemd 托管（与现有服务同风格）。
- 劣：需控制台操作；仍无鉴权（除非另做）。

**C. nginx + TLS + Basic Auth（推荐用于"要干净 URL + 要鉴权"）**
- 做法：`apt install nginx`；443 上反代静态目录；Basic Auth；用 `xingqiao.meetfunbp.com` 申请证书（acme）。
- 需：**控制台放行 80/443**；安装 nginx；证书签发。
- 优：**有鉴权**（蓝图是商业敏感内容）、有 TLS、URL 干净、可加访问日志；不占通讯进程。
- 劣：服务器上多一个常驻组件（与现有"极简、无 nginx/docker"的风格不同）。

**D. Tailscale-only（推荐用于"只要内部可达、零公网暴露"）**
- 做法：让服务器加入 tailnet（`tailscale up --authkey=...`），静态服务只绑 tailnet 地址。
- 需：**你提供 tailnet auth key**（或你手动登录一次）。
- 优：**零公网暴露**（蓝图不上公网）、无需改安全组、三端（mac-mini/MBP/i9）已在 tailnet。
- 劣：非 tailnet 设备访问不到；服务器多一个 tailscale 进程。

**E. 维持现状 + 只做"更新"**（不做服务器部署）
- 做法：把公网那份从 9 小时旧版刷新到最新，并（若你要）加鉴权。
- 优：零新组件。
- 劣：**不满足你"放上通讯服务器"的意图**；且公网无鉴权的问题继续存在。

## 五、我的建议（可分批）

**第 1 步（今天就能做，无需你操作）**：在服务器 `/opt/systemgraph/` 放一份**最新导出**并用 **D 的前置**或 **B 的临时口**……
> 但注意：D 需 auth key、B/C 需控制台 → **没有"完全不需要你"的路径**。唯一例外是 **A**（复用 8792），但它把可视化塞进通讯进程。

**推荐组合**：**D（tailnet-only）+ 保留公网那份作为"外部可看的旧快照"**，或 **C（443+BasicAuth）** 若你希望有个正式 URL。
理由：它**现在正无鉴权挂在公网**（实测命中股权/融资表述，具体敏感上限待属主口径）——这条本身比"放不放服务器"更该先定。

**发布与新鲜度**：复用现有门（`bb-blueprint-gallery.py` → `export-marker.py` 的 `.export-done`，含逐文件 sha256），在服务器侧加一个"同步 + 校验"步骤（比对 `.export-done` 内的 sha256 才算发布成功——**不比对不发布**）。可用 systemd timer 定时或由发布者触发。

## 六、需要你决定的四件

1. **访问模型**：A（复用黑板口，无鉴权/URL带token）· B（新端口，无鉴权）· **C（443+TLS+BasicAuth）** · **D（tailnet-only，零公网）** · E（只更新公网那份）。
2. **既有公网那份怎么办**：`tm.meetfunbp.com/systemgraph/` 现在**无需凭据即可访问**且落后 9 小时 —— 保留/加鉴权/撤下？
3. **若选 B/C：请在控制台放行哪个端口**（建议 8790 或 80/443）。
4. **属主与协调**：SystemGraph 属明鉴/session-f38244df；通讯服务器部署链属 comm-server。**是否授权我牵这个部署，还是由明鉴或 comm-layer 属主执行、我只出方案与验收？**（我倾向：**明鉴出导出 + 我出部署与验收**，避免我改她的产物。）
