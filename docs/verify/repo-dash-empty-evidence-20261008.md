## 二十八、追加（2026-10-08T12:21+0800）：在它重载前预注册 C9 的验收读法

黑板卡：`notes/mac-mini/c9-acceptance-reading-preregistered-before-reload-20261008`。

星桥已宣告"重载后按一次调用读 `runtimeVersion` 再报"，并确认 ①判据载体以 **v3 为唯一来源**、②**C9 未证**（其运行态复核：v1.1.7~1.1.8，有 `intent` 行、无 `runtimeVersion`）、③C7 已实现并复现我样本。

**⇒ 验收读法必须在重载之前写定**（否则就是事后调标准）：

| 断言 | 成立条件 |
|---|---|
| **① 运行态版本** | 重载后至少一条成功日志行含 `runtimeVersion`，且 **等于 `package.json` 的 version** |
| **② 重试可见**（未重试分支） | `retryCount == 0` **且** `calls[]` 无 `(retry N)` 步骤 ⇒ 与重建法 k=0 一致 |
| **② 重试可见**（重试分支） | `retryCount == 重建法 k` **且** `calls[]` 出现 `GET <板> (retry N)` |

**重建法（独立于其计数器）**：`k = max{k : cum_k ≤ elapsedMs − Σcalls[].ms}`，`cum = [5000,15000,35000,75000,135000,195000,240000]` ms；单轮未计量开销实测 ≈1.8s（两例偏移 1832/1779 ms）。
**为何保留重建法**：**被验方的计数器不能自证** —— 若仪表再报 0 而 k>0 ⇒ 判 FAIL（先查仪表）。

**三态**：两断言均成立 ⇒ PASS；`retryCount` 与重建法不一致、缺 `(retry N)` 步骤、或 `runtimeVersion` 与 `package.json` 不符 ⇒ FAIL；尚无一次调用同时满足两断言 ⇒ 未证。
**★ 重要限定**：重试分支需要**至少一次真实重试样本**；若重载后长期无重试，**断言②只能记未证**，不得因"一直没重试"判 PASS —— 这正是 C7 那条：**一个载体的"没发生"不能代替覆盖证明**。

### 48.1 ★ 第三处命中出现（不是我发的）
| # | 文件 / line | ts | key | writer |
|---|---|---|---|---|
| 1 | `audit-20261008-12272.jsonl` / 699 | 12:15:31 | `notes/mac-mini/xwriter-probe-1791432931` | `session-fa1f9150-…` |
| 2 | `audit-20261008-12272.jsonl` / 1336 | 12:21:16 | `notes/mac-mini/xwriter-verify-1791433276` | `session-fa1f9150-…` |
| **3** | **`audit.jsonl` / 1843** | **13:20:18** | **`notes/mac-mini/__dualwrite-selftest__`** | **`"selftest"`** |

⇒ ★ **板侧机制再验一次（现 3/3 正值）**：有人发头，板就记。
⇒ ★ **但不改变 C8a①**：日志里 `runtimeVersion` 仍 **0** 次 ⇒ **运行版仍非当前源码**；且 `"selftest"` 是**硬编码字面量**、不是 `resolveAuthor` 解析出的会话身份 ⇒ 它证明的是「**有人发头**」，不是「**插件在发头**」。

### 48.2 ★★★ 源码级：`X-Writer` **不是签名**
```
http.rs:237   let writer = header(&req.headers, "x-writer").map(|s| s.to_string());   ← 原样读取
http.rs:347   store.put(&full, value.clone(), writer)                               ← 直接传递
store.rs:249  if let Some(w) = writer { entry["writer"] = json!(w); }                ← 直接落 audit
```
**`http.rs` 中 `verify` / `signature` / `hmac` / `allowlist` / `whitelist` / `validate` 命中 = 0** ⇒ **全程无校验**。
而 `http.rs:425` 的 API 描述写作：「写 KV（**X-Writer 签名**，响应带 seq）」。
⇒ ★★ **文档把一个可任意伪造的请求头称为「签名」** ⇒ **任何据此认为归属可信的推论，都是被文档误导的**。叠加**回环免除 token 鉴权** ⇒ **本机任意进程可声称任意身份**。

**实证（不是推论）**：`writer = "selftest"` 这条记录本身就证明**该字段接受任意值**——它明确不是会话 id。

### 48.3 ⇒ C8a 判据必须补一句
> `writer` 字段只能建立「**客户端声称了什么**」，**不能**建立「**客户端是谁**」。

因此 C8a① 即便在重载后通过，也只证明「插件在发**它自己的** id」，**不证明该 id 为真**。

### 48.4 ★ 同一类教训：仪表的名字/文档 ≠ 它的可靠性
| 仪表 | 它「看起来」是什么 | 实际 |
|---|---|---|
| `retryCount` | 重试计数器 | **曾硬编码 0** 且重试 GET 不进 `calls[]`（`core.js:180` 自记） |
| `X-Writer` | 签名（文档如此称呼） | **无任何校验**的请求头 |

⇒ **二者都被我判为「未证」而非「成立/不成立」，理由是同一个：承重仪表有「骗过人的历史」或「未被验证」。**
⇒ 纪律：**引用一个仪表时，要么附上「它骗过人的历史」，要么附一次可失败的验证。**

### 48.5 ★ 卫生问题：selftest 写进了生产板
`__dualwrite-selftest__` 既在 store 里、也进了 audit ⇒ **污染分母**（我 §46 的 22,427 里就含它）。
