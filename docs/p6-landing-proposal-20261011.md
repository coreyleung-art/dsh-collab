# P6（门边界）落地提案 —— 「纳入规则」为什么不产生效力，以及怎样才算真有效

> **出件**：2026-10-11 · 星桥第二任 `session-e317d6ab`（mac-mini）
> **缘起**：用户提问 —— 「你说的传下去是纳入规则？还是怎样才真的有效？」
> **性质**：★ **提案**（不是自证，也不是裁定）· ★ 执行权与裁定权**均不在本线**

---

## 〇、一句话

**「纳入规则」是【必要但不充分】**；★ **以本机实证，单靠纳入规则几乎等于没做**。
**真正有效的形态 = 可执行 + 进必经点 + 有负控 + ★ 由异体宣布闭合。**

## 一、★ 四条本机实证：「写进文件」不产生效力

| # | 实证 | 事实 |
|---|---|---|
| **1** | **`J44`（安装前先搜索本地）** | ★ 它是 **`enforced`** 规则 —— **却曾长期没有执行件**；直到 `reuse-before-build` skill + `j44-reuse-gate.py` 出现，它才**真的拦得住人**（有命中不显式裁决就 **exit 1**） |
| **2** | **`CCEP` / `blackboard-dispatch-protocol` / `失败可见性体系`** | ★ 三份都**成文**（4,508 B / 2,425 B / §四 96 行）—— 但在 v6 中**命中 0 / 0 / 1** ⇒ ★ **新会话读锚点恢复不到它们** ⇒ 它们成了「**已存在而无人知**」 |
| **3** | **`R060`（静默失败禁止）/ `R061`（假绿禁止）** | ★ v6 **自己立的** —— 而外部复核者的判语是：**「v6 立了 R061，却没把 R061 用在自己身上」**（当时最严重的缺陷 N1 在 8 个审查目标下**全部报「成立」**） |
| **4** | ★★ **编辑规程 E1（本线自己立的）** | ★ 我在 v6.1 §0.0b **立了 E1**（「凡给『某字面串计数 = 0』判据，须先核该字面是否被你要求写入的内容所包含」）—— ★ 而**紧邻同一节**，我把**【内容关键词】口径的 0** 当成**【文件名命中】口径**抄入 ⇒ `agent-comm-portal` 实测 **4** 而非 0 ⇒ ★★ **立规则的人在同一节里犯了该规则** |

⇒ ★★ **结论**：**「写进文件」与「被遵守」之间，本机已积累 4 次反例** —— 其中包括**立规则者本人在同一节违反**。

## 二、★ 本机唯一的成功案例：`tools/beacon-check.py`

★ 它是本机**真正在起作用的**门（本夜它**多次**跑出 FAIL / PEND，且**每次都被当真**）。它的五个特征：

| # | 特征 | 具体 |
|---|---|---|
| **①** | **可执行** | 有命令、有**退出码**（0 / 1） |
| **②** | **进必经点** | ★ 在 **§4.6 四件同步的第 7 步** —— **不跑就过不去** |
| **③** | **有负控** | 它内建 `--accept-shrink`（**显式接受体量骤降**）⇒ ★ **反证它真的会因骤降而红** |
| **④** | **三态如实** | 会输出 **FAIL / WARN / SKIP / PEND / PASS** 五态，且 ★ **自己写明「未抽检 ≠ 通过」「不得读作全绿」** |
| **⑤** | ★★ **不判语义** | 它只判「**声明是否完整**」（指纹、行数、规范形、指针未回退）—— ★ **从不宣布「内容为真」** |

⇒ ★ **⇒ 这五条合起来，才是「传下去」的样子。**

## 四、★★★ P6 的自指问题（这是本提案最要紧的一节）

**P6 的原文**（round7 给出、本线接受）：

> **门只判「声明是否完整」，不判语义真假** —— 语义真假仍须第三方裁定。理由 = **R046（verifier ≠ executor）**：**若起草人自己写门又自己运行并据此宣布「已闭合」，则门变成【自审】（§S3），并把「探针输入取自被检对象」（第 6 态）引入本流程。**

⇒ ★★ **⇒ 因此有一个自指**：

**要让 P6「真有效」，就需要把它做成 L3/L4；而 L4 要求「闭合由异体宣布」—— ★ 所以【P6 的落地本身不能由本线单方面宣布有效】。**

⇒ ★★★ **⇒ 本线能做的与不能做的**：

| 能做 | 不能做 |
|---|---|
| ★ 写**提案**（本件） | ✗ 宣布「P6 已落地」 |
| ★ 写**门的设计**（判据、退出码、负控） | ✗ 自己实现并**自己宣布有效** |
| ★ 给出**可检验判据**（见 §五） | ✗ 用它**替代异体复核** |

## 五、★ 可检验的判据：「怎样才能知道它真的有效？」

★ **判据（一条，可复跑）**：

> **在 P6 落地之后 —— 若有人「自写门 + 自跑 + 宣布闭合」，是否会被【自动】拦下？**
> 　· **会被自动拦下** ⇒ **有效**（因为它已进必经点、且闭合权不在执行者）
> 　· **不会被拦下，只能靠人记得** ⇒ ★ **仍是 L1/L2** —— **写进了文件，但没进流程**

★ **反例（造断 ⇒ 必须红）**：
1. **造一次「自写门自跑并宣布闭合」** ⇒ 流程必须**报错或要求异体签名**；★ **若只是弹个提醒，判 L2**
2. **把 `beacon-check` 从 §4.6 第 7 步拿掉** ⇒ 应有另一个**必经点**接住它；★ **若没有，说明「必经点」是偶然而非设计**

⇒ ★★ **⇒ 这条判据自己就说明**：**P6 的有效性【不在文本里】，在「有没有一个必经点会拦住自证」**。
