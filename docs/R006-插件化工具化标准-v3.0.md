## 0 · 一句话与适用范围

**一句话**：凡新做插件或工具，**十项全达标才交付**；第 ⑩ 项要求"不该发生的路径"在**结构上不可绕过**，并自带 `--lean4-check` 证明。

| 维度 | 口径 |
|---|---|
| 适用对象 | 一切智能体工具/服务：dsh 插件、CLI 工具、服务器端服务（xingqiao `/opt/comm-layer` 的 systemd 单元、bus-bridge、bb-sub 等）及其部署脚本 |
| 强制级别 | **enforced** —— 未达标不得交付；存量工具按 §8 排期补课 |
| 判断入口 | 本文 §2 十项规格 + §5 验收流程 |
| 豁免 | 一次性临时脚本（不进库、不留链）可豁免 ⑤⑥⑧；**其余七项不可豁免** |

## 1 · 为什么有这条标准（历史事故，全部有实据）

| 事故 | 缺哪一项 | 后果 |
|---|---|---|
| central-inbox 缺 `type:module` | ⑤文档化 / 自查 | CLD 启动崩溃 |
| 插件 apply 阶段 `ReferenceError`（未导入符号） | ②TCC 检测 | 启动即崩，靠外部 restart-guard 事后发现 |
| 为局部目标远程重启 CLD，打断活跃会话 | ⑩约束门 + R035 | 两次打断他人会话（2026-09-10） |
| 工具"报失败"但服务其实健康（假失败） | ②TCC + 判据正确性 | 误导运维，人工白跑一轮（2026-09-10） |
| 检查器把「PATH 缺 node」报成「语法错误」 | ⑩门型选择 | 让人去修不存在的问题（2026-09-10） |
| 同名工具两处实现、行为不一致 | ⑥版本管理 + ⑧落链 | 认知分裂，故障归因困难 |

**规律**：出问题的从来不是"没写代码"，而是**缺一项可机械核验的标准**，或**有一道会撒谎的检查**。

## 2 · 十项逐项规格

> 每项给出：**定义 / 验收标准（可机械核验）/ 自检命令 / 反例**。

### ① dsh 插件形态
- **定义**：以 dsh 插件形式交付，可被宿主挂载（而非裸脚本）。
- **验收标准**：
  1. `package.json` 含 `"type":"module"`、`main`、`version`、`dsh.bundle.patch`
  2. 存在 `cordis.patch.yml`，内容为 `- insert: [{id, name, config}]`
  3. `lib/index.js` 导出 `apply(ctx, config)`；需要工具时 `export const inject = ['tools']`
  4. 有客户端能力时声明 `dsh.client.{platform,inject}` **且**具备真实 `./client` 出口
  5. **★ 真挂载冒烟（2026-09-11 用户批准为硬项）**：交付必须含一段**真挂载自检**——真实 `import` 插件入口（非只读源码）+ 用**桩 ctx** 调 `apply(ctx, config)` + 断言**注册结果**（工具名/数量、槽位、命令等）。
     - **三种结果必须三态分开报，不得合并**：`pass`（挂上且注册了预期的东西）/ `fail`（apply 抛非依赖类异常）/ **`skipped`（依赖在本目录解析不到，如 `ERR_MODULE_NOT_FOUND`）**。
     - **`skipped` 必须如实说"跳过"并给出原因**，**绝不假装通过**（假的通过比没有检查更危险）。
     - **代价依据**：其它九项可以全绿而插件**根本挂不上**——apply 阶段抛异常＝交付物在运行时**不存在**。实测案例（2026-09-11，dispatch 交付方）：输出 schema 的嵌套对象漏写 `additionalProperties` → dsh-tools 抛 `UNSUPPORTED_SCHEMA` → 插件挂不上。
- **自检**：`node -e "import('./lib/index.js')"` 无报错（或包内 `--selfcheck`，且其中含第 5 项真挂载冒烟）
- **存量追溯范围**：**2026-09-11 用户裁定「全部 32 个都补」**。盘点基线（同日实测）：32 个真实插件中**仅 3 个**具备真挂载冒烟（`~/dsh-plugin-openpencil`、`dsh-plugin-reflect-collect`、`dsh-plugin-reflect-dispatch`），**29 个没有**（含本标准此前的参考实现 `dsh-plugin-cldvoice-activate`，即**本标准自己也未达标**）。存量补课见 §8。
- **反例**：只有 `.py`/`.sh` 无插件包装 → 无法被调度与观测；**或**自检只 `import` 不调 `apply()`（只证"文件能加载"，不证"能挂载"）

### ② TCC 检测（能力边界自检）
- **定义**：工具必须能自报**能力边界**——它能做什么、**不能做什么**、哪些路径"不该发生"。
- **验收标准**：`--selfcheck` 输出至少三段：① 能力清单 ② 不该发生路径清单 ③ 依赖完整性（见 §3 selfcheck.js）
- **自检**：`<tool> --selfcheck` 退出码 0
- **反例**：只能回答"我依赖齐全"，答不出"我能碰什么/碰不到什么"

### ③ CLD 自适应
- **定义**：不依赖 CLD/宿主内部 API 才能工作；在无 CLD 环境下可独立运行（降级或拒绝，而非崩溃）。
- **验收标准**：运行期依赖仅限 node 内置模块 + 系统命令；对外部服务缺失有明确分支
- **自检**：断网/无宿主环境下 `--selfcheck` 仍能给出结论
- **反例**：import 宿主的私有路径；没有 CLD 就抛栈

### ④ dsh 版本自适应
- **定义**：不锁死某个 dsh/宿主内部 API 版本；peer 依赖走正式声明并被解析。
- **验收标准**：`peerDependencies` 声明全部 peer；运行期不 import 未声明的内部模块；对未知版本给出**明确降级行为**
- **自检**：`--selfcheck` 中 peer 解析结果可见（本目录 → profile `node_modules` 两级尝试）
- **反例**：`require('../../dsh-runtime/...')` 这类相对路径硬引用

### ⑤ 文档化
- **定义**：一个读者能据此**独立复现**的文档。
- **验收标准**：文档含 ① 为什么需要（事故/证据）② 用法（含退出码）③ 达标矩阵 ④ 坑 ⑤ 复现命令；文档路径写进 `package.json` 的 `r006.documented`
- **自检**：文档中每条命令可复制即用
- **反例**："见代码" / 只有一句摘要

### ⑥ 版本管理
- **定义**：版本号**单一来源**，改动有 CHANGELOG。
- **验收标准**（**2026-09-11 用户批准修订**）：**版本号只有一个声明处**，CLI `--tool-version` **机器可读地**从该来源读取（**不得硬编码两份**）；`CHANGELOG.md` 记录变更与**纠错**（含错误模型复盘）。
  · **载体按形态区分**：**dsh 插件形态** → 版本写在 `package.json`；**无包文件的独立工具**（如独立 `.py`）→ 写在其**唯一版本常量**内，且**必须提供自动校验证明不存在第二处声明**（如自检时反查自身源码）。
- **自检**：`<tool> --tool-version` 与**该唯一来源**一致；若存在包文件则与 `package.json` 一致
- **反例**：`const VERSION='1.0.0'` 与包版本各写一份 → 必然漂移；**只宣称"单一来源"而无自动校验** → 退化（见 §6 坑）

### ⑦ 统一日志
- **定义**：结构化、可追溯、落盘固定路径。
- **验收标准**：日志路径固定（本项目 `~/dsh-collab/logs/<tool>.log`）；每次动作记录 时间/输入/判断/结果/诊断；**失败也留痕**
- **自检**：跑一次后日志追加行数 > 0 且含结果字段
- **反例**：只 `print` 到 stdout；失败路径无日志

### ⑧ 自动落链
- **定义**：产出必须被登记，别人能**检索到**它。
- **验收标准**：① RULES.md 规则号（若定义规则）② 黑板 `data/registry/` 登记卡 ③ 本文 §9 索引更新（若属标准件）④ 知识库入库（长文档）
- **自检**：`GET /data/registry/<key>` 200；`knowledge_search` 能命中
- **反例**：产出只在会话里说过，落盘后无人知

> ★★ **v3.1.2 修订（2026-10-09 · 用户明示同意）—— ⑧ 补【push 判据】，不改十项数目**
>
> **动因（有实证，非推断）**：2026-10-09 完整评估实测到一个反例 ——
> 本机有两个 R006 补课器（`scripts/r006-retrofit.js` / `r006-retrofit-scripts.js`）与一份 273 条合规矩阵，

### ⑨ CLI 治理
- **定义**：CLI 行为规范、可预测、可脚本化。
- **验收标准**：① 参数解析严格（未知旗标 → 用法错误）② **退出码语义固定**：`0` 成功 · `1` 失败/门失效 · `2` 用法或 IO 错误 ③ 存在 `--dry-run`（**零变更**）④ 存在**机器可读输出开关**（默认名 `--json`；**若该名已被该工具既有的非输出用途占用**，可用 `--json-out` —— 但**必须在 `--help` 与 README 显式声明**，且该偏离须在 CHANGELOG 记明）⑤ `--help` 自解释
  · **④ 的具名逃生舱（2026-09-11 用户批准）**：本条要的是**可脚本化**（机器可读），**不是名字统一**。故当 `--json` 已被一个**不同用途的无损接口**占用时，标准允许具名替代，条件是**声明显式、可机械核验**（查 `--help`/README 中两名字之一即判达标）。**不得**用"名字被占"当借口省略机器可读输出。
- **自检**：未知旗标 exit 2；`--dry-run` 前后外部状态实测未变；机器可读开关在 `--help` 中可见（`--json` 或已声明的替代名）
- **反例**：失败也 exit 0；无 dry-run 只能"真跑试试"

### ⑩ 约束前置 · 不可绕过（Lean4 逻辑门）
- **定义**：工具若涉及"**不该发生的路径**"（违规写 / 越权 / 跳步 / 非法引用 / 为局部目标杀全局），约束必须**结构上不可绕过**，并自带证明。
- **验收标准**（四条同时满足）：
  1. **没有那个入口**：危险操作在参数/schema 层**无法表达**（枚举、冻结常量、封闭白名单）
  2. **没有那个能力**：实现里不含危险原语（如宽杀、按 PID 杀、任意命令执行）；有能力时用**命令白名单**收口
  3. **有那个证明**：`--lean4-check` 自证全绿（§4 六项模板）
  4. **失败即停**：门不通过时**拒绝执行**并给可操作原因（不是警告后继续）
- **自检**：`<tool> --lean4-check` exit 0
- **反例**：靠"检查后放行"（可绕过）；只有文档说"请勿"（无结构约束）

## 3 · 交付物模板

```
<tool-or-plugin>/
├── package.json          # ① shape + ⑥ 版本单一来源 + r006 段声明达标
├── cordis.patch.yml      # ① 插件行（- insert: [{id,name,config}]）
├── lib/
│   ├── index.js          # ① apply(ctx)：inject + ctx.tools.register（+ ctx.effect 回收）
│   ├── selfcheck.js      # ② R014 自查门（apply 最前调用）
│   ├── gate.js           # ⑩ 结构门：冻结白名单 / 负例矩阵 / 源码扫描
│   └── <core>.js         # 业务内核（无危险原语）
├── cli.js                # ⑨ CLI 治理（--selfcheck/--lean4-check/--tool-version/--dry-run/--json）
├── docs/README.md        # ⑤ 文档（含十项矩阵 + 坑）
├── CHANGELOG.md          # ⑥ 变更 + 纠错复盘
└── (logs/…)              # ⑦ 统一日志（实际写 ~/dsh-collab/logs/<tool>.log）
```

### 3.1 `package.json` 最小字段

```json
{
  "name": "dsh-plugin-<x>", "version": "1.0.0", "type": "module", "main": "lib/index.js",
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } },
  "peerDependencies": { "@deepseek-ai/cordis": "^4.0.1", "@deepseek-ai/dsh-tools": "^0.1.0-rc.6" },
  "r006": { "category": "engineering", "scope": "mac-mini", "status": "enforced",
            "documented": "docs/README.md", "unified_log": "~/dsh-collab/logs/<tool>.log",
            "lean4_gate": "lib/gate.js 冻结白名单 + 命令白名单 + --lean4-check 六项" }
}
```

### 3.2 `selfcheck.js`（② 的落地）

```js
export function runSelfCheck(pluginName, spec = {}) {
  // 1) peer 可解析：先本目录，再 ~/.dsh/profiles/<profile>/node_modules（两级；不要只试一级）
  // 2) sourceFiles 里逐个检查 requiredSymbols 是否真的导入（★ 必须显式给 sourceFiles）
  // 3) type:module 匹配
  // 输出：{ok, missing[], warnings[], notes[]} + 落盘 ~/.dsh/plugin-selfcheck/<plugin>.json
}
```
**★ 血泪条**：不给 `sourceFiles` 时，检查会扫到 selfcheck.js 自己身上 → **假失败**。宁可如实说"符号检查已跳过"，也不要假装通过或假装失败。

## 4 · ⑩ 约束门的四种门型与 `--lean4-check` 六项模板

### 4.1 四种门型（按场景选，可叠加）

| 门型 | 机制 | 适用 |
|---|---|---|
| **类型锁** | 危险值无法构造（枚举/字面量类型/冻结常量） | 参数化危险操作 |
| **入口门** | 只有唯一受控入口能触发副作用 | 状态变更类工具 |
| **Schema 门** | 入参 schema 即约束（`enum`/`required`），非法值在解析期被拒 | 有 JSON schema 的工具 |
| **状态机** | 只允许合法状态迁移（如 `idle→running→done`） | 流程/编排类工具 |

### 4.2 `--lean4-check` 六项模板（全绿才交付）

| 项 | 证明内容 | 实现要点 |
|---|---|---|
| **A** | 源码无危险原语 | **去注释/字符串/正则字面量后**扫描（否则会把自己的检测正则当靶子=假阳性） |
| **B** | 负例全部被拒 | 造 N 条越界输入（框架名/通配/空值/路径穿越/外部服务名）逐条实测 `GateError` |
| **C** | 正例可用 | 合法输入必须能通过（**防"门太宽把功能也拦了"**） |
| **D** | `--dry-run` 零变更 | 运行前后**外部状态实测一致**（PID/端口/文件 mtime） |
| **E** | 白名单冻结 | `Object.isFrozen(...)` 为真 |
| **F** | 外部命令白名单 | 枚举全部 exec/spawn 调用点，断言命令集 ⊆ 允许集；**步骤：去字面量定位调用点 → 回原文读实参**（否则会"空集通过"） |

> **三句口诀**（都是踩出来的）：**门太宽会砍掉自己人 · 扫原文会误伤自己 · 读不到实参会空集通过**。

## 5 · 验收流程（三步，可复制）

```bash
# 1) 自查门 + 能力边界（②③④）
<tool> --selfcheck            # 期望 exit 0

# 2) 结构门自证（⑩）
<tool> --lean4-check          # 期望 A–F 全绿、exit 0
