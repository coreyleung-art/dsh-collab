> 工具：~/dsh-collab/scripts/pre-delete-archaeology.py（纯规则零 LLM，属主=HR）

## 一、纪律（J47 破坏性操作纪律的考古前置）

**删除前必考古**——不是直接删，三步走：
1. **评估**：`python3 scripts/pre-delete-archaeology.py --path <目标>` → 得判定
2. **按判定处置**：
   - ✅ safe_delete → 直接删（日志/缓存/噪音，零价值）
   - 📋 archive_meta → 生成考古清单（`--gen-manifest`）→ 删本体留元数据
   - 🧠 sediment_first → 先提炼向量化入库（KB）→ 再删
3. **登记**：删除动作入 registry changelog（版本+条目），红绿灯走完

## 二、工具三态判定（纯规则，零 LLM）

| 判定 | 含义 | 处置 |
|---|---|---|
| safe_delete | 日志/缓存/噪音（noise:signal > 50:1） | 直接删，无需沉淀 |
| archive_meta | 二进制资产（模型/权重/打包） | 考古清单留档（名称/大小/来源/用途），本体可删 |
| sediment_first | 文本含独特价值信号（经验/配置/教训） | 先提炼→KB 向量化→再删 |

## 三、向量化决策（何时入库）

| 场景 | 是否入库 | 原因 |
|---|---|---|
| 日志（噪音主导） | ❌ 不入库 | 无独特模式，向量化纯浪费 token + 污染知识库 |
| 二进制模型 | 清单落盘（非向量化） | 开源 GGUF 可重下，元数据即可；向量化二进制无意义 |
| 独特经验/配置/踩坑 | ✅ 入库 | 教训复利（三因子样本同款） |

## 四、通用规则（泛化声明）

1. **所有智能体**：删除共享资源前跑本工具（不依赖自觉——先考古再删）
2. **所有项目**：删除资产前生成考古清单（可追溯恢复）
3. **端侧（i9/MBP）**：删除前同样先评估；二进制资产先清单后删（Windows 同规则，工具 Python 跨平台）
4. **新增**：J47 纪律扩展为「先备份 + 先考古 + 先用户同意 + 先确认角色」
