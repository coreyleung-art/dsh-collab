## C. 基础设施（两项，均属通道变更 ⇒ 需 R048 + 用户批准）

### C1. CLD 端口不稳定（**官方答案已找到**）
- 事实：CLD 以 `bin.js web --port 0` 启动；官方 `@deepseek-ai/dsh-host-webserver` 的 `port` 定义即「**0 = 请求 OS 分配端口**」⇒ 每次重启换地址（实测历史：65074/65021/63723/61044/31888 → 现 51127）。
- 官方路径：`architecture.md:55`「Desktop defaults to port `19387`; **profile configuration can override it**」。
- 动作：在 **profile 配置**里为 host-webserver 设定固定端口（而非改启动参数）；`host` 保持官方支持值之一（建议 `127.0.0.1`）。
- 附带（同一配置）：`compression: gzip` 可减负。
- 验收：重启后地址不变；旧标签页不再失联；且固定端口天然防「runtime 悄悄增殖」。

### C2. 中枢板写路径退化（今日两次）
- 事实：PUT 超时 20-30s；服务器内存 211/400MB（非内存瓶颈）⇒ I/O/负载型；数据面 66MB（audit 45MB / snapshot 21MB）+ 10 个 SSE 订阅者，跑在 1GB 机器。
- 已做：两次重启 comm-server（远端 PUT 恢复 200 / 0.03-1.03s）。
- 待议（用户定）：① 内存上限 400→600MB ② 每日定时重启（systemd timer）③ 快照写频率/target 优化（板端改动 ⇒ 送审）
- 验收：连续 24h 无写超时；GET 延迟 P95 < 1s。
