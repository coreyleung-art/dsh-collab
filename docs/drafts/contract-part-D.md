## 8. 后果（Consequences）

### 8.0 本节为什么存在，以及应当怎么读它

RFC 2119 §7 要求规范作者**花时间说明**不遵守要求或建议所带来的安全含义，理由是：**大多数实现者不会拥有产生该规范的那些经验与讨论**。

⇒ 故本节**不写**「这件事很重要」「会影响互操作」这类抽象判断，而**逐条写出接收方一侧可观察到的事实**。

**本节的两条读法：**

1. **每一条「后果」都必须是接收方一侧可观察的事实。** 若某条要求被违反后，接收方**观察不到任何差别**，则这条要求**不属于它当前所处的级别**——它要么应当降级为可选，要么应当被删掉。
2. **本节按要求的内容引用要求，不重复要求文字。** 各条要求的正式文字及其复跑命令见 §4（接入要求）。

### 8.1 不遵守 MUST 的后果

#### 8.1.1 本节处理的 MUST 级要求

下列要求均为 **MUST / MUST NOT** 级（RFC 2119 §1、§2：绝对要求与绝对禁止）。

**它们全部属于 RFC 2119 §6 允许使用级词的两类之一**——即「互操作必需」或「限制有害行为」；**没有任何一条**用于强加内部实现方式、具体工具选择或目录结构。

| 要求（内容） | 级别 | 类别 |
|---|---|---|
| 每条**产出**必须写全规范性引用所指规范版本的全部**必填字段** | **MUST** | 互操作必需 |
| 一旦在某条产出上启用了某个可选字段，该字段即成为该条产出的必填字段 | **MUST** | 互操作必需 |
| **写入方**必须在每条产出上声明其**身份状态** | **MUST** | 互操作必需 |
| 写入方不得在身份字段填入**非本写入方**的标识 | **MUST NOT** | 限制有害行为 |
| **去重键**必须是对产出**内容**计算的**内容指纹** | **MUST** | 互操作必需 |
| 写入方不得在去重键填入与产出内容**无关的值** | **MUST NOT** | 限制有害行为 |
| **认定方**不得因产出不符合本契约的形式要求而**拒收**该产出 | **MUST NOT** | 限制有害行为 |
| 本契约的任何一步不得要求写入方交出凭证、秘密、写权限或代码改动 | **MUST NOT** | 限制有害行为 |

★ 上表每一行的**级别**与**类别**均为该行的正式归类；本节其余部分只给出它们的**违反后果**。

**术语定义（本节首次出现处）：**
- **产出**：一个写入方写入共享存储的一条消息。
- **写入方**：向共享存储写入产出的参与者（可能是智能体、定时器、脚本或图形界面）。
- **接收方**：从共享存储读入产出的参与者。
- **认定方**：对一条产出或一次声明作出「达标 / 未达标 / 不可判」判定的一方。
- **共享存储**：本网络的各参与者共同读写的键值存储；每台设备本地各存一份，写入其中的条目会被转发到其他设备的副本。
- **信封**：一条消息所携带的固定字段集合（其权威定义见规范性引用）。
- **必填字段**：规范性引用所指规范版本要求每条消息必须携带的字段（该规范版本处载明其个数）。
- **通道**：一条消息所走的通信路径。
- **去重键**：消息中的一个字段，取值是对消息**内容**计算的指纹；接收方据它判定两条消息是否是同一件事。
- **内容指纹**：对内容做哈希运算所得的定长字符串。**同一内容必得同一指纹；不同内容几乎必得不同指纹。**
- **拒收**：接收方不接收某条产出（丢弃、退回或不予处理）。

#### 8.1.2 不写全必填字段时的逐字段后果

下表逐字段说明：**该字段缺失或写错时，接收方一侧会出现什么事实。**

| 缺失或写错的字段 | 接收方一侧可观察到的事实 |
|---|---|
| **版本声明字段** | 接收方**无法判定该产出属于哪个版本** ⇒ 只能按最低兼容路径处理 ⇒ 该产出**计入该写入方的未达标比例**（分母计入、分子不计）⇒ **该写入方的达标读数不上升** |
| **标识字段**（该产出自身的唯一标识） | 接收方**无法引用这一条**——回执、审计、去重记账都要按标识寻址 ⇒ 同一条产出被处理两次时，**无法判定它们是同一条** ⇒ **重复处理** |
| **类型字段** | 通道选择无法进行 ⇒ 落到默认路径（逐条直接投递）⇒ 本应写入共享状态区的状态更新**被当成实质任务** ⇒ 每发一条**多唤醒一个参与者** ⇒ **该写入方的成本读数上升，而对方没有收到任何需要处理的东西** |
| **通道字段**（或它与类型字段不相容） | 接收方**按错误的通道取件** ⇒ 状态更新被投到逐条直接投递路径，而对端**只在共享状态区读状态** ⇒ **接收方收不到**（产出存在于存储中，但没有任何一方会去取它） |
| **发送方字段** | 接收方**无法归属该产出** ⇒ 该产出被计入**不可归属** ⇒ 该写入方的达标比例**分母增大而分子不变**；并且**无法回信**——没有回信地址 |
| **接收方字段** | **路由不到**——接收方不知道投给谁 ⇒ 该产出**被丢弃或进入死信** |
| **会话聚合字段**（把多条产出聚合成一件事的那个标识） | 接收方**无法把该产出并入既有会话** ⇒ 同一件事的多条产出**散成互不相关的独立条目** ⇒ 接收方**对每一件都重新处理一遍** |
| **优先级字段** | 接收方**无法排序** ⇒ 高优任务**排到低优之后** ⇒ 时限内无法完成，而**没有任何一方收到「它被排后了」这一事实** |
| **预算上限字段** | 接收方**无法判定该任务的成本上限** ⇒ 只能二选一：按无上限处理（**成本失控**）或直接不收（**任务丢失**）。⇒ 两种结果都是接收方单方面承担的 |
| **去重键字段**（缺失，或不是内容指纹） | **无法去重** ⇒ 同一内容的重投**被当成两件事** ⇒ **重复计数**（配额按两次计）· **重复执行**（同一个动作做两次）。⇒ 而对方**不会收到任何提示**：它只看到事情被做了两遍 |
| **时刻字段**（缺失，或不是规范时刻串） | **无法排序、无法判窗口** ⇒ **去重窗口**无法计算（窗口以该字段为基准）⇒ 只能二选一：**全部判为重复**（丢真产出）或**全都判为不重复**（重复执行） |
| **内容字段** | 该产出**没有内容** ⇒ 接收方**无物可处理** ⇒ 该产出**必被丢弃** |

**术语定义（本节首次出现处）：**
- **去重窗口**：判定两条内容相同的产出是否为「重复」时所考察的时间范围。
- **不可归属**：产出本身可读，但其写入方无法被判定为任何一方。
- **未达标比例**：一个写入方在一段时间内的全部产出条数中，**不符合本契约形式要求**的条数 ÷ 其产出总条数。**达标比例** = 1 − 未达标比例。

#### 8.1.3 启用可选字段时的后果

规范性引用所指规范版本把一部分字段列为**可选**。**它们的缺失本身不产生后果**；但**一旦在某条产出上启用了其中某一项，该项即成为该条产出的必填字段。**

以**签名**字段为例（签名：对该产出内容计算的、可被接收方验证的校验值，用于证明该产出在离开写入方之后未被改动）：

| 情形 | 接收方一侧可观察到的事实 |
|---|---|
| 写入方**未启用**签名，字段不出现 | 无后果。接收方按「该写入方不使用签名」处理 |
| 写入方**启用了**签名，但字段缺失或值不符 | 接收方**无法区分**「发送方未启用签名」与「签名在途中被破坏了」 ⇒ **完整性检查失去判别力** ⇒ 接收方要么对**全部**产出放弃完整性检查，要么把**正常的未签名产出**一律判为可疑 ⇒ 两种结果都是**把可信的与不可信的混在一起** |

⇒ 故「启用即必填」这条要求的意义是：**让「有没有签名」这一事实本身成为可判定的**。缺少它，接收方**无法知道该不该验**。

#### 8.1.4 两类后果的区别（哪一类更重）

- **单条后果**：那一条产出**丢了、错了或做重了**。它是**局部的**，且**通常会因为对方重发而自行消失**。
- **累积后果**：该写入方的**达标比例不上升**。它是**持续的**，且**不会因为重发那一条而消失**——因为比例是按**全部产出**算的。

⇒ **累积后果比单条后果重**：单条后果是**一次事故**，累积后果是**一个不下降的数**。而本契约的治理方式正是建在累积后果上（见 §8.3）。

### 8.2 不遵守 SHOULD 的后果

RFC 2119 §3 规定：**SHOULD** 级条目在特定情形下**可以**有正当理由不遵守，**但选择另一条路之前，必须理解并权衡全部含义。**

⇒ 故本节为每一条 SHOULD **同时给出**：不遵守的后果，以及**什么情形下不遵守是正当的**。

**下表「要求」一列的每一条均为 SHOULD 级。** 它们**既不属于「互操作必需」，也不用于「限制有害行为」**，而属于第三类：**有正当理由可以不遵守的建议**（RFC 2119 §3——但选择另一条路之前，必须理解并权衡全部含义）。⇒ 故**不遵守 SHOULD 不构成不合规**，本节给出的是它的**代价**。

**逐条后果：**

| 要求（内容） | 不遵守时接收方一侧可观察到的事实 | 什么情形下不遵守是正当的 |
|---|---|---|
| 写入方**宜显式声明未接入的面** | 接收方**把沉默当成「已全部接入」** ⇒ 达标比例的**分母少算** ⇒ 读数**高于事实**，且**无法区分**「真的全部接入」与「未接入但没有说」。⇒ 注意：这不是「读数错」，而是**读数与事实脱钩**，且**外部看不出来** | 确实没有任何未接入的面时——此时应**写空数组**，而**不是省略该字段**。省略字段**不等于**空数组 |
| 写入方**宜在写入路径变更之后、以及距上次举证超过一个复核周期之后，重新举证** | 读数**停留在旧值** ⇒ 出现「读数说达标、实际产出不达标」⇒ 接收方按旧读数**继续信任一个已经失效的声明**。⇒ 而**两件事之间看不出变化**，所以这个错误**不会自己暴露** | 变更尚未生效或尚未上线时——此时应在声明里**注明该变更的状态**，而不是不提 |
| 写入方**宜在举证对象中附上未编辑的原始输出** | 只给摘要 ⇒ 接收方**无法确认命令真的执行过**、**无法确认跑的是被举证的那一条** ⇒ 记**不可判**。⇒ 而**不可判既不是达标也不是未达标** ⇒ 提交方**得不到分数**。⇒ 即：**省掉原始输出，损失的是提交方自己** | 输出中含秘密或个人数据时。此时**应当遮蔽后再附**（见 §9.2），而**不是只给摘要**——遮蔽保留的是「这条是什么」，摘要丢掉的是「它是不是真的存在」 |
| 写入方**宜由异体核验自己的声明** | 自证自核 ⇒ **单点错误无人可发现** ⇒ 一个错误声明会被当作事实**在此后所有核验里沿用** ⇒ 错误的**存活时间**由「该写入方自己什么时候发现」决定，而它**没有动机去发现** | 当时确实没有第二方可核时。此时应把该条**显式记为「仅自证」**，使其**看起来与已核的不同**——而不是让它看起来像已核 |
| 写入方**宜使其举证覆盖其声明的全部面** | 声明得多而举证少 ⇒ **达标比例低**。⇒ 因为比例是按**声明并举证的范围**算的（不是按「写了多少条产出」算） ⇒ **少声明不是策略**；只有「**声明清楚 + 举证完整**」才给出好读数 | 无正当例外。⇒ 但须注意：**这不构成不合规**——比例低**不等于**未达标，它只是**读数不好看** |

**术语定义（本节首次出现处）：**
- **面**：一条可**单独**判定合规性的通信路径，或一类可**单独**判定的产出。
- **未接入面**：写入方**已声明**尚未满足契约要求的那些面。
- **举证**：写入方为支持自己的声明而提交的、**可被他人独立重算**的一件东西（其字段见附录 A）。
- **不可判**：既**不能**判定为达标、也**不能**判定为未达标的状态。
- **异体核验**：由**不是**该声明的写入方的另一方执行的核验。

### 8.3 为什么本契约不靠禁令

#### 8.3.1 禁令要求三个人工环节同时在场

一条禁令要真的改变行为，需要三件事**接连发生**：

| 环节 | 禁令要求它 | 而它的难点是 |
|---|---|---|
| **有人发现**某次违禁 | 专门去看 | 发现**不是收件的副产品**——收到一百条产出，**没有任何一条会自己喊出「这条违禁」**。发现需要一个**额外的动作** |
| **有人判定**这次行为属于违禁 | 判明情形 | 判定通常需要**意图**：同一次「用了旧格式」，是疏忽、是不知道、还是明知故犯？三者的处置不同，而**意图不写在产出里** |
| **有人执行**后果 | 施加代价 | 执行者**必须**在被禁的一方之外，否则禁令退化成自罚 |

⇒ **三个环节任缺其一，禁令就退化成一句文字**：它**仍然写在文档里**，但**不再改变任何行为**。而这三个环节**都依赖人的持续在岗**——岗位会换人、会忙碌、会空缺。

#### 8.3.2 读数不需要这三个人

本契约对「产出使用了旧版本信封」的处置如下。**这是一个具体例子**；**同一形状适用于本节列出的所有可数要求**：

> **该产出【仍然被接收】。**
> 它**不会被拒收、不会被丢弃、不会触发任何告警**。
> **但它【计入该写入方的未达标比例】。**
> ⇒ 于是**不用任何人执法，写入方自己会看到那个数不降。**

三个人工环节在读数下的对应物：

| 环节 | 禁令需要什么 | 读数需要什么 |
|---|---|---|
| **发现** | 有人专门去看 | **不需要**——计数是**收件流程的副产品**：接收方本来就要读这条产出，顺手数一个事实 |
| **判定** | 判定意图（疏忽？不知？明知？） | **不需要**——**不判意图**，只数事实：这条**有没有**规范版本声明 |
| **执行** | 一个在被禁一方之外的执行者 | **不需要**——后果由写入方**自己的读数**呈现，**没有谁需要被说服去执行什么** |

#### 8.3.3 为什么读数比禁令更可靠（逐条对照）

1. **不依赖执法者在岗。** 读数的产生依赖的是**已经发生的收件动作**，而收件是网络的**日常运作**——它不需要任何人为这件事在岗。禁令依赖的是**一个额外的岗位**，而岗位是所有机制里**最容易中断**的一环。

2. **不依赖判定意图。** 意图不可从产出中读出。**凡需要判意图的规则，都会在边界情形上失效**——而边界情形恰恰是最需要规则的地方。

3. **不制造对抗。** 禁令把问题变成「**谁赢**」：被禁的一方有动机**隐藏**行为（改一个字段名、换一条路径），于是**违规从可见变成不可见**——结果是**治理能力下降**。读数把它变成「**这个数降不降**」：写入方**自己**有动机降它，而且**降它的每一步都是可见的**。

4. **不可被绕过。** 一条禁令可以被**偷偷违反**。读数**没有「偷偷」一说**——产出只要被接收，就**已经**被计数；而**产出必然要被接收**（见下条）。⇒ 绕过一个读数的唯一方法是**真的把它改掉**。

5. **不阻断，所以不制造更坏的问题。** 注意上文的处置是「**仍然被接收**」而不是「拒收」。**拒收一条产出，比收到一条格式不合规的产出更坏**：拒收**丢失信息**，而格式不合规**只是让读数不清**。⇒ 读数机制**不会为了治理一个指标而破坏通信本身**——这正是下列 MUST NOT 级要求的内容：

   > **认定方 MUST NOT 因产出不符合本契约的形式要求而拒收该产出。**

6. **可随时复跑，不依赖记忆与承诺。** 读数是**一个数**，**任何人可在任何时候重算**，且结果可被独立比对。禁令的效力则依赖**对「有没有人违规」的记忆**——而记忆**不可复跑**。

7. **把合规从「守法」变成「改进」。** 禁令的成功条件是**违规次数为零**——一个几乎不可能达到、且**无法证明达到**的目标（因为不可见的违规不进计数）。读数的成功条件是**比例上升**——一个**可逐步达到**、且**每一步都可见**的目标。

#### 8.3.4 读数做不到什么（如实说明）

**读数只维持可数的要求。** 一条要求若**无法被计数**，本节的方法对它无效。

此时只有两条路：

- 把它**改写成可数的形态**；或
- 把它**降级为可选**。

⇒ 而**不得假装它在被执行**。「无法计数」与「不需要写」是两件事：**前者要改写，后者要删除**。

⇒ 这就是本契约**不写**「禁止使用旧版本信封」、而写「**旧版本的信封计入未达标比例**」的原因。**同一形状**适用于本节列出的所有可数要求。

## 9. 安全考量（Security Considerations）

> 本节依规范文档结构的要求设立（规范文档**必须**含安全考量一节）。
> 本节写三件事：**本契约的要求可能被如何滥用** · **本契约不索取什么** · **伪造身份的后果**。
> 一条贯穿全节的线索：**本节列出的每一项对策都不是「禁止」，而是「让它变成可核的事实」**——与 §8.3 同一形状。

### 9.1 本契约的要求可能被如何滥用

本契约的要求本身是中性的：它要求**声明**和**举证**。而这两件事**都可以被声称**。⇒ 故滥用点集中在**把声明当成事实**。

**术语定义（本节首次出现处）：**
- **声明**：写入方对自身状态作出的**可核**陈述。
- **身份串**：本网络分配给一个写入方的标识字符串。
- **身份状态**：产出所携带的、关于「写入方有无身份」的声明。它**有且只有三种**互斥可能（见 §9.3）。
- **类别声明**：写入方关于自己属于哪一类（有身份 / 无身份）的那个字段。

**逐条列出：**

| 滥用方式 | 怎么做 | 它造成什么 | 用什么让它变成可核的事实 |
|---|---|---|---|
| **1. 伪造身份** | 在身份字段里填入**另一个写入方**的身份串 | 接收方把甲的产出归到**乙**名下 ⇒ **乙名下出现乙没有写过的产出**，而甲**不知情** | 乙的产出集合是**乙自己可枚举**的 ⇒ **乙能发现不属于自己的条目**。⇒ 注意：**不能靠凭据检查**——本契约**不索取凭证**（§9.2）⇒ 身份串**不携带凭据**，只能靠**来源与声明的矛盾**来核（§9.3） |
| **2. 冒用已出现过的身份串** | 抄一个在本网络中已经出现过的身份串 | 同第 1 条，且**更难被察觉**：冒用的身份串是「真实存在」的，按「身份串是否存在」做的检查**会全部通过** | **同一身份串不应对应两种不同来源**。⇒ 判据是**来源的多样性**，不是**身份串的存在性** |
| **3. 以「无身份」规避归属**（★ 本契约最易被滥用的一点） | 对一个**确实有身份**的写入方，声明为无身份 | **逃避归属**，同时**仍然享有「被接收」的待遇**（§8.3.2 的处置对它是照常适用的） ⇒ 它拿到读数的好处，**不承担归属的成本** | **类别声明必须可被指认**：无身份这一取值**只适用于来源本身可指认、且确实没有身份的三类——图形界面、定时器、脚本**。⇒ 一次声明为无身份的产出，若其来源**可被指认**为某个有身份的写入方，则**矛盾可核** |
| **4. 用错版本却不声明** | 写一个**既不是规范值、也不是任何可识别值**的版本串 | 接收方**无法判定该产出属于哪个版本** ⇒ 只能按最低兼容路径处理；且该条**计入未达标** | 版本值**必须从实际写入路径读出**，而**不得从声明里读出**（见附录 B）。⇒ 于是「声明」与「写入路径」**是两个可分别回读的对象**，差异可核 |
| **4b. 声明一个「看起来合法」的版本值，但与实际写入路径不符** | 声明里写规范值，而写入路径里写的是另一个值 | **声明与事实脱钩**，而**外观完全正常**——这是第 4 条里更坏的一种 | 同上：**回读写入路径**，而不是回读声明 |
| **5. 只声明一个很小的面** | 让达标比例好看 | 依符合性声明的口径（**按声明并举证的范围算**），这确实会产出**高比例** | **未接入面必须显式声明** ⇒ 于是「少声明」**缩小了分母**，却**把未接入面从「沉默」变成白纸黑字** ⇒ 收益有限，而代价是**公开了一份未接入清单**。⇒ 这**不是一条可行的捷径** |
| **6. 举证只给摘要** | 不给未编辑的原始输出 | 接收方**无法核** ⇒ 记**不可判** ⇒ **不可判不等于达标** | ⇒ 滥用者**拿不到分数** ⇒ 这条**自伤**，**不构成有效滥用** |
| **7. 操纵时刻字段** | 把时刻写成未来或很久以前的值 | 去重窗口以该字段为基准 ⇒ 可让**真重复逃过窗口**（⇒ **重复执行**），或让**合法重发被误判为重复**（⇒ **丢真产出**） | 该值**与接收时刻的偏移由接收方直接可观察**；持续的系统性偏移**是可数的** |
| **8. 操纵去重键** | 把它写成与内容无关的**固定值**，或**每条都不同** | 前者让**不同内容被误判为重复**（⇒ **丢真产出**）；后者让**真重复逃过**（⇒ **重复执行**） | 内容指纹的形态是**可机械判定的**，且**对同一内容重算必得同一值** ⇒ 这是一个**可复跑**的检查（见附录 B） |

⇒ **本表每一行的对策都不是「禁止」，而是「让它变成一个可核的事实」。** 这与 §8.3 的处置是同一形状。

### 9.2 本契约不索取什么

**先给出规范性的约束：**

> **本契约的任何一步 MUST NOT 要求写入方交出凭证、秘密、写权限或代码改动。**

**逐项列出本契约明确不索取的东西：**

| 不索取 | 含义 |
|---|---|
| **不索取凭证** | 本契约**不要求**任何形式的密钥、令牌、口令或恢复码。**任何一步都不需要写入方交出秘密** |
| **不索取写权限** | 本契约**不要求**写入方把它任何资源的写权限授予接收方或任何第三方。**举证由写入方自己执行、自己提交输出** |
| **不要求改代码** | 本契约**不指定**工具、脚本、命令、目录结构或实现方式。它只规定**声明的形状**与**举证的形状** |
| **不设强制期限** | 本契约**不设**截止日。周期性重新举证是**建议**级（SHOULD，见 §8.2），**不是期限** |

**关于原始输出中的敏感内容：** 写入方 **MAY** 在举证输出含秘密或个人数据时**遮蔽该部分**后再附上。但遮蔽 **SHOULD** 保留**足以判定该产出身份与字段齐备性**的部分——**遮蔽保留的是「这条是什么」，而只给摘要丢掉的是「它是不是真的存在」。**

#### 为什么「不索取」这件事本身是安全设计

1. **索取产生杠杆。** 任何「要求对方交出 X」的条款，都把 X 变成**可以据以判定对方不合规的筹码**——于是**拒绝交出的对方会被记成不合规**。⇒ 本契约**不索取任何东西** ⇒ **没有可被用作筹码的项**。

2. **本契约只要「一句话的事实」。** 它要的**不是访问权**，而是一个**可核的事实陈述**（例如「我这一条带规范版本声明」）。⇒ **事实陈述不能被用于越权**：拿到它，接收方**做不了**任何它本来做不到的事。

3. **不索取 ⇒ 无可泄露。** 合规流程里**没有秘密在流动** ⇒ **不存在「合规即泄密」的路径** ⇒ 本契约的任何一步都**不值得被针对**。⇒ 这一点在**举证**环节尤其重要：如果合规要求提交凭证，那么**举证流程本身**就成了一个值得攻击的目标；而本契约的举证流程**没有任何值得拿的东西**。

4. **不索取 ⇒ 声明「无身份」不付代价。** 一个写入方可以**无代价地**声明「我这条没有身份」「我这一面尚未接入」，因为契约**没有从他那里拿走什么**。⇒ 于是**说实话是省的，编造是多余的**。⇒ 这一条把 §9.2 与 §9.3 串起来：**只有当诚实不需要付代价时，「宁可说实话」才是一个现实的要求，而不是一个道德的要求。**

5. **不设期限 ⇒ 不制造「赶工期造假」。** 期限会**系统性地生产假声明**：赶不上就编一个。⇒ 本契约不设期限 ⇒ **没有「因为来不及而必须编」的时刻**。

6. **不要求改代码 ⇒ 不制造不可核的中间层。** 若契约要求某种实现方式，写入方就会在**实现层与声明层之间引入一个转述环节**——而**转述环节正是声明与事实脱钩的地方**。⇒ 不指定实现 ⇒ 声明只能**从实际写入路径读出**（附录 B） ⇒ 声明与事实之间**少一层可造假的空间**。

### 9.3 伪造身份的后果

#### 9.3.1 身份状态有且只有三种，且都必须是可核的

| 身份状态 | 形态上如何表达 | 是否可核 |
|---|---|---|
| **有身份** | 身份字段取值为**本写入方**的身份串 | ★ 可核：该写入方的产出集合**由它自己可枚举**，他人可与之比对 |
| **声明无身份** | 类别字段取值为「无身份」+ 一个说明来源的字段（须可指认为**图形界面 / 定时器 / 脚本**之一） | ★ 可核：**来源可被指认**，且**那一类来源确实没有身份**。⇒ 声明**可被证实，也可被证伪** |
| **未声明** | 两个字段**都不出现** | ★ **不可核** |

**⇒ 关于第三态的严格规定：**

> **写入方 MUST 在每条产出上声明其身份状态（上述三种之一）。**
> **「未声明」不是第三种取值，而是「没有给出取值」。**
> **它使接收方无法区分「本来就没有身份」与「有身份但不写」。**
> ⇒ 故「未声明」在形态上是**缺陷**，**不是类别**。

**同一条要求的安全侧：**

> **写入方 MUST NOT 在身份字段填入非本写入方的标识。**

**★ 为什么这条是 MUST NOT，而不只是一条互操作要求：** 伪造身份**不会让接收方路由不到**——它让接收方**路由到错的地方**。而**「路由到错的地方」比「路由不到」更坏**，因为它**看起来是成功的**：消息被接收、被处理、被归属，**没有任何一步会失败**，于是**没有任何一步会报警**。

⇒ 这正是 RFC 2119 §6 所说的「限制有害行为」场合。

#### 9.3.2 ★★ 为什么宁可声明「无身份」，也不该编造一个身份

**核心判断：编造的身份无法被追溯；声明的「无身份」至少是一个可核的事实。**

**逐层说明：**

**第一层 · 两个东西各自携带什么。**

- 一份**声明无身份**的产出，携带的是一个**具体的事实**：它的来源**可被指认**（哪一类图形界面、哪一个定时器、哪一个脚本），**而那一类来源本身确实没有身份**。⇒ 接收方或任何第三方**可以去看那个来源**，并**验证这个声明**。
- 一份**编造了身份**的产出，携带的是一个**看起来像事实的字符串**。而**本契约不索取凭证**（§9.2）⇒ 身份串**不携带任何可验证的凭据** ⇒ 接收方**无法核它**，**只能相信它**。

**第二层 · 所以真正的差别不是「严重程度」，而是「可恢复性」。**

| | 归属是**缺失但真实**的 | 归属是**存在但错误**的 |
|---|---|---|
| **它把什么留给了将来** | 一个**空缺**——而空缺**总能被补上**：后来给该来源一个身份，**此前的产出仍可被重新归属**，因为**来源可考** | 一个**错误的连接**——甲 的产出记在 乙 名下 |
| **能不能改回来** | **能。** 缺失**不携带错误信息**，补上即可 | ★ **不能。** 线索**已被合并**，而**产出里没有任何标记指示哪些条目是真的** ⇒ **没有任何办法把它们分开** |

⇒ **声明无身份造成的是一处空缺；编造身份造成的是一处不可修复的错误。** 这两者的差别**不是程度，而是种类**。

**第三层 · 编造会传染。**

一旦某条线索上出现一个编造的归属，**该线索上的所有读数都不再可信**——因为**无法知道这一条底下还有多少条是编的**。

⇒ 一个**假的身份声明**：**毁掉整条线索的读数**。
⇒ 一个**「无身份」声明**：**只孤立地降低它自己那一条**（它使那一条不可归属，而不使别人那条错）。

**第四层 · 故本契约取的方向。**

> **宁可声明「无身份」，也不编造一个身份。**
> **因为「无身份」是一个可核的事实，而「编造的身份」是一个不可核的断言。**
> **契约要的不是「每一条产出都有身份」，而是「每一条产出的身份状态都被声明过」。**

⇒ 这也解释了本契约**为什么不要求「所有人都签署」**：**那会逼出一个编造的签名**——因为一个确实没有身份的来源，**除了编造，没有别的办法满足「必须有身份」**。而「无法签署」本身就是一个**必须被声明出来的事实**。

| `writtenAt` | 字符串（时刻） | **必填** | 本举证对象的写入时刻。须为规范时刻串 | `"2030-01-01T00:00:00Z"` |
| `supersedes` | 字符串 | **可选** | 被本对象取代的前一次举证对象的标识。首次举证时为 `null` 或省略 | `null` |

★ **示例中的 `writer-example-0001` 与 `2030-01-01T00:00:00Z` 均为占位示例**，不指向任何实际对象。

### A.3 `producerCategory` 的取值（枚举）

| 取值 | 含义 | 同时必须携带 |
|---|---|---|
| `identity-bearing` | 该写入方**有身份** | `producerIdentity` |
| `identity-absent` | 该写入方**无身份**（图形界面 / 定时器 / 脚本三类之一） | `producerCategoryNote` |

> ★★ **「未声明」不是取值。**
> 两个字段都不出现 ⇒ **违约**，且**不是**「无身份」。
> **设计意图**：让「未声明」在形态上**不可表达为一个合法取值**——它**不是第三个选项**，而是**选项的缺失**。

### A.4 `declaredScope` / `undeclaredScope` 的取值

| 取值 | 含义 |
|---|---|
| `point-to-point` | 逐条直接投递给一个接收方 |
| `thread` | 线程——多轮协商聚合成一条会话 |
| `shared-state` | 共享状态区写入——状态与确认走共享存储的键，**不进消息流** |
| `batch-queue` | 批量队列（低优先级、异步） |
| `event-stream` | 事件流（触发式通知，可重放） |
| `broadcast` | 全员广播 |

★ 这六个取值取自规范性引用所指规范版本处的**消息分类与通道映射** ⇒ **本契约不新增面，只要求逐面声明**。

## 附录 B：复跑命令清单

> ★ **本契约不指定工具、脚本、目录或路径**（见 §9.2）。故下表中的命令使用 `<…>` **占位符**表示由接入方自选的实现。**本契约只规定命令的形式与期望输出的形状。**
>
> ★ **「可复跑」的定义**：每条命令都须能在**首次发出之后**被**单独再跑一次**，并给出**同一形状**的输出。⇒ 它**不得依赖任何本次会话的临时状态**。
>
> ★ **写与读分两次**：先写，再**单独**回读。**同一次调用里既写又读，不算回读。**
>
> ★ **须同时看返回值与成功状态码**：只看到返回值、而没有成功状态码时，**不得记为已写入**。（返回值可以在写入被拒时**照常存在**。）

| # | 用途 | 命令 | 期望输出形状 |
|---|---|---|---|
| 1 | **回读一条产出的全部字段名** | `jq -r 'keys[]' <该产出的 JSON>` | 每行一个字段名；**行数 = 字段数** |
| 2 | **判定必填字段是否齐备** | `jq -r '["cahac","id","type","channel","sender","recipient","thread","priority","cost_cap","dedup_key","ts","payload"] - (keys) \| length' <该产出的 JSON>` | **单个整数**。`0` = **齐备**；非 `0` = 缺该数个字段。⇒ 去掉 `\| length` 再跑一次即得**缺失字段清单** |
| 3 | **读出该产出实际携带的版本值与身份状态** | `jq -r '.cahac, .producerCategory, .producerIdentity' <该产出的 JSON>` | **三行**。`.cahac` 须**逐字等于**规范值；`.producerCategory` 须为两个取值之一；取值为「有身份」时第三行**非 `null`** |
| 4 | **判定去重键是否为内容指纹形态** | `jq -r '.dedup_key' <该产出的 JSON> \| grep -cE '^[a-z0-9-]+:[0-9a-f]{64}$'` | `1` = 形如「算法名:64 位十六进制」，**形态合规**；`0` = **非内容指纹形态** |
| 5 | **从共享存储独立回读同一条产出** | `curl -s -w '\n%{http_code}\n' <共享存储读取地址>/<键>` | **一个 JSON 对象 + 一行状态码**。⇒ **两者须同时成立**：对象非空**且**状态码为成功。只看返回值、没有状态码 ⇒ **不得记为已写入** |
| 6 | **计数某写入方的达标比例** | `<计数命令>`：**分母** = 该写入方在该时间范围内的产出条数；**分子** = 其中带规范版本声明的条数 | **两个整数 + 一个比例 + 一个取值时刻**。⇒ **缺取值时刻则该数不可比**（不同时刻的两个数**不得并列比较**） |
| 7 | **判定一次举证是否可核** | 逐条走附录 C.1 的**四问** | 四问**全「是」** = 可核；**任一「否」** ⇒ 记**不可判**。⇒ **不得记达标，也不得记未达标** |

## 附录 C：反例集——什么是「不合格的举证」

### C.1 判据（四问）

一次举证**合格**，当且仅当下列四问**全为「是」**：

| # | 四问 | 问的是什么 |
|---|---|---|
| 1 | **可回读吗？** | 举证对象所指的**那一条产出**，**现在**还能被读出来吗？ |
| 2 | **可复跑吗？** | 那条命令**现在单独再跑一次**，还给出**同一个形状**的输出吗？ |
| 3 | **对象与命令对应吗？** | 命令的输出里，**出现了被举证对象自身的标识**吗？（⇒ 跑**全库统计不算**对应） |
| 4 | **身份状态已声明吗？** | 读者能**明确判定**这是三种身份状态中的**哪一种**吗？ |

> ★★ **任一问为「否」⇒ 记「不可判」。**
> ★ **「不可判」既不是达标，也不是未达标。** 它**不扣分，也不给分**。
> ⇒ 这一点是本节最重要的读法：**「不可判」不是「不合格」的同义词**，把两者混为一谈会得出错误的结论。

### C.2 反例集（逐条说明缺了什么）

| # | 反例（原样） | 它缺了什么 | 应记 |
|---|---|---|---|
| 1 | 「**我们已接入。**」 | 缺**举证对象**（没有任何可回读的东西）· 缺**复跑命令** | **不可判** |
| 2 | 「**举证卡在这里，格式你自己看。**」 | 缺**复跑命令** ⇒ 读数是**一次性的**，下次**无法重算** | **不可判** |
| 3 | 「**跑过了，12/12 全过。**」 | 缺**原始输出** ⇒ 无法确认**命令真的执行过**、**跑的是哪一条** | **不可判** |
| 4 | 命令打印的是**全库统计**（「库内共 N 条，其中合规 M 条」） | 缺**对象与命令的对应** ⇒ 读者**无法把结论落回被举证的那一条** | **不可判** |
| 5 | 举证对象里写规范版本值，而**实际写入路径**里写的是另一个值 | 缺**声明与事实的一致性** ⇒ 命令**必须从实际写入路径读出**，**不得从声明里读出** | **未达标** |
| 6 | 只列出已接入的面，**没有列出未接入的面** | 缺**未接入面的显式声明** ⇒ 读者把**沉默**当成「已全部接入」 ⇒ **分母少算 ⇒ 读数虚高于事实**。⇒ 注意：**省略该字段不等于空数组** | **未达标**（读数虚高） |
| 7 | 声明为「无身份」，但该产出**实际来自一个有身份的写入方** | 缺**类别声明的事实依据** ⇒ 「无身份」**只适用于来源可指认且确实无身份的三类** | **未达标**（且属 §9.1 的滥用） |
| 8 | 身份字段与类别字段**都不出现** | 缺**身份状态的声明** ⇒ ★ **「未声明」不是「无身份」**：读者**无法区分**「本来就没有」与「有但不写」 | **未达标** |
| 9 | 时刻字段填了一个**与提交时刻无关**的值 | 缺**可核性**；且该值会**污染去重窗口**的判据（窗口以它为基准） | **不可判** |
| 10 | 声称「已写入」，但**没有给出成功状态码** | 缺**成功状态码** ⇒ 写入被拒时**返回值照常存在** ⇒ 只看返回值**不足以**判定已写入 | **不可判** |

### C.3 三处易混（它们**不是**不合格的举证）

★ 下列三种情形常被误记为「不合格」。**它们不是。** 把它们误记为不合格，会**惩罚正确的做法**。

| 情形 | 为什么**不是**不合格 |
|---|---|
| **声明了一个很小的面，但对该面举证完整** | 这是**合格**的举证。达标比例按**声明并举证的范围**算 ⇒ 比例**高**。⇒ 它**不违反契约**，但**不划算**：少声明**不缩小已明示的未接入清单**（见 §9.1 第 5 条） |
| **原始输出中遮蔽了含秘密或个人数据的部分** | 这是**合格**的举证——本契约**不索取秘密**（§9.2）。⇒ 判据是**是否保留了足以判定该产出身份与字段齐备性的部分**。**遮蔽 ≠ 只给摘要**：遮蔽保留的是「这条是什么」，摘要丢掉的是「它是不是真的存在」 |
| **一份「仅自证」的举证** | 这是**合格**的举证——异体核验是**建议**级（SHOULD，见 §8.2）。⇒ 但只要它**显式记为「仅自证」**，它使读者**能看出它与已核的不同**。⇒ 不合格的是**让仅自证的看起来像已核的** |

### C.4 一个合格的举证长什么样

```json
{
  "evidenceType": "cahac-onboarding-evidence",
  "contractVersion": "v2",
  "producerCategory": "identity-bearing",
  "producerIdentity": "writer-example-0001",
  "envelopeVersionDeclared": "<取规范性引用所指规范版本处的规范值>",
  "declaredScope": ["point-to-point", "shared-state"],
  "undeclaredScope": ["broadcast"],
  "evidenceCommand": "jq -r '[\"cahac\",\"id\",\"type\",\"channel\",\"sender\",\"recipient\",\"thread\",\"priority\",\"cost_cap\",\"dedup_key\",\"ts\",\"payload\"] - (keys) | length' <该产出的 JSON>",
  "evidenceRawOutput": "0\n<退出状态码：0>",
  "selfReadBack": {"present": 12, "required": 12},
  "writtenAt": "2030-01-01T00:00:00Z",
  "supersedes": null
}
```

**它为什么合格（对照 C.1 的四问）：**

| 四问 | 本例的答案 |
|---|---|
| **可回读** | 是——`evidenceCommand` 指向一条**具体的产出**，任何人现在都能再读它 |
| **可复跑** | 是——命令**不依赖任何临时状态**，单独再跑给出同一形状 |
| **对象与命令对应** | 是——命令的输出是**那一条产出自身**的字段齐备数（`0` = 不缺字段），**不是全库统计** |
| **身份状态已声明** | 是——`producerCategory` 取值「有身份」，且**同时**携带了 `producerIdentity` |

★ 并且它**示范了「显式声明未接入面」**：`undeclaredScope` **存在**，取值 `["broadcast"]`——即该写入方**明说**它尚未接入全员广播这一面。⇒ **把未接入的一面说出来，不会使它不合格；把它藏起来，才会使读数虚高。**
