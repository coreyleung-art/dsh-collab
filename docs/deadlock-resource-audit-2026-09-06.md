# 明鉴 v2 死锁事件 · 资源浪费审计报告

> 审计: HR 司库(成本监察)· 2026-09-06 · 数据源: 会话 session.jsonl.zstd 解压全量分析(4,116 条 usage 记录)
> 审计方法: 会话内 assistant/message 的 usage 权威字段(inputTokens/outputTokens/cacheReadTokens), 非估算

## 一、会话总体成本(8 天 8/30-9/06)

| 指标 | 数值 |
|---|---|
| 使用天数 | 8 天(552 turns / 4,124 steps) |
| 累计 inputTokens | 9,523,506(952 万) |
| 累计 outputTokens | 1,911,858(191 万) |
| **LLM 总消耗(input+output)** | **11,435,364(1,143 万 tokens)** |
| 累计 cacheRead(上下文缓存读) | **1,935,157,888(19.35 亿)** |
| 会话峰值上下文 | 792,192 tokens/请求(上限 1,048,576 的 75.6%) |

## 二、死锁直接浪费(可避免部分)

| 浪费项 | 估算 | 说明 |
|---|---|---|
| 3 次失败压缩 summarize 调用 | ~237 万 tokens 输入 | 每次 summarize 需处理全量历史(~79 万/次 × 3) |
| 3 次失败摘要输出 | 6,778 tokens | 1872+1936+2970(全部被门控拒绝, 零产出) |
| **直接浪费小计** | **~238 万 tokens** | 全部产出被拒, 纯沉没 |

## 三、放大效应(结构性浪费, 更值得警惕)

死锁只是终点, 真正的成本大头是 **上下文膨胀的边际成本递增**:

| 日期 | 日均 cacheRead | 说明 |
|---|---|---|
| 09-03 | 3.38 亿 | 上下文已 ~33 万 |
| 09-04 | 0.88 亿 | 当日任务少 |
| 09-05 | 3.39 亿 | ~74 万 |
| 09-06(死锁日) | 4.43 亿 | **峰值 79.2 万**, 每请求缓存读逼近上限 |

**关键洞察**: 后 4 天 cacheRead 合计 **12.08 亿 tokens**——其中越往后, 每次请求携带的历史上下文越大, 即使 cache 命中打折计费, 也产生显著成本。
若在上下文 ~50%(52 万)时提前压缩/重建, 高峰期每请求可省 ~27 万 cache tokens × 数百请求 ≈ **数千万 tokens 的缓存读成本可避免**。

## 四、浪费性质判定

| 类别 | 是否浪费 | 金额级(粗估) |
|---|---|---|
| 正常工作成本(8 天真实任务产出) | ❌ 非浪费(有产出: R006 十项/SystemGraph/lean4 补丁等全部落盘) | — |
| 死锁 3 次失败压缩 | ✅ **纯浪费**(产出全拒) | ~238 万 tokens |
| 上下文膨胀边际成本(后 4 天) | ⚠️ 部分可避免(治理缺口: 无提前压缩机制) | ~数千万 cache tokens |
| 死锁后重建人工/时间成本 | ✅ 一次性(已工具化 amortize) | 低 |
| **记忆继承** | ✅ 非浪费(4 段摘要 26.4K 字符全部复用, v3 零重复劳动) | 节省了 v3 重学成本 |

## 五、根因与对策(防复发)

| 根因 | 对策 | 状态 |
|---|---|---|
| 宿主压缩阈值 0.8 过高, 触发时已太晚 | watchdog 提前巡检(>60% 预警/门控拒≥1 观察) | ✅ 工具已就绪(session-rebirth watchdog), launchd 待挂 |
| 无死锁候选早期检测 | session-rebirth.py diagnose/watchdog | ✅ 已实现 |
| 压缩门控小遮蔽区间死锁 | 上下文卫生纪律: 长任务分段推进+及时落盘 | ✅ 已入 v3 提示词 |
| 会话 8 天不重建 | 代际档案 + 主动轮换(定期评估上下文水位) | ✅ 本档案建立 |

## 六、结论

**有浪费, 但可控且已收敛**: 直接浪费 ~238 万 tokens(死锁失败压缩)占比总消耗 1,143 万的 ~2%, 非灾难;
真正值得治理的是**上下文膨胀的结构性成本**(后 4 天 12 亿 cacheRead 中可提前压缩部分), 已通过 watchdog + 代际档案 + 上下文卫生纪律三重机制闭环。
**记忆继承使浪费最小化**: 死锁后 v3 靠 26.4K 字符继承包零重复劳动续接, 8 天产出(全部落盘)无一丢失。
