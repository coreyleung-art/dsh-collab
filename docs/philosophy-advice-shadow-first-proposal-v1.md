## 〇、原则表述(用户原话→结构化)

**用户原话**: "工具要守好建议+影子先行，有能力做不一定是应该做作为蓝图推进逻辑"

**结构化三命题**:
1. **建议先行**(Advice-first): 工具的默认输出是"建议", 不是"执行动作"
2. **影子先行**(Shadow-first): 需自动化的环节先跑"影子模式"(并行模拟/建议供人审), 验证可靠后(采纳率达标)才考虑转正
3. **有能力≠应该做**(Capability ≠ Mandate): 蓝图推进的决策逻辑 = 技术可行(能) ≠ 该推进(该); 必须过价值/门禁/人类确认闸

## 一、建议+影子先行的推进阶梯(泛化 d3-3 四阶段为通用模板)

```
L0 纯建议:  工具只输出建议/洞察, 人类全权执行        ← 默认起点(新工具一律从此)
    ↓ (建议被采纳达阈值, 验证价值)
L1 影子模拟: 工具并行"跑一遍"(不碰真实), 输出"如果执行会怎样"
    ↓ (影子结果与人类决策一致率达标)
L2 半自动:   工具预填/建议, 人类一键确认(仍有人闸)
    ↓ (采纳率≥90%, 用户授权)
L3 全自动:   无人值守(每环节独立 R027 开关, 默认 OFF)
```

**关键**: 每级上行 = 数据验证 + 用户授权; 下行可随时(熔断)。

## 二、蓝图 gate 模板(新增条款)

凡涉及"自动化执行"的蓝图 works(改价/上下架/回复/接拒单/代运营动作等), BP-9 gate 须含:
```
gate: ① 新工具一律 L0 建议先行起步 ② 自动化需影子模拟验证(决策一致率达标) 
      ③ 全自动须 R027 人类授权 ON + 采纳率≥90% ④ 有能力做≠应该做——每步上行须价值/门禁双确认
```
