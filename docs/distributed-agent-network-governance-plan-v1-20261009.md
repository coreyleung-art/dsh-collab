## 1. 目标（六个能力目标）与策略原则

### 1.1 目标
| # | 目标 | 判据（可核） |
|---|---|---|
| G1 | **可信**：归属可验，不靠自由文本 | 板层/卡层归属有签名或不可伪造载体；「声称 vs 身份」可区分 |
| G2 | **有界**：队列/上下文/inbox 都有界 | 三处均有上界与超限策略；无界增长不可达 |
| G3 | **可退**：拥塞可退（反压→限流→熔断→泄洪） | 四级齐备，每一级有触发判据与解除条件 |
| G4 | **根因受控**：上下文膨胀受控 | 会话体积/处理时延入 SLO，超限自动压缩 |
| G5 | **可观测**：风暴与堵塞先被系统发现 | 队列深度/滞后/风暴评分有 SLO 与告警，不靠人肉 |
| G6 | **可治理**：每个改动可审可回滚 | 全部经 R046 判据 + R048 审查 + 回滚点 |

### 1.2 策略原则（用户指定）
1. **优势优先**：先扩大并保持强项（黑板共享状态、反压回传、DLQ 可追溯、治理门与自证纪律）。
2. **开源优先 → 过渡自研**：能"评估并直接调用现有开源能力"的，先接开源拿能力；跑通后再定自研替换（避免一次性重写与重复造轮子）。
3. **判据先行**：每项补全都先写「判据 + 负控 + 回滚点」，再动手（今晚 20+ 次实证有效）。
4. **不得制造同类问题**（R022）：治理工具自身必须过「注入前量校验」（新注入 < 原队列）与自证矩阵。

## 2. 治理架构（五层栈）

```
L5 治理与规则层   规则账本 · 验收门 · 命名门 · 审查名册 · 样本窗 · 审计留痕
L4 观测与编排层   指标/SLO · 风暴评分 · 队列滞后 · cron 编排 · 告警
L3 上下文与内存层 compaction · 会话体积 SLO · inbox 背压(有界+优先级) · 缓存
L2 拥塞与背压层   反压信号 · token bucket · 优先级/公平 · 熔断 · 泄洪态
L1 传输与投递层   bus/黑板/邮箱 · at-least-once + **持久幂等键** · DLQ · 时序(HLC)
L0 节点与身份层   节点注册 · 心跳 SLO · **身份签名** · 归属双载体 · 端口稳定性
```

**关键设计取舍**：
- 黑板（共享状态）继续做**跨设备主干**（一次写 N 次读，08-19 报告测算降本 70–85%）；
- 会话级 bus 保留为**点对点快通道**，但必须补持久幂等键与熔断；
- 邮箱（inbox）改 **Actor 有界邮箱**（背压 + 优先级 + 批量），对齐 Histrio/AgentScope。

## 3. 逐项补全计划（WBS）

> 每项格式：**现状 → 差距 → 方案（含开源候选）→ 判据 → 回滚 → 成本/依赖/属主**

### Wave 1 — 基准能力补齐（P0，先做，全部低成本）

| ID | 项 | 现状→差距 | 方案 | 判据 | 回滚 |
|---|---|---|---|---|---|
| **W1.1** | 幂等键持久化 | 内存 `Set`（重启即失）+ 10 分钟窗口漏判 | 边车文件（JSONL + 原子写）持久化 seen；键含内容指纹不含 thread；TTL 与队列对齐；central-inbox 已有 `seen.json` 先例可复用 | 重启后重放同内容消息 ⇒ 0 重复注入；>10 分钟重发 ⇒ 被抑制 | 删边车文件即回旧行为 |
| **W1.2** | 熔断 | 无（grep 0 命中） | 同目标连续 N（建议 3-5）次未达 ⇒ 停发 + 落状态卡；与 `rate_limited` 共用降级通道；开源参考 `sony/gobreaker`、`resilience4j`、`tower::limit` | 造 N 次失败 ⇒ 第 N 次后停发；恢复探针通过后自动闭闸 | 开关常量置 0 即禁用 |
| **W1.3** | 根因指标 | 上下文膨胀无度量 | 采集：会话文件体积/条目数、单会话处理时延、inbox splice 次数（对齐 08-17 调查员指标） | 指标可产出且与 queued 深度同窗对照 | 只读采集，无副作用 |
| **W1.4** | 观测与编排层 | floodgate 只读、未接 L1–L4、未接 SLO | floodgate 改造：并入根因指标 + 队列滞后 SLO + 接 L1–L4 状态；输出**一张状态卡**（含样本窗） | storm_score 与人工判断一致率 ≥80%；误报上界已量化 | 只读层，随时停 |

### Wave 2 — 传输语义与拥塞（P1）

| ID | 项 | 方案（开源候选） | 判据 |
|---|---|---|---|
| **W2.1** | 限流改 token bucket | 桶容量+补充速率（RFC 1363）；参考 `x/time/rate`、`bucket4j`、`redis-cell`、Envoy RLS | 突发 ≤ 桶容量；持续 ≤ 补充速率；边界不再双倍放行 |
| **W2.2** | 优先级 / 公平 | 「需对方动作」独立配额（与致谢/状态分离）；参考 K8s API Priority & Fairness 三级（system/leader/workload） | 风暴期关键消息通过率 ≥90% |
| **W2.3** | inbox 背压（Actor 邮箱） | 有界 + 优先级 + 批量注入；参考 Histrio 2410.21793 / AgentScope / Pekko Streams | inbox 文件数有上界；积压时延不随量线性恶化 |
| **W2.4** | 泄洪态（flood mode） | 三态（normal/warm/storm）+ 分级处置（聚合/抑制/熔断）+ 滞回解除；参考 SPILLWAY | 风暴中系统仍推进关键任务；解除条件自动 |
| **W2.5** | DLQ 策略完善 | expired 保留已有；补「重放工具」（受 R022 量校验约束） | 重放注入量 < 原队列量 |

### Wave 3 — 可信与身份（P2 但安全关键）

| ID | 项 | 方案 | 判据 |
|---|---|---|---|
| **W3.1** | 板层归属校验 | 给 `X-Writer` 加 HMAC（共享密钥）+ 时间戳；无签名则一律标「声称」 | 伪造 writer ⇒ 校验失败；合法 ⇒ 通过 |
| **W3.2** | 卡层归属双载体 | `from`(运行时自派生) + `writerLabel` + `identitySource` 写入卡内容 | C1 来源盲区关闭（grep 非零、卡内可读） |
| **W3.3** | 历史归属分档 | 已实现四级（可信/已知误归/疑似/不可判），补机器可读枚举 | 归属可判率可统计 |

### Wave 4 — 跨设备一致性

| ID | 项 | 方案 | 判据 |
|---|---|---|---|
| **W4.1** | 端口稳定化 | 官方机制：profile 里 `host-webserver.port` 固定（非 `--port 0`） | 重启后地址不变 |
| **W4.2** | 域白名单登记 | 命名空间登记 v2 已加「上行/本机专有」列；补「谁在写/谁在拦」索引 | 任一键可查出为何在某板 |
| **W4.3** | 时序与因果 | 已用黑板时间轴；补 HLC 或逻辑时钟用于跨设备排序 | 跨设备事件可全序复原 |
| **W4.4** | 节点心跳 SLO | 心跳新鲜度 + 换代风暴检测（今日 MBP 6 次换代、末两次 1.8 分钟） | 异常换代率告警 |
| **W4.5** | 设备注册与凭据纪律 | token 不进 plist/argv（10-03 审计 P1）；统一凭据源 | 扫描 0 明文 |

### Wave 5 — 治理与自动化（长期）

| ID | 项 | 方案 | 判据 |
|---|---|---|---|
| **W5.1** | 规则入工具 | 每条规则的判据做成可跑断言（c9 同形） | 注释里的判据归零 |
| **W5.2** | 样本窗 | 每条规则标时间+主题族+样本量（已入清单） | 引用时带射程 |
| **W5.3** | 前置清单 | 「生效条件 + 验证法」登记（X-Writer / runtimeVersion 等） | 分得清「未做」与「做了未生效」 |
| **W5.4** | 审查名册常态化 | 席位 1-4 已入；补 5-7；审查与自证分离 | 每项产出都有第三方 |

## 4. 开源能力评估（直接调用 → 再过渡自研）

| 能力域 | 候选开源 | 重量/成本 | 建议 |
|---|---|---|---|
| 消息层（幂等键/持久化/背压） | **NATS JetStream**（单二进制，`Nats-Msg-Id` 去重窗口、per-subject 限额、KV、监控端点）· Redis Streams（XAUTOCLAIM/去重）· Redpanda（Kafka 兼容单二进制） | NATS 最轻，可先做 PoC | **首选 NATS PoC**：用 `Nats-Msg-Id` 直接拿到「持久幂等 + 有界 + DLQ」，跑通后再决定是否自研替换 |
| 耐久执行/工作流 | **Temporal** · Restate · DBOS · Cadence | 较重（需服务端） | 中期评估：用于「跨设备长事务」；短期用文件+黑板 |
| 限流/熔断/退避 | `tower`(Rust) · `resilience4j`(JVM) · `sony/gobreaker`(Go) · `pybreaker`/`tenacity`(Py) · Envoy RLS | 轻（库级） | **直接对齐其参数与语义**，本地实现（我们栈混合语言，接库成本 > 自实现语义） |
| 背压抽象 | Reactive Streams · Pekko/Akka Streams · Rust tokio | 中 | 借鉴语义（有界+需求驱动），不引入运行时 |
| 可观测 | **OpenTelemetry** + Prometheus + Grafana；NATS/Prometheus 导出器 | 中 | **选做**：先本地 JSONL 指标 → 有 SLO 需求再接 OTel |
| 上下文管理 | MemGPT/Letta 记忆分层 · rolling summary（slimcontext）· LangGraph checkpointer | 中 | 借鉴「分层记忆 + 摘要 + 裁剪」；我们已有 compaction，补 SLO 与阈值 |
| 智能体协议 | A2A（Linux Foundation）· MCP | 长线 | 跟踪，不急于引入（防逆向原则） |

**过渡路线**：开源 PoC（NATS/OTel）→ 量出真实收益与集成成本 → 决定「保留开源」或「按同一语义自研替换」。**每一步都保留可回滚点**。

## 6. 风险与治理约束

1. **R022 铁律**：治理工具不得制造同类问题 → 任何"批量重放/注入"必须先过**量校验**（新注入 < 原队列）并有回滚点（08-31 事故教训）。
2. **样本窗**：本计划所有阈值须标样本（当前主要样本 = 2026-10-08 单日下午 + 观测面不一致主题族）。
3. **审查协作**：每项改动走 R048（方案送审 → 执行 → 复核），P0 项可先做**只读**部分。
4. **不可逆操作**：端口固定化/板端改动/删除类先备份 + 官方预查 + 用户批准。
5. **不得以静默方式改变语义**：任何「豁免/降级」必须显式列出依据（今晚教训）。
