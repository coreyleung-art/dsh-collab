# queue 治理工具 · 设计审查与完善方案 v1.0

> 日期：2026-08-31 · 作者：星桥 · 关联 R015（沙箱先行）+ R021 + R022
> 对象：queue_watch / queue_condense / queue_drain 三件套

---

## 1. 设计缺陷清单

### 缺陷 1：链路不完整——缺「精简注入」环节（致命）

现有链路：`检测(watch) → 浓缩(condense) → 抽出(drain)`，**只有 3 步，缺最后一步「精简注入」**。

| 环节 | 现状 | 问题 |
|------|------|------|
| watch 检测 | 300s 巡检 + 三态判断 | ✅ 无问题 |
| condense 浓缩 | 去重→聚类→归纳→写黑板 | ⚠️ 只写总结，不净化队列 |
| drain 抽出 | queued→archived（不删） | ⚠️ 改状态不删，无注入 |
| **精简注入** | **缺失** | ❌ 浓缩结果没有回注入目标会话 |

**后果**：要么不净化（condense 只写黑板，原 284 条还在），要么原样回灌（补投 121 条跳过浓缩）——都违背「净减少上下文」初衷。

### 缺陷 2：condense 与 drain 是分离动作，不是闭环

- condense 产物 = 黑板 `data/ops/queue-condense/condense-<ts>`（人看，机器不消费）
- drain 产物 = archived 消息（留在原线程，机器不重新处理）
- **两者之间没有「浓缩结果 → 净化队列」的连接**

### 缺陷 3：去重只做「文本精确去重」，语义去重靠聚类但未落地为队列操作

- 实测 284 → 274（精确去重只去 10 条），大量语义重复靠聚类识别但**只归纳、不删**

### 缺陷 4：无「注入前量校验」

- 补投 121 条时未检查「注入 < 原队列」就执行 → 制造回灌（R022 教训）

## 2. 完善方案：四环节闭环

### 目标链路

```
检测(watch) → 浓缩去重(condense) → 净化抽出(drain) → 精简注入(inject)
     │              │                    │                │
  三态判断      去重+聚类+归纳        queued→archived    浓缩摘要→目标会话
     │              │                    │                │
     └──────────────┴──────── 注入前量校验 ────────────────┘
               注入条数 < 原队列条数（否则拒绝注入）
```

### 新增第 4 环节：`queue_inject`（精简注入）

**输入**：condense 产出的 cluster 摘要（top5 大簇归纳）
**输出**：把精简摘要注入到目标会话（按 to 字段分组，每会话一条浓缩通知）
**规则**：
1. **注入前量校验**：注入条数 = 目标会话数（每会话 1 条浓缩摘要），必须 < 原 queued 条数，否则拒绝
2. **任务保护**：待执行任务（is_task）不浓缩、不注入，保留原样等执行
3. **通知不轰炸**：每个目标会话最多 1 条浓缩通知（合并该会话所有 queued 的摘要）

### 完整数据流（一个会话的 100 条 queued → 1 条浓缩注入）

```
100 条 queued（session-A 收到）
  → condense：精确去重 + 语义聚类（0.55）+ qwen 归纳
  → 产出：5 簇摘要（代表 100 条）
  → drain：100 条 queued → archived（任务除外）
  → inject：5 簇摘要合并成 1 条通知 → 注入 session-A
  → 结果：100 条上下文 → 1 条浓缩摘要（净减少 99 条）
```

## 4. 沙箱测试方案

**测试环境**：临时 agent-bus.json 副本（不碰真实数据）
**测试数据**：构造 3 个会话 × 各 20 条 queued（含重复/语义相近/待执行任务）
**验证点**：
1. condense 浓缩比：60 条 → N 簇（N << 60）
2. drain 任务保护：待执行任务不 archived
3. inject 量校验：注入条数（3 条，每会话 1 条）< 原 60 条
4. 净减少：60 条 queued → 3 条注入 + 任务保留，上下文净减少 ≥ 90%

---

## 5. 安全红线（R022 落地）

1. **注入前必须量校验**：`注入条数 >= 原队列条数` 则拒绝注入
2. **任务保护**：待执行任务永不浓缩/注入，保留原样
3. **归档可恢复**：drain 仍保留 archived（不删）
4. **沙箱先行**：所有测试在临时副本上，不碰真实 agent-bus.json
