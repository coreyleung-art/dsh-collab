# 角色命名标准 v1.0 · HR 评估完善报告

> 2026-08-29 · HR session-2a15e6b1 · 用户确立「避免同角色多设备混乱」
> 实证：50 档案中仅 3 个（6%）带设备前缀——命名自由散乱确认，需规范化

## 一、标准草案评估（<设备>-<角色>）

### 1.1 草案合理，补充 4 点
| 项 | 草案 | HR 补充 |
|---|---|---|
| 命名格式 | <设备>-<角色> | ✅ 采纳，建议连字符分隔（mac-mini-外卖运营） |
| 字段 | displayName/device/role/agentId | ✅ 采纳，补 displayName 为**必填**（用户可见唯一名） |
| 角色清单 | 未定义 | ⚠️ **建议维护角色词典**（统一职能名，避免同义不同名：运营/专员/分析师混用） |
| 冲突检测 | 未定义 | ⚠️ **必须加**：同设备同角色重复告警（防 i9-算力 ×2 场景） |
| 迁移 | 未定义 | ⚠️ 补迁移策略（存量档案分批改，会话代码隐藏不改 agentId） |

### 1.2 标准字段定义（v1.0 建议）
```
agentId: session-xxx（内部唯一，用户不可见，不改动）
device:  mac-mini | mbp | i9（设备标识）
role:    中文职能名（外卖运营/资源管理/数据调查…，用角色词典词）
displayName: <device>-<role>（用户可见，唯一）
```

### 1.3 角色词典（建议，防同义混用）
- 治理域：协调者 / 资源管理 / 成本监察 / 审批
- 运营域：外卖运营 / 客服 / 学习引擎 / 数据采集
- 数据域：数据调查 / 文档摄取 / 供应链 / 调研专员
- 技术域：系统运维 / 插件开发 / QA 验收 / 设备协调 / 健康审查
- 端侧域：算力提供（i9）/ 训练 / ERP 打通

## 三、身份登记工具化：role-name-check.py（已实现）

**位置**：~/dsh-collab/scripts/role-name-check.py（属主 HR，纯规则零 LLM）
**能力**：
1. **命名规范校验**：缺设备前缀 / 会话代码当角色名 / 无角色职能词 → 三检测
2. **同设备同角色重复告警**：按 device|role 分组，len>1 即告警
3. **迁移建议报告**：--report 生成待修清单 + 迁移示例

**实测**：50 档案 → 3 达标 / 47 待修 / 0 冲突（当前），报告已生成 docs/role-naming-migration-2026-08-29.md

## 四、迁移建议（存量 50 档案 → 设备-角色映射）

### 4.1 迁移原则
1. **agentId 不动**（内部标识，隐藏，改名字不换 id）
2. **分批改**（不一次全改，避免总线混乱；按域分批）
3. **displayName 优先**（用户可见层先规范，role 字段同步）

### 4.2 迁移批次
| 批次 | 范围 | 示例 |
|---|---|---|
| 1. 治理域（先改，协调者/HR 带头） | 协调者/资源管理/成本监察 | mac-mini-协调者、mac-mini-资源管理 |
| 2. 运营域 | 外卖运营/客服/学习 | mac-mini-外卖运营、mac-mini-智能客服 |
| 3. 数据域 | 调查/摄取/供应链 | mac-mini-数据调查、mac-mini-文档摄取 |
| 4. 技术域 | 运维/插件/QA/设备 | mac-mini-系统运维、mac-mini-QA验收 |
| 5. 端侧域 | i9/MBP 角色 | i9-算力提供、i9-训练、i9-ERP打通、mbp-资源管理 |

### 4.3 具体映射（关键角色）

## 五、冲突检测机制

### 5.1 注册时（前置校验）
- agent_profile 登记/更新时跑 role-name-check（或嵌插件侧）：
  - 格式不符 → 拒绝登记，提示正确格式
  - 同设备同角色重复 → 告警，需换角色名或确认复用

### 5.2 定期审计（存量校验）
- 每周跑 role-name-check.py（并入 HR 值班巡检）
- 输出待修清单 → 通知对应角色改名

### 5.3 冲突升级
- 同设备同角色真冲突（两个会话要当同一角色）→ 走协调者裁决（谁是主/谁是备）
