## 2 · 工具面（宿主级，任何会话可调）

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `plugin_standard` | 规范台：N1–N8 / R006 十项 / P1–P5 / 门型 A–F；`action=selfproof` 跑门自证矩阵 | `action=norms\|r006\|patterns\|gates\|all\|selfproof`（**取判据一律用 `all`**） |
| `plugin_name_gate` | 命名门：check / allocate / audit / explain | `name`、`tools[]`、`selfTools[]`（见下）、`base` |
| `plugin_review` | R006 十项审查（单插件或全量） | `target`、`all`、`deep`（真跑挂载冒烟）、`limit` |
| `plugin_pattern_list` | P1–P5 模式目录 | `detail` |
| `plugin_pattern_scaffold` | 模式化交付生成 | `pattern`、`slug`、`purpose`、`tools[]`、`outRoot`、`dryRun`（默认 true）、`confirm` |

**`selfTools` 的用法（容易误判）**：`check`/`allocate` 会把「已在活体工具表里的名字」报为 N4 冲突。若那个名字是**该插件自己已挂载的工具**，它是正常状态、不是冲突——此时把它列进 `selfTools[]`，判定即转 advisory 而不导致 `ok=false`。`audit`（只判形式）不需要它。

**语义纪律**：
- 真挂载冒烟有**四态**：`pass` / `fail` / `skipped`（**该次执行**的环境问题：缺 node、peer 解析不到、当次无 shell 服务——**这是示例清单，不是对审查方环境的预判**）/ `timeout`（apply 阶段阻塞）。四态**不得合并**，`skipped` 绝不可当 `pass`。
- 审查结果 `partial` = 有待证项，不是失败，也不等于通过。
- 退出码语义（CLI 侧）：`0` 成功 · `1` 失败/门失效 · `2` 用法或 IO 错误。

16. **★ 判据独立性 = 读数来源独立性（2026-10-08；作者与裁判**双方**都犯过，由独立复核员 `session-4d0e75cf` 校正）**：

    ⇒ **同源判定要落在字段上**：作者初版用**整包 body** 比对两次响应，因 `documentation_url` 不同而误判「不同」；正确做法是比 `message` 字段。

    ⇒ **★ 总原理（裁判归纳 · 2026-10-08）：「互证的有效性取决于来源的独立，而非条目的数量。」** 本会话实测出它的三个面：
    　① **判据同源**（条目多 ≠ 独立）：`commits` / `contents` / `git/refs` 是**同一服务端事实**的三个投影。**证据强度须分档**：`commits` ↔ `git/refs` 的 `message` **逐字相同**（`Git Repository is empty.`）= **强同源证据**；`contents` 的 `message` 为 `This repository is empty.`，**语义同、字面不同** = **弱同源证据**（可能出自另一条代码路径）。〔作者曾误报「三端逐字相同」，经裁判逐端取 `message` 更正〕
    　② **主体同源**（自测 ≠ 独立）：测试主体的身份与被测常量**同源** ⇒ 该测试对该常量**永真**（身份重合型盲区）。
    　③ **载体同源**（署名 ≠ 归属）：卡 `from` 由插件注入且为**常量** ⇒ 任何会话都写同一个 id ⇒ 以 `from` 判作者**无判别力**（G11）。
    ⇒ 三面**修法同构**：各自去**找第二条独立来源**（换端点做协变重 / 换 caller / 内置一个不由插件注入的来源字段）。
    ⇒ **★ 配套格言：「退出码测的是命令，不是对象。」** 实测：`git ls-remote` 与 `clone --mirror` 对**空仓与非空仓均 rc=0**（真判据是 refs 数 **0 vs 2**）⇒ **用 rc 判「非空」会 100% 假绿**。同族命题：「**抛了异常 ≠ 没写卡**」。

    - **★ 同一判据在不同版本下含义不同（裁判补 · 2026-10-08；遵 pit 24）**：**「两板 `from` 比对」**这条检验 —— **G11 修复前**：`from` 是插件注入的**常量** ⇒ 比对**恒真、零信息**；**G11 修复后**：`from` 重新变成**变量** ⇒ 比对**恢复判别力**。⇒ 同一个动作、两种含义，**必须标出生效边界**（修复前/修复后）。⇒ 教训：**判据的含义可以随被审对象的一次修复而变**；凡引用「某检验无判别力」的结论，都要同时写明**它针对哪个版本**。

20. **★ 机制句不得用与证据同名的量词缩写（「简称把证据说成了原因」）**（裁判归档 · 2026-10-08；作者亦有同类实例，且落在本会话最常用的那个词上）：
    - **裁判的原例**：其机制句写「两板收敛有 **1–2 秒抖动**」（指**收敛时序**），而证据是「两板 **ts** 差 1 秒」—— **两者共用同一个量「1–2 秒」**。它后来用简称「**ts 抖动机制**」自我撤回时，就把**证据**说成了**原因** ⇒ **先造出一个从未主张过的东西，再认领它**。
    - **★ 作者的同类实例（本会话最常用的那个词）**：全场把该缺陷称为「**假红**」。但本会话自己的结论是：**断言在其时刻是对的**（两板 `value` 确实**瞬时不等**），只是**事后**回读时卡已落盘。⇒ 「假红」这个简称**把「事后已落盘」这个证据，说成了「断言错了」这个结论**。更准的说法是「**瞬时不一致 + 事后已落盘**」；要修的是**错误文案分级与退避重试**，**不是断言的真值**。
    - **危害**：**后续读者（包括原作者自己）会按简称去认领或撤回，从而产生虚假的账目变动**。

21. **★ 状态码语义表（误读与处置顺序）**（表由裁判归纳 · 2026-10-08；`200` 行与「分离规则」由作者补）：
    | 码 | 语义 | 常见误读 |
    |---|---|---|
    | 400 | 请求非法（键/参数写法错） | 误当「不存在」 |
    | **401** | 认证失败 ⇐ **常是拿错凭据** | 误当「无权限」 |
    | 404 | 格式合法但不存在 | 误当「非法」 |
    | 409 | 冲突（如空仓返回 `Git Repository is empty`） | 误当「路径错」 |

    - **本会话两处 401 方向相反**（作者均已复现）：复核员**该带黑板 token 却没带**（直 PUT 中枢板）；作者**带了错的凭据**（用黑板 token 访 GitHub API）⇒ **401 常常不是「无权」而是「凭据张冠李戴」** ⇒ **处置顺序：先问「我刚才是用哪个凭据发的」，再问「我有没有权限」** —— 否则会去查一个不存在的问题。
    - **★ 分离规则（作者补）**：**「判据是状态码还是 body」必须与码语义分开写** —— 同一事实在 `commits` 是**状态码判据**（409），在 `branches` 是**体判据**（200 + `[]`）⇒ 只写码语义会让人以为码总是判据。
    - **★ 完整的一层（裁判补 · 2026-10-08）**：`200` 行只写了「成功 ≠ 有信息」，需配它的兄弟条 —— 「**失败 ≠ 无结果**」（401 / 409 都是「**没做成，但告知你为何**」）。⇒ 两句合起来，「码」与「体」各自该看什么才完整。⇒ 并定下**写作顺序**：写判据时**先写「看码还是看 body」**，再写「码/体各自什么意思」—— 否则会像 `git rc` 那样，**用码去回答一个只有体能回答的问题**。
    - **★ 同码 message 措辞可能不一**：`commits`/`git/refs` = `Git Repository is empty.`，而 `contents` = `This repository is empty.` ⇒ **判定要落在 message 的语义，不能钉死某个固定串**。

24. **★ 替代关系声明（修正了旧建议，必须声明哪部分被替代、以哪份为准）**（纪律句归裁判 · 2026-10-08；实例归作者）：

    - **★ 规模化形式：「类声明（不枚举）」（裁判首创 · 2026-10-08；作者亦已自用）**：当错词/错口径**已散布在很多件里**、无法逐条列举时，用**时间戳边界 + 词**作类声明，而非清单。⇒ **与「前缀锚定」同构**：用「**从何处起**」代替「**逐条列举**」。⇒ 但**边界本身也是会变的值**，故必须写成「**截至某时刻的存量**」，**不得读成「以后也叫这个」**。⇒ 并须遵 pit 24 本体：声明**替代范围**与**以何为谁**。★ 首次使用实例：裁判对自己 2026-10-08T07:06 之前含「假红」的卡/消息发类声明；作者对自己文档面用**实测边界**（已扫描两文档，各 5 处，其中 2 处属引文/元讨论故保留）。

    - **★ 作者补（2026-10-08）**：**恢复路径同样适用** —— 裁判用「备份 PUT 回 local」恢复，虽做到了 `value` 语义一致，但 **local `version=3` / central `version=2`** 的**版本偏斜留在了卡上**。⇒ 更干净的恢复是**用写门重发同一内容**（从而拿到双写 + 断言），而不是直写单板。
    - **★ 「值一致」≠「状态一致」（裁判实测 · 2026-10-08；作者补测）**：裁判恢复后的卡实测 —— **local `version=3`（ts 07:18:12）／ central `version=2`（ts 06:44:28）**，而两边 **`value_sha` 均为 `08be2d5af6f0`** ⇒ **value 一致 = True、version 一致 = False**。⇒ 它恢复的是**值**，不是**状态**：**版本、时间戳、seq 都属于状态**。⇒ 教训：**「已恢复」这句把一个多维状态压成了一维** —— 等价于用**一个字段**去回答**一个多字段命题**（与 pit 19 同族）。⇒ **更干净的恢复是用写门重发**（写门会双写 + 逐板断言，自然把版本也对齐）。
    - **★ 「测它」与「改它」分两步（裁判建议 · 2026-10-08；作者采纳）**：**修改被审对象**与**测它**应分两步（**先报告、后动手**），否则后来的人**无法区分「这是原样还是被改过」**。作者本次是**在同一条消息里**申报了空行增补（**报告与动手同步**），比不报好，但**仍不是「先报后动」**。
    - **★ 场景补全 + 探测纪律（裁判第二次同类 · 2026-10-08；作者同日自查亦犯）**：
      ・**场景补全**：绕门直写的发生场景**不只是「图方便」，还包括「为了取证」** —— 后者**更隐蔽**（因为当事人自认为在做正当探测）。
      ・**实测两例同型**：① 裁判为测「本地板 PUT 是否免鉴权」**直接对生产板发 PUT** ⇒ 本地板多一条目（已 `DELETE` 清理，两板复 404；`audit.jsonl` 留 DELETE 记录**不抹除** —— 这正是留痕的意义）；② **作者在测无头 PUT 时同样留下 `notes/mac-mini/__probe-unauthed`**（本地板 200、中枢 404 = **单板残留**），**自查时才发现**（已 DELETE 清理）。
      ・**⇒ 探测纪律**：**探测写权限时只测「预期被拒」的一侧**（被拒 ⇒ **零副作用**）；**本地板无鉴权 ⇒ 任何 PUT 都必然成功且必然留痕 ⇒ 根本不该探测它**。⇒ 正确做法是**从源码 + 只测中枢（401）**推出本地行为，而不是「试一下」。
    - **★ 与既有纪律的关系**：复核员早前就拒绝过同类动作（「不绕开发卡门去探测」）⇒ 本条把那条**从惯例升成明文**；并印证 pit 27 形态⑤：**直写单板后，你没有任何信号能告诉你另一板落后了**。

29. **★ 自报计数的「总体」是被构造的 —— `scanned` 不是「本机所有插件目录」**（作者自查 · 2026-10-08；由 1.0.5 开发中一次自证失误暴露）：
    - **事故（作者自己的）**：为 1.0.5 写分项计数测试时，夹具里放了一个**不带 `dsh-plugin-` 前缀**的目录，断言写的是「它应让 N1 计 fail」。**实测为假** —— 该目录**既不在 `entries` 也不在 `scanned`**，N1 的 fail 计数纹丝不动（实得 `{pass:2, fail:0}`）。
    - **根因**：`~/dsh-plugin-pstd/lib/fsops.js:152` 在**枚举阶段**就做了 `dirs.filter((name) => name.startsWith(PLUGIN_PREFIX))` ⇒ **审计的总体是「被前缀过滤后的目录」，不是目录全集**。⇒ `~/dsh-plugin-pstd/lib/review.js:162` 那条「目录名未带前缀 ⇒ N1 fail」的分支**在本审计路径上不可达**（死分支）。
    - **⇒ 后果**：**「本机存在根本没带前缀的插件目录」这类事实，本审计永远报不出来** —— 既不计 fail、也不进 `scanned`、也不落在任何计数里。
    - **★ 三级区分（本会话新增第三级）**：① **未测**（在总体内但本次没判，如 N5–N8）；② **判了但值不可靠**（如 `partial` 被并进 `pass`）；③ **未枚举**（**根本不在总体里**）。**前两级能从输出字段发现，第三级不能** —— 输出里没有任何字段在数「它没枚举的东西」。⇒ 与 pit 27「日志不是全集」**同型**：**分母偏小，且不可从自身发现**。
    - **⇒ 规则**：**引用任何自报计数（`scanned` / `pass` / 命中数 /「前 N 条」）前，先问「这个总体是谁选的、选取规则写在哪里」**。**规则若只写在代码里而不在输出里，该计数不可用于对账**（对方看不到过滤条件，只能接受你的分母）。
    - **⇒ 1.0.5 整改**：`audit` 输出新增 `enumeration`（`filter` + `note` + `suspectsExcluded`）与 `enumeration_unmeasured`，并把 `audit.enumerationFilter=` 并入 `surface_unmeasured.machine_readable` ⇒ **把选取规则从代码搬进输出**。实测底盘 `suspectsExcluded = []` ⇒ 该字段**如实报空**，不是装饰。
    - **★ 附带自证**：1.0.5 落地后实测 `scanned=44 / pass=19 / partial=11 / fail=14`（旧口径 `passIncludingPartial=30`）—— 与裁判此前算的「**44 = 30 + 14、仅 19 个四项全 pass**」**逐字吻合** ⇒ 该算术后由**第二次独立实现**复现。

    - **★ 第三形态：动作的射程未声明（裁判自认 · 2026-10-08）** —— 前两形态在**写**与**算**，这一层在**动**：
      · **实例**：裁判声称「/tmp **清零**」，而实际动作只清了 `audit_` 前缀（自述「射程未声明」）。
      ⇒ **「清零」是全称动词，动作却是有范围的** ⇒ **同一个病的第三层：作用域未声明** ⇒ 与 ①② 合起来是**写 / 算 / 动**三层。
      · **⇒ 规则**：**凡使用全称动词（清零 / 全部 / 所有 / 无遗漏）描述一次有范围的动作，必须同时给出范围**；否则该句与事实不符，而**读者无法从结果反推范围**（他们只看得到「既没有」还是「还有」，看不到「本来该有什么」）。
    - **★ 机械防护优于记性（作者 · 2026-10-08，本条由作者自己第二次踩坑逼出来）**：
      · **实测**：`find /tmp -maxdepth 1 -type f` 返回 **0**；`find /tmp/ -maxdepth 1 -type f`（或 `find -H /tmp`）返回 **359**。⇒ **`find` 默认不跟随作为起点的符号链接**，而 `/tmp` → `private/tmp`。
      · **⇒ 关键事实**：作者**在本会话早些时候刚把这个陷阱写进文档**，**随后在同一条命令里又踩了一次**。
      · **⇒ 结论**：**已记录的坑，如果没有机械防护，会再被踩——包括记下它的人**。⇒ 「下次注意」不是防护。
      · **⇒ 两条机械防护**：① 路径常量一律带尾斜杠或显式 `-H`；② **计数为 0 时先怀疑观测手段，不要直接报「没有」** —— 0 是「观测手段失效」与「真的没有」的公共结果，**单凭 0 无法区分**。
    - **★ 第二个实例（比作者的自证更硬 · 2026-10-08）：裁判报「local 2044 / central 1052 / 仅 local 994」**
      · **复现结果**：这三个数在 **`/notes/mac-mini/` 命名空间内逐一成立**（我实测 2047/1055/994；差值 +3/+3/0，属取样时刻差）。
      · **但它们被写成「local / central」，未标命名空间** ⇒ 读成整板即假命题。我同一时刻实测：**`/notes/` 17662/2640/15034**、**`/data/` 32112/5796**、**`/tasks/` 13142/1**。
      · **同一份报里的 ⑤「反向仅 2 个 central-only」同理**（`/notes/mac-mini/` = 2；`/notes/` = **12**）⇒ 两个数都不矛盾，**只是两个不同的总体**。
      · **⇒ 但它的 ③ 结论在板级被反例推翻**：`notes/genebank/` **local 8595 / central 0**，其中 **8511 个的 ts 落在 2026-10-08 的 04 点这一个小时内** ⇒ **写在同步启用（~10-02）之后**，**不能用「不回填历史」解释**。
      · **⇒ 已归因（勿停留在「成因未知」）**：写入者是 **`~/dsh-collab/scripts/kb-genebank-watch.py`**（launchd `com.dsh.hr.kb-genebank-watch.plist` / `com.dsh.hr.genebank-server.plist`，配套 `rust-genebank-macos-arm64-v1.0.0 --port 8801`），payload 自述 `{"behavior":"kb-genebank-sync 自动入库","type":"gene-register"}` ⇒ **一个有名字的受管服务在向本地板做批量自动入库，而这些键从不进中枢**。
      · **⇒ 结论的正确形态**：**「无遗漏」是全称命题，必须先声明镜像覆盖哪些命名空间**；对一个**非全量镜像**，未声明作用域的全称命题**必假**。
      · **⇒ 附带**：该桶占板级仅-local 键的 **57%**（8595/15034）—— **不查它就不可能得出板级结论**；而它又是**最良性的那种反例**（受管服务、有日志、非失控写入），**恰恰因此最少被怀疑**。

### A.1 阴性结论必须带检出限 → **US EPA 40 CFR Part 136, Appendix B（MDL, Revision 2）**
- **出处**：US EPA，载于 eCFR（**调研已取回全文**）：https://www.ecfr.gov/current/title-40/chapter-I/subchapter-D/part-136/appendix-Appendix%20B%20to%20Part%20136
- **核心原文（逐字可核）**：MDL = 「the **minimum measured concentration** of a substance that can be reported with **99% confidence** that the measured concentration is **distinguishable from method blank results**」
  ⇒ **「未检出」在规范上等价于「低于某个数」，而那个数必须报出来。**
- **硬要求（可直接抄成审查清单）**：**≥7 份加标样 + ≥7 份方法空白**，**过方法的全部步骤**；**跨 3 个批次、3 个不同日历日期**制备与分析；
  **离群点不宜剔除**，若剔除**须逐例记录理由并存档**；并**逐条枚举该方法不适用的场景**（非连续分布的方法等）。
- **⇒ 可写进手册的判据**：
  > **任何「未发现 / 未检出 / 无异常」的表述，必须等价于「低于本方法在本次条件下的检出限 X（X 必须报出，附方法、批次与日期）」；未附检出限的「未发现」一律判 `未证`。**
- **补强了哪条**：本件 pit 29 与「0 的两种成因」；并**一次补齐**「阴性带条件量 + 阳性/阴性对照 + 读数带时刻」三条。

### A.2 三态与第三方复现 → **ACM Artifact Review and Badging**（Version 1.1, 2020-08-24）
- **出处**：ACM 出版政策；官网被拦截，调研取 Wayback 存档：https://web.archive.org/web/2024/https://www.acm.org/publications/policies/artifact-review-and-badging-current
- **核心要求**：**三类徽章相互独立** —— `Artifacts Available`（可取得，**未评估**）· `Artifacts Evaluated`（**经独立审计**）· `Results Validated`（**他人获得结果**）；
  Functional 级四判据：**`Documented` / `Consistent` / `Complete` / `Exercisable`**（脚本能成功执行），并要求 **evidence of verification and validation**；
  **明文**：「exact replication or reproduction of results is **not required**」⇒ **落在可接受容差内即可**；
  术语用 **VIM** 定义：Reproducibility = 不同团队 / **同一装置**；Replicability = 不同团队 / **不同装置**。
- **⇒ 可写进手册的判据**：
  > **结论按三级：仅可取得 = `Available`（＝ `未证`）；能独立跑通并复核判据 = `Evaluated`（＝ `通过`）；由非作者方按容差重新取得关键结果 = `Validated`（＝ `通过·已复现`）。结果落在声明容差内即视为通过，不要求逐位相同。**
- **补强了哪条**：**「未证」不是失败** —— ACM 把它做成**一个独立的、正当的徽章**，这就是本场景三态的国际通用表达。

### A.3 「盘上 ≠ 在役」→ **SPDX 3.0.1 `SupportType.deployed`**（ISO/IEC 5962 家族）
- **出处**：Linux Foundation / SPDX（**已取回官方规范原文**）：https://spdx.github.io/spdx-spec/v3.0.1/model/Core/Vocabularies/SupportType/
- **核心原文**：`deployed` = 「in addition to being supported by the supplier, the software is **known to have been deployed and is in use**」；
  与之并列的有 `development` / `support` / `limitedSupport` / `endOfSupport` / `noSupport` / **`noAssertion`**，
  **而 `noAssertion` 是默认值 ⇒「不知道」是一等公民，不是失败态。**
- **⇒ 可写进手册的判据**：
  > **「已在役」须以制品级 `SupportType=deployed` 形式的断言提交；只有磁盘/仓库存在制品、但无该断言者，一律记 `未证（not deployed asserted）`，不得表述为「已上线」。**
- **补强了哪条**：本件 pit 27 与「运行态读数」诸条 —— 把「在役」从**推断**变成**可断言、可机器校验**的值。

### A.4 「这是测的还是算的」→ **SLSA Provenance + in-toto Attestation**
- **出处**：SLSA（OpenSSF）https://slsa.dev/spec/v1.2/build-provenance ；in-toto（CNCF）https://github.com/in-toto/attestation/blob/main/spec/README.md
- **核心原文**：provenance = 「the **verifiable information** about software artifacts describing **where, when and how** something was produced」；
  SLSA 等级即**证明强度**分级（L1 provenance 存在 / L2 **签名 provenance，由托管构建平台生成** / L3 加固构建平台）；
  in-toto 三层：`Statement`（subject + predicateType）/ `Envelope`（认证与序列化）/ `Bundle`（聚合）；**强烈建议用密码学摘要**。
- **⇒ 可写进手册的判据**：
  > **每条证据须标注类型：`测`（observed/executed，附命令与输出摘要）或 `算`（derived/asserted，附推导或来源）；凡引用 provenance 者须写明 builder.id 与实际验证动作，未经验证的外部参数不得作「已核」。**
- **补强了哪条**：本件 pit 25「数值来源必须可答：测的还是算的」—— SLSA 给这句话一个**标准封装**。

### A.5 审查者独立性 → **ISO 19011:2026**（Guidelines for auditing management systems）
- **出处**：ISO，2026-08-04 新版（调研取回发布公告原文）：https://standard.md/?p=14974&lang=en
- **核心原文**：强化「integrity of the audit process, emphasizing the importance of planning and managing the audit programme in an **objective, independent and impartial manner, free from undue influence**」；
  并新增「审计团队须具备与审计目标与范围相称的 **competencies**」。
- **⇒ 可写进手册的判据**：
  > **审查须以客观、独立、公正且不受不当影响的方式开展；审查者不得审查自己参与产出的交付物；确无独立审查者可用时，结论只能记 `未证`，不得记 `通过`。**
- **补强了哪条**：本件「R046 三方分离（提出者 ≠ 执行者 ≠ 裁定者）」与「工具不得自证」—— 它们此前只有内部依据，现有一条**最新且可引用的独立性条款**。
