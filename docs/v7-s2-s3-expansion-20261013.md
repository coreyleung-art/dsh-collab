该项目自认需要【三层独立性】，而本机只能做到第一层：
  ① 认知独立（不同会话/上下文/提示词）      —★ 成立

证据：全机 whoami / 进程属主 / 会话文件属主全为 coreyleung；
     tailscale status 的 4 个节点属主也全为 coreyleung@。
  ⇒ ★★ 而你不在本机 ⇒ 你是这个项目第一次真正拥有②的审查者。

═══ 二、你要做一件事：独立验证一批【声称】═══

（请先提供一句话背景：你手上应该有一份材料包。若没有，请告诉我们你能看到什么。）

对每一条声称，请给：★ 原文引用 · ★ 你的独立判断（成立/不成立/不可判）· ★ 你的依据。

重点验这四类：
  1. ★★ 【结论形】声称—★ 如「所有告警都有读者」「同类复发 = 0」—★ 这些真的成立吗？
  2. ★★ 【数字形】声称—★ 凡报一个数（条数/比例/分母），★ 口径是否已声明、能不能复算？
  3. ★★ 【判据形】声称—★ 它说「这个检查能红」，★★ 而你能不能想到一个它抓不到的情形？
  4. ★★ 【独立性形】声称—★ 它说「已经有独立审查归档」—★ 而那些审查者到底算不算独立？
     （★ 关键：同一台机、同一账户、同一人委托 ⇒ 只算 ①）

═══ 三、五条硬性纪律═══
1. 无依据即不可判 —★ 看不到的就写「看不到 ⇒ 不可判」，不许猜
2. 三态：成立 / 不成立 / 不可判（★ 不可判 ≠ 不成立）
3. 凡报「0/未发现」必附【你查过什么」

5. ★★ 不要客气：★ 本次要的是【找错】，不是鼓励

═══ 四、交付格式═══
一份 markdown，四节：
  节一：逐条判定（★ 声称引用 · 你的三态判 · 依据）
  节二：你发现的错（★ 按严重度）
  节三：你想不通的地方（★ 包括「为什么会这样」的疑问）
  节四：你的限制（★ 看不到什么·需要什么才能判）

═══ 五、重要声明═══
★★ 你提供的是 ②设备独立；★ 而 ③主体独立（不同委托方）仍由用户判定。
