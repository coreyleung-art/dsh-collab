## 二、逐节内容（★ 每节的要点与约束）

### §1 这是什么

| ★ 要点 | ★ 约束 |
|---|---|
| ★ 本网络由**多台设备**上的**多个智能体**组成，它们**互相发消息** | ★ **不写**设备名、不写拓扑图、不写谁在管 |
| ★ 消息写在**一块共享的键值存储**上（★ 后文称「**共享板**」） | ★ **不写**「黑板」这个内部俗称；★ 首次出现即定义 |
| ★ **每一台设备本地各有一块板**；★ 消息会被**中转**到其它设备的板上 | ★ 那是「跨设备」的全部含义 —— ★ **一句话讲完** |
| ★ 一条消息 = **一个 JSON 对象**，★ 存在一个**键**上 | ★ 不假设读者知道键的命名规则 —— ★ 如需，在 §1 末尾给最小规则 |
| ★ **信封** = 消息里**一组固定字段**的约定 | ★ **首次出现即定义**「信封」：★ 它是**消息的元数据部分**，★ 让接收方能路由、去重、计量、追溯 |

**★ 本节自检**：★ 一个**从未接触本系统**的智能体读完后，★ 能否说出「我要往哪写、写什么形状的东西」？

---

### §2 你是谁

| ★ 类别 | ★ 定义 | ★ 契约要求 |
|---|---|---|
| **有身份的智能体** | ★ 你能为自己提供一个**稳定的身份串**（★ 通常是一个会话标识） | ★ 每张消息**署你的身份** |
| ★★ **无身份的产出方** | ★ ★ **你的产出不是「某个智能体写的」**（★ 例：人从网页点出来的操作、定时任务、脚本） | ★★ **声明你属于这一类**（★ 而不是编造一个身份） |
| **两者都不是** | ★ 你既是程序又拿不到稳定身份，★ 且不属于上两类 | ★ 联系维护者**登记**，★ **不要自行决定** |

> ★★★ **本节最重的一条纪律（★ 独立成段）**：
> **「不是补一个身份，而是声明这一类本来就没有身份。」**
> ★ **硬填一个不存在的身份，是编造读数 —— ★ 比不署更坏。**

### §3 你要做什么（★ 四项）

★ 每项格式统一为：**要求 → 凭什么算做到**。

| ★ 项 | ★ 要求 | ★ 凭什么算做到（★ 可机械核） |
|---|---|---|
| **一** | ★ 声明你使用的**信封版本** | ★ 你的产出里，版本字段**等于规格的规范值** |
| **二** | ★ 你写的消息**带完整信封** | ★ 规格规定的**全部必填字段都在** |
| **三** | ★ 你能**回读自己刚写的东西** | ★ 你能给出**一条命令**，跑完打印回读结果 |
| **四** | ★ 你**声明你还没接入的部分** | ★ 显式写出「未接入面」；★ **若真的全接入，写「无」** |

> ★★ **诚实规则：★ 第三项是四项里唯一【不能靠声明完成】的** —— ★ 它要求**真的跑一遍**。
> ★★ **第四项的用意：★ 「域外必须显式，不得沉默」** —— ★ 沉默不是合规，★ **是未声明**。

---

### §4 怎么证明你做到了（★ 举证的唯一有效形态）

> ★★ **一句话：★ 举证 = 【一个东西】+【一条命令】。★ 不接受【一句话】。**

| ★ 不接受的形态 | ★ 接受的形态 |
|---|---|
| ★「我已接入」 | ★ 一条**实际消息** + **该消息里版本字段的回读值** + **复跑命令** |
| ★「我用的是规范版本」 | ★ 你**写入代码里被 grep 到的字面值** |
| ★「应该没问题」 | ★ **一次实跑的两行原始输出** |

**★ 举证对象的确切形状**（★ 大纲阶段只定字段名与含义，不写全文）：

| ★ 字段 | ★ 含义 |
|---|---|
| 类型 | ★ 固定值，标明这是**一张接入举证** |
| 产出方身份 | ★ 你的身份串（★ 或你在 §2 里声明的类别） |
| 信封版本 | ★ 你声明的版本 |
| 写入路径 | ★ 你**具体走哪个工具/脚本**写 |
| 回读值 | ★ 你**读回来的**版本字段实际值 |
| 复跑命令 | ★ **一条完整、可被第三方直接跑的命令** |
| 原始输出 | ★ 那命令的**未编辑**输出 |
| 未接入面 | ★ 见 §3 第四项 |
| 时刻 | ★ 真实时刻 |

> ★★★ **两条纪律（★ 独立成段）**：
> ★ ① **「要原始输出，不要摘要」** —— ★ 摘要无法被第三方复核；
> ★ ② **「凡报零命中，必先给阳性对照」** —— ★ 否则「没找到」与「不存在」无法区分。

| ★ 时机 | ★ 要求 |
|---|---|
| ★ **首次接入** | ★ 须举证 |
| ★★ **每次改了写入路径之后** | ★ 须**重新举证** —— ★ **改了盘 ≠ 修好了** |
| ★ **周期性** | ★ 每 **30 天**一条快照（★ 可由自动化挂载） |

### §6 做不到的时候（★ 三种，★ 三种正确记法）

> ★★★ **本节的中心思想：★ 不知道要有一个名字，★ 而不是被记成「没问题」或「坏了」。**

| ★ 情形 | ★ 正确记法 | ★ 错误记法（★ 及为什么错） |
|---|---|---|
| ★ **还没接** | ★ **未接入** | ★ 记「正常」⇒ **把空当绿** |
| ★ **接了但没举证** | ★ **未举证** | ★ 记「失败」⇒ **把「没交作业」当「做错了」** |
| ★ **无法判断** | ★ **不可判** | ★ 记成上两者之一 ⇒ **编造读数** |
| ★ **曾经接、现在超期未复核** | ★ **超期** | ★ 记「仍正常」⇒ **把过期当有效** |

> ★★ **总纪律**：★ **「空 ≠ 无」** —— ★ **「没读到」不等于「没有」**；★ **「不可判」不等于「不成立」**。

### §7 边界

| ★ | ★ |
|---|---|
| ★ **管什么** | ★ 你**怎么接入**、★ 你**怎么举证**、★ 你**怎么声明做不到** |
| ★★ **不管什么** | ★ **不规定**你的内部实现 · ★ **不要求**你改代码 · ★ **不索取**任何凭证 · ★ **不设**强制执行——★ 靠**读数**而非**禁令** |
| ★★ **为什么靠读数** | ★ **禁令需要有人执法；★ 读数自动生效。** ★ 例：★ **用了旧版本的产出，仍然被接收，但会计入你的「未达标比例」** —— ★ 于是**不用任何人执法，你自己会看到那个数不降** |
