## 〇、形态谱系总览(从软到硬)

```
A. 远程接入(软件)      B. U盘钥匙(便携)      C. 带屏盒子(常驻)     → 双形态产品化
门店现有电脑跑采集     U盘=身份钥+自举器    门店独立 AI 运营终端      商家盒(自用) + 服务商钥(上门)
[B 形态已三方共识]     [能力收中央, 零安装]   [星台对话+老登壳融合]    (B/C 两档按客户形态选)
```

**共同本质**: 门店 = MCP 运营网络的边缘节点(E2 注册 + comm-mcp 接入); 差异 = 接入端形态与交互面。

## 一、形态 A · 远程接入(软件, 已共识)

| 项 | 内容 |
|----|------|
| 形态 | 门店 Windows 跑 Chrome(登录态留店) + 只读采集器(E2 节点) |
| 接入 | comm-mcp 栈1(经 E2 + R-ERR4), 数据回流 notes/store-<id>/ |
| 门 | lean4: 采集器结构无写原语; 动作回中枢 + R027 |
| 状态 | ✅ 三方共识(B 形态), 待用户裁决试点(i9 模拟 2-3 店) |

## 二、形态 B · U盘钥匙(服务商随身)

| 项 | 内容 |
|----|------|
| 本质 | U盘 = 身份凭据 + 便携负载(Node+采集器+智能体壳) + 自举启动器; **能力收中央, 门店只当宿主** |
| 拉什么 | 能力与指令(操作模板/定价参数/话术/待办) —— 门店大脑留服务器 |
| 推什么 | 门店渠道实时状态(订单/告警/竞品/操作结果) |
| 目的 | 门店线上经营"插上即托管": 服务商上门插钥→门店账号进运营网→拔钥走人(妙记2 轻资产代运营交付) |
| 关键点 | ①便携 Node+隐形 Chrome 负载 ②自举(引导启动, Windows autorun 被禁) ③凭据加密+远程吊销(E2) ④多钥备份 |
| 门 | 动作仍建议+影子先行(用户原则); 护栏只在中央 |

## 三、形态 C · 带屏盒子(商家常驻 = 星台+老登融合体)

| 项 | 内容 |
|----|------|
| 本质 | 门店专属 AI 运营终端: 屏幕常显经营看板 + 触控/语音对话(星台壳) + 经营功能页(老登壳) + 后台 MCP 客户端 |
| 硬件候选 | A 轻量安卓盒(¥400-600, 量产稳) / B 树莓派触屏(¥600-1000, 可玩) / C 二手平板改造(¥200-400, 最快样机) |
| 交互 | 看板常显(销量/告警/评分); 点击/语音唤起对话; 语音唤醒词=门店名? |
| 身份 | 每盒一 E2 身份烧录; 绑定 store-id; 换店=后台改绑 |
| 商业 | 硬件月租摊薄(获客钩子?) + 能力订阅(栈3/4 定价) —— 硬件是钩子还是利润源待定 |
| 兼容 | 可兼老登触达(培训/产品展示) 摊薄成本; HDMI 复用收银屏? |
| 决策待办 | 本地微模型兜底(断网可用) vs 纯云端瘦终端? 信任模型(服务商资产锁死 vs 商家开放)? 语音在门店环境可用性? |

## 四、双形态产品化(B + C)

| 档 | 客户 | 硬件 | 订阅 | 核心 |
|----|------|------|------|------|
| C 商家盒 | 单个商家/连锁 | 带屏盒(常驻) | 硬件月租 + 栈3 能力 | 商家自用: 看板+对话+建议确认 |
| B 服务商钥 | 代运营服务商 | U盘钥(随身) | 硬件一次 + 栈4 能力 | 上门托管: 插钥接入 + 中央运营 |

> 双形态共享同一后端(四栈 MCP + 运营网), 硬件只是接入端差异。
> 原则: 两者能力动作一律"建议+影子先行"(用户定案), 硬件非能力前提。

## 五、决策 gate(防过早烧钱)

按用户已定原则(有能力≠应该做 + Φ7 成本意识 + 建议影子先行):

```
启用条件(全部满足才进入硬件化):
  ① 软能力验证: 四栈 MCP + 门店节点(A 试点)跑通, 价值被确认
  ② 商业模式确认: 栈3/4 有人付费(非自嗨)
  ③ 形态选型: 客户形态决定 C(商家) or B(服务商) or 双形态
  ④ 硬件预算批准(用户): C 样机或 B 钥批产
不满足 → 保持软件形态(A), 文档留存
```
