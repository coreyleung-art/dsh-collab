## 一、流程本体（★ 可复用）

```
① 大纲        →  定义目标 + 模块 + 判据 + 反例 + 范围外
② 调研（并行） →  每模块一个代理，产出【复跑命令 + 未编辑输出 + 退出码】
③ 撰写（并行） →  每模块一个代理，产出【判据 · 现测 · 三态 · 复跑 · 负控 · 口径】
④ 审查（交叉） →  写 A 的审 B，轮转 + 反面审查
⑤ 合并        →  主文 + 附录，含【更正账】与【取舍记录】
```

**实际投入**：

| 段 | 代理数 | ★ 产出 |
|---|---|---|
| 调研 | **9** | ★ 55 篇 · 15,462 行 · 5 个 evidence 目录 |
| 撰写 | **5** | ★ 4,679 行（1247 / 914 / 889 / 1022 / 607） |
| 审查 | **3**（+1 外部） | ★ 3 份本机 · 1 份外部（304 行） |
| 合并 | ★ 本线 | ★ 233 行主文 + 5 份草稿作附录 |

## 二、★★★ 十三条教训（★ 每条有证据）

### ★★★ 1. 从「手上的问题」反推目标，必然偏移

★ **初版大纲**把主目标定为「让假绿归零」，★ 并把 S-4 / I-2 / I-3 / L 维**划到范围外**。
★★ **而实测：锚点有 49 个 ❌、约 91 项未完成** ⇒ ★ **初版只盖了【四维 + M4】一小块。**

★★★ **⇒ 正确顺序：★ 从【登记了什么没做完】正推，不是从【我手上有什么】反推。**

### ★★★ 2. 清点的口径决定一切 —— 行级抽取会漏掉整片

| 版本 | 口径 | ★ 结果 |
|---|---|---|
| 第 1/2 版 | ★ **行级关键词**（❌ / open / 待 / 未） | ★ §15 只 **3 条**（★ 实际 **17 条**）· §18 只 **1 条** |
| ★ **第 3 版** | ★★ **登记表为权威层** + 正文表格 + 关键词（三层取并集） | ★ 覆盖到位 |

★★ **⇒ 教训：★ 关键词抽取只能抓到「行里带那些词」的条目；抓不到【表格里按 id 登记、行文不带那些词】的。**

### ★★★ 3. 提示词里必须塞【已确认发现】

★ 我给了 W1 **13 条**、W3 **9 条**、W4 **10 条**已确认发现。
★★ **理由：★ 否则 5 个撰写代理会各自重建一遍** ⇒ **两边口径打架。**

### ★★★ 4. 提示词里必须塞【审查抓出的错】

★ 我把 V3 的 **9 条**发现写进 W3 的提示词，★ 并写明「**必须采纳，不得重犯**」。
★★ **⇒ 结果：W3 全篇改以【字面量 + 复跑命令】为据，不以行号为据**（★ 应对 D-193）。

### ★★★ 5. 要写「自我保护」条 —— 它救了缺位的审查

★ `research/v7-review-V2/` **两次皆空**。★ 而我在 W1/W2 的提示词里写了：
> ★ **若 V2 为空，你必须自己做这三件**：① 抽 3 条命令重跑逐字对 ② 核分母口径 ③ 核登记表 ↔ 锚点分叉
★★ **⇒ W1/W2 都执行了，并各自抓到我 3 处错。**

### ★★★ 6. 交叉审查（写 A 的审 B）真的能抓到东西

★ **V4 抓到**：★ 我的裁定文档「表内合计 252 ≠ 正文声称 294」（★ 我漏了 3 行）。
★ **V3 抓到**：★ 我的清点件把「§18 = 1 条」**署名给了 R-M3** —— ★ 而 **R-M3 原文明确反对该值**。
★★ **⇒ 两处都是【我自己的错】，都靠独立审查才暴露。**

### ★★★★ 7. 外部审查补的是【本机结构上做不到】的那一层

★★★ **17 个本机代理，没有一个指出「独立性是三层」** —— ★ **而外部线 `ext` 一句就指出了。**

| 层 | ★ 含义 | ★ 实测 |
|---|---|---|
| ① 认知独立性 | 不同会话/上下文/提示词 | ★ **成立** |
| ② 设备独立性 | 不同主机 | ★ **未取得** |
| ③ **主体独立性** | ★★ **不同委托方** | ★★ **不可判** |

★★★ **⇒ 而 R046/S3 要的是 ③。** ★ 本机三条判据（`whoami` / 进程属主 / 会话文件属主）**全在本机**；
★★ **`tailscale status`（外部控制面）更强 —— ★ 但 4 节点属主仍全为 `coreyleung@`。**

★★★ **⇒ 结论：★ 换台机器跑同一读数，得到的是【跨设备可复现】，不是【第二个主体】。**

★ **另：外部审查还做了本机做不到的【业界来源核实】** —— ★ 抽 6 条：**5 成立 · 1 不可判 · 0 编造**（★ 含 404 阴性对照）。

### ★★★ 8. 纪律必须【写进提示词】，否则不会被遵守

★ 以下四条我写进了每个代理的提示词，★ **而它们都被执行了**：

| 纪律 | ★ 效果 |
|---|---|
| ★★ **写文件用【临时文件 + 原子替换】** | ★ 16 个代理**无一**再发生截断事故（★ 而本线自己当天犯过一次） |
| ★★ **凡报「未搜到」，必先给阳性对照** | ★ 多个代理自曝「阳性对照选错」 |
| ★ **退出码必须在管道之前取** | ★ R-M1M6 自曝踩过 · W1 立为硬纪律 |
| ★ **不得修改 `docs/` 既有文件** | ★ 全部代理**均自证未改**（★ 双 sha 核对） |

### ★★★ 9. 代理会【自曝】—— 而自曝是质量的信号

★ **R2** 自曝 **3 次探针事故**（★ 前缀重复拼接 / 段长判据写错 / 阳性对照选错）。
★ **W1** 自曝 **3 处自己的错**（★ 单尺读表 / 把插件源码 patch 当在役配置 / 把硬编码当证据）。
★ **W5** 自曝一次真探针故障（cwd 错 ⇒ 两处 0 命中）。
★ **W2** 自曝「我第一版把 `FAIL 2` 落盘，6 分钟后复跑发现是 `FAIL 1`」。

★★★ **⇒ 自曝多的代理，产出质量反而更高** —— ★ 因为**自曝 = 它真的在核。**

### ★★★ 10. 代理会【推翻自己人】—— 这是好的

| 谁 | ★ 推翻了什么 |
|---|---|
| ★ **W1** | ★★ **「G-CR 门有 5 条自证」** —— ★ 实测那 5 条「负例」**全是恒真字面量**（`0 == 0`）⇒ 可信负控 = **0** |
| ★ **W2** | ★ **「`data/ops` 有 11 个目录」** —— ★ 那是代码清点，★ 板普查第三段 **265 个** |
| ★ **W5** | ★ **「L-1/L-2 三条件未找到」** —— ★ 实测**逐字原文在锚点 `:262`/`:263`** |
| ★ **R2** | ★ **本线建的读者三态「读不到 ⇒ 不可判」结构上不可达** |

★★ **⇒ 它们推翻的都是【本线先前写下的】。** ★ 这是流程在起作用。

### ★★ 11. 失败是常态，不是例外

★ **审查 V2 两次皆空**（★ 第二次派于 20:33，至 22:00 仍 0 篇）。
★ **调研 R2 首次零产出**（★ 跑了约 40 分钟，只留下 `evidence/` 5 个文件，0 篇 md）⇒ ★ **重派后交付 8 篇 1592 行。**

★★ **⇒ 应对：★ ① 派工时写「自我保护」条 ② 零产出就重派，不纠缠 ③ 不因一次失败调整整个流程。**

### ★★★ 12. 主文不能拼贴 —— 草稿作附录

★ 5 份草稿合计 **4,679 行**。★ **若原样搬进主文，主文就变成拼贴。**
★★ **⇒ 实际做法：主文 **233 行**（更正账 + 模块指针 + 同形诊断 + 不可判 + 待裁）+ 草稿作【附录】保留全文。**

### ★★★ 13. 【更正账】是最有价值的部分

★ v7 主文里最重的是 **`§0.0` 更正账**：

- ★★ **v6.1 → v7 推翻 22 条**（★ 逐条：v6.1 写什么 / 实情 / **谁发现的**）
- ★★★ **本线自己的错 5 条**（★ **同列，不隐**）

★★ **⇒ 理由：★ 下一任读 v7 时，最需要的不是「v7 说了什么」，而是「**上一版哪里错了、怎么错的**」。**

## 三、提示词模板（★ 实测有效，可直接抄）

```markdown
你是 <计划名> 的【<角色> <编号>】。工作目录 <路径>。全程中文。

# 你的任务
<一句话说清产出物 + 它不是什么>

# 你的范围（★ 只写这些）
<模块清单 + 对应锚点章节>

# 必读（★ 按顺序）
1. ★ 你自己的调研 / 上游产出
2. ★★ 对它的独立审查（★ 若无，见「自我保护」）
3. <大纲 / 清点件 / 锚点章节>

# ★★ 你必须吸收的已确认发现（★ 全部已被独立复现）
<逐条列，★ 免得它重建>

# ★★ 你必须【自己现测】的（★ 不得照抄任何文档）
<具体命令清单>

# 输出规格
<结构化章节 + 每条的字段要求>

# 硬性约束
1. ★★ 每条读数必须【本轮现测 + 带时刻】
2. ★★★ 凡断言「某机制有效」，必须给【它在什么输入下会红】—— 给不出就标「未验」
3. ★★ 凡报「未搜到」，必先给一个必定命中的阳性对照
4. ★★★ 不得修改既有文件；你只写 <你的产物路径>
5. ★★ 写文件必用【临时文件 + 原子替换】
6. ★ 退出码必须在管道之前取

# ★ 自我保护（若上游审查缺位）
<列 2–3 件它必须自己替代做的核查>

# 项目纪律
「空 ≠ 无」·「一个断言若从未红过，它就不是判据」·「不得升格」·「不得代裁」
★ 你是同一主体 ⇒ 你的产出不能自证独立 —— 请文末如实标注。

最后回复 400 字以内：写了什么、最重三条、你没做到的、你的限制。
```

★★ **六个设计点**（★ 每个都有实测效果）：

| # | 设计 | ★ 为什么 |
|---|---|---|
| 1 | ★ **「你必须吸收的已确认发现」独立成节** | ★ 防重建、防口径打架 |
| 2 | ★ **「你必须自己现测的」独立成节** | ★ 防照抄（★ v6.1 的读数 28 小时内被推翻 22 处） |
| 3 | ★★ **「自我保护」节** | ★ 上游缺位时不塌 |
| 4 | ★★ **纪律单列 + 编号** | ★ 未写进提示词的纪律不会被遵守 |
| 5 | ★★ **要求文末自报「限制」** | ★ 逼它自己划边界（★ 实测：都写了） |
| 6 | ★ **要求末段 ≤400 字** | ★ 防交付回执淹没实质 |
