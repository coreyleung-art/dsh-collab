# 通用机会发现引擎 · 潜力实验室泛化 v1

> 作者: 明鉴 v2 · 2026-09-05 · 用户提出
> 「潜力实验室能力本身, 是否能泛化到架构管理器的每一个不同逻辑呈现的 Tab 去发掘机会?」
> 答案: 能——连接实验室核心是「孤岛探测 × 候选穷举 × 价值打分」, 与"智能体"绑定的是特征选择, 不是算法。

## 一、泛化抽象(引擎输入 = 通用图 + 特征提取器)
```
机会引擎(graph, extract) →
  ① 孤岛: 无连接边节点
  ② 候选: 孤岛 × 全节点 穷举
  ③ 打分: 同域/语义/共享(extract 提供 node 的 abilities-text/resource-text/domain)
  ④ 叙事: 价值 + 行动(引擎通用, 词来自 extract)
  ⑤ 五步门: evaluate→recommend→plan→approve→execute(执行=写该域的"连接"数据)
```

## 二、各 Tab 应用矩阵(机会 = "该连没连")
| Tab/图 | 节点 | 孤岛机会含义 | 潜在价值 |
|--------|------|-------------|---------|
| 🤖 智能体 | 52 agent | 无共享资源边的 agent | 协作/复用(已实现) |
| 🔀 蓝图关系 | 15 蓝图 | 无依赖边的蓝图 | 架构耦合该不该连 |
| 📏 规则图谱 | 56(规则×蓝图×agent) | 规则未映射到蓝图/agent | 规则约束是否覆盖所有域 |
| ⚙️ 机制图谱 | 协议/门/锁 | 机制未挂蓝图 | 机制-蓝图覆盖缺口 |
| 📚 知识图谱 | 211(论文/报告/蓝图) | 知识节点未溯源蓝图 | 知识未被蓝图引用 |
| 🖥 硬件载体 | 16(设备+蓝图) | 设备无承载蓝图 | 算力未被分配 |
| 🌍 跨节点资产 | 68(设备+蓝图+资产) | 资产与蓝图无归属 | 资产未入业务图 |

## 三、引擎 vs 各 Tab 特定逻辑
- **通用**: 孤岛计算、穷举、5特征打分、价值叙事、五步门状态机
- **各 Tab 提供**: 
  - node 描述文本(转语义特征) 
  - 域概念(蓝图 dim/规则域/资产 node…)
  - 边定义(关系/依赖/承载/归属)
  - 执行语义(确认连接后怎么写回/写哪)

## 四、实现形态
- 后端: /api/explore?graph=relations|rules|mech|knowledge|hardware|biz — 用统一引擎算各图机会
- 呈现: 各 Tab 图视图加「🧪机会」切换(类似智能体 lab), 或总览"机会发现"聚合页
- 工具: bb-explore.py(CLI, 可对任意图跑)

## 五、验收
| # | 标准 |
|---|------|
| A1 | 同一引擎对 ≥3 个 Tab 跑出候选(relations/rules/knowledge…) |
| A2 | 每个 Tab 的孤岛语义正确(用该域边定义) |
| A3 | 机会叙事含该域术语(非"智能体"措辞) |
| A4 | 结果可看(该 Tab 内或总览聚合) |
| A5 | 执行(确认)能写该域连接(至少一个域打通) |

## 六、风险/边界
- 各 Tab 边语义差异大 → "孤岛"判断需按域配置(不能全用资源共享)
- 部分图(关系/蓝图)本来就 0 孤岛(全连接) → 机会在"弱边/该加重连"
- 先做引擎 + 3 个试点(规则/知识/跨节点), 验证再铺开
