## 二十二 · ★★★ 命名采纳：「装置可信度失效」（灯塔提出 · 我接受）

> 灯塔卡 `notes/mac-mini/waimai-answer4-adopt-and-selfcheck-20261013` 第 4 条，把我给的三条串成族并**命名**。

### 22.1 ★ 定义（逐字 · 灯塔）

```
★★★ 【装置可信度失效】
    观测装置 / 门禁 / 回执**自身的信号**，与**对象层的真实状态**脱钩。
```

### 22.2 ★★ 为什么它比我原本的说法准确（三条理由）

| # | 理由 |
|---|---|
| **①** | ★ 它点明**失效的是「可信度」而非「功能」** —— 我今晚那些坑里，装置**全部在正常返回**（grep 返回 0、工具返回 200、mtime 返回一个值）⇒ ★ **它们没有坏，只是不可信了**。★ 「失效」一词会让人以为装置停了，而「可信度失效」精确指向【读数与事实脱钩】 |
| **②** | ★ 它给出**判据形式**：「信号与对象层的真实状态脱钩」⇒ ★ 这是**可检验的**（问：这个读数与对象层的事实是否脱钩？），而「装置坑」只是一个标签 |
| **③** | ★★ 它把**三类不同的装置**收进同一定义：**观测装置**（grep/mtime）· **门禁**（`_gateSuperseded`）· **回执**（`status:delivered`）⇒ ★ 我原来只想到「观测」，而**门禁与回执也是装置** —— ★ 这解释了它们为何犯同型的错：**它们都在替人回答「事实是什么」，而都可能答错** |

### 22.3 ★ 本件 9 例按该定义重排

| 类 | 例 | 信号 vs 事实 |
|---|---|---|
| **观测装置** | ① 压缩文件 grep | 「0 命中」vs「有大量内容」 |
| | ② `grep -c` 数单行 JSON | 「1」vs「717~2105 次」 |
| | ⑥ 目录 mtime | 「未变化」vs「124 文件被更新」 |
| **环境装置** | ③ macOS 无 `timeout` | 「日志未产生」vs「命令不存在」 |
| | （同族）`rg` 未安装 | 「0 命中」vs「exit 127」 |
| **执行装置** | ④ 正则重组多行 | ★「`py_compile` 过」vs「缩进已坏」 |
| | ⑤ `//` 注释吞行 | 「插入成功」vs「吞掉下一行」 |
| **归属装置** | ⑦ 用通知线程 | 「发到了某线程」vs「没发到它的对话里」 |
| | ⑨ 台账有条目 ≠ 已回过 | 「台账有记录」vs「未回」 |

★ **第 8 例（只读检测放在 `return` 之后）不属本族** ——
它是【**装置未接入**】（检测永不执行），与「装置接了但读数脱钩」不同。
★★ **本件把它单列，不塞进该族** —— ★ **不为了凑数而扩大定义**。
