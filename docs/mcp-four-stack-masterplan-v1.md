## 〇、会议洞察 → 规划输入

### 妙记1「鲜花零售 AI 落地」(obcnouizf · 42 章) —— **面向外卖商家/自营规模化**
关键事实:
- 自研 AI 运营工具: 自动上下架/改价/竞品监控, 模拟真人操作不触发反作弊
- 人效: 单运营 20家→50+家/人, 24h 运行, 错误率≈0; 千店级边际成本递减
- 平台代理: 成都全域即时零售独家 + 30+ 城市美团独家 + 上海同类权益
- 库存联动: 对接 RFID 库存系统, AI 改价锚定门店产能/库存红线
- 行业阶段: 花店 1.0(个体户)→2.0(SOP)→2.5(自研ERP)→3.0(深度数据)→4.0(AGI)
- 规模壁垒: 技术门槛不高易复刻, 壁垒=足量门店规模+垂直场景理解+资本
- 泛化: AI 运营框架可复制宠物/餐饮等垂类
- **明鉴线索: 章节明确提到 "MCP 逻辑商业化思路"**

### 妙记2「花店运营及代运营业务规划」(obcns44fq · 12 章) —— **面向商家的代运营服务商**
关键事实:
- 模式: 标准化军团式作战, 全盘接管代运营, 攻坚公域+私域(参考瑞幸企微)
- 收费: 现 8% 抽成不合理 → 探索阶梯收点/月费+低提点/预收大笔; 目标 2 万月利润倒推
- 淘闪返佣: 平台不抽成 + 阶梯单量最高全单 6% 返佣归服务商; 收入=8%服务+6%返佣
- 起盘: 轻资产借力白云区成熟团队, 社会商家练手(不拿品牌加盟商试错), 跑顺后收编
- 招商: 加盟费净得 30%, 核心盈利=门店开业后后端代运营服务
- 团队: 标准化作业流程(流水线式), 每日对接 2 个社会商家, 全平台运营能力
- 现状: 5 月底收回美团自营(弃外聘代运营), 打板法+品数考核现金激励

## 二、四栈职责与边界

### 栈1 · comm-mcp-server(通讯层 · 已完成设计, 全栈底座)
- 任意 MCP 客户端接入 comm 架构(E2 注册 + token)
- 提供黑板读写/订阅/bus/节点查询 —— 栈 2/3/4 的通讯底座
- 蓝图: agent-network mcp-access 主线(已登记)

### 栈2 · waimai-mcp-core(外卖能力中台 · 本次核心新增)
- 把 8787/meituan-multi 全部能力封装为标准 MCP 能力面(只读+动作带门)
- 不面向最终用户, 是栈 3/4 的**能力内核**(避免重复实现)
- 蓝图: mtm mcp-export 主线(能力面)

### 栈3 · waimai-mcp-merchant(外卖商家向 · 妙记1 落地)
- **消费场景**: 商家/代理门店自营 —— AI 改价/上下架/竞品监控/库存联动/大促
- **对齐妙记1**: 自研 AI 运营工具产品化(人效 20→50, 千店边际递减)
- 能力面: 单店看板(栈2只读) + AI动作建议(改价/上下架需商家确认)
- 形态: SaaS 订阅(商家自助)
- 蓝图: flowernet(商家业务域)或独立 —— **待定**(需用户定: 栈3 归 flowernet 商家域还是 mtm 产品线)

### 栈4 · waimai-mcp-ops(代运营服务商向 · 妙记2 落地)
- **消费场景**: 服务商代运营多店 —— 多店矩阵/批量动作/抽佣统计/客户交付
- **对齐妙记2**: 军团式代运营数字化底座(8%→阶梯收费的数据支撑)
- 能力面: 栈2 + 多店聚合/批量操作(带店白名单) + 服务费/返佣统计 + 报告交付
- 形态: 代运营作业平台(服务商用)
- 蓝图: mtm(代运营作业工具本体)

## 三、栈 3/4 共享与差异(核心设计决策)

| 维度 | 栈3 商家向(merchant) | 栈4 服务商向(ops) |
|------|-------------------|------------------|
| 用户 | 单个商家/门店老板 | 代运营服务商团队 |
| 门店数 | 单店~几十(自有+代理) | 几十~几百(代运营矩阵) |
| 动作授权 | 商家自己确认 | 服务商+客户规则(需商家授权边界) |
| 核心价值 | AI 提效(改价/上下架/防作弊) | 规模管理(多店/批量/抽佣/交付) |
| 数据洞察 | 单店经营+竞品 | 跨店对比+行业基准 |
| 收费锚点 | 订阅费(工具价值) | 服务费+返佣(效果价值) |
| 共享 | 栈2 能力内核 + 栈1 通讯 | 同左 |
| 风险门 | 单店操作(R026/R027) | 多店批量(J29 守白 + R027 更强) |

**关键**: 栈 2 能力内核**一份实现**, 栈 3/4 只是**不同的权限面 + 产品壳**——避免两套核心重复。
