# 角色命名标准 v1.0（设备名 + 角色名）

> 2026-08-29 ｜ 用户确立：避免同角色多设备同时出现的混乱
> v1.1：加智能体自命名（有温度）｜ 关联规则账本 R009

---

## 一、原则

1. **设备名 + 角色名**：每个智能体身份 = `<设备>-<角色>`（如 `mac-mini-协调者`、`i9-算力提供`）
2. **会话代码隐藏**：`session-xxx` 是内部标识，**不用于用户可见命名**（用户记不住）——隐藏到思维链/内部字段
3. **角色唯一**：同角色多设备时，用设备前缀区分（`mbp-运营` vs `mac-mini-运营`），避免混乱
4. **人类可读 + 有温度**：命名面向用户（自命名+中文角色），智能体有自己的「名字」而非冷冰冰职能
5. **自命名自主**：智能体可自选自命名（体现性格/定位），总线登记；同设备内自命名唯一

## 二、命名格式（v1.1：加智能体自命名）

```
规范：<智能体自命名>-<设备>-<角色>
自命名: 有温度的代号（智能体自己选，如「星桥/老登/阿花」）——让智能体有「名字」而非冷冰冰职能
设备: mac-mini / mbp / i9 / (新增节点)
角色: 中文职能名（协调者/运营/学习/审查/摄取/供应链/媒体/...）

示例:
  星桥-mac-mini-协调者     (中枢 fa1f9150)
  老登-mac-mini-运营       (运营 aa528267，已有自命名「老登」)
  阿花-mac-mini-资源管理   (HR 2a15e6b1)
  桥灵-mbp-桥接           (MBP node-bridge)
  算盘-i9-算力提供         (i9 GPU/训练)
```

## 三、字段结构（身份登记）

```json
{
  "agentId": "session-xxx",       // 内部标识（隐藏，用户不可见）
  "displayName": "星桥-mac-mini-协调者", // 用户可见名（自命名+设备+角色）
  "nickname": "星桥",              // 自命名（有温度，智能体自己选）
  "device": "mac-mini",            // 设备
  "role": "协调者",                // 角色
  "domain": "治理/协作",           // 领域
  "abilities": [...],              // 能力
  "resources": [...]               // 资源
}
```

## 四、实施

- agent_profile 的 role 字段改为 `displayName` 规范（设备-角色）
- 会话代码 session-xxx 保留在 agentId（内部），不暴露给用户
- 跨设备同名角色：设备前缀天然区分
