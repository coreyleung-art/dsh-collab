# Flowernet 分档里程碑评估坐标 v1

> 明鉴 · 2026-09-09 · 把里程碑拆成"可量化的评估坐标"——每档关键结果拆成多维度指标+三档阈值(达标/部分/未达)
> 用途: 建立"做到/部分/没做到"的量化标尺, 取代笼统的"动销1200+/打平36万"
> 原则: 每个坐标轴都有明确阈值; 部分达标=分级预案(砍非核心保核心); 未达=重估/收缩
> 维度: 现金/规模/增长/质量/平台/数据 六轴(每档都铺)

---

## 〇、评估坐标总则
**每个里程碑不再是一个数，而是一组"坐标轴"，每条轴有达标/部分/未达三档阈值**。用六轴评：
```
现金轴(毛利/打平) · 规模轴(在管商家池/城市) · 增长轴(增速/复购)
质量轴(留存/续约/人效) · 平台轴(帮平台增量/战绩) · 数据轴(端口/回流)
```
> 「在管商家池」= 成都淘闪交我方(城市合伙人/服务商)管理的鲜花商家数, 原始口径约750家(紫阳: "8000即时零售门店里750家鲜花店"; ⚠️内部口径无公开信源); **非"有订单才算"的有效动销**——有效动销需另定门槛, 不作为评估坐标。
> **阈值基准(2026-09-10指标基准调研, 非拍脑袋)**: 续约率40-70%(中枢50-60%, 抽佣绑定65-75%); 人效纯人工15-35店/人(鲜花重交付10-20); GMV单城爬坡+5-15%/月; 新签扩张期月净增=存量4-8%; 订阅按效果/抽佣+年15-30%; 端口授权无公开基(机制OAuth前置, 抽佣~80-95%⚠️)。全部详见 research/flower-ops-metrics-benchmark-2026。
> 部分达标→砍非核心(数据端口/区仓)保核心(代运营/商家信任); 未达→重估模型/收缩。

## 档1 · 单城（0-6月）评估坐标

| 轴 | 指标 | ✅达标 | ⚠️部分 | ❌未达 |
|---|---|---|---|---|
| 现金 | 代运营毛利 | ≥36万/月(打平) | 15-36万 | <15万 |
| 规模 | 在管鲜花商家池 | ≥900(扩张) | 750-900 | <750 |
| 增长 | GMV环比(爬坡) | +5~15%/月 | 0~5% | 持平/降 |
| 质量 | 商家续约率(按效果绑定) | 65-75% | 50-65% | <50% |
| 质量 | 人效(鲜花重交付) | 20-35店/人 | 15-20 | <15 |
| 平台 | 帮淘闪增量 | 首场售罄+新注册≥N | 部分售罄 | 未售罄 |
| 数据 | 端口P1白名单 | 50店>80%授权(抽佣绑定) | 50-80% | <50% |

> **阈值说明(基于2026-09-10指标基准调研, 非拍脑袋)**: ①续约率行业中枢50-60%, 按效果/抽佣绑定可达65-75%, >80%需极强绑定(报告校准); ②人效纯人工15-35店/人, 鲜花重交付10-20店/人, 50店/人需AI工具化(报告校准); ③GMV单城爬坡+5-15%/月, >10%常态偏高(报告校准); ④端口授权无公开基, 机制上OAuth前置, 抽佣模式~80-95%(报告⚠️)。"在管商家池"750起点=紫阳口径(内部无公开)。

**档1判定**：现金+规模两轴达标 → 进档2；仅平台轴达标 → 优先保代运营+IP，砍端口/区仓；现金轴未达 → 动用缓冲250万重估。

## 四、评估坐标使用法（每档执行时）

1. **每月对六轴打分** —— 现金/规模/增长/质量/平台/数据，每条轴判 达标/部分/未达
2. **看是"核心轴"还是"边缘轴"** —— 核心轴(现金/规模/质量)不达标→警讯; 边缘轴(数据/增长)部分达标→可砍
3. **分级触发动作** —— 部分达标→砍非核心保核心; 未达→重估/收缩, 不硬撑
4. **对照资本计划** —— 达标→继续自转/融; 部分→调策; 未达→不动融资

### 精简版坐标（速查）
```
达标 = 现金+规模+质量 三核心轴达标 → 进下一档 / 融
部分 = 核心轴1-2达标, 边缘轴缺 → 砍边缘保核心, 观察
未达 = 现金轴<底线 → 收缩/缓冲/重估, 不融
```
