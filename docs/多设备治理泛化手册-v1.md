# CLD/DSH 多设备治理泛化手册 v1

> mbp-ops · 2026-09-05 · 目标：把 mac-mini 上成熟的治理体系（版本管理/Lean 门/实验/考古/观察）泛化到 MBP + Windows
> 原则：**先手册后动作**——本手册是设计图，执行按手册分阶段推进，每阶段独立验证可回滚
> 配套：tools-registry.md（版本台账）· device-registry.md（设备矩阵）· 规则全集-v2（纪律）

|---|---|---|---|---|---|

## 二、平台差异盘点（泛化障碍清单）

### 2.1 guard 工具硬编码（需路径抽象）
| 工具 | mac 硬编码数 | 硬编码内容 | 泛化方案 |
|---|---|---|---|
| guard-gate | 5 | `/Applications/CLD.app/...`、`~/.dsh/profiles/web/...`、`/opt/homebrew` | 引入 `DSH_PATHS` 配置（每机一份 paths.json）|
| guard-cld-release | 4 | CLD.app Resources 路径、backups 路径 | 同上 + Windows 版 CLD 路径未知先行标记 |
| guard-doc-check | 0 | — | 天然跨平台 ✅ |
| guard-risk | 0 | — | 天然跨平台 ✅ |
| labforge | 0-1 | SSH 目标 host 可配（LABFORGE_MACMINI env）| 已支持 env 覆盖 ✅ |

### 2.2 CLD 本体跨平台
- **MBP**：macOS 同构 → 同步 v0.6.0 asar/runtime/补丁/配置即可（同 OS 直接 cp + 重签）
- **Windows**：CLD（Electron 壳 + dsh runtime）Windows 版**可用性待官方确认**——先行标记为评估项；dsh runtime 本身 Node 跨平台，但 CLD 壳分发形态未知

### 2.3 主动工作流（调度器）
| mac-mini | MBP | Windows |
|---|---|---|
| 后台 job（本会话托管）| 后台 job（MBP 会话）| Windows 计划任务 / NSSM / WSL cron |
| archaeology-loop 6h | 同脚本（改 LABFORGE_MACMINI→本机）| Rust 侧 health/load-gate 已有 |

### 2.4 命令差异
| 操作 | macOS | Windows |
|---|---|---|
| 进程查询 | ps/pgrep | tasklist / powershell Get-Process |
| 优雅重启 | osascript quit + open | taskkill / 服务重启 |
| 崩溃记录 | ~/Library/Logs/DiagnosticReports/*.ips | 事件查看器 |
| 路径 | /Applications/... | %ProgramFiles%\... |

## 三、分阶段执行计划

### 阶段 A · MBP 热备化（同 OS，优先级最高）
1. **备份**：guard backup MBP 的 CLD 封装全资产（app.asar/icon/配置）
2. **同步 v0.6.0**：mac-mini → MBP（asar + runtime 补丁文件 + cordis.patch + guard 插件 + my-brand）
3. **验证**：MBP CLD 重启 → C1-C7 + guard 工具注册确认
4. **登记**：MBP 侧 cld-release.json tag v0.6.0（fingerprint 独立）
5. **热备验证**：mac-mini 故障时 MBP 可接管（会话数据同步策略另议）

### 阶段 B · Windows Rust 治理面（无 CLD 依赖）
1. **dsh-tools win-x64** 部署到 i9（已有 GitHub Release 资产）
2. 验证：version/health/load-gate 等治理子命令在 Windows 工作
3. **guard 路径抽象版**：guard-gate/cld-release 加 DSH_PATHS 配置 → Windows 路径可用
4. 登记：i9 加入 tools-registry（Windows 列）

### 阶段 C · Windows CLD 本体（评估项，依赖官方）
1. 查官方：CLD/DSH Windows 分发可用性
2. 若可用 → 重复阶段 A 流程（Windows 路径适配）
3. 若不可用 → i9 保持算力节点（Docker/WSL2 跑 dsh headless 可选）

## 四、统一配置方案（DSH_PATHS）

每机一份 `~/.dsh/paths.json`（或环境变量），guard 工具读取：
```json
{
  "cld_resources": "/Applications/CLD.app/Contents/Resources",  // mac
  "dsh_runtime": ".../dsh-runtime/runtime",
  "profiles": "~/.dsh/profiles",
  "backups": "~/dsh-collab/guard/backups",
  "scheduler": "launchd"  // or "windows-task" / "background-job"
}
```
Windows 版对应路径自动切换（guard-gate 硬编码 5 处 → 读此配置）。

## 五、验收标准（每阶段）
- **A**: MBP `guard-cld-release verify` = v0.6.0 一致 + C1-C7 过 + 热备演练
- **B**: i9 `dsh-tools version/health` 返回正常 + guard-gate Windows 路径判定正确
- **C**: 官方 Windows 支持确认 + 阶段 A 流程复用

## 六、风险与边界
| 风险 | 等级 | 缓解 |
|---|---|---|
| MBP CLD 同步破坏其现有运行 | 中 | 先备份 + 同步后验证可回滚（guard backup）|
| Windows CLD 不可用 | 中 | 阶段 C 先行评估，不强行铺 |
| guard 路径抽象改坏 mac-mini | 低 | paths.json 默认值保持 mac 现状，回归验证 |
| MBP 会话数据与 mac-mini 不同 | 中 | 热备定位为"进程/工具热备"，数据同步策略单独立项 |
