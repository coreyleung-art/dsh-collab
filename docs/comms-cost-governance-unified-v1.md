## 一、通讯成本治理总纲

### 核心命题
消息的每一步都有 token 成本(发送/接收/上下文注入/群聊放大 20.8x/无效投递)。
治理目标 = 每条消息「必要 + 可达 + 恰好够用」。

### 三大浪费源与对策
| 浪费源 | 实证 | 对策 |
|---|---|---|
| 对空气说话(目标离线/未知) | queued 635 + 无效目标 1044 ≈ 6.5% | 探照灯握手(§二) |
| 群聊放大 | 20.8x(消息×参与者) | 群聊约束 G1-G4(§三) |
| 通道错配 | 内容走错通道/重复投递 | 通道纪律(§四) |

## 二、探照灯握手(送达前置确认)

### 三灯语义(沿用红绿灯逻辑)
- 🟢 绿灯(目标在线可收) → 直接传(agent_send/S3 信封)
- 🟡 黄灯(目标离线) → 不盲发, 落黑板 notes/<目标>/ 自取(不塞队列)
- 🔴 红灯(忙/锁/不可达) → 不硬发, 等/替代通道

### 5 条防对空气纪律
1. 发送前看 agent_send 返回(targetLive/queued)或 E2 发现层查在线
2. 黄灯转黑板(离线不积压消息队列——防上线一次性轰炸)
3. 红灯不硬发(记录待办, 不重复)
4. 风暴熔断(同目标 10 分钟 >5 次同内容 → 转黑板/死信)
5. 积压回收(离线 >7 天队列清理)

### S3 送达保证(永续通讯既有, 衔接)
- 重试×2 + 死信告警(data/ops/deadletter/)
- 服务器 TTL 自动 failed(无无限滞留)
- 角色映射唤醒(S1: to=角色名→会话 id 精确注入)

## 三、群聊约束(G1-G4 + C1-C6)

### 分类
G1 全员广播(制度/重启/事件, 月≤5, 黑板指引) | G2 任务协作(≤5人, 完成归档) | G3 评审讨论(≤8人, 48h 散) | G4 状态同步(≤6人, 可走黑板)

### 硬约束
C1 规模闸(>5 人须论证) C2 用途闸(仅四类) C3 黑板闸(>50 字走黑板) C4 生命周期闸(禁永久群) C5 放大预算(消息×N 估算) C6 存量清理

### 决策树
无互见→点对点 | 长协→新会话 | 临时讨论→G3 | 制度→G1(工具: group-gate.py)

## 四、通道纪律(选择正确通道)

| 通道 | 用途 | 成本 | 何时用 |
|---|---|---|---|
| 点对点 agent_send | 定向任务/通知 | 线性 | B/C 无需互见 |
| 黑板 notes/<域>/ | STATUS/ACK/长内容 | 低(不唤醒) | 离线目标/状态/登记 |
| 群聊 thread | 多方互见讨论 | 放大(控规模) | G1-G4 限定 |
| 会话 | 长协共同产出 | 长驻 | 用完归档 |
| 推送 SSE/信封 | 实时唤醒 | 免轮询 | S3 送达 |

### 推送规则(永续通讯)
- 服务器 SSE 推送优先(bus/events), 守护免轮询
- 信封链路(S2)断网仍通(公网兜底)
- 部署门 G-D1/G-D2/G-D3(漏变量 Lean4 门)
