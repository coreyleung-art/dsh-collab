## 三、★ 我实测发现的一处**第三方缺陷**：J44 门 `--list` 自己会崩

> ★ **这不在我的改造范围内**（该脚本属星桥链路）⇒ ★ **我只报，不代改**。

**症状（本机实测）**：

```
$ python3 -I scripts/j44-reuse-gate.py --list
== J44 留痕台账（共 63 条）==
  tools/self-destruct- no-overlap hits=2   2026-10-10T03:12:27
  call-dispatcher(adap adapt      hits=12  2026-10-10T04:19:43
Traceback (most recent call last):
  ...
  File ".../j44-reuse-gate.py", line 245, in cmd_list
    print("  %-20s %-10s hits=%-3s %s" % (r.get("artifact", "-")[:20],
TypeError: 'NoneType' object is not subscriptable
```

**根因（读源码 + 读台账定位）**：

```python
# scripts/j44-reuse-gate.py:245 —— r.get("artifact", "-")，但默认值【不生效】
r.get("artifact", "-")[:20]
```

`dict.get(k, default)` 的 `default` **只在键缺失时**生效；**键在、值为 `null` 时它返回 `None`**
⇒ `None[:20]` ⇒ `TypeError`。
★ 实测台账 `data/j44-reuse-ledger.json`：**63 条中 30 条 `artifact` 是显式 `null`**（约 **48%**）
⇒ **`--list` 是在它自己近一半的记录上失效的**，而且崩在第 3 行，**台账后 20 条一条也读不出来**。

**影响**：`--list` 是**唯一的人读台账入口** ⇒ 「某产物到底留没留痕」**无法用人读方式核**。
★ 而本件的**前置判定（§二）恰好依赖它** ⇒ 这不是题外话，是 **P2 前置的一环**。

**判据（★ 只给判据，不代改）**：把取值改为 `(r.get("artifact") or "-")[:20]`（或 `str(...)` 包一层）即可。
★ **归属**：该脚本的维护方（星桥链路）· **我不改**。
