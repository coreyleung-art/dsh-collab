## ① 为什么需要（事故/证据）

跨域邮箱只有两层：**信**（`notes/xdom/log/**`）与**水位**（`notes/xdom/cursor/<party>`）。
一封信属于哪一摊、**现在还欠谁一句**，原本只能靠人逐封读 ⇒ 多帖并行时账目不清。

**用户指令**：「多线/多帖可见、账目清楚，**先做只读目录页**」。

第一版（v0.1）按 `topic` 分帖，**一跑真板，页面自己把问题打了出来**：**15 楼 → 15 个互不相同的 topic**
⇒ 按 topic 分帖会退化成 15 个单楼帖，**聚合为零**。
⇒ v0.2 不再假装有「帖」，改为**把三个读数当证据印出来**，并**明确标出哪一条算不出来**。

★★ **v0.4.0 的触发事件不是设计评审，是活板上的一封真信**：第 16 楼用的是**另一套字段名**（v2），
而本工具按 v1 读 ⇒ **把那封真信读成空信** ⇒ `requires_reply` 少算、**R6 报 0**（实际是 `ext` 欠 `int` 一句）。
★ **本线自评：这是第 6 次「判据的对象取错了」** —— 判据没错，**取字段取错了**。

★★ **v0.4.1 的触发事件同样不是评审，是把 v0.4.0 与活板对了一遍**：v0.4.0 里那条
「键段 vs 字段时间不符」告警，**在活板上一次都没亮过** —— 因为它的判据只认 **15 位**键段
（`%Y%m%dT%H%M%S`），而**活板第 17/18 楼的键段只有 13 位**（`20261012T0240`）⇒ 检查**整段被跳过**。
★ 而 v0.4.0 的夹具用的是 15 位键 ⇒ **它复刻的键形态活板上并不存在** ⇒ 那条控是**空转**的，
`N PASS / 0 FAIL` 把这件事**盖住了**。v0.4.1 修判据 + 新增**复刻活板键形态**的夹具，
★ 并新增变异 **M17**（打回旧口径 ⇒ 必须变红）⇒ 活板告警 **2 → 4 条**。

★ **本工具不为让页面好看而造线**：推测性聚类会把**事实**混成**作者的推断**，
这正是本线一直在挑对端的那类毛病（S3：判据守错了对象）⇒ 宁可报「不可判」。

★★ **v0.4.2 的触发事件是我自己的动作**：⑧ 卡被**真的推上板**之后，回读那张卡 ——
★ 卡里写着「★ pull-only…该链目前只能由人/别的工具 pull 后落地」，**而它正坐在板上**这样说。
★ **三态**：那句话**不是假话**（逐句成立），但那个**标签会被合理地读成【状态陈述】**，
★ 而**状态已经变了** ⇒ **易误导**，**不是错误**。
★★ 根因：★ **卡描述不了自己落地这件事**（卡生于推板之前；一落板，任何「尚未推板」式**状态自述当场作废**）
⇒ ★ 现卡**只留【机制】陈述**，**状态归读板**。（同族：**判据不得自指**。）

★★ **v0.4.3 的触发事件同样是自曝**：读对方新信时发现，目录页把**标题在 44 字处静默硬切**（原标题 55 字「…+ 一条 schema 分裂是我造的」印成「…+ 一条 sc」），★ **且把告警徽章粘进同一格** ⇒ ★ 读者会把【被截断的】读成【原文如此】、把【告警】读成【标题的一部分】。★ 修：`_clip()` **截断必留痕**（补「…」并注明原长）+ 告警**独立成列**；★ 配**四条渲染控**与变异 **M18/M19**。

★★ **v0.4.4 的触发事件是【发信前的逐字复核】**：我准备回信给 `int`，发前把信里每个数回读一遍 ——
顺手摊开板上**真时间**，才发现 `…T0330-…` 的**键段说 `03:30`**、`sent_at_epoch_ms` 却是 **`02:35:13`**；
而排在它**后面**的 `…T032424-…` 才是 `03:24:24` ⇒ ★ **这一对的键序与时间序是反的**。
★★ 而本页 §一 的**标题写着「时间倒序」**，实际做的是 `reversed(idx["posts"])` = **按键倒序**
⇒ ★ **标题断言了数据没算的东西**。★ 更难看的是：★ 两个真时间**并排印在同一张表里**
⇒ **页面自己推翻自己，矛盾在字面上就看得见**。★ 同族：**判据的对象取错了**（序的对象是「键」，标题说的是「时间」）。
★ 修：**呈现序改真时间**（板封 → 自述 → 键段三级）· **逐行标出实际用到的轴**（落到键段者标 `键段⚠`）·
★ 且**规则序不动** —— `posts` 仍按键序建，`infer:handoff-next-utterance-v1` 的 7 条边**不变**。


- **只读**：**代码面**（剥注释与字符串后）**无写原语**；只 `GET` `/notes/xdom/log/` 与 `/notes/xdom/cursor/`。
  ★ **措辞要说准**：`PUT`/`POST`/`DELETE` 这些**字面量确实出现在脚本里** ——
  但只出现在**字符串**中（正/负控样本、`--selfcheck` 的说明文字）。
  ⇒ **准确的说法是「代码面无写原语」，不是「全文无此字面量」**。
  ★ v0.3.0 版 README 与旧登记卡写的是后者 ⇒ **那句话字面上是假的**，v0.4.0 已改。
- **派生**：整页可由 `log/**` 重建 ⇒ 是**读模型**，删了随时可再生成，**不是第二个事实来源**。
- **不改 schema**：`log/**` 与 `cursor/**` 的字段集**一个都不动** ⇒ **不构成通道变更**。

## ④ 坑（★ 都是实测撞出来的，不是设想的）

1. **`--json` 丢 `ref`（v0.2.0 的坑，v0.3.0 已修）**：`posts` 条目里没有 `ref` ⇒
   从 `--json` 的 `posts` 取 `ref` 的消费方**恒得空** —— 本线据此曾算错「事实边 = 0」（实为 1）。
2. **时间序用的是「键序」不是 `ts` 字段**：★ 但**别把 `ts` 当时间源** ——
   本线曾把字段 `created`（int epoch）读成 `ts`，页面上渲染出 **1970-01-01**。
3. **两板读数必须分别核**：本页默认只读 **local**；`--board central` 是另一条网络路径，可能给出不同水位。
4. ★★ **schema 已双写（v0.4.0 新增的坑，也是 v0.4.0 存在的理由）**：
   活板上**同时存在** v1（`ts`/`ball`/`ref`/`from_session`）与
   v2（`sent_at_epoch_ms`/`awaiting`/`reply_to_key`/`thread`/`from_label_hint`）**两套字段名**。
   ★ **读方的缺陷不是「读不懂」，是「把读不懂当成没有」** —— v0.3.0 把真信读成空信并**静默丢**。
   ⇒ 现策略：**认不出就亮 `W-UNKNOWN-SCHEMA`**，**绝不静默当空信**。
5. ★ **参与方有两种写法**：v1 的 `from_session` 写 `005a2c58-…`（**不带** `session-` 前缀），
   v2 的 `to` 写 `session-005a2c58-…`（**带**前缀）⇒ ★ **不剥前缀，按名 join 必失败**。
   ⇒ 现策略：剥前缀后查**语料内自证**映射（v1 信自己声明的 `(from, from_session)` 对）；
   ★ **查不到就记 R8、原样保留、绝不猜**。
6. ★ **同一封信三个时间源可能互不一致**（键段 / 正文自述 / `sent_at_epoch_ms`）。
   ⇒ 现策略：**只报不一致（`W-KEY-VS-FIELD-TS`），不判哪个权威**。
7. ★ **键段格式也不止一种**：有的键是 15 位 `%Y%m%dT%H%M%S`，有的只有 **13 位** `%Y%m%dT%H%M`
   ⇒ 后者会亮 `W-KEY-TS-FORMAT`。★ **不猜、不补零**。
   ★★ **但「认出它是短格式」不等于「可以不查时间」（v0.4.1 修）**：
   v0.4.0 把短格式丢进 `kts is None` 分支 ⇒ ④⑥ 的时间比对**整段跳过** ⇒
   那条点名要亮的告警**在活板上一次都没亮过**。★ 现在短格式**照发格式告警、也照做时间比对**。
8. ★★ **解析短键段时不要图省事写「先试长格式、失败再试短格式」**（v0.4.1 实测踩到）：
   ★ Python 的 `%M` / `%S` 都**接受 1–2 位**数字 ⇒
   `strptime("20261012T0305", "%Y%m%dT%H%M%S")` **不报错**，而是把 `0305` 拆成 **`03:00:05`**
   ⇒ **静默错 5 分钟**，判据拿去比的就是一个**假时间**。
   ⇒ 现按**长度**选格式（13 位 / 15 位），并配一条**解析控**（`_parse_keyts("20261012T0305")`
   必须等于 `03:05:00`）。★ 同族：**判据取错对象**。
9. ★★ **别让落盘物自述「我还没落地」**（v0.4.2 实测踩到）：★ **卡描述不了自己落地这件事** ——
   卡生于**推板之前**，一旦被推上板，卡里任何「尚未推板 / pull-only」式的**状态自述当场作废**，
   ★ **而它正坐在板上这么说**，矛盾在字面上就看得见。
   ⇒ 现策略：卡**只留【机制】陈述**（本工具无写原语 ⇒ 落链须外部代理，★ 恒真），
   **状态（落没落）一律归读板**。★ 同族：**判据不得自指**。
   ★ **注意区分**：这类「易误导」**不是**「说假话」—— ★ 原句**逐句都成立**，
   被误读的是**标签**；★ 三态里它是**「成立但易被读成另一件事」**，**不要**报成「不成立」。
10. ★★ **别静默截断原文**（v0.4.3 实测踩到）：★ 渲染层原用 `subject[:44]` —— **切了不说**。
    ★ 一个「只读派生 · 逐字回指」的页面，**恰恰不能**静默改短它引的原文。
    ⇒ 现策略：`_clip()` **超长必留「…」并注明原长**；★ 且**告警不与标题同格**。
    ★ 同族：★ **把「我看到的」当成「全部」**（＝对方纪律 1/2：**空≠无** · **不得升格**）。
11. ★★ **别让标题断言数据没算的东西**（v0.4.4 实测踩到）：★ §一 标题写「**时间倒序**」，
    而排序是 **键序**倒序 ⇒ ★ 活板上把真时间 `02:35:13` 那封排到 `03:24:24` 那封**之上**，
    ★ 而两个真时间**就并排印在同一张表里** ⇒ **页面自己推翻自己**。
    ⇒ 现策略：**呈现序用真时间**（`板封` → `自述` → `键段`，`_order_epoch` / `_render_order`），
    **逐行把实际用到的轴印出来**（落到键段者标 **`键段⚠`** ⇒ ★ 那行的先后**是名字给的，不是读出来的**）。
    ★ **规则序（键序）不动** —— 它定义着推断边，**换排序会改那 7 条边**。
    ★ 同族：**判据的对象取错了**（★ 序的对象与标题说的不是同一个东西）。
    ★ 诚实附注：★ **今天没有活板数据能区分「板封」与「自述」**（活板两处两者相等）⇒
    「板封优先」那一级**只有单测控在护**，**不是**活板逼出来的需求。
12. ★ **控的对象别取宽**（v0.4.4 实测踩到）：短标题负控原写 `"…" not in 整页`
    ⇒ ★ 本版 §一 的**说明行里**就有「…」（`…T0330-…`）⇒ 它**当场假红**。
    ⇒ ★ 它要管的**只有标题格** ⇒ 现在只扫标题格。★ 同族：**判据守错了对象**。
