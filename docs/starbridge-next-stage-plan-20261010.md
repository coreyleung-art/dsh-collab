## 二、三个候选方案

**为什么是它**：锚点 §14 的执行序把 Wave S 排在 Wave 0 之前，而它 `blocked` 的原因**不是缺授权，是缺建成证据** —— 那是可以自己做的。且本阶段的两项产出（信息包实例、审查委托）**已分别是 S2/S3 的实际运行**，衔接自然。

| 子项 | 可交付 | DoD（含负控） | 需批？ |
|---|---|---|---|
| **S5** G-CR 门校验脚本 | 一个可跑的校验器，逐条覆盖 G-CR1–G-CR17 | 正向：17 条各有可跑校验；**负控**：造「遮蔽目录」「根级 required」「未重签 dylib」⇒ **必须红**；边界：干净仓库应全绿 | 否 |
| **S2** 信息包模板 | 从本阶段实例抽出模板 + 自检（缺项即拒） | 正向：14 项齐时通过；**负控**：删任一项 ⇒ 必须报缺哪项 | 否 |
| **S4** 官方校对门 | 把 `guard_doc_check` 封装为「涉 dsh 设计项必须有条款引用」的准入 | 正向：有引用则过；**负控**：无引用 ⇒ 拒 | 否 |
| **S1** 沙箱模拟框架 | 按产物类型（插件/脚本/配置/数据/判据工具）的隔离复跑骨架 | 正向：五类各跑通一例；**负控**：断言「未写生产路径」，故意写 ⇒ **必须红** | 否 |
