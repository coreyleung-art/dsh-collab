> **提出**：用户 2026-10-12「帮我规划优化手机侧的交互体验」
> **起草**：明鉴 v3（SystemGraph 主源架构师）· `session-a190c54c-ca73-4845-9a65-9dc002d45044` · mac-mini
> **性质**：规划 + 可测判据。**不含已裁定的施工授权**；实施按 R001 取锁、写前备份。
> **证据基础**：★ **实渲染**（iPhone 16 Pro 视口 390×844 @2x，Chrome headless 逐页截图）+ 静态量化 + 手机实况截图（`devicectl device capture screenshot`）

---

## §0 一句话

**这个页面从来没有为手机做过适配** —— 有 `viewport` meta，**但零 `@media`、零触摸事件、零安全区**；每页只是**靠 flex/grid 碰巧换行**，所以「总览」好看、「图谱」灾难。

---

## §1 实测现状（证据，非印象）

### 1.1 移动端设施：全零

| 项 | 命中数 | 含义 |
|---|---|---|
| `@media` 媒体查询 | **0** | ★ **无任何响应式断点** |
| `touchstart`/`touchend`/`touchmove`/`pointerdown` | **0** | ★ 无触摸事件处理 |
| `touch-action` / `user-select` / `overscroll-behavior` / `-webkit-overflow-scrolling` | **0** | 无移动端滚动与手势调优 |
| `viewport-fit` / `env(safe-area-*)` | **0** | ★ **无安全区**（刘海/底部横条） |
| `viewport` meta | 有（`width=device-width,initial-scale=1.0`） | 只是「有」，没配套 |

### 1.2 必然溢出的固定宽度

`width:400px` · `width:420px` · `width:440px` · **`width:620px`**（一处 `position:fixed` 浮层还带 `min-width:380px`）
⇒ 在 390px 视口上**必然溢出**；而 `max-width` 有 `640/860/1500px`（按桌面设计）。

### 1.3 逐页实渲染结论（iPhone 视口）

| 页 | 观感 | 具体问题（截图实证） |
|---|---|---|
| **总览 `#dash`** | ★ **最好** | 4 个状态卡一行可读；导航网格 2 列正常；★ 底部状态条 `● 在线 更…` 被裁 |
| **关系图谱 `#relations`** | ★★ **最差** | 右侧节点被切（`N-` 断在边缘）；提示行 `…agent-network→memory-…` 溢出；子tab `规则图谱` 被切；画布吃掉 500/844 px |
| **体系 `#philosophy`** | 待细看 | 图片体积最大（582 KB）⇒ 内容最重 |

### 1.4 ★ 提示语是**桌面措辞**

页面上写着：**「拖拽 · 滚轮缩放 · hover 高亮 · 点击进详情」**

★★ **手机没有滚轮、没有 hover。** 这不是文案问题 —— `hover&&...` 的逻辑有**十几处**，**这些交互在手机上根本触发不了**。

## §3 优化方案（五期，每期可独立验收）

### P1 · 基础适配（**收益最大、风险最低，应先做**）
- 新增 `@media (max-width: 768px)` 与 `(max-width: 430px)` 两档断点
- `viewport-fit=cover` + 四边 `env(safe-area-inset-*)` 内边距
- 四处固定宽 → `min(<N>px, calc(100vw - 32px))`
- **全局兜底**：`* { max-width: 100% }` + `html,body { overflow-x: hidden }`（★ 但**不是**用 `hidden` 掩盖问题，须**同时**修根因）
- 验收：**每页 `documentElement.scrollWidth <= innerWidth`**

### P2 · 交互从 hover 迁到 tap（**功能补全，不是美化**）
- 所有 `hover 看 X` 增补 **tap 等价**（点击展开 / 长按看详情）
- 提示语改写：**滚轮缩放 → 双指缩放**；**hover 高亮 → 轻点选中**
- 引入 `pointerdown` 事件（统一鼠标/触摸），替换纯 `mouseover/mouseenter`
- ★ 判据：**页面上不再出现「hover / 滚轮 / 右键」字样**（可机械扫描）

### P3 · 图谱页专门重建（最差的一页）
- 画布：宽度 `100%`；高度由视口计算（`calc(100vh - 头部 - tab栏 - 底部)`），**不写死 500px**
- 节点标签：手机上**只画 `short`**；**轻点节点 → 底部抽屉弹详情**（替代 hover 弹层）
- ★★ **新增「列表模式」**：小屏上图谱本质难用 ⇒ 提供 **关系列表（父→子 + 类型）** 视图，一键切换
- 验收：画布无横向溢出；任一节点可**只靠轻点**看到完整信息

### P4 · 移动专属易用性
- **下拉刷新**（`overscroll-behavior-y` + 手势）
- **返回手势 / hash 前进后退**（页面已支持 `#hash`，补 history 语义）
- 触摸目标 **≥ 44×44 px**
- 首屏**骨架屏**（避免白屏等 200 KB）
- 子tab 行加**可滚动提示**（渐变遮罩或箭头），或改成**两行自动换行**
- ★ 「**数据截至时间**」按我已裁的方案显示（每件 mtime + 页面刷新时间双戳）

### P5 · 蜂窝网络优化
- 大载荷**按需/分页**（`cap-perm` 202 KB、`biz-assets` 171 KB）
- ★ **复用 A 组 SSE**：页面订阅模型版本号，**变了才重取**（A 组已给版本号）
- 离线态 UI：明确显示「**缓存数据 · 截至 xx:xx**」（`__dataState.mode` 已有，补 UI）

## §4 验收判据（★ 全部可机械测）

| # | 判据 | 测法 |
|---|---|---|
| **A1** | 每页**无横向溢出** | `documentElement.scrollWidth <= innerWidth + 1` |
| **A2** | **零 hover-only 交互** | 静态扫描：UI 文件中不再有 `hover 看/滚轮/右键` 文案；且每个 hover 处理器有 tap 对应 |
| **A3** | **安全区不遮挡** | 底部状态条 `getBoundingClientRect().bottom <= innerHeight - safeAreaBottom` |
| **A4** | 触摸目标 **≥44×44** | 遍历可点元素 |
| **A5** | **移动端判据可复跑** | ★ 新建 `bb-ui-mobile-check.py`，含正负控（负控：故意留一个 620px 弹层 ⇒ 必须红） |
| **A6** | 首屏可交互 **< 3s**（4G 节流） | Chrome 网络节流 + 性能标记 |

★ **A5 是关键**：没有这道门，这些判据下次会被"改回去"而无人发现（今晚已两次栽在「无门 ⇒ 静默回归」）。

## §5 风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| **改 CSS 影响桌面** | 这个页面**桌面也在用**（Mac 壳 + 浏览器） | 断点用 `max-width` 而非替换；桌面路径逐页回归 |
| **`overflow-x:hidden` 掩盖问题** | 它会「看起来修好了」但内容真的被切掉 | ★ **必须同时修根因**，且 A1 判据查的是 `scrollWidth`（隐藏后仍可测） |
| **图谱改造面大** | force-graph 是核心交互 | P3 单独立期；**列表模式**是低风险兜底，可先上 |
| **无移动端判据 ⇒ 会再退化** | 今晚两次教训 | ★ **A5 的门与改造同批上线** |
