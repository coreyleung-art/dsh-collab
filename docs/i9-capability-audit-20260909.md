## 三、通道成本对比(核心)

| 通道 | 成本 | 浪费点 |
|---|---|---|
| agent-msg(错) | 黑板写 1 + 唤醒 1 | **对无人值守 i9 是空投**——i9 不消费 agent-msg, 消息滞留; 且违反 R033 有治理成本 |
| bus/send(对) | 服务器入队 + SSE + 守护收信 | 无——送达保证(两级确认 delivered/done), 守护常驻必收 |

**关键**: 两种通道「单次发送成本」相近, 但 **agent-msg 的有效成本≈0 且需重发(总成本翻倍)**, bus/send 一次送达——正确通道单次即成, 反而更省。

## 六、结论

1. **本次总成本低**(~10-12K tokens, 纯低推理), 远低于单次高推理任务——采集类任务成本本身可控
2. **通道错误的真实代价 = 治理成本 > 通讯成本**: 违规触发 G-C42 + 纠错轮次 ≈ 2-3 tool 轮(约 3-4K tokens)一次性; 若门未上线会反复空投重发(每轮浪费)
3. **正确通道更省**: bus/send 送达保证一次即成, agent-msg 对无人值守节点是无效投递(需重发=成本翻倍)
4. **门 3 价值**: 正确通道顺手化后, 未来采集零浪费(本次审计即证明)

## 七、可复用结论

- 跨设备采集/任务 → bus/send(送达保证)必选
- 采集类成本本身就低(纯结构化), 无需担心; 真正浪费在「错误通道重试」
- G-C42 门 = 防止反复空投的长期成本守护
