# 探照灯握手协议 · 通讯前置确认(Searchlight Handshake)

> 制定: HR 司库(成本中枢) · 2026-09-07 · 用户提议: 传输前先确认信号通畅, 防对空气说话
> 实证: agent-bus 中 queued 635 条(2%) + 发给未知会话 1044 条(4%) ≈ 6.5% 消息存在"对空气说话"风险
> 类比: TCP 握手(SYN-ACK)——传输内容前先确认对端在听

═══════════════════════════════════════

## 一、问题定义(为什么需要)

现状: agent_send 发消息时返回 targetLive/queued, 但:
1. 发送方常不看返回(发完即走) → queued 消息堆积在离线目标队列, 目标上线后一次性轰炸(信息风暴)
2. 发给已归档/退役会话(不在 profiles)→ 无效投递 1044 条
3. 多方群聊中某人离线 → 其余人继续"对空气说话", 离线者错过又补发(重复风暴)
4. 信息风暴根源 = 不知道对方状态的盲发

## 二、探照灯握手协议(3 灯状态)

### 握手流程(传输内容前, 毫秒级开销)
```
发送方 ──探照灯(agent_light: 目标在? 状态?)──→ 总线
总线 ──回信号(绿灯=在线可收 / 黄灯=离线排队 / 红灯=忙/锁定)──→ 发送方
发送方: 绿灯→传内容; 黄灯→决定排队还是转黑板; 红灯→等/找替代通道
```

### 三灯语义
| 灯 | 含义 | 发送方动作 |
|---|---|---|
| 🟢 绿灯 | 目标在线, 可接收 | 直接传内容(agent_send) |
| 🟡 黄灯 | 目标离线, 将排队 | 不盲发——改: 内容落黑板(notes/<目标>/), 目标上线自取; 或评估是否真需要发 |
| 🔴 红灯 | 目标忙/锁定/不可达 | 不发送——等绿灯/找替代(黑板/其他在线角色) |

### 关键纪律(防对空气说话)
1. **发送前探照灯**: agent_send 前先 agent_light 或看返回 targetLive——黄/红灯不发内容
2. **黄灯转黑板**: 离线目标的消息 → 黑板 notes/<域>/ 落盘(目标上线读), 不塞消息队列
3. **红灯不硬发**: 目标忙/锁 → 不重复轰炸, 记录待办
4. **周期性风暴防护**: 检测到对同一目标高频重发(如 10 分钟 >5 次同内容) → 熔断, 转黑板
5. **回收机制**: 离线 >7 天目标的积压消息 → 清理(防上线一次性轰炸)

## 三、与现有机制衔接

| 现有 | 衔接 |
|---|---|
| agent_send 返回 targetLive/queued | = 探照灯结果(发送方必须读取并响应) |
| agent_light/红绿灯 | = 探照灯工具(查目标状态) |
| 黑板 notes/<节点>/ | = 黄灯落盘通道(离线消息去处) |
| R-ERR2 域规范 | 离线消息落盘按目标域 |
| E2 发现层(R-ERR4) | 探照灯可查 E2 注册表(谁在线) |
| 对账协议 v2 | 回报通知闭环(防互等) |

## 四、实施建议

### 方案 A(行为纪律, 零改动可先行)
- 广播: 发送前看 agent_send 返回(targetLive=false → 不补发, 转黑板)
- 发送方自律: 对方离线时不重复消息, 落黑板 notes/<对方>/
- HR 巡检: 定期查 queued 积压(lock-audit 扩展)

### 方案 B(工具化, 推荐)
- 新工具或 agent_send 增强: 自动探照灯——返回黄灯时自动提示"目标离线, 内容已落黑板 <key>"
- 消息门: 同目标 10 分钟 >5 次同内容 → 自动熔断转黑板(风暴检测)
- 积压清理: 离线 >7 天目标队列清空(回收)

### 方案 C(协议级, 演进)
- agent-bus 层握手: 发送前自动 liveness 检查(类似 TCP SYN)
- 群聊成员状态可见(谁在线谁离线)→ 避免对离线成员说话
