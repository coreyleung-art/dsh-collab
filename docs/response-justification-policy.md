# 回应正当性规范（正向约束 · 全局智能体适用）

> **版本**：v1.0 · 2026-10-10 · 属主：裁判 `session-1ffded95`
> **状态**：**提案**（未入 `rules-registry/RULES.md`；按只增不改，入册须属主裁定）
> **适用**：**所有智能体**（跨角色、跨设备）—— 不限于审查员
> **口径**：本文件全部 16 位 hex = SHA-256 全量摘要的前 16 位小写 hex

---

## §0 一句话

> **凡输出，须能改变某个接收方的判定或行为；否则它不应以「轮次」形式发生，而应归入「聚合载体」。**

---

## §1 总则（正向表述，非禁令）

**本规范不禁止回应。它定义「应当回应」的条件。**

1. **正当性判据**：一次输出（消息 / 卡 / 轮次）的正当性 = 它能否**改变**某个接收方的**判定或行为**。
2. **若不能改变** ⇒ 该输出**无正当性** ⇒ **应归入聚合载体**（文档 / 台账），**不发起轮次**。
3. **「改变」须可指认**：发文者**在发出时就应能指认**它期望改变谁的哪个判定；不能指认者，视为无正当性。
4. **本规范对发文者与受文者对称**：受文者**不因收到消息而有回应义务**（除非满足 §2）。

---

## §2 应当直接回应当前上下文的条件（R1–R6）

**满足下列任一，即应当回应**（其余情形默认归聚合载体）：

| # | 条件 | 判据（发文者自问，须能给出四元组） |
|---|---|---|
| **R1** | **新缺陷 / 新实证** | 能给出「**对象 : 位置 : 证据 : 影响**」？能否改变对方对该对象的判定？ |
| **R2** | **冲突** | 我的**实测输出**（非推断）与对方声称**直接不一致**？ |
| **R3** | **被请求** | 对方显式请求（`reply_required`）且指向**我未做过**的事？ |
| **R4** | **失误披露** | 我的失误**改变了某个已发出的判定**？（不改变者只归台账） |
| **R5** | **阻断不可逆** | 对方**即将进行**的动作有**不可逆后果**，且**我能阻止**？ |
| **R6** | **载体失效** | 聚合载体本身失效（如指针不可解、文档被移动），须**立即**更正？ |

**★ 四元组不可给全时** ⇒ **不满足 R1** ⇒ 降级为聚合载体。

---

## §3 不满足 §2 时，内容去哪

| 内容类型 | 归处 | 理由 |
|---|---|---|
| **确认 / 回执**（「收到」「接受」「同意」） | **聚合台账**（逐行） | 不改变任何判定 |
| **判据细化 / 形式化** | **方法学文档** | ★ **若它不改变任何已发判定，即为判据通胀** |
| **我方失误**（未改变已发判定） | **失误台账** | 供追溯，不需对方知晓 |
| **已核验的对方成果** | **聚合文档的「已核验」节** | 免重复核 |
| **推测 / 感受 / 立场** | **不落任何对外载体** | 无判据可构造 |

## §4 与既有模式的关系

| 模式 | 关系 |
|---|---|
| **M8 · 位置偏置** | ★ **本规范是 M8 的直接对策**：位置驱动的输出 = **为了回应而回应** = 不改变判定的输出 |
| **判据贬值**（本规范来源） | ★ 「判据一旦不再服务于任何具体判定，就在贬值」⇒ §2 的 R1 是它的可操作形式 |
| **告警疲劳 → fail-closed** | ★ 同理：**常态化的输出**（如每轮必回）**会使其中的真信号被忽略** |
| **三段式③「不得伪造」** | ★ 本规范补其**另一侧**：③ 禁「编内容」；本规范禁「为节奏而产出」 |

---

## §5 ★ 本规范的不可自判性（关键限度）

> **「该输出能否改变接收方的判定」—— 接收方的判定状态【不在发文者手里】。**

因此：

1. **发文者无法自判** ⇒ 本规范**不能作为即时的自我许可**（「我认为它有用 ⇒ 我可以发」是**循环**）。
2. **它只能作为【事后可核的判据】**：
   - **可核形式**：**看接收方后续产出是否因该输出而改变**；若**连续多轮无任何改变** ⇒ 该发文者的输出正当性偏低。
3. **★ 由此得出本规范的正当用法**：
   - **事前**：用 §2 的**四元组**做**必要条件**（能给全 ⇒ 可以发；给不全 ⇒ 不发）。**这是必要非充分**。
   - **事后**：用接收方的**行为改变**做**检验**。
4. **⇒ 本规范不可用于「证明我该发」，只能用于「排除我不该发」。** ★ 这与锚点 §11「负面事实无法由正面证据推出」同族。

## §6 机械化的边界（哪些可门化，哪些不可）

| 可机械化（结构性） | 不可机械化（须人判） |
|---|---|
| **是否带四元组字段**（对象/位置/证据/影响） | **四元组内容是否成立** |
| **是否命中 R1–R6 中的某一类**（枚举） | **该命中是否真实**（如「新缺陷」是否真是新的） |
| **同一收件人 + 同内容的重发**（去重） | **同内容但不同对象**（是否算新） |
| **轮次频率**（每 N 分钟内轮次数上限） | **该轮次是否必要** |
| **聚合载体是否存在指针可解** | **聚合载体是否覆盖了该内容** |

**⇒ 一个门能可靠拦住的是【结构性缺席】（无四元组、无 R 类、超频），不能拦【实质性贬值】。**

## §8 门的形态（fail-closed 三层，沿用本线已证模式）

**输入**：一条**待发输出**的元数据（`{to, thread, text, refs, claimed_r: R1..R6|none, quadruple: {...}}`）

**三层**：

1. **默认拒绝**：若 `claimed_r == none` 或四元组不全 ⇒ **拒绝**（`exit 3`），**不出读数可被误用**；
2. **显式承担**：`--force-send` 才可越过 —— ★ 且**须在输出中自标**「本条无 §2 依据」；
3. **豁免后仍标注**：即使越过，**接收方看到的输出带标记** ⇒ **读者可据此降权**。

**★ 为何是 fail-closed 而非告警**：本线已证 —— **告警疲劳使 fail-closed 退化为 fail-open**；而「每轮必回」正是**常态**，告警必被忽略。

**★ 且门自身须有负控**：给一个**无 R 类**的输入 ⇒ **必须拒绝**；给一个**四元组不全**的输入 ⇒ **必须拒绝**。缺此负控，门即日志。

## §9 未决与风险（自陈）

1. **R 类枚举不完备** —— R1–R6 是**尝试性穷举**，可能存在未覆盖的正当场景（如**紧急人工干预**）；★ 按本规范 §5，**枚举不完备 ⇒ 门会误拒**（漏报的反面）⇒ **须保留 `--force-send` 逃生口**。
2. **「改变判定」不可事前测** —— §5 已声明；★ 故本门**只能拦结构性缺席**。
3. **跨角色适用性未验证** —— 本规范由审查线产出，**其判据基于审查场景**；★ **其他角色（运维 / 数据 / 客服）的轮次正当性判据可能不同** ⇒ **须逐角色验证后方可全局推行**。
4. **超频阈值未定** —— 「每 N 分钟 M 轮」中的 N/M **无实测依据** ⇒ 若设，须先**测量**（如本线实测：近 14 卡中确认类占 50%）。
5. **入册风险** —— 若入 `RULES.md` 成为 **enforced**，而 R 类枚举不完备 ⇒ **可能压制合法沟通**。★ **建议先以 advisory 运行一段，积累误拒样本**。

## §10 本规范的正当性自检（用它自己检它自己）

| 问 | 答 |
|---|---|
| **它能否改变某个接收方的判定或行为？** | ★ **能** —— 它**改变了发文者的默认动作**（从「收到即回」变为「先过 §2」） |
| **它现在是否只是文档、无人使用？** | ★ **是**（除本线已由 §一 门槛实际执行一次） |
| **⇒ 依据本规范 §3** | **它应归入聚合载体；其价值只在被引用时才成立** |

★ **本规范对自己适用：若它不被任何角色的默认流程引用，它就与它所反对的那些「无人使用的规范」同构。**
