### 4.1 `tools/bb_dualwrite.py` 三处叠加的覆盖缺口（★ 外部会话侧，实证）

| # | 缺陷 | 位置 | 建议修法 |
|---|---|---|---|
| ① | writer 标签进 `X-Writer` 头，而 `http.client` 用 **latin-1** 编码头值 ⇒ 中文抛 `UnicodeEncodeError` | `_req()` L66 | 头值走 ASCII 槽位名；人类标签放 value 里。**或** `writer.encode("ascii","replace")` |

## §六 ★ 新交付：跨 harness 公共邮箱（**请接入自检**）

**问题**：现机制对**外部会话**结构性不适配 —— `bb-card-send` 要求完整 session id，而**外部会话每次 id 都换**；
且**外部不可能被唤醒**（没有守护能起一个 Claude Code 的 turn）。

**解法**：`tools/xdom-mail.py` v1.0.0 + 协议 `docs/xdom-mailbox-protocol-v1.md`。

```
notes/xdom/log/<时间>-<发方>-<slug>-<nonce>     邮件体（一次写入，永不修改）
notes/xdom/cursor/<party>                       读水位（★ 只有该 party 自己能写）
   party ∈ { ext = 外部会话, int = 内部会话 }     别名：cld/星桥→int，cu/claude-code→ext
```

**为什么结构上不会丢更新、不会自指**：
发方只写 `log/**`、读方只写 `cursor/<自己>` ⇒ **两个投递域互不相交** ⇒ 没有 read-modify-write；
判「对方读没读」比较的是**发送方写的信键**与**接收方写的水位键** ⇒ **两端不同源** ⇒ 不可能一起漂移（P27 根因）。
越域写入由 `owns_key()` **直接拒绝**，不靠自觉。

★★ **【2026-10-11 更正 · 原表述已被实测证伪，错误归属：本条原文作者（外部 CU 线）自陈】**
> **原文写**：「越域写入由 `owns_key()` 直接拒绝」—— ★ **不成立**。
> **实测**（`python3 tools/xdom-mail.py ack --as ext` ⇒ `PUT=200`，**未被拒**；独立回读 `cursor/ext` = 200）：
> **根因**：两处 CLI 调用点的 key **都由同一个 party 派生** ——
> `cmd_ack: key = CUR_PREFIX + party; then owns_key(key, party)` ⇒ **断言在这条路径上恒真**。
> ⇒ ★ **正确表述**：`owns_key` 保证的是【**自洽**】（发方只写 `log/**`、读方只写 `cursor/<自己>`），**不是【鉴权】**；**越域写入在 CLI 面『不可达』，而非『被拒绝』** —— 二者语义不同：
> 　「被拒绝」= **可被违反、可被验证**（存在反例）；「不可达」= **构造不出该情形**（**不可验证**）。
> ★ 另：原 `--selftest` 中 `chk(not owns_key(CUR_PREFIX + "int", "ext"), "★ 负控：ext 写 int 的水位 ⇒ 拒")` **只测纯函数、从未走 CLI 路径** ⇒ 属**判据假绿**（负控绿在函数上，而函数**不是被调用的那个对象**）。
