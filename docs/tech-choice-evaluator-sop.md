# 技术栈选型评估制度 · SOP v1.0（R010 候选）

> 建立：2026-08-29 · HR session-2a15e6b1（司库）· 用户指示「选型必须有评估器，防模型偷懒/幻想」
> 工具：~/dsh-collab/scripts/tech-choice-evaluator.py（属主 HR，纯规则零 LLM）

## 一、核心原则（防模型偷懒/失忆/猜测/幻想）

**任何新开发工具的编程语言/技术栈选型，必须先跑评估器**——禁止：
1. 凭印象/图省事选「看上去最方便」的语言（阉割降级路径）
2. 凭模型记忆猜测（失忆风险：记错版本/生态/维护状态）
3. 拿系统冒险验证假设（没有评估就写代码）
4. 每次重复搜索（论文/官方文档先搜集到本地，一次入库反复用）

**必须**：
1. 依据论文 + 官方文档标准（本地 KB 优先查）
2. 有论文的检查是否最新版本
3. 选需求相关最可靠稳固的（类型安全/单二进制/低内存/无崩溃循环）
4. 证据链留档（评估报告 = 选型依据）

## 二、评估维度（6 维评分，每维 0-10）

| 维度 | 内容 |
|---|---|
| D1 官方文档标准 | 官方文档/规范存在且本地可查 |
| D2 论文/研究基础 | 有论文支撑（KB/papers-db 检索，查版本新鲜度） |
| D3 生态成熟度 | 包管理/社区/维护活跃度 |
| D4 架构契合 | 与现有资产（Rust 四件套/Node 插件/Python 脚本）契合 |
| D5 可靠性稳固 | 类型安全/内存/崩溃循环风险 |
| D6 反幻想 | 该语言在此任务是否易图省事（并入陷阱检测） |

**评分参考**：>=7.5 推荐 / 6-7.4 备选 / <6 不推荐

## 三、反阉割陷阱检测（防「看上去省事」的降级方案）

| 陷阱 | 检测 |
|---|---|
| shell 脚本顶替 | 用 bash 顶替正式化能力（无错误处理/日志/回收） |
| 阉割 API | 免费/简化 API 顶替官方完整 API（功能缺失/限额） |
| 内存泄漏长驻 | 高频轮询顶替事件驱动（CPU 空转） |
| 临时文件堆积 | /tmp 缓存顶替正式存储（重启即丢） |
| 无类型安全 | 动态类型实现有约束的协议（运行时炸） |
| 单线程阻塞 | 同步阻塞顶替并发通道（互相拖慢） |

## 四、标准流程

1. 评估器 --check-kb（本地知识覆盖？缺语言先搜集入库）
2. 评估器 --compare "lang1,lang2,..." --task "<需求>"（数据驱动评分）
3. 反阉割检查（陷阱检测命中 → 标记风险）
4. 决策：推荐语言 + 证据链（评估报告留档）
5. 落链：选型决策入 KB + registry 登记（复用，不重复评估）

## 五、本地知识优先（省搜索 token）

1. 语言知识库内嵌 LANG_KB（rust/node/python/go 官方文档源 + KB 证据）
2. 新增语言 → 先搜集论文/官方文档入库（一次投资，反复使用）
3. 论文版本新鲜度：评估时查 KB 中论文记录时间 vs 现状
4. 与 research-first-policy（优先调研）衔接：选型调研是「调研优先」的子环节

## 六、边界

- 本工具管**选型评估**（语言/技术栈决策），不替代调研执行（4787d717）
- 官方 SDK 锁定场景（Node 插件/wecom 等）：D4 架构契合会自然加分，无需强制 Rust
- 评估结果供决策参考，最终选型由需求方 + HR 确认
