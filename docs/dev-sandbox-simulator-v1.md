# 开发沙箱模拟器（Dev Sandbox Simulator）v1.0 — 泛化隔离验证模式

> 2026-08-29 星桥-mac-mini-协调者 · 用户指示：把「隔离小样本验证」泛化到工具化/插件化/其他开发工作流；制作本地模拟器，评估是否节省重复 token
> 定位：所有开发工作的「先小样本验证，测通再推进」统一入口——从 CLD 重启专用，泛化到一切开发类型

## 一、核心模式（从 CLD 重启验证提炼）

**隔离小样本验证（Sandbox-first）**：
```
任何开发/变更 → 先在隔离环境用小样本验证（不动生产）→ 测通 → 再推进生产
```

已验证的 4 个子工具：
| 工具 | 场景 | 验证内容 |
|------|------|---------|
| cld-shell-sandbox-test | CLD 壳行为 | 崩溃处理/模式对话框/KeepAlive |
| restart-stress-test | 重启稳定性 | boot 冒烟 N 轮/自查门/注入 |
| restart-guard | 插件完整性 | type:module/ESM/符号链接/加载 |
| checks-transfer | 交付完整性 | 完整体七要素 |

## 二、泛化到所有开发类型

| 开发类型 | 隔离验证什么 | 模拟器模式 |
|---------|------------|-----------|
| 插件开发 | 插件加载/依赖/API | `dev-sandbox plugin <目录>` |
| 工具开发（Rust/Py）| 编译/运行/参数 | `dev-sandbox tool <源码>` |
| 脚本开发 | 语法/执行/边界 | `dev-sandbox script <文件>` |
| 配置变更 | 语法/生效/回滚 | `dev-sandbox config <文件>` |
| 模型/训练 | 数据/超参/评估 | `dev-sandbox ml <配置>` |
| 工作流编排 | 步骤/依赖/失败处理 | `dev-sandbox workflow <定义>` |

## 三、dev-sandbox 统一入口设计

```
dev-sandbox <type> <target> [--isolate] [--dry-run] [--rounds N]
  --isolate    隔离环境（默认）：临时目录 + 独立配置，不碰生产
  --dry-run    只分析不执行
  --rounds N   小样本轮次（默认 1）

阶段（自动探测类型后选择）：
  0. 预检：目标存在/语法/依赖声明
  1. 隔离执行：临时环境运行/加载（小样本）
  2. 验证：输出检查/退出码/日志扫描
  3. 报告：PASS/FAIL + 证据（可落踩坑档案）
```

## 四、token 节省评估（基于历史案例）

### 无沙箱时（现状历史数据）

| 案例 | 无沙箱消耗（多轮排查）| 有沙箱应消耗 |
|------|---------------------|-------------|
| central-inbox 缺 type:module 崩溃 | 崩溃→MBP 修复→重启验证 ≈ 10+ 轮 | 沙箱 1 轮抓出（模块加载 FAIL）|
| openchronicle require 死代码 | restart-guard 抓到 + 修复 ≈ 4 轮 | 沙箱 1 轮（静态扫描）|
| NODE_ID 探测 bug | 2 版修复 + 冒烟 ≈ 6 轮 | 沙箱 1 轮（探测断言）|
| node-bridge header 空行 | 沙箱实测发现 ≈ 3 轮 | 沙箱 1 轮 |

### 节省估算

```
每案例平均节省: (10+4+6+3)/4 ≈ 6 轮排查
每轮排查平均: ~2k-4k token（工具调用+分析）
每案例节省: ~12k-24k token
每月新开发案例（估）: 8-15 个
月节省: ~100k-350k token ≈ 25-90 RMB/月（deepseek 定价）
```

### 结论
- **沙箱先行模式已实际节省**：node-bridge header bug（沙箱抓出）、openchronicle（restart-guard 抓出）——都是「先验证再推进」的收益
- **泛化后**：所有开发工作流（插件/工具/脚本/配置）都用 dev-sandbox 先行 → 避免「生产崩溃后多轮排查」的重复 token
- **主要节省点**：① 避免崩溃后的远程修复轮次 ② 避免多版本试错 ③ 避免人工排查
