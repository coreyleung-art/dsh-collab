# 约束前置 · 不可绕过 (Φ9) — 哲学详档 + 实现细则

> 作者: 明鉴 v2 · 2026-09-05 · 用户提出(Lean4 跨项目洞察) · 双层: 哲学(governance-philosophy.json Φ9) + 本细则
> 一句话: 凡"不该发生的路径", 约束不要靠自觉/文档/事后检查, 尽量前置为"结构上不可能"。

## 一、为什么值得成哲学(用户洞察的还原)

你在多个项目套用 Lean4 逻辑规则化(R027 人开关锁 / R029 原语分级锁 / rule-judge 灰度硬阻断), 发现:
- 它**解决资源浪费**——违规被结构拒绝, 不会发生"事后才发现→返工/回滚/补救"
- 它是**底层的东西**——应渗入所有智能体做任何事的过程, 不只是特定项目技巧

抽象后: 你用的"Lean4"只是实现工具之一; 本质是一条普适哲学——

> **约束前置 · 不可绕过**: 规则应建进结构, 而非贴在文档。违规路径在结构上不存在, 而非运行时被拦一下。

## 二、核心机制(为什么能防浪费)

| 约束方式 | 违规时机 | 代价 |
|---------|---------|------|
| 文档/自觉遵守 | 执行时(靠人记得) | 遗漏→违规→事后补救(高) |
| 运行时 if 检查 | 执行时(靠人写对) | 漏写分支→绕过(中) |
| **结构上不可能(类型/编译/入口)** | **设计/构建时** | 一次投入, 永久防(低) |

> 资源浪费 = 事后补救。约束前置把代价从"每次事后补救"挪到"设计期一次投入"——最高杠杆防浪费。呼应 Φ7 成本意识。

## 三、三形态(按强度递增)

1. **类型级(最强)**: 无合法值即无路径 — Lean4 `Unlocked : Authorization → SwitchState`, 没 Authorization 构造不出 Unlocked
2. **编译/静态期**: 结构检查 — Rust 类型系统 / 枚举穷尽匹配(未覆盖分支编译不过)
3. **入口门禁(最弱但常够)**: 单点守卫 — 所有写入走唯一 API, 门内校验, 无旁路

> 决策: 能上类型/编译就不止于入口; 入口能拦就不靠自觉。但不过度——Φ6 理论先行: 最小可用约束先落, 重复/出事再升级强度。

## 四、Lean4 实现范式(已验证模板)

```lean
-- R027 人开关锁范式(用户 2026-09-01 定案)
inductive Authorization          -- 授权凭证: 人类审批产物
  | HumanApproval : Record → Authorization    -- 人类审批记录
  | Verified : J45Gate → Authorization         -- J45 分级门禁通过
inductive SwitchState
  | Locked : SwitchState                        -- 默认锁
  | Unlocked : Authorization → SwitchState      -- 开启必须带授权证明
def openSwitch (auth : Authorization) : SwitchState := Unlocked auth
-- 类型系统保证: 没有 Authorization 就构造不出 Unlocked
```

推广(跨项目模板):
- **R029 原语分级锁**: L3 动作 → `Unlocked(auth)`; L2 → 确认(轻级)
- **规则硬阻断**: 违反规则的操作类型上无构造路径
- **资源/资产操作**: 未授权/未 verified 的关系不可入图(数据层不可绕过)

## 五、适用决策树(所有智能体做任何事前问)

```
这件事有"不该发生"的路径吗?
 ├─ 没有 → 无需约束前置(Φ6 最小)
 ├─ 有, 且靠人自觉/文档约束 → ❌ 违反 Φ9, 应升级
 ├─ 有, 运行时 if 检查 → 问: 能被漏写/绕过吗? 能→升级
 └─ 升级目标:
     ├─ 有类型系统可用(Lean4/Rust/Haskell) → 类型级
     ├─ 有编译期结构(枚举/穷尽) → 静态期
     └─ 只有运行时 → 至少收敛到唯一入口门禁(无旁路)
```

## 六、对智能体协作的意义(用户: "应沉淀到所有智能体做任何事情的过程中")
- 每次建规则/门/锁, 默认问: 这约束是"文档声明"还是"结构强制"?
- R027/R029/红绿灯(agent_light/lock)已是结构层; 新规则优先结构落地
- 规则账本(rules.json)是声明层; 关键规则要有结构实现(rule-judge 蓝图)

## 七、关系
- **与 R027(Φ2)**: R027 是"能力权限分离"的具体开关锁; Φ9 是通用方法论(不只权限, 一切约束)
- **与 Φ8(重复即工具化)**: Lean4 跨 3 项目复用 → 满足 Φ8 触发 → 沉淀为本哲学

- **与 Φ7(成本)**: 防浪费的直接机制
- **与 Φ6(理论先行)**: 先最小约束验证, 重复/出事再升强度
