## 四、裁决

### P0 —— `failed to fetch` 真因（送审未列，HR 补列）

根因 = **dsh heap cage 4096 MB 耗尽**（峰值 4268 MB，17 次 OOM / 当日 12 次 boot）。

**裁决：属框架级配置，不在 mac 资源治理范围，本报告不予立项，转协调者 / 星桥处置。**
mac 侧我能做的已做完（释放约 3 GB 常驻，RSS 16.1 GB → 13.2 GB）。**不越权改 runtime 堆参数。**

### P1 —— 子代理产出源治理：**同意立案，但目标重定义**

- 送审表述「治理 3 个会话 + 产出上限 + 完成后回收」**方向正确**。
- **HR 修订**：子代理仅占 155.9 MB（**17.5%**），**清理磁盘不是目的**——真实成本是**并发上下文与进程**。
  故 P1 目标定为：**父会话扇出配额 + 子代理完成即回收 + 扇出速率限制**。
- **不新造规则**：直接复用公约 **G-C13 风暴熔断**（已在《服务器通讯成本治理补丁集》定稿并经星桥批准）。
  297 子代理 / 2 父会话 = **教科书级子代理风暴**，现行规则已可覆盖。
- **上限建议**：单父会话 **≤ 50 子代理/日**；全机并发子代理 **≤ 8**。
  （4787d717 单会话 152 = **超限 3 倍**，为本次首要约谈对象）

### P2 —— 会话数软上限：**同意立案，但口径必须下调**

- 送审「总量 ≤ 200」**不可用**——377 里 297 是子代理，不该与主会话共用同一阈值。
- **HR 修订为双轨阈值**：
  - 主会话（登记在册）≤ **80**（当前 80，**已达线**，只出不进）
  - 子代理总量 ≤ **300**（当前 297，**已达线**）
- 超限动作 = **归档压缩，不是删除**。

### P1.5 —— 子代理生命周期（HR 新增提案）

子代理创建 > 7 天且已完成 → 归档为冷存并移出活跃目录。**这是 155.9 MB 大头的低成本治理**，且子代理不会再生效，风险极低。

### P2.5 —— 42 个未登记空壳清理（HR 新增提案）

51.7 MB，40 个 ≤ 500 KB。低风险、高确定性，**建议先做**。

> **但依法不擅自执行**：涉及删除用户会话，**挂异步审批队列**，待用户统一审核。不阻塞主线。
