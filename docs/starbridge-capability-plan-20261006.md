# 星台 App 能力补强完整计划（2026-10-06）

> 依据：能力差距表（vs ChatGPT/Claude/豆包/讯飞听见）+ 星台「个人协调中枢」定位。
> 基线：v0.9.13 付费签名（2027 到期）· 服务器中继通道已上线 · TestFlight 流水线已建（starbridge-release.sh）。

## 阶段 0 · 一次性基础设施（约 1 天，无新货币投入）
1. **APNs Auth Key**：用户在 ASC → 用户与访问 → 密钥 → 生成 APNs Key（免费，5 分钟）→ 交付星桥入库（0600，同 appstoreconnect 目录）。
2. **推送发送器**：桥侧（mac-mini）加 APNs HTTP/2 发送器（python，读 APNs key；苹果 api.push.apple.com 出站 HTTPS）。触发点：协调者回复/待决策卡到达 → 推。
3. **App 注册 device token** + 接收模块（Swift，APNs 授权请求+注册）。

## 资源投入评估
| 资源 | 现状 | 新增需求 |
|---|---|---|
| 货币 | Apple $99/年已付 · 服务器已付费 · DeepSeek 已付费 · SFSpeech/本地 ASR 免费 | **≈0**。唯一可选增量：若想要更高精度语音转写，可选云端 ASR（讯飞/whisper API，约 ¥0.x-1/千秒）——非必需 |
| 人日 | — | 总计约 10-15 人日（阶段 0-2 核心 ≈ 8-12；长尾 3-4） |
| 苹果账号操作 | 已建 App 记录 · 已建两把 API key | 仅 1 个动作：**APNs Key 生成**（5 分钟，免费） |
| 苹果节奏成本 | TestFlight 内测免审 | 若对外测（Beta App Review）每次大版本 1-2 天审核——星台定位个人用，建议**只用内测**，零审核等待 |
| 协调者资源 | 语音连续对话需要协调者实时在线响应 | 星桥会话常驻已具备；真流式要求协调者回复走桥（机制已通） |
| 风险 | 服务器 1GB 内存（OOM 教训） | 推送/chat-log 均放 mac-mini 或轻量进程，**不再往服务器加常驻内存大户** |

## 建议执行顺序
**第一批（本周）**：1a + 1b + 1c（三天内体感质变，全部零新资源）→ 同时你在 ASC 建 APNs Key。
**第二批**：2a 推送闭环 + 2b 历史同步（「它找你」+「数据不丢」）。
**第三批**：2c/2d 语音通话（等第二批稳定）。
长尾随缘。
