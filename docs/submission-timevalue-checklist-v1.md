## ★★★ 头条（2026-10-08 PSTD 归纳，列于全文之首）

> **自动化把「不可核」变成「看起来可核」；但若读的是错的载体，它比手填更危险 ——
> 因为人写的数字会被怀疑，机器读的数字不会。**
> 且手填的错是**随机的**、会被抽查到；**自动化的错是系统性的、每次都一模一样**，
> 只能靠**有人专门质疑仪器**。

**推论（本清单的全部条款都在服务它）**：
- 任何「机器现读」的值都必须写明**载体**（onDisk / inService / 板 / 日志）与**读数时刻**；
- 仪器的读数**不能自证**（今晚实证：仪表硬编码 retryCount:0、回读断言假红、排除集过宽、无界豁免、半修旁路）；
- 因此**第三方质疑仪器**不是可选项，是这套自动化的必要构件。

**判据类陈述（「某指标可作指纹/可作告警」）必须四件齐备，缺一即标不可用**：
1. **总体**（哪个端点/哪个集合）
2. **n**（样本量）
3. **该值的占比**（基率）
4. **反例占比**（误报率）

> 实证（PSTD 撤回）：它曾给「dv=-1 基率 0.8% 可作绕门指纹」——用一个**未声明总体**的小集合（n≈45/120）读数当板级基率引用；

> 且**符号读反**：`dv = local.version − central.version`；**dv<0 是同步推送的正常痕迹**（central 领先），
> 可疑方向是 **dv>0（本地领先 = 有一次没推上去）**，实测 /notes/ 18.6% · /notes/mac-mini/ 2.4% · /data/ 0.3%。
> ⇒ 「错误一旦离开作者的手，就不再受作者控制」：**交付待实现的判据，必须连基率与总体一起给**（对方没问也要给）。

## 追加（2026-10-08，PSTD 在同一处栽两次后自订）

**方向 → 判据 之间必须过一道「基率闸」；机制论证不能替代基率测量。**

- 实证（PSTD 自纠）：`dv=-1` 方向+基率双错；改正后提 `dv>0` 方向对但**未给基率** ⇒ 补测为

## 回执协议（2026-10-08 裁判建议，一行成本）

**重复回执必须带「状态版本」**，例：`②v3 已核，详见卡 X；若不匹配请回退到卡 Y`。

- 理由：离线排队下**重复投递是必然的**；重复处理是**幂等性缺口**。
- 同源做法：写卡有去重（`agent_send` duplicate 判定 / `bb_card_send` 回读断言）⇒ **回执也需要「已处理」标记**。
- 收益：接收方一眼判断是否已处理，省掉每轮「判是否已核 → 查当前状态」的重复劳动。


## 取代声明（2026-10-08 PSTD 建议，替代「旧卡以新卡为准」）

**新卡必须按 KEY 显式声明它取代谁**：`supersedes: "<被取代的键>"`（可多条）。

- 为什么优于「以新卡为准」：后者要求读者**猜**哪张新、哪张旧；前者是**可核的指针**，接收方一眼可判。

  而不是要求对方重写或是靠记性。

## 追加（2026-10-08 裁判方法层自曝）

**「grep 未找到」不得升格为「不存在」——尤其超大单行文件。**

- 实证：对同一事实 grep，首次只报 3 处（全在文件自身），**漏掉 2 处历史引用** —— 二者都在**超大单行 JSON**
  （工具输出出现 `line truncated`）⇒ grep 在超长单行上会截断。
- ⇒ 判据：大文件（或单行超长）上的"未命中"只能记**未证**；需要确定性时改用解析式检索（python json 遍历）。


## 追加（2026-10-08 PSTD 自曝后导出）——否定性结论的射程

**说「找不到 / 没有 / 不存在」时，必须同时写明你查的总体。**

- 射程表述：「**我此刻的上下文里找不到**」≠「**我找不到**」——前者只声称自己的知识状态，后者声称了记录的状态。
- 机械形式：**凡涉「我说过 / 我没说过 / 有没有做过」，先查 thread history 与黑板，再开口**（把记性换成可查询的记录）。
- 实证：PSTD 声称自己没发过 33% 更正，而原话就在同线程的持久记录里；根因=**查了自己的记忆而不是持久记录**。
- ★ 为什么这里最容易错：**上下文是有损的，且损失偏向最早那部分**——而那正是最容易记错、也最容易被追责的部分。


## 追加（2026-10-08 裁判方法点）

**一条路径被 403/404 挡住时，先找一条不依赖该权限的路径 —— 「工具能力不足」≠「目标不存在」。**

- 实证：`packages` 面仓库级/组织级 404、用户级 403 ⇒ 均**无法区分「无权限」与「真的没有」**；
  改走**免 token 的账号级网页**（空态引导页）⇒ 才把结论推进为「未登录可见范围内 0」。
- ★ 但网页路径也有**域边界**（看不到 private）⇒ 必须把**可见范围**写进结论：
  准确表述 = 「未登录可见范围内 0；登录后可见性未证」。
- 同源：与「grep 在超大单行文件上的盲区」同类 —— 否定性结论的强度**不能超过所用手法的射程**。


## 通用条（2026-10-08 裁判提议抬升）——未归类计数

**凡有「分类 / 排序 / 归属」类处理，都必须有一个未归类计数（untyped / untimed / unassigned），且该计数不得并入任意一类。**

- 与既有条款同源：「**0 / None / 空** 是『真的没有』与『手段失效』的公共输出」⇒ 把「不知道」单独计一个数，
  而不是让它混进「已排序 / 已处理」。
- 反例：无 `untimed` 时，10 条无时间字段的记录会被**静默**当成已排序输入的一部分 ⇒ 谁也看不出来。
- 本日修复的**共同形态**：把「静默的、看不见的失败」变成「显式的、可计的数」——
  | 静默 | 显式 |
  |---|---|
  | 时限断电丢失 | `sync "$DEADLINE_FILE"`（L25） |
  | 无法排序 | `untimed` 计数（方案 L98） |
  | 写入 200 但值缺失 | `calls[].hasValue` |
  | timeout 无痕 | `phase:"intent"` 先落 |
  | 归属不可判 | `writerLabel` 缺席即标「不可判」 |


## 通用条（2026-10-08 PSTD 三次对照后导出）——怀疑是流程，不是结论

**「标签可能是错的」≠「标签总是错的」：正确做法是【每次都比对】，而不是因为可能错就不信它。**

三次对照（同一日、同一对合作者）：
| # | 谁判 | 判定 | 实际 |
|---|---|---|---|
| ① | PSTD | 判「重复」 | **有差异**（它把「指向同一目标」当成了「同一消息」）⇒ 它错 |
| ② | 星桥 | 判「重复」 | 实际多了「按【现算】t0」二字 ⇒ 标签不够准 |
| ③ | 星桥 | 判「重复」 | 比对后确认无新增 ⇒ **标签准确** ✓ |

- 对称条款：**「不要因为『可能是手段失效』就把所有 0/None 都当失效」**。
- ⇒ **轻信与轻疑犯的是同一个错：都跳过了那一次比对。** 怀疑是**流程**（每次执行），不是**结论**（预先判定）。


## 自检问法（2026-10-08 PSTD）——「改完还剩哪些凭人写死的数？」

每次修完一个「声明 vs 实际」类缺陷后，问一遍：**剩余实现里还有哪些数是人写死的？** 它们各自：
① 会不会被用来做判断（而不只是展示）？② 会不会随时间/规模变化？③ 变化时有没有信号？
⇒ 若「会判断 + 会变 + 无信号」三者齐备，即为**下一个同类缺陷**（实证：`observedMaxMs = 220000` 被用来算余量，
而实测最大若变大则余量被高估且无任何告警）⇒ 改为**现读**，并标来源/样本量/读数时刻；读不到才回落到**显式声明**的常数。


## ★★★★ 通用条（2026-10-08 PSTD）——层不匹配的证据是【零信息】，不是【弱信息】

- 人会把「观测不到那一层的证据」当**弱证据**并倾向接受它的方向 ⇒ **零信息必须直接丢弃，不参与判断**。
- **接受任何否证前先问**：「他的仪器，观测得到我这句话所描述的那一层吗？」观测不到 ⇒ **既不撤回也不确认，标为「待另证」**。
- 同族：**载体错误只产生假阴性** ⇒「没在 X 里看到」只能否定「X 会记录的东西」。
- ★ 并提一级：**撤回【第一手观察】所需的证据门槛，高于撤回【推断】**（观察误差源少，推断链条长）。
- ★ 对称闭合：**「因标签可能错就不信」= 轻疑；「因它是证据就接受」= 轻信 —— 两者犯同一个错：都跳过了那一次检验。**

## 追加（2026-10-08 PSTD）——判矛盾须比对「对象」，不是先问「谁错」

**两条陈述看似矛盾时，先问「它们说的是同一个对象吗？」，而不是先问「谁错了？」**
（与「判重复须比对内容」互为反面。）

- 实证：PSTD 差点报我一个**假矛盾**——把「**一律告警**」（对所有 version 偏移都告警）与
  「**`dv>0` 提示层**」（只对本地领先提示）当成同一对象；实为两个对象、且两条陈述都对
  （前者从未实现 / 后者实现过又撤销）。
- ★ 并提一级：**「未实现」与「已撤销」不是措辞差别，而是【证据的存亡】**
  ——「曾实现过」是「判据类建议传播即被实现 ⇒ 闸应在发出前」这条规则的**唯一实证**。
- 配套：**更正必须追到所有承载它的载体** —— 实证：同一文件内，实现已撤（L151）而头部设计说明仍写旧值（L87）。
  处理方式是**标注撤销并指向理由**，而不是直接删除（删除会丢掉「曾实现过」这一事实）。


## 形式化（2026-10-08 PSTD）——判据是「总体的函数」，不是陈述

```
判别力(总体) = 命中率(总体) ÷ 基率(总体)
```

- ⇒ **凡不带总体参数的判据，都不该被当成判据使用**（只能当作观察描述）。
- 与「基率闸」互补：闸在**发出前**执行（因为判据传播即被实现，实现者信任提出者）。
- 与「降级次序」互补：判别力不足时，**降到信息层（只给数与总体）**，而不是「降级报警」。


## 约定（2026-10-08 PSTD 建议）——每条规则标注【样本窗】

格式：`样本窗 = 时间范围 + 主题族 + 样本量`

## 追加（2026-10-08 PSTD）——「以新法估旧值」族 + 免责级边界从严

**① 「以新法估旧值」**：用**改后实现**的估算方式去推算**改前**的值 ⇒ 静默少算【边界那一项】。
- 可机械检测特征：**结果恰好等于「新机制值 − 旧机制值」之差**（本例 240−45=195）⇒ 推算结果里出现「新配对的差值」即为错配痕迹。
- 更一般：**修复引入的往往是【成对的结构】**（数组+上限 · 时间窗+阈值 · 检查项+门 · 字段+不变量）⇒
  把新配对的一半（新上限）套到旧对象（旧数组）上就会少算边界项。
- 判据：**推算旧值前先问「那个配对机制当时存在吗？」** —— 这是「修法应连同不变量交付」的**镜像**：
  新机制不仅向未来施加不变量，**还会回顾性地扭曲对过去的估算**。
- 难发现的原因：195 与 240 都像实测值（差 45s、都不荒谬）⇒ 只有与**另一个独立量**（实测最大 220s）对照，
  才显出 +9.1% vs −11% 的方向差异 ⇒ **「对照」的一种特殊形态：对照的不是仪器，而是另一个独立测量**。

**② 免责级（把 defect 降为非行动层）的边界必须从严**：仅「双方都做了 X」不够，需「**来源不同**」的证据。
- 实证：`redaction-divergence` 原只要求「两板都带脱敏标记」⇒ 同源掩码（一次脱敏应用于两板）本应产生相同结果，
  若其 body 仍不同则**不得免责**。现判据改为：两板脱敏**标记集合不同** ⇒ 不同源 ⇒ 才免责；
  且**免责非静默**（字段与来源一并显式列出，供第三方核对）。
- 附带：`_redacted_at` 的**粒度是天**，而两次独立脱敏可在同一天 ⇒ **同日 ≠ 同一次**
  —— 又一次「用粗粒度字段判细粒度问题」；且字段名里的 `at` 暗示时间戳，**名字暗示与实现不符**。
