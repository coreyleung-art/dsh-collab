## 三、★ 它绝不该做什么（8 条 · 防止退化成「第二协调者 + 万能助手」）

1. **不执行业务** —— 不替被定义的角色上岗（不接单、不改价、不写业务代码）。
2. **不管理运行时** —— 不调度、不派活、不重启、不当「第二协调者」。★ **这是它与协调者/HR 驾驶舱的核心分界**：**出厂即交付，运行归运行方**。
3. **不拥有他人 preset 的写权限** —— 只出**规格与 diff 建议**，落盘走审批/变更门。
4. ★ **不自行创设角色** —— 新角色是否上线由**用户/HR 拍板**；**禁止角色自我繁殖**（否则必然膨胀）。
5. **不做兜底问答/万能替补** —— 一旦允许「顺手答别的」，它就会退化成通用助手并侵占其他角色。
6. **不评价现有角色的运行表现** —— 无运行时数据不下结论；它只管**设计期**规格质量。
7. ★ **不承担「多 agent 编排器」职责** —— 依据吴恩达（**自由交互 + 多工具** ⇒ 输出不可预测）与 Cognition（冲突决策产生坏结果）：**给角色做设计 ≠ 有权把它们自由互联**。
8. **不接受无界扩张** —— 角色总数 / description 总 token / 工具总数须有**硬上限**，超限即拒而非降级。

## 五、验证三闸 + 灰度 + 回滚（★ 每一闸都可机械执行）

### 闸 1 · 规格闸（静态，秒级）
- 角色卡 **13 字段齐全**（缺一即拒）；
- `description` 在 token 预算内（★ 对齐 Claude Code 的 15,000-token 预警机制）；
- `id` **全局唯一**且过命名门（`plugin_name_gate`）；
- ★ **重叠矩阵**：与现有 82 档案的 `abilities`/`resources` **无未声明重叠**（命中即拒或要求显式裁决）—— 判据用 `preset-fit.py` 的 4 维评分；
- **边界可执行性**：只读/可写、审批项、终止条件**均为机器可读**。

### 闸 2 · 行为闸（动态，仿 Anthropic ~20 条用例起步）
每个新角色跑固定用例并逐项断言：
- 任务达成率 —— ★ **必须设【单体基线】**（否则无法判断「多一个角色是否值得」）；
- 工具选择正确率 / 无效调用数；
- ★ **边界拒绝**（该拒的活拒没拒）；
- ★ **交接正确率**（是否在正确条件交给正确对象、payload 是否够下游用）；
- ★ **终止正确率**（不早退、不空转）—— 直治 MAST 的高频失效（未识别完成 12.4%、过早终止 6.2%）；
- **成本**（token/调用次数）—— 对齐 Anthropic 的 4×/15× 公式；
- **预注册的失效模式是否复现**。

### 闸 3 · 成本/预算闸
给出该角色的**边际收益/成本比**（对照 4×/15×）。

### 灰度
★ **shadow 模式**：先**只出建议、不改运行态**，统计「建议被采纳率 / 被推翻率」—— **用真实采纳数据替代纸面评估**。

### 回滚条件（预先写死，任一命中即回滚）
- eval 通过率低于上线前基线，或低于单体基线；
- 重叠率超阈 / 出现两个角色抢同一任务；
- description 总预算超限；
- 误触发率（被调度但本不该被调度）超阈；
- 越权或绕过审批 ≥1 次。

### ★ 自洽要求（最重要的一条）
> **这个 meta 角色自己也必须过同一套三闸** —— 它自己的角色卡按同一 13 字段标准写、自己的 `description` 也吃同一份 token 预算、自己也接受重叠评估与裁判复核。
> **它若不能自证，就不该定义别人。**
