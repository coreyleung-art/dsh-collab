> 明鉴 v2 · 2026-09-02 · 用户指示：把自研的通讯协议、门和锁的关系独立出来展示
> 范围：核心机制（协议+门+锁）；J1-J44 资源锁为扩展项（另表）
> 用途：盘点先行 → 后续决定是否入蓝图管理器独立 Tab

## 〇、三类资产定义

| 类型 | 定义 | 示例 |
|------|------|------|
| 🔗 **协议 Protocol** | 通讯/传输/迭代的**流程约定**——怎么做（步骤/通道/回滚） | CCEP / 黑板协议 / agent-bus / 重启救援 / 升级备用 |
| 🚪 **门 Gate** | 放行前的**校验关卡**——什么条件才允许继续（硬性检查） | restart-gate / 插件自查门 / dev-sandbox / rule-judge L1-L3 / J45 分级 |
| 🔒 **锁 Lock** | 执行权的**授权闸门**——谁能做/何时授权（权限开关） | R027 人开关锁 / R029 分级锁 / 红绿灯互斥 / Lean4 逻辑锁 |

**关系链**：`协议(怎么做) → 门(条件够吗) → 锁(授权谁做) → 执行`
门=静态校验；锁=动态授权。门与锁常组合（如 rule-judge 判门 + R027 授权锁）。

## 四、关系链（协议→门→锁→执行）

```
通讯层     校验层       授权层       执行层
CCEP ─────→ 端侧就绪门 ─→ (无锁,信任) ─→ 通道切换
黑板协议 ──→ agent_send门禁 ─→ ──────→ 黑板写入(R003)
agent-bus ─→ (红绿灯内嵌) ─→ 红绿灯锁 ─→ 跨会话操作
规则评审 ──→ rule-judge L1-L3 ─→ R027 人开关 ─→ 自动化实施
原语操作 ──→ J45 分级门 ─────→ R029 分级锁 ─→ 运营原语
CLD 重启 ──→ restart-gate ───→ (守望 pre-change) → 重启
插件安装 ──→ J37 验证门 ─────→ dev-sandbox 锁 ─→ 挂载生产
```

## 五、核心洞察（为什么独立展示有价值）

1. **门与锁常被混淆**——门=校验条件(静态)，锁=授权(动态)。如 rule-judge 是门，R027 是锁，两者配合但职责不同
2. **协议是流程、门锁是开关**——CCEP 讲怎么做，restart-gate 讲何时能，R027 讲谁授权
3. **三类均有「默认拒绝」哲学**：门不过=停，锁不开=禁止——与 R027「生产区默认 OFF」一致
4. **Lean4/类型级保证**：R027/R029 已用类型系统锁死（无 Authorization 无法构造 Unlocked）——门锁可升级为编译期保证
