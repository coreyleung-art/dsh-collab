# R006 第十项提案 · Lean4 约束门(constraint-gate)

> 提案人: 明鉴 v2 · 2026-09-06 · 走 R008 规则流程(提交→总线审核→裁决评估→吸收→同步)
> 背景: 用户本会话完成"全工作流 Lean4 逻辑门审查改造"(W1-W10 达 L2), 要求把 Lean4 逻辑纳入 R006 九标准扩为十项

## 一、提案定义
**第 10 项: 约束前置 · 不可绕过(Lean4 逻辑门)**
凡工具/规则涉及"不该发生的路径"(违规写/越权/跳步/非法引用), 约束不得靠文档/自觉/事后检查,
须前置为**结构上不可绕过**(类型锁/入口门/schema 门/状态机), 且工具须带 `--lean4-check` 自检证明门生效。

## 二、验收对照(mark)
| 维度 | 判据 |
|------|------|
| 结构门 | 违规路径被 API/工具结构拒(实测可复现) |
| lean4-check | 工具带 --lean4-check: 断言门的拒绝路径(试一次违规应返回拒) |
| 状态类型 | 涉及状态转换的不跳步(如五步门) |
| 写前校验 | 涉及写数据的过 schema/契约校验(非法引用拒) |
| 审计 | 结构性写操作带 auth/留痕 |

## 三、实例(本会话已验证的)
- 连接五步门: 不可跳步(evaluate→approve 逐级, approve 跳步拒)
- merged 写关系: 连 ghost-bp(未注册蓝图) → 契约拒
- execute 通知: 非法 agent → 契约拒
- manager-event: 未知事件/非法级别 → schema 拒
- schema-gate.py: 规则引用/关系端点/蓝图字段 契约校验

## 四、生效后影响
- 新工具交付: 9→10 项全达标(工具涉及"不该发生的路径"时必须有结构门 + --lean4-check)
- 存量工具: 逐步补 --lean4-check(可按 todo-eval 排)
- 对应 R006 版本 1.1 → 2.0
