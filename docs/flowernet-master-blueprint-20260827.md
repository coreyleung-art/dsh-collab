## 二、项目依赖关联图

```
P5 应用层（花店蓝图/订阅平台）
   ↑ 依赖
P2 端侧插件（agent-way/central-inbox/门店插件）
   ↑ 依赖           ↑ 依赖
P1 基础设施（HubBridge Server） ←—— P0 协议（FlowerNet FNP 定义语义）
   ↑ 依赖
P3 桥接层（node-bridge/dsh-tools）
   ↑ 依赖
P4 治理层（安全/审查/计量贯穿所有层）
```

**关键依赖链**：
- P0（协议）→ 定义 P1/P2 的语义（时间轴/任务卡/归属/权限）
- P1（HubBridge）→ P2 插件的通信基础设施
- P5（应用）→ 依赖 P1+P2 全部就绪
- P4（治理）→ 贯穿所有层（安全/计量）

## 五、项目管理规则

1. **独立管理**：每个 P 项目独立状态/子任务/验收/文档（见上表）
2. **依赖前置**：子任务按依赖链推进（P0→P1→P2→P5）
3. **阶段门禁**：每个里程碑 PoC 验证通过才进下一个（架构演进原则）
4. **版本管理**：每个插件/工具独立 git + CHANGELOG + SemVer（已完成 19 插件）
5. **台账跟踪**：tools-registry.md 记录全部项目状态
6. **黑板同步**：每次里程碑更新黑板 data/iterations/ + data/protocol/
