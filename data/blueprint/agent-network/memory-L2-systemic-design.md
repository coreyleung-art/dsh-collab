# 内存治理 L2 · 体系化内存持久化设计（未来·知识层）

> 明鉴 v2 · 2026-09-02 · 用户分层洞察的「第二部分」深化
> 定位：层1 工具链内存治理（M1-M3，现时效率）之外的 **整个体系的长期记忆架构**
> 关联：memory-two-layer-design.md（分层总纲）· blueprint:agent-network 主蓝图

## 〇、为什么需要 L2（层1 治不了的问题）

层1（compaction/pruner/批处理）解决「单会话上下文只增不减」，但它有结构性盲区：

1. **压缩即遗忘**——层1 把旧内容压成摘要，摘要外的关键决策/教训随会话归档丢失；跨会话后无人记得
2. **记忆孤岛**——每个 agent 的记忆长在自己的会话里，OpenChronicle/黑板/KB/Obsidian 四套资产各自为政，无统一写入/检索/遗忘规则
3. **无生命周期治理**——什么值得记/记多久/何时忘/谁可读，目前靠各 agent 自觉，无体系约束
4. **无知识复利**——体系运行一个月产生的决策/教训/数据，未沉淀成「越用越聪明」的集体记忆

**L2 = 把 20+ 智能体会话、4 套记忆资产、跨设备（mac-mini/i9/MBP）的记忆，治理成一个有分层、有归属、有生命周期、可检索复利的体系。**

## 一、L2 参考架构：记忆五层模型

```
┌─────────────────────────────────────────────────────────┐
│ L2-0 记忆消费面：agent 推理时怎么取记忆                     │
│   常驻前缀(约束/身份) + 近期原文(本会话) + 滚动摘要(会话级)    │
│   + 语义检索(体系级) + 按需拉取(记忆工具)                   │
├─────────────────────────────────────────────────────────┤
│ L2-1 会话记忆层（现存·层1 管辖）                           │
│   会话 transcript / compaction 摘要 / checkpoint          │
├─────────────────────────────────────────────────────────┤
│ L2-2 工作记忆层（现存·需治理）                             │
│   黑板 KV（data/* 命名空间）· 迭代报告 · 任务卡 · 队列      │
├─────────────────────────────────────────────────────────┤
│ L2-3 结构化记忆层（现存·需统一入口）                        │
│   OpenChronicle(感知/当下) + 黑板 changelog(事件/决策)      │
│   + KB 8 库(语义/研究) + Obsidian wiki(编译知识)           │
├─────────────────────────────────────────────────────────┤
│ L2-4 归档与遗忘层（缺失·需建）                             │
│   冷存储规则 / TTL / 归档清单 / 遗忘审计（数据治理）         │
└─────────────────────────────────────────────────────────┘
```

**核心洞察：层1 管 L2-1，L2 管 L2-2/3/4——层1 压缩出的摘要 = L2 固化（promote）到长期记忆的候选输入。**

## 二、L2 记忆资产现状盘点（2026-09-02 实测）

| 资产 | 载体 | 内容 | 现状 |
|------|------|------|------|
| OpenChronicle | ~/.dsh/openchronicle/captures/ | 每日感知捕获 capture-2026-08-27…09-02 | 7 天有记录·无检索治理 |
| 黑板 | 127.0.0.1:8792 | data/blueprint·data/iterations·events 事件流 | 事件流有 timeline 无「决策记忆」索引 |
| DSH KB | ~/.dsh/storages/knowledge.json | **8 库 547 文档**：waimai 运营/ops-science/paper-cache/poi-cache/flower-price/zhaoshang/rust-network | 库多·无跨库目录 |
| Obsidian | iCloud vault | raw/ + wiki/ + 日记 三层（LLM wiki 模式） | 29 文件级·wiki 索引存在 |
| 会话存档 | ~/.dsh/sessions | 各 agent 持久化会话 | 压缩摘要可固化 |
| agent-bus | ~/.dsh/agent-bus.json | 跨会话消息/线程历史 | 有归档式 queue-drain |

**缺口：① 无「统一记忆写入入口」（各资产各写各的）② 无「promote 规则」（什么该从会话/黑板固化到长期）③ 无「体系级检索」（要跨 4 资产查需人工逐个找）④ 无遗忘治理。**

## 三、L2 子阶段规划（入 agent-network 蓝图 v1.2）

### MG4 记忆写入治理 [todo]
- mg4-1 写入入口统一 [todo] — 记忆写入 3 通道收敛：迭代报告(已规范)→黑板+KB 双写；决策教训→L2 断言/lessons 库；感知→OpenChronicle（勿散落）
- mg4-2 固化 promote 规则 [todo] — 明确「什么值得固化」：跨会话要用的结论/可复用的教训/用户定案/指标基线——产出 promote 判定清单（对齐 rule-judge L2 断言模式）

### MG5 体系检索 [todo]
- mg5-1 记忆索引目录 [todo] — 4 资产统一目录（memory-registry）：记录每资产内容/更新时间/检索方式——对齐 message-registry 模式
- mg5-2 跨库检索面 [todo] — 先人工/脚本聚合检索（knowledge_search + oc_search + 黑板 grep 三合一 CLI），后评估向量统一索引

### MG6 生命周期与遗忘 [todo]
- mg6-1 记忆分级 TTL [todo] — 分级：常量(规则/身份/授权，永久) / 长时(定案/教训，年) / 短时(过程数据，季度) / 瞬态(队列/消息，周)——对齐 R027 授权档案
- mg6-2 归档与遗忘审计 [todo] — 冷存储规则+归档清单+定期遗忘审查（数据治理：不无限膨胀）

### MG7 记忆复利（L2 北极星） [todo]
- mg7-1 决策-教训闭环 [todo] — 每阶段复盘：失败/教训 → L2 断言库（对齐教师节 5 教训入 rule-judge L2）→ 后续自动拦截
- mg7-2 记忆体检 [todo] — 周期检查：固化率（会话→长期实际沉淀比例）/检索命中/过期清理——量化「体系越用越聪明」

## 四、L2 里程碑（验收标准）

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| M1 | MG4 写入治理落地：3 通道收敛 + promote 清单 v1 | 两周新决策 80% 可在记忆资产找到出处 |
| M2 | MG5 检索面可用：memory-registry v1 + 聚合检索 CLI | 单命令跨 4 资产查「教师节教训」3 秒内出结果 |
| M3 | MG6 生命周期落地：分级 TTL + 首次遗忘审计 | 记忆资产增速受控，无无限膨胀项 |
| M4 | MG7 复利可见：决策-教训闭环 + 记忆体检报告 | 教训拦截命中 ≥1 次/月；体检报告出「固化率/检索命中/清理量」 |

## 五、与既有体系的衔接

- **rule-judge**：mg4-2 promote 清单 / mg7-1 教训闭环，直接复用 L2 断言模式（断言=可机械判定→可自动拦截）
- **R027 授权**：mg6-1 分级 TTL 中「授权档案=长时记忆」——人类批准过的开关/授权是体系级长时记忆，不得被压缩遗忘
- **OpenChronicle**：感知记忆 = L2-3 中「当下」子层——每日 capture 已有，需纳入统一目录与 TTL
- **文汇/守灯塔**：知识摄取已有管道，L2 不重建，只补「统一目录 + promote + 遗忘」三治理面
- **层1→层2 衔接**：compaction 摘要中符合 promote 判定的条目 → 自动/半自动固化到黑板 changelog 或 lessons 库
