## 〇、先说清：为什么需要一个"推理引擎"

**要解决的问题**：公司做重大决策时（选哪个市场地位、走重资产还是轻资产、加人还是压 AI、钱怎么花、股权怎么设计），最常见的做法是"拍脑袋"或者"谁嗓门大听谁的"。这样做的坏处是：
1. **不可复现**——换个时间、换个人，结论就变了；
2. **不可追溯**——说不清"为什么这么定"；
3. **容易自欺**——把"我希望是这样"当成"事实是这样"；
4. **看不到代价**——只看见选中那条路的好处，看不见被放弃那条路的损失。

**推理引擎要做的**：把"决策"变成一道**可以按固定步骤走、可以复盘、可以把代价摆出来**的题。它不保证结论一定对（没有任何方法能保证），但它保证**推理过程是透明的、可被质疑的、可以被数据修正的**。

**一句话定义**：**推理引擎 = 一套把"可能性"摆开 → 逐条比较 → 排序 → 说清代价的方法 + 工具 + 记录。**

## 一、引擎设计：四步方法（每一步是干什么的）

### 第①步：第一性穷举（先把可能性摆开，不急着选）

**做法**：先画价值链（这个行业从上游到下游有哪些环节），然后问一个问题——**"在价值链的哪一环、用什么方式，我能卡成一个别人绕不开的位置"**。沿着这条链，把**所有可能的"地位"穷举出来**（不是问"怎么赚钱"，而是问"卡住哪一环"）。

**为什么要这一步**：人在做选择时，天然倾向于在"自己已经想到的几个选项"里选。**穷举的作用是强制把视野打开**——例如我们做鲜花项目时，穷举出 10 种可能的地位（供应链整合者、零售连锁、平台服务商、数据底座、工具供应商、IP 品牌、牌照卡位、资本并购、跨行业 AI、消费者品牌）。**如果不穷举，很可能一开始就盯错了方向。**

**输出**：一份可能性的清单（每种写清：是什么、凭什么、难度多大）。

### 第②步：反向推演（从终点倒着想）

**做法**：从"我想要达到的终点"出发，**倒着推前置条件**——要到那个终点，我必须先拿到什么？要拿到 A，必须先有 B；要拿到 B，必须先有 C。一路倒推到"现在能做的事"。

**为什么要"反着推"**：正向思考容易变成"我现在有什么，那我能做什么"（被现状限制）。**反向思考是从目标出发，看"目标和现实之间的差距是什么"**——这样才能说清"第一步到底该干什么"。例如从"2030 上市"倒推，得出的前置条件是：资格（牌照）→ 数据（单店回流）→ 战绩（平台增量）→ 能力（AI 工具）→ 资本。**倒推完才发现，"第一步"不是融资，而是先拿资格、跑战绩。**

**同时要找"分水岭"**：哪一关打赢了才能上台阶（例如"单店单位经济为正"就是第一道分水岭）。

**输出**：一条从"现在"通往"终点"的分阶段路径 + 每一阶段要拿到的东西 + 分水岭。

### 第③步：价值再评估（把可能性排序）

**做法**：把第①步穷举出来的所有可能，用**同一套标准（六维，见下节）**逐条打分，然后排序、分档（S/A/B/C）。

**为什么要"同一套标准"**：如果每个选项用不同标准评价，就无法比较（"这个赚钱多但难，那个容易但不赚钱"——到底选哪个？）。**统一标准 = 强行把不同维度的好处与代价换算到一把尺子上。**

**输出**：一张排序表 + S/A/B/C 分档。

### 第④步：资本与赢法（钱从哪来、怎么赢、按什么顺序）

**做法**：对排在前面的选项，回答三个问题：①**需要多少钱、从哪来**（自有现金流/融资/银行/并购/资源作价…）②**赢的杠杆是什么**（靠什么用更少的钱做更多的事）③**按什么顺序做**（先做什么后做什么）+ 纪律（什么不做）。

**为什么要单列这一步**：一个地位再好，如果"钱不够、顺序错了"，也做不成。**这一步把"战略"翻译成"资本与节奏"。**

**输出**：资本介入方案 + 杠杆 + 次序 + 纪律。

## 二、评分依据：六维框架（每一维测什么、怎么打分）

### 2.1 六个维度及其权重

| 维度 | 权重 | 这一维在问什么 |
|---|---|---|
| **护城河深度** | **30%** | 别人能不能复制、能不能替代？我做成之后，后来者要花多久才能追上？ |
| **天花板** | **20%** | 如果做到极致，这件事最大能有多大？（市场空间 × 我的份额上限） |
| **可进入性** | **15%** | 以我们现在的资源与能力，能不能进得去、能进多深？ |
| **资本化效率** | **15%** | 需要投多少钱？能不能用杠杆（借力、复用、伙伴出资）更快上？ |
| **现金流健康** | **10%** | 能不能自己养活自己（现金流自转）？还是必须靠不断融资烧钱？ |
| **风险** | **10%** | 政策、市场、执行的确定性有多高？（这一维分越高 = 风险越低） |

### 2.2 为什么权重是"30/20/15/15/10/10"

这不是随手定的，而是一条**明确的价值观**：

- **护城河给最高的 30%**——因为**这门生意要做成"能长期存在"的，核心是"别人抢不走"**。赚钱但随时能被复制的生意，天花板再高也不牢。所以我们把"护城河"排第一。
- **天花板 20%**——排第二，因为**再牢的护城河，如果空间太小也没意义**（例如只做一个城市的某类目，再垄断也有限）。
- **可进入性 15% + 资本化效率 15%**——这两维是"能不能干得成"的现实约束。**一个我进不去的、或者要砸巨资才能进的机会，即使护城河再深也要打折。**
- **现金流健康 10% + 风险 10%**——放在最后，**不是不重要，而是因为它们是"约束条件"而不是"目标"**：现金流差、风险高，会在前四维的分数里体现出来，所以权重给得低一些，避免"为了安全而错过机会"。

### 2.3 每一维怎么打分（0-10 分的锚点）

为了让打分不至于变成"感觉"，每一维都有可对照的锚点：

| 维度 | 高分（8-10）长什么样 | 中分（5-7） | 低分（0-4） |
|---|---|---|---|
| **护城河** | 需要长期积累才有的东西（独家数据、牌照 + 规模、行业 know-how 复合体）；后来者追不上 | 有一定门槛（技术、渠道、先发），但能被复制 | 谁都能做（纯执行、通用工具、批发转手） |
| **天花板** | 面向全国/全行业，可复制到多个城市与品类 | 单区域或单品类，规模有限 | 单点、单客户、不可复制 |
| **可进入性** | 现在就有资格、有团队、能马上起步 | 需要补资源（资金、人、牌照）才能进 | 缺关键资格或能力，短期进不去 |
| **资本化效率** | 轻资产、能借力（平台/伙伴/租赁）、边际成本低 | 需要一定投入但可控 | 重资产、重投入、回本慢 |
| **现金流健康** | 能自转、有正向现金流、不依赖持续融资 | 打平或需要少量补贴 | 持续烧钱，靠融资续命 |
| **风险（越高越安全）** | 政策稳、市场确定、执行路径清晰 | 有一定不确定性但可控 | 政策依赖强、单一依赖（如只靠一个平台） |

### 2.4 打分的纪律（三条，很重要）

1. **分数是"独立分析判断"，不是客观测量值**——所以我们在每份结果上都写明："**以上分数为独立分析判断，可调；重点看排序逻辑而非绝对分**"。**我们从不主张"8.3 分"是真理，我们主张的是"在同样的标准下，A 比 B 更适合我们"这个排序关系。**
2. **分数可调，但标准不可换**——允许讨论"某一维该给 6 还是 7"，但不允许"对某个选项换一套标准"（那是自欺）。
3. **不能让"我希望"影响打分**——如果发现某个选项被"感情分"抬高了，必须调回。这也是为什么我们要做**"空跑 vs 数据跑"两轮对照**（见第四节）。

## 三、分档与解读

### 3.1 分档阈值

| 档 | 分数区间 | 含义 |
|---|---|---|
| **S** | ≥ 7.0 | 强烈建议优先做（通常作为主攻方向） |
| **A** | 6.2 - 6.9 | 可以做，但适合作为第二曲线或条件性推进 |
| **B** | 5.5 - 6.1 | 暂不做（或等条件成熟再做） |
| **C** | < 5.5 | 不建议做（通常是重资产、低护城河、或被现实约束堵死的路径） |

### 3.2 怎么解读分档（三个必须注意的点）

1. **档位是"优先级"而不是"好坏"**——一个 B 档的选项不代表它"不好"，只代表"在我们的资源与时机下，它排在后面"。例如零售连锁是 B/C 档，不是因为它不是好生意，而是因为**它和我们"用现金流自转、轻资产起步"的路线冲突**。
2. **排序比分数重要**——我们真正用来做决策的是"谁排在谁前面"，不是"它是 7.3 还是 7.5"。**分数会随着新事实变化，但只要排序稳定，决策就成立。**
3. **要警惕"全部高分"**——如果十个选项全是 S 档，说明标准太松或打分不严。我们出现过不少 A/B/C 档，这才是正常的。

## 四、三种跑法（怎么让结论经得起检验）

| 跑法 | 做法 | 它检验什么 |
|---|---|---|
| **①反向跑** | 从终点倒推前置条件 | 检验"路径是否成立"——目标有没有可能达到、第一步该做什么 |
| **②空跑（无数据）** | 先不看真实数据，凭框架与常识打分 | 得到一个"抽象基线"——**防止我们被手头数据的细节带偏** |
| **③数据跑（注入真实数据）** | 把真实业务数据（实测人效、AI 省时、订单结构、用户画像）填进去重跑 | 检验"抽象判断是否成立"——**真实数据往往会加分，也会纠正误判** |

**为什么必须做三轮而不是一轮**：
- 只做"空跑"，结论容易停留在想象；
- 只做"数据跑"，容易被现有数据的偏差带跑（数据只反映已经发生的事）；
- **两轮对照的最大价值，是让我们看见"真实数据把哪些以为最优的选项纠正成了真正最优的"。**

**一个真实例子（写在这里作为方法有效的证据）**：IP 业务线在空跑时，"收藏卡/盲盒类包装"排第一；注入真实数据后，"女性向高热度 IP"反超成为第一——因为真实数据证实了用户画像中**女性占 74%**，女性向 IP 的匹配度被数据验证了。**这说明"用数据校正判断"不是口号，它真的会改写结论。**

## 六、诚实红线（这套方法的"防腐剂"）

引擎自带四条纪律，任何一条被破坏，结论就不可信：

1. **测算 ≠ 验证**——凡是会议口径、模型外推，一律标"测算"；只有真实财务和订单回填，才允许标"已验证"。
2. **文档冲突必须标出**——不同版本的资料数字打架，必须点明，不准假装一致。（本项目的实际例子：种子预算 G 类出现过 44.5 万 / 58 万 / 75 万三个版本，我们裁定取 44.5 万——因为**只有它能让九类合计恰好 = 1000 万元**，其余版本已作废。）
3. **来源不明必须标注**——没有公开信源的数字，标"待考证/需补信源"。
4. **资产归属必须核实**——"牌照/资源"到底在不在自己名下，不核实就推演等于自欺。（本项目的实际例子：两张牌照目前都在合作方名下，这件事被明确写进计划书，没有回避。）

**并且工具里内置了"约束门"自检**：当有人试图把"测算"冒称"已验证"、或提交未核实的结论时，**引擎会拒绝**——这是用工程手段保证诚实，而不是靠自觉。

## 七、可复现性（为什么这套结论可以被别人验证）

1. **每一步都有记录**——30 多次推演的结果都自动落盘存档（`deliverables-wargame/`，33 份），任何一次都能翻出来看当时的备选与排序。
2. **工具是命令行程序**——任何人拿到这份方法与记录，可以重跑：`wargame-sim.py` 有 `enumerate / reverse / value / capital / run / lean4-check` 六个命令。
3. **有可复用模板**——方法被整理成模板（四步方法 + 六维框架 + 九类清单 + 三跑法 + 诚实红线），**换个项目也能直接套用**。

## 八、能力边界（这套方法不能做什么）

诚实地划清边界，比吹嘘能力更重要：

1. **它不能替你决定价值观**——权重（护城河 30%、天花板 20%…）本身就是一种价值观选择。如果你的价值观不同（例如更看重短期现金流），权重就该调整，结论也会变。
2. **它不能给出"绝对正确"的分数**——分数是判断，不是测量。它的价值在于**排序与代价透明**，不在于数字精确。
3. **它不能替代验证**——**推演出来的"能行"不等于"真的能行"**。这正是我们把"把测算变成验证"定为第一阶段头号任务的原因。
4. **它不能替代专业意见**——法律条款、税务处理、平台规则，必须由专业律师、会计师和平台官方口径确认，引擎只负责把问题结构化。
5. **它不能消除不确定性**——它只能让不确定性**被看见**、被定价、被安排应对（例如用对赌条款兜住牌照风险），而不能让它消失。

---

## 九、一句话总结

> **推理引擎 = 把"拍脑袋决策"变成"可复现推演"的方法。**
> 它用**四步**（穷举 → 反向 → 价值 → 资本与赢法）把可能性摆开，用**六维**（护城河 30 / 天花板 20 / 可进入 15 / 资本效率 15 / 现金流 10 / 风险 10）把不同选项换算到一把尺子上，用**三种跑法**（反向、空跑、数据跑）让结论经得起检验，用**四条诚实红线**防止自欺。
> **它保证的不是"答案对"，而是"推理透明、可被质疑、可被数据修正"。**
