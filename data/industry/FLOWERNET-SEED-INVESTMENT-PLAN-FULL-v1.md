> 口径统一：**实测** = 真实业务数据（人效 6-8 店/人、AI 省时 60-98%、成都 15% 份额）；**测算** = 其余。

| 项 | 内容 |
|---|---|
| **募集金额** | **1000 万元人民币** |
| **出让比例** | 15-20%（**测算**【待各方协议确认】） |
| **投后估值** | **5000-6667 万元**（= 1000 万 ÷ 15~20%）【待确认】<br>**⚠️ 估值说明**：该区间不是传统估值法的结果，而是**由「融资额 ÷ 出让比例」倒推得出**；依据 = 成本法（重置成本）+ 可比参照 + 里程碑链起点（详见《各轮次 Term Sheet 汇总》第〇节） |

| **出资形式** | 梁振宇真实出资（部分由背后 LP 协助）+ 梁振宇 sweat（非出资股权，按贡献计价） |
| **用途** | 把**成都单店经济模型跑正** + **数据底座地基打好** + **能力层搭起来**，从而拿到 Pre-A 资格 |
| **周期** | 覆盖约 12 个月（种子期） |
| **验收** | 8 项验证标准（见第六节），核心是**单店单位经济跑正（从测算→验证）** |

**为什么是"自己人/股东借资"而不是外部投资人**：
1. **种子阶段的不确定性最高**（平台授权一年一签、单位经济未验证）——**用自己人的钱，快、灵活、不用做太多承诺**；
2. **避免过早稀释与过早承诺**（种子估值低，出让同样的钱会让出更多股权；且外部投资人会要求更严的条款）；
3. **保留后续轮次的谈判空间**（Pre-A 时公司已有真实验证数据，估值与条款都会好得多）。

## 二、资金结构与权利安排

### 2.1 出资结构（双层有限合伙）
```
【上层 · 有限合伙】
   梁振宇 = GP（普通合伙人）——负责经营控制
   背后出资方 = LP（有限合伙人）——出钱、拿收益、不干预经营
        ↓ 上层持有下层 51% 表决权
【下层 · 运营公司（合资主体）】
   上层有限合伙（梁振宇经 GP 控制）= 51% 表决权
   橙果 = 现金出资 + 全国牌照/流量权（作价·分开计价）
   声通 = 城市合伙人牌照（作价·每城可能不同主体）
```
**技术要点**：GP 承担无限连带责任 → **用一家有限责任公司担任 GP** 以隔离个人风险。

### 2.2 出资方的权利（种子轮）
| 权利 | 内容 |
|---|---|
| **安全退出** | 保底回购（本金 + 年化 8%）+ 优先清算 + 业绩对赌 + 反稀释（加权平均）+ 每轮退出权 |
| **收益分配** | 按约定比例分享公司估值增长（不是只拿固定收益） |
| **信息权** | 定期获取经营报表（范围与频率【待确认】） |
| **不干预经营** | **这是它获得上述保护的前提**——LP 不进经营层 |

### 2.3 出资方的义务与限制
- **不干预经营**（不参与日常决策、不进驻经营层）；
- **回购义务在公司层面，梁振宇个人不兜底**（⚠️ 这意味着：LP 的安全底线依赖"**公司有资产/有现金流**"，而不是依赖梁振宇个人信用——**这一点出资方必须在签字前看清**）。

## 四、资金的时间分布（什么时候花）

> 以下为**测算的季度分布**（实际按进度调整）。

| 季度 | 主要花什么 | 约占 |
|---|---|---|
| **Q1（第 1-3 月）** | **启动与地基**：公司注册/双牌确权（G）、设计师双环境工作站（H5）、云资源开通（I）、合规建立（B2）、端口方案设计（B1 部分）、运营主管与 FDE 招聘（F 启动）、平台关系（A1） | **约 25%** |

## 五、资金释放与里程碑挂钩（建议机制）

> **⚠️ 以下为建议机制，具体以各方协议为准。**

| 释放批次 | 触发条件（建议） | 释放比例（建议） |
|---|---|---|
| **第一批** | 签约即释放（启动公司注册、双牌确权、环境搭建） | 30%（约 300 万） |
| **第二批** | 达成"**环境就绪 + 合规方案成文 + 端口方案确定**" | 25%（约 250 万） |
| **第三批** | 达成"**采集器封装完成 + 试点落店通过平台风控 + 中央汇聚跑通**" | 25%（约 250 万） |
| **第四批** | 达成"**单店单位经济跑正（真实财务验证）**" | 20%（约 200 万） |

**为什么建议分期释放**：
1. **对出资方**：每一笔钱都对应一个可验证的成果，降低"钱花完了但没结果"的风险；
2. **对公司**：强制"每一批钱只干一批事"，避免超前花钱；
3. **对梁振宇**：里程碑清晰，避免"钱在手上就忍不住花快"。

**⚠️ 如果出资方希望一次性到位**（更简单的做法）：则需配套**更强的信息权与预警机制**（如月度报表 + 超支预警 + 关键节点确认）。

## 六、1000 万花完必须达到什么（验收标准 8 项）

| # | 验收项 | 是"验证"还是"测算" | 谁验收 |
|---|---|---|---|
| 1 | **单店单位经济跑正（真实财务验证）** | **从测算 → 验证**（第一道分水岭） | 出资方 + 财务 |
| 2 | 数据端口 P1 稳定运行（订单 43 列 + IM + 评价） | 验证 | 出资方 + 技术 |
| 3 | 合规清单 100% 成文 + PII 隔离到位 | 验证 | 出资方 + 律师 |
| 4 | **采集器封装完成**，新店部署不需工程师到店 | 验证 | 出资方 + 技术 |
| 5 | 能力层三层分工搭起（梁振宇设计 + FDE 落地 + 智能体执行） | 验证 | 梁振宇自评 + 出资方 |
| 6 | 设计师生产级双环境就位（能跑 agent 设计/编排） | 验证 | 梁振宇自评 |
| 7 | 成都样板 SOP 可复制（含代运营承接八步） | 验证 | 出资方 + 运营 |
| 8 | **达到 Pre-A 的融资条件**（用真实数据写融资材料） | 验证 | 出资方 + 梁振宇 |

**换句话说**：**1000 万买到的是"从『测算』跨到『验证』的资格"**——跨过去，Pre-A 才有得谈；跨不过去，后面所有轮次都不成立。

## 七、风险与保护（出资方视角）

| 风险 | 表现 | 出资方保护 | 公司侧应对 |
|---|---|---|---|
| **牌照风险（最大）** | 两张牌照不在公司名下、平台授权一年一签 | 若牌照层面重大不利 → 触发**业绩对赌/优先清算** | 40 万确权预算 + 对赌条款（牌照出问题由牌照方补偿/让渡） |
| **单位经济未验证** | 所有金额仍是测算 | **里程碑验收 + 分期释放**（第四批绑定"单位经济跑正"） | **把测算变验证定为头号任务** |
| **平台政策变化** | 返佣/活动规则变更影响单店经济 | 业绩对赌 + 反稀释 | 平台关系维护 + 单店模型压力测试 |
| **合规风险** | 触碰个人信息（PII）→ 顶格处罚 | 合规是红线（B2 预算专款专用） | 先立规矩再采集 + 匿名化 + 审计 |
| **执行风险** | FDE 招不到 / 封装做不出来 | 分期释放（第三批绑定"封装完成"） | 本周启动招聘；找不到用外部合作 + 梁振宇带 |
| **资金安全** | 公司把钱花完没结果 | **保底回购（本金+8%）+ 优先清算 + 反稀释 + 每轮退出权** | 预算台账 + 季度对账 |

**⚠️ 一条必须看清楚的**：**回购与补偿义务在公司层面，梁振宇个人不兜底**——所以出资方的安全底线依赖"**公司有资产/有现金流**"，**不是依赖梁振宇个人信用**。这也是为什么"分期释放 + 里程碑验收"对出资方尤其重要。

## 八、与后续轮次的衔接

| 轮次 | 触发条件（建议） | 金额 | 投后估值（测算） |

| **种子（本轮）** | 现在 | 1000 万 | 约 6000 万 |

**核心纪律**：**外部资本只补到 10 城满配（累计约 5000 万）**，剩下 20 城靠 10 城每月约 1200 万经营净现金流滚动——**不为扩张牺牲股权比例**。

**种子的位置**：**种子轮不是"扩张轮"，而是"验证轮"**——它的成功标准是"**证明单店能赚钱、数据能采到、人能搭起来**"，而不是"开了多少家店"。

## 十、口径与依据（诚实声明）

1. **全部金额为测算**——来自会议讨论口径与模型外推（单城投入 180-220 万、打平线 36 万/月、毛利 160-200 万/月等），**尚未用真实报价与财务验证**；
2. **实测数据**仅包括：人效 6-8 店/人（峰值 2-3）、AI 省时 60-98%、成都淘闪约 15% 份额（我方业务口径·无第三方审计）、在管约 750 家、门店侧 IM 回复率 60%；
