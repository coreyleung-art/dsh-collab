## 偏离记录（R006 v3.1.1 ⑨ 要求）

### ⑨ 机器可读输出：命名为 `--json-out`，而非默认的 `--json`

- **偏离内容**：本工具的机器可读输出开关名为 **`--json-out`**（R006 ⑨ 修订条文的默认名是 `--json`）。
- **原因**：`--json` 这个**名字已被本工具既有的非输出用途占用** —— `put <key> --json <JSON>` 是 **payload 输入**通道，
  与 `put --body <文本>` 并列（两个不同通道，不冗余），且**已文档化、已被多会话使用**。强制改名属**破坏性变更**。
- **这正是 R006 v3.1.1 ⑨ 所设的「具名逃生舱」情形**（条文原文：「若该名已被该工具既有的非输出用途占用，
  可用 `--json-out`，但须在 `--help` 与 README 显式声明」）。
- **声明位置（两处均已满足，属主星桥 2026-09-11 实测）**：`--help` 3 处 · README 2 处（我复数为 5 处，见下）。
- **实现方式**：`argv` 预扫描**显式剥离并置位** `--json-out` / `--json`（非 put 子命令）/ `--dry-run`，
  **不依赖 argparse 前缀匹配** —— 后者会因日后新增 `--jsonl` 之类而**静默失效**。
- **兼容性**：除 `put` 外，`--json` 亦被显式接受为等价别名（v1.3.2 起声明于 `--help`）。

### v1.6.0 详情（同晚第二次「单侧落盘」，与 v1.5.0 同机理）

- **触发**：明鉴用**本地文件系统**取真键抽验，发现 `~/dsh-collab/data/registry/bb-write-{selfcheck,deliver-gate}-2026-09-11.json`
  **两侧皆 404** —— 即这两个「落链产物」**根本不是黑板键，只是本机文件**。
- **性质**：**落盘 ≠ 落链**。⑧ 的判据是「跨设备可读」，只写本机文件在观测上**等于没落链**。
  与 v1.5.0 的「只写单侧」**同机理、同晚、同一工具**。
- **★ 同时更正 v1.5.0 的分母错误**：我据「手写 10 键样本全双写」判「双写是惯例」；
  实测全量 `data/registry/*` = **202 键**，**20 双侧 / 182 仅本机** ⇒ 单写本机才是多数。
  我的样本落在那 20 个双侧键里，是**方向确定的取样偏差**（能回忆起的 ≈ 最近被讨论的 ≈ 最近被双写的）。
- **不做什么**：**不**把「双写」设为默认要求 —— 无判据、且与实测多数实践相反；
  单写本机**不判失败**，仅警示。⑧ 断言**只断言 local 侧黑板键回读**。

### v1.5.0 详情（为什么改的是「信号」而不只是「补那两张卡」）

- **触发事实**：明鉴以 `check-key-refs.py` 连试两轮，`notes/mac-mini/hr-reply-criterion-two-halves-20260911` 与
  `data/registry/method-criterion-six-two-halves-20260911` 中央侧**稳定 404**；对照卡 R003 双写成功 ⇒ 不是黑板整体故障。
- ~~**我复验的范围**：`data/registry/*` 我名下 **10 张卡全部** local=200 **且** central=200 ⇒ **既有先例是双写**。~~
  ⚠️ **已作废**（v1.6.1）：真分母是 **204**（不是 10）；**22 双侧 / 182 仅本机**。详见 v1.6.1 条。
  ⇒ 本次两张**是漏写，不是「按设计单写」**。
- **根因**：`put` 默认 `--server local`；**写入成功时对「另一侧没写」零信号** ⇒
  「按设计不写中央」与「忘了写中央」**在观测上不可区分**。这是 **0b 无信号族（潜伏缺陷）**，不是能力缺口。
- **修法（两步，均不改默认行为，避免影响既有调用方）**：
  1. **能力侧** `--server both`：两侧都派发、都回读、都报结论；任一侧失败则整体非零退出，并逐侧打印。
  2. **信号侧**：`data/registry/*` 且用默认 `local` ⇒ 打印**单写警示**（不阻断）。
- **机械核验**（不靠人记得）：`--selfcheck` 新增
  「`both` 双写派发」（**用 `--dry-run` 走完整派发但零变更**，断言两条 DRY-RUN 且 server 各异）
  与「登记命名空间单写警示」**正控 + 反控**（`--server both` 不得误报）。
- **未解决的（不在本条声明为已解决）**：`data/registry/*` 是**我按「规范」设的命名空间判据**（v1.6.1 起不再以「先例」为依据）：
  **尚未成为网络级条文**；`notes/*`、`tasks/*`、`mbp/*` 等是否该双写**未知**，未覆盖。
