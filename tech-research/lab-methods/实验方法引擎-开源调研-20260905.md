# 实验方法引擎 · 开源方案调研（借鉴映射）

> mbp-ops · 2026-09-05 · 目标：为 labforge（实验设计/生成/评估/循环引擎）找可借鉴开源方案，避免重复造轮子
> 结论先行：**不重复造轮子**——采用"轻量自研骨架 + 借鉴开源模式"混合：labforge 保持零依赖 CLI（我们的黑箱约束），但吸收四类方案的设计模式

---

## 一、调研矩阵（四类方案）

### 1️⃣ 自主科研 Agent（最前沿，思想借鉴）
| 项目 | 定位 | 关键可借鉴点 | 重量级 |
|---|---|---|---|
| [Sakana AI-Scientist-v2](https://github.com/sakanaai/ai-scientist-v2) | 端到端自主科研（假设→实验→论文） | **实验管理器 agent + 渐进式树搜索**；v1 模板化（高成功率）vs v2 开放式探索（低成功率但广）——启示：**有强基线时用模板化，开放式才用树搜索** | 重（GPU/LaTeX/Docker） |
| [Kosmos](https://github.com/jimmc414/Kosmos) | 自主 AI 科学家（Claude Code/API 驱动，据 [Lu et al. 2024 arXiv:2511.02824](https://arxiv.org/abs/2511.02824)） | **与我们场景最贴近**：①假设生成 ②实验设计 ③沙箱执行 ④**8 维质量框架验证发现** ⑤**知识图谱追踪概念关系** ⑥自主循环任务生成 | 中（Python+Docker，Claude Code 驱动） |
| [ResearchFlow](https://github.com/devpulse-star/ResearchFlow) | AI agents 自动化科学发现 | 结构化推理 + 工具使用 + 工作流自动化 | 中 |

**借鉴**：labforge 加"假设库"概念（Kosmos 的 knowledge graph 简化版）+ 发现质量多维校验（8 维框架 → 我们的断言=验证维度）

### 2️⃣ 实验生命周期管理（仓库原生，最实用）
| 项目 | 定位 | 关键可借鉴点 |
|---|---|---|
| [g-experiment (wrm3/galdr)](https://github.com/wrm3/galdr) | **仓库原生实验生命周期管理器**（LobeHub skill） | ⭐**最直接可借鉴**：①从模板创建实验+自增 ID ②**HYPOTHESIS.md 登记假设** ③**stage-gates 门禁**（分阶段跑+门检查） ④master EXPERIMENTS.md 登记表 ⑤**autopsy（事后剖析）** ⑥实验链（carry-forward findings） ⑦单变量变更纪律 |

**借鉴**：labforge 补 `HYPOTHESIS.md` 假设登记、`EXPERIMENTS.md` 主登记表（registry.json 已有雏形）、autopsy 报告模板、stage-gates 概念（= 我们的断言即 gate）

### 3️⃣ 实验追踪/编排（ML 工业界标准）
| 项目 | 定位 | 关键可借鉴点 | 取舍 |
|---|---|---|---|
| MLflow | 实验追踪+模型注册 | 追踪 UI/参数记录/artifact | 重（需 server），我们场景过重 |
| DVC + [Hydra](https://github.com/treeverse/dvc/issues/10750) | 数据版本 + 实验编排 | **hydra 组合式配置覆盖**（`dvc repro` 下跑多组参数）；声明式 pipeline | Hydra 的**配置组合/覆盖**思想值得借鉴（labforge 卡片 params 已是雏形） |
| ZenML / Neptune | 全栈 pipeline | 步骤化 + 追踪 | 重 |

**借鉴**：卡片 params = hydra 式可覆盖配置；结果 artifact = MLflow 式按实验归档（results/<id>/<ts>.json 已有雏形）

### 4️⃣ 持续自改进 Harness（循环/自举）
| 项目 | 定位 | 关键可借鉴点 |
|---|---|---|
| [Continual Harness](https://github.com/sethkarten/continual-harness) | 无重置自改进 agent harness（arXiv:2605.09998） | **Refiner 在轨重写 harness**（prompt/sub-agents/skills/memory CRUD）——启示：实验引擎本身应可被实验结果改进（我们已在这条路上：guard 工具链自举） |
| [SIA (Self-Improving AI)](https://github.com/hexo-ai/sia) | 自改进 AI | 自我评估循环 |

**借鉴**：labforge 的"引擎改进"= 每次实验沉淀的模式（如发现某断言设置不当）回写引擎模板

## 二、对 labforge 的升级建议（借鉴映射）

| 开源概念 | 来源 | labforge 落点 |
|---|---|---|
| HYPOTHESIS.md 假设登记 | g-experiment | 卡片加 `hypothesis` 强制字段 + 全局假设索引 |
| stage-gates | g-experiment | 断言即 gate；支持多 stage 卡片 |
| EXPERIMENTS.md 登记表 | g-experiment | `labforge status` 输出 markdown 登记表 |
| autopsy（剖析） | g-experiment | FAIL 时自动生成剖析（哪条断言挂/可能原因） |
| 8 维质量框架 | Kosmos | 断言维度化（正确性/性能/资源/回归…） |
| 知识图谱追踪 | Kosmos | 实验→结论→决策 链接（黑板已承担） |
| hydra 配置组合 | DVC+Hydra | 卡片 params 支持 `+覆盖` 语法 |
| 树搜索管理器 | Sakana v2 | 可选：`labforge explore` 多假设并行 |
| Refiner 自改进 | Continual Harness | 实验沉淀回写引擎模板（自举） |

---

## 三、决策

1. **不 clone/部署任何重量级开源**（Sakana/Kosmos/MLflow 需 Docker/GPU/server——违背零依赖黑箱约束）
2. **labforge 保持轻量自研骨架**（已是零依赖 Node CLI），但按上表吸收模式
3. **优先落地**：HYPOTHESIS 登记 + autopsy（FAIL 剖析）+ markdown 登记表——这三个是"科研逻辑"的核心增量
4. 未来若需完整自主科研循环 → 评估 Kosmos（Claude Code 驱动，与 CLD 生态兼容度最高）作 labforge 的"探索模式"后端
