## 0. 背景与现状

- **当前主通道 = agent_send**：向目标上下文 inbox 拼接消息并唤醒回合。实测上下文最大 21.1MB/会话（239MB 总量）、单会话 inbox 拼接 160 条、上下文只增不减 → 排队堆积 + token 膨胀（bus-queue-mechanism-analysis v0.1）。
- **黑板 = 轻量版**：resource-registry.md / pending-work-plan / token-monitor 等登记表；**无订阅唤醒**。
- **S1 试点**：ACK 免回 + STATUS 写台账 → 成本省 76%（回执黑板化的行为层验证）。
- **S6 = 基础设施层**：正式黑板/邮箱/事件总线未建；CAHAC v1.0 §6-8 已定规范与成本权重，本文做论文支撑的架构选型评估。

## 2. 每架构论文支撑（arXiv id + 关键结论）

### 2.1 黑板
- **arXiv:2507.01701（bMAS）**：黑板 + 控制单元 + 角色 agent 三件套；控制单元按黑板当前消息选 agent 参与，全部消息存黑板后**免记忆模块、整体 prompt 变短**，token 约束下可承载更多讨论。
- **arXiv:2510.01285（LLM 黑板系统）**：黑板作共享广播面，主 agent「张贴子任务」而非 master-slave 直派；实验显示增加 action 预算可持续提升系统平均表现。
- 关联 **arXiv:2602.23193（ESAA）**：黑板即物化视图——状态由 append-only 事件投影而来，可哈希校验回放。

### 2.2 Mailbox
- **Zenodo:19369171（Mailbox Principle，文件系统优先通信）**：消息即文件、签名内嵌；三传输 1744 条签名消息 30 分钟**零协议失败、98.8% 推理成功率**——异步松耦合场景最简设计即可稳健，无需连接导向协议。
- **arXiv:2301.01919（TEM 邮箱机制 MARL）**：类邮件本地通信 + 消息链转发，Transformer 选择性选下一接收者；相对「建模所有 agent」可扩展，多基准优于基线。

### 2.3 事件总线
- **arXiv:2602.23193（ESAA）**：agent 只发结构化意图，确定性编排者写入 **append-only 日志**（activity.jsonl）、哈希校验重放 → 不可变 + 可审计，缓解长程上下文退化（lost-in-the-middle）。
- **arXiv:2501.05207（CoDe）**：跨决策周期的异步延迟会显著误导协作、甚至**差于不通信**；需「意图 + 时效」双对齐——事件必须带 ts 并显式处理乱序。
- **通信定价**：**arXiv:2511.13193**（带宽稀缺 → VCG 拍卖分配发言权，对抗 token 指数膨胀与低信噪比）；**arXiv:2608.07532**（贪心边际价值路由达最优效用 **99.5%**、仅激活平均 1.96/8 agent，而全广播仅 **38.8%**）——直接支持 eventbus 0.5× vs broadcast 10× 的权重设计。

### 2.4 现状 p2p（agent_send）
- **arXiv:2504.16736（AI Agent Protocols 综述）**：协议分层与互操作是主流结论——p2p 是底座而非替代品，各通道应分层组合。
- **arXiv:2602.11583（Five Ws 综述）**：通信四问 who/when/what/why 是设计面；当前 agent_send 无成本感知（who=全部、when=即时、why=不过滤）→ 结构性浪费。
- **arXiv:2501.05207**：直接注入上下文队列即延迟/异步场景，若不做时效处理可能误导接收方（S1 回执黑板化正是缓解）。

## 3. 落地建议（分级引入）

1. **A 级 · registry 订阅检测（1-2 天，成本≈0.05×读 + 1×摘要唤醒）**：本地监听 resource-registry 等变更，定向唤醒订阅者；沿用 S1 行为层纪律。
2. **B 级 · 事件总线 PoC（0.5×按订阅 vs 广播 10×）**：注册 CAHAC §8.2 五类基线事件（cost.alert / store.alert / task.completed / agent.offline / risk.detected），append-only 日志 + dedup_key + 断点续读，只唤醒白名单订阅者。
3. **C 级 · 邮箱批量（0.05×）**：mailbox/<agent>/inbox 任务卡状态机；低优/批量任务走邮箱，高频小状态仍走黑板。
4. **D 级 · 定价治理**：把 2511.13193 / 2608.07532 的拍卖/预算思想落到通道选择器 cost_cap，超限拒绝或降级本地模型。

## 4. PoC 最小可行方案（A 级先行）

**目标**：本地监听 registry 变更 → 定向唤醒订阅者（当前唯一缺口就是「无订阅唤醒」）。

- **输入**：resource-registry.md（或 pending-work-plan）+ 订阅表 subscriptions.json（agent_id → topic patterns）。
- **流程**：watcher（mtime+hash 差分）→ 解析变更 topic/key → 匹配订阅者 → agent_send 仅发「变更摘要 + 指针」（非全量）→ 记账。
- **验收**：无广播；每变更每订阅者 ≤1 条定向消息；唤醒延迟目标 <5min；成本 ≈ 0.05×读 + 1×摘要（远低于 10×广播）。
- **护栏**：dedup_key + 静默窗口防重复唤醒；写前 agent_light/agent_lock（CAHAC §6.3）；审计 append-only。

## 5. 结论（一句话）

**保持 agent_send 为 p2p 底座，按 A→B→C→D 分级引入：先给现有黑板加订阅检测做定向唤醒（最小 PoC 验证成本 0.05×），再上事件总线（0.5×，替换 10× 广播），最后用邮箱承接批量异步任务——论文证据一致支持「按需订阅 + 稀缺定价」替代「全量唤醒 + 免费通信」。**
