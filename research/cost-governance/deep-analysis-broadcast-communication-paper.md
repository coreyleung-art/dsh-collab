## 一、广播：不取消，收窄到「高紧急×高覆盖必需」

### 1.1 广播的成本本质
广播=推模式（push）：N 会话全唤醒 = N × 完整上下文轮次——成本 O(N×上下文)，是我们成本结构中放大系数最高的操作。

### 1.2 广播 vs 黑板（推 vs 拉）
| 维度 | 广播（推） | 黑板（拉） |
|---|---|---|
| 到达 | 即时全达 | 按需拉取（有延迟） |
| 成本 | O(N×上下文) | O(写1次 + 读者各拉取) |
| 确定性 | 高（收到即知） | 中（依赖读者主动） |
| 适用 | 紧急/制度/窗口 | 常规状态/公告 |

### 1.3 广播仍然适用的场景（收窄后）
1. **紧急安全告警**：成本熔断（如日成本 >¥100）、安全漏洞、平台风控——必须即时全员行动，拉取来不及
2. **全员制度发布**：新纪律生效（J37/J34 升级）——需要「即时知悉」保证，但**内容极简=指向黑板详情**（广播只发通知，不搬运正文）
3. **重启窗口**：全体会话需同步收尾（agent_restart_request 机制已存在）
4. **不可预期的读者**：无法预知谁会关心的事件（广播=兜底覆盖）

### 1.4 结论
- **不取消**：取消=牺牲紧急响应能力
- **收窄**：限「紧急+制度+窗口」三类（J34 已有），**目标频率 ≤ 每月几次**
- **瘦身**：广播内容只含「触发词+指向」（详情在黑板/文档），杜绝内容搬运
- **替代映射**：常规状态更新→黑板；非紧急公告→论坛（J36 广场）；批量信息→邮箱

## 二、智能体直接沟通：允许，但「实质任务限定 + 状态去耦」

### 2.1 现状与问题
J36 已允许协作层直连（agent_send 不经协调者转发）——方向正确。但**无差别使用**导致 ack 风暴（61.8%）：确认/状态同步/闲聊全部走消息=上下文重发。

### 2.2 消息分级（直接沟通的边界规则）
| 消息类型 | 示例 | 通道 |
|---|---|---|
| 实质任务委派 | 请执行 X 并回报 | ✅ agent_send（直接沟通） |
| 协作协商 | 方案讨论/多轮对齐 | ✅ agent_send（限线程内） |
| 确认回执 | 「收到✓」 | ❌ 消息 → **黑板状态更新** |
| 状态同步 | 进度/资源状态 | ❌ 消息 → **黑板/登记表** |
| 闲聊/保持联系 | 无信息量寒暄 | ❌ 禁止 |

### 2.3 直接沟通的治理（防复发）
- **通信预算**：每会话日实质消息上限（quota 精神延伸：如 ≤30 条/日）
- **消息审计**：全部实质消息可追溯（已有 agent_thread）
- **线程纪律**：协作在既有线程内进行，不新建散线程（单上下文原则）
- **回执协议**：纯确认免回；需要知会时=写黑板状态（一次写 N 次读）

### 2.4 结论
**允许直接沟通（必要性），但限定「实质任务/协作」，回执与状态走黑板**——这是「直接沟通 + 状态去耦」的结合：保留协作灵活性与低延迟，同时消除成本结构问题（ack 61.8% → 目标 <15%）。

## 三、混合架构论文化评估：可以，实证架构论文定位

### 3.1 新架构定义（自研候选：Cost-Aware Hybrid Agent Communication，暂名 CAHAC）
按消息类型自动选择通信模式：
- 任务/协作 → 点对点（agent_send）
- 确认/状态 → 黑板（共享状态，一次写 N 次读）
- 批量/任务队列 → 邮箱（文件优先）
- 紧急/制度 → 广播（收窄+瘦身）
- 事件 → 事件驱动唤醒（有事件才轮）
叠加：推理路由分层（本地/云端/压缩）+ 成本预算治理（quota/熔断/日审）。

### 3.2 新颖性评估（学术诚实）
| 已有 | 我们的差异化贡献 |
|---|---|
| Blackboard（经典）、Mailbox（zenodo）、Pub/Sub、A2A/MCP、KVCOMM（KV 共享）、SafeSieve（通信剪枝）——均为单点方案 | ① **成本感知的通信模式选择框架**（按消息类型路由到最省通信模式）② **回执-状态去耦模式**（ack 风暴的定义+解法：确认移出消息流）③ **端到端成本模型**（通信×上下文×推理路由联合）④ **真实世界实证数据**（66 会话/26B tokens/¥1,906/19 天/峰值归因——n=1 但数据稀有） |

**新颖性判断：中上**——组合架构+成本聚焦+真实数据是差异化；单点机制均非首创（学术诚实），组合与实证是贡献。

### 3.3 实验设计（我们有天然 A/B 数据）
| 组 | 配置 | 数据 |
|---|---|---|
| 基线 | 当前同步总线（无分级） | 8 月 1-18：ack 61.8%、26B tokens、峰值 ¥748 |
| 处理组 | CAHAC（分级+黑板+邮箱+事件） | 治理后：¥5.79/日（极端）；R1 恢复后预期 ¥15-30/日 |
| 指标 | token/成本/延迟/任务完成率/可观测性 | 精确账单+audit |

补充对照：与 LangGraph/CrewAI/AutoGen 的通信模式（在相同任务集）对比，证明泛化性（否则 n=1 批评成立）。

### 3.4 发表路径与现实定位
| 路径 | 适合度 | 说明 |
|---|---|---|
| arXiv preprint | ✅ 立即 | 架构提案+case study，先占位 |
| ICML/NeurIPS Workshop（Agentic AI/LLM Agents） | ✅ 首选 | 实证短文（4-8 页） |
| AAMAS（多智能体系统顶会） | ✅ | 通信架构+实验，主题契合 |
| 期刊（JAIR/ACM TIST） | ⏳ 后期 | 需泛化抽象+更大实验 |

**现实定位：实证架构论文（case study + 成本模型 + 通信模式框架）**——不是纯理论首创，而是「问题定义（ack 风暴/成本结构）+ 架构方案 + 真实世界证据」的经验贡献。

### 3.5 风险与对策（学术严谨性）
| 风险 | 对策 |
|---|---|
| n=1 单系统 | 泛化抽象（框架无关的通信模式选择器）+ 对照实验 |
| 平台特定（DSH 总线） | 论文中将模式抽象为「通道选择器」（broker 无关） |
| 机制非首创 | 明确定位为「组合+实证」，不夸大 novelty |
| 数据敏感（业务） | 脱敏（会话 ID 化、成本归一化） |
| 实验完整性 | 先补齐 R1-R2 恢复期数据（处理组）再投稿 |

### 3.6 结论
**可以输出论文**——作为「自研新架构 CAHAC」的实证架构论文（arXiv → Workshop 路径）。核心卖点：① 成本感知通信模式选择 ② 回执-状态去耦（ack 风暴解法）③ 真实多智能体系统成本数据（稀有）。立项前需：泛化抽象设计 + 恢复期实验数据（R1-R2）+ 脱敏方案。

## 四、综合结论与建议

| 问题 | 结论 |
