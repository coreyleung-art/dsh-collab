# D1 硬预算选型评估 · 防单日 ¥700+ 失控

> 评估：2026-08-19 · HR 驾驶舱 · 背景=8/17-18 峰值 ¥678/¥748（≈一个运营月薪），成本治理后需常态硬预算防失控
> 候选：agent-cost-guardrails / tokenbudgetorchestrator(TBO) / Runcap / gov quota（现有）

---

## 一、需求定义（防什么）

| 需求 | 说明 |
|---|---|
| 单日上限 | 单日成本超阈值即熔断（8/17-18 教训：¥700/日不可接受） |
| 每 agent 配额 | 单个会话失控不拖垮全局（TBO 核心价值） |
| 超限行为分级 | block（拦截）/ fallback（降级到便宜模型）/ warn（告警放行） |
| 自动重置 | 日/周/月周期自动恢复（不必手动解封） |
| 路由降级 | 草稿→本地/便宜模型，正式→主模型（与 A4 本地路由协同） |
| 数据不出域 | 提示词不离开本机（隐私+合规） |

## 二、候选对比

| 维度 | agent-cost-guardrails | tokenbudgetorchestrator (TBO) | Runcap | gov quota（现有） |
|---|---|---|---|---|
| 机制 | 框架 hook（CrewAI/AutoGen/LangGraph）@before/@after | SDK 包装 LLM client，调用前决策 | 预检代理+无损压缩 | 治理层配额（per-agent day/week） |
| 预算粒度 | per-agent 硬预算 | per-agent/project/user + 自动重置 | 单任务 cap | per-agent 配额 |
| 超限行为 | BudgetExceededError + circuit breaker + 告警回调 | block / fallback 路由 / warn（可配） | HTTP 429 中止 | 超限拦截（未实施） |
| 模型价目 | 30+ 模型内置（含 DeepSeek） | 通用 token 计数+价目 | 有限 | 无（只用审计代理口径） |
| 数据隐私 | 进程内 | SDK 本地计数，引擎仅见数字 | 本地 | 本机 |
| 语言 | Python | Python + Node.js | CLI/npm | DSH 工具 |
| DSH 适配 | 需接入 DSH 工具面（成本高） | 需包装 DSH 的 LLM client（SDK 层） | 代理 OpenAI 兼容端点（DSH 用不到） | ✅ 已有，未启用配额 |

## 三、评估结论

1. **不引入新系统**：DSH 的 gov quota 已有 per-agent 配额骨架（day/week），当前缺口=①配额未设置 ②超限行为只有拦截没有降级/熔断 ③无价格模型。**路径=启用 gov quota + 借鉴 TBO 超限行为分级**，不自研新系统
2. **借鉴 TBO 的三个机制**（写入配额规范）：
   - 超限行为分级：常规任务超限→block；可降级任务→fallback 到本地模型（qwen3.5-2b）；非关键→warn 放行
   - 自动重置周期：按 agent 角色设 day 配额（如 HR/协调者高配额、后台低配额）
   - 调用前决策：长任务启动前预估成本（借鉴 Runcap 运行前预估）
3. **agent-cost-guardrails 作为兜底参考**：若 gov quota 的熔断粒度不足（需要 circuit breaker 连续违规熔断），可评估接入
4. **Runcap 不适合 DSH**（其价值=压缩+预检，DSH 无法走 OpenAI 兼容代理），但其"单任务 cap"思想可人工固化为纪律（任务级预算申报）
5. **TBO 关键佐证**：其 README 明确「agent-to-agent 通信产生 3-5x token」——与我们实测 ack 风暴 61.8% 完全吻合，通信治理优先级再确认

## 四、实施建议（P0）

1. **本周**：启用 gov quota 为前台角色设 day 配额（先宽后严：按 7 月日均 ¥24.86×3 倍≈¥75/日/agent 起步，观察一周）
2. **配额分档**：治理必需（协调/HR/健康）高配额；业务角色中配额；后台低配额
3. **熔断分级**：配合 J34——协调者广播类豁免；常规操作超限拦截；报告/台账类降级本地
4. **月复盘**：按精确账单校准配额（8 月治理后健康月成本 ¥500-1,500 为锚）
5. **持续**：A4 本地路由落地后，fallback 目标=本地模型（零成本）
