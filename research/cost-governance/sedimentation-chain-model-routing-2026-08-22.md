# 自动沉淀交付链 · 模型路由决策表（本地优先 + 置信度门控）

> 日期：2026-08-22 · 协调者 · 用途：C/B+ 方案「任务完成→自动沉淀七步链」落地前，明确每个环节用哪个模型，防止误用订阅模型烧钱。
> 衔接：model-routing-rules-v1.0（静态表）· v1.1-draft（置信度门控）· J35（本地模型互斥）· J36（沉淀闸门）。

## 一、核心原则（一句话）

> **向量化/判定/审查/查重/登记 全本地（零订阅）；只有「提炼总结 + 工具化写脚本」才可能用订阅模型，且先本地、低置信才升级。**
> 目标：每次自动沉淀的订阅 token ≈ 0（约 60-80% 任务全程零订阅），仅质量敏感环节按需升级。

## 二、交付链七步 → 模型路由（权威决策表）

| # | 环节 | 用什么模型 | 成本 | 是否需 LLM | 路由依据 |
|---|---|---|---|---|---|
| 0 | **触发**：task.completed 事件/黑板登记 | 无（事件机制） | 0 | 否 | event-bus 纯规则 |
| 1 | **判定**：值不值得沉淀 | **qwen:1.8b 本地**（分类） | 0 | 是（轻） | 短文本分类，L0 档，可错可复核 |
| 2 | **查重**：先查后写 | **向量检索**（bge-m3 本地嵌入 + knowledge_search） | 0 | 否 | 嵌入本地 + 检索纯规则 |
| 3 | **安全审查**（仅插件改动） | **纯规则脚本**（cordis-crash-audit.py） | 0 | 否 | grep 规则，无 LLM |
| 4 | **工具化**（生成脚本） | **gemma4:9b 本地先试 → 低置信升级 L2 flash** | 0→低 | 是（重） | 写代码需质量，本地先干，门控升级 |
| 5 | **双文档沉淀**（复用经验总结） | **gemma4:9b 本地先试 → 低置信升级 L2 flash** | 0→低 | 是（重） | 提炼需质量，门控升级 |
| 6 | **KB 向量化** | **bge-m3 本地**（knowledge_add_document 自动嵌入） | 0 | 否 | 嵌入本地 |
| 7 | **chroma 向量化** | **bge-m3 本地**（chroma_index 1024 维） | 0 | 否 | 嵌入本地 |
| 8 | **profile/registry 登记** | **无 LLM**（规则化 append） | 0 | 否 | 结构化追加 |

**关键结论**：七步中 **5 步零 LLM、2 步轻/重 LLM 且本地优先**。纯执行型任务（判定=跳过）则 0 LLM。

## 三、置信度门控（仅步骤 4/5 生效）

复用 v1.1-draft 的 FrugalGPT 级联，但只套在「重 LLM」两步：

```
步骤 4/5（工具化/提炼）:
  local = gemma4:9b(task)                     # 本地免费
  if local.confidence >= 0.9: use(local)      # 高置信 → 零成本采用
  elif 0.7 <= conf < 0.9: use(local, review)  # 中置信 → 采用+标记复核（人在环）
  else: cloud_flash(task)                     # 低置信 → 升级订阅（按需付费）
```

置信度来源（v1.1 复用）：JSON 解析失败 / 输出长度异常 / 关键词缺失 / 自检 prompt（本地问「是否确定」）。

## 四、本地模型能力边界（实测校准，勿高估）

| 模型 | 适合 | 不适合 | 本次实测 |
|---|---|---|---|
| qwen:1.8b（1068MB） | 分类/意图/关键词/短摘要/判定 | 写代码/长提炼/复杂推理 | 判定任务够用 |
| gemma4:e4b（9163MB） | 长摘要/草稿/结构化提取 | 战略级/高精度代码 | 提炼勉强，慢、占 9GB 内存 |
| bge-m3（1104MB） | 向量嵌入（1024 维） | 生成/推理 | 本次 chroma 检索命中 1.000 ✅ |
| nomic-embed-text（261MB） | 向量嵌入（768 维，旧集合） | 生成 | 与 bge-m3 维度冲突，新集合统一 bge-m3 |

**⚠️ 陷阱**：gemma4:9B 占 9GB 内存 + 慢，且质量不如订阅 flash。**默认不常驻**（J35 用完即关），仅步骤 4/5 按需加载，用完 unload。

## 五、J35 本地模型互斥（执行约束）

- LM Studio（1234）与 Ollama（11434）**不同时开**；本次 LM Studio 已停（000），Ollama 在线。
- bge-m3 嵌入 + gemma4 推理若同时跑，会争内存——**串行**：先嵌入（bge-m3）→ unload → 再推理（gemma4），或错峰。
- 嵌入任务（步骤 6/7）高频且轻，单独用 bge-m3；推理任务（步骤 4/5）低频且重，按需加载 gemma4。

## 六、省钱量化预期

| 任务类型 | 订阅 token | 本地环节 |
|---|---|---|
| 纯执行（判定=跳过） | 0 | 无 |
| 沉淀但无工具化（如规则/流程总结） | 0 | 判定+查重+向量化+登记全本地 |
| 沉淀 + 工具化（写脚本） | 0~数万（仅低置信时） | 其余全本地 |

- 预期：**60-80% 任务全程零订阅**（本地消化）；20-40% 任务仅步骤 4/5 可能升级订阅。
- 与 v1.1 门控预期一致（本地命中率 60-80%，升级率 20-40%，综合成本 = 纯云端的 30-50%）。
