# 节点关系模型 · node-relationship-model v1.0

> 设计：2026-08-22 · HR · 用户推动（总线星型/角色节点矩阵/任务卡/分级边界 + 商业化防逆向安全）· 阶段 2/3 实现依据

## 一、总线星型模型（中枢唯一，节点接入）

```
                中枢（唯一权威总线）
        协调者 / HR / QA / 外卖 / 监察 / 知识库
                 │  │  │  │
   ┌──────────────┼──┼──┼──────────────┐
   │  MCP 工具通道  黑板:8792   事件总线   │
   └──────┬───────┬─┴──┬────────┬─────┘
          │       │    │        │
       内部节点  内部节点   云网关     外部AI
       (i9/MBP) (门店设备)  (公网)  (订阅/门店)
       信任协作   信任协作   隔离层    隔离消费
```

**原则**：总线只有一条（中枢）；节点是执行端；外部 AI 永不进入总线（云网关隔离）。

## 二、两类接入：信任协作 vs 隔离消费

| 维度 | 内部节点（信任协作） | 外部 AI/门店（隔离消费） |
|---|---|---|
| 信任 | 高（Tailscale 自有设备） | 低（公网未知调用方） |
| 协作模式 | 任务卡派单+自治延伸 | 只读消费（无调度权） |
| 数据边界 | 按角色（internal 全量） | data/<tenant>/* 聚合/脱敏 |
| 能力 | 全工具/全权限（内部 J45） | 白名单最小集（网关硬过滤） |
| 审计 | 双向协作审计 | 全审计+异常检测（防逆向） |
| 反逆向 | 不适用（自有） | **强防护（见 §五）** |

## 三、角色-节点职责矩阵

| 角色 | 与节点关系 | 职责 |
|---|---|---|
| 协调者 | 派单者 | 任务卡调度（tasks/<node>/cmd）· 跨节点协调 |
| HR | 治理者 | 节点注册/审计/资源登记/分级配置下发 |
| 设备协调 | 运维者 | 心跳监控/健康/互斥/节点生命周期 |
| 业务角色（外卖等） | 能力调用者 | 调节点能力（如 i9 视觉） |
| 节点本身 | 执行者 | 接命令→本地执行→回报；宪法内自治 |
| 外部 AI | 消费者 | 只读调用白名单工具（无节点身份） |

## 四、任务卡流转协议

```
中枢 ──PUT tasks/<node>/cmd──▶ 黑板 :8792
  ◀──GET（节点轮询/订阅）──    节点读取
  ◀──PUT tasks/<node>/result── 节点回报 {ok, output}
  ──▶ task.completed 事件 ──── 中枢收讫+审计
```

- 内部节点：全流程（派单/执行/回报）
- 外部 AI：**无任务卡能力**（只读白名单工具，无调度权）

## 五、商业化安全强化（防过度授权 + 防逆向）

### 5.1 最小暴露（不给太多能力）

| 措施 | 实现 |
|---|---|
| 白名单快照 | 外部只暴露 report.read/knowledge.search 等 ≤5 工具；**不暴露内部工具全集** |
| 无内部路径 | 外部 AI 无会话通道/黑板/总线路径——无法触发内部任何 agent |
| 配额硬限 | 每订阅 key 日配额（调用数/token）· 超限即断 |
| 无写操作 | 外部零写权限（网关层+本地层双重拒绝） |

### 5.2 防逆向（防止外部 AI 穿梭回来逆向项目）

| 攻击面 | 防护 | 论文支撑 |
|---|---|---|
| 提示注入/工具投毒 | 工具参数严格校验+内容过滤（外部输入不进入内部 prompt 链） | 2603.22489 |
| 架构探测 | 响应**脱敏**：不含内部路径/角色名/会话 id/黑板地址/版本细节；错误只回「denied」不解释 | — |
| 知识外带 | 检索返回**聚合/脱敏摘要**（不给内部文档全文）；敏感库（凭据/审计/内部决策）不进外部检索集 | — |
| 枚举攻击 | 工具列表固定快照（不动态枚举）；频繁调用/批量拉取=异常信号→自动封禁 | 2605.30998 |
| 反向连接 | 隧道**单向**（外部→网关→本地只读；本地永不主动连接外部 AI） | — |
| 沙箱隔离 | 外部调用独立进程/容器配额，异常不影响内部 | 2403.01862 |

### 5.3 分级权限延伸（本地执行点也过滤）

- role-config 不只网关过滤：**节点本地每个工具调用也过白名单/边界**（本地 403 越权）
- 规则宪法（J 规则）经 rules-sync 同步到节点：本地自治自动遵守中枢规则
- 越权/审批类动作：本地拒绝或自动升级中枢（J45 硬性升级延伸）

## 六、实施对照（阶段映射）

| 阶段 | 本模型落地 |

| 2（节点接入） | 任务卡协议+node-join-notify（内部信任协作） |

## 七、验证标准（商业化前）

1. 外部 AI 枚举工具 → 只见白名单快照（无内部工具）
2. 外部 AI 注入尝试 → 被参数校验拦截，内部无影响
3. 外部 AI 拉取知识 → 只得聚合摘要，内部文档不可达
4. 外部 AI 探测内部结构 → 响应脱敏，零信息泄露
5. 门店 A 调 B 店数据 → 403（隔离）· 订阅无写操作 → 403
6. 异常调用（枚举/批量）→ 自动限流/封禁告警
