# 分布式节点总线 · 设计方案 v1.0

> 设计：2026-08-21 · HR · 用户指示推进（i9 节点受管化）· 与跨设备黑板（cross-device-blackboard-design-v1.0）一体两面
> 定位：**节点总线=调度执行层**（命令分发/任务调度/健康），**跨设备黑板=状态中枢**（nodes/ 域）——总线读黑板状态做决策，黑板记总线执行结果

## 一、要解决的问题

| 现状 | 问题 | 节点总线目标 |
|---|---|---|
| i9 Docker/Ollama 本地手动管理 | Reset/启停/排查全靠人 | 总线统一调度：命令→执行→回报 |
| 节点状态不可见 | 手动 curl/排查才知道 | 心跳+状态上报黑板，全网可见 |
| 任务-节点匹配靠人 | 不知道哪个节点能干 | 能力注册+负载感知调度 |
| 跨设备互斥无统一机制 | J35 靠约定 | 节点级锁（node:i9 互斥） |

## 二、架构

```
┌────────────────────────────────────────────────┐
│  总线控制器（协调者/HR/设备协调 侧逻辑+服务）        │
│  职责：节点注册审批 / 任务调度 / 命令分发 / 健康裁决  │
└──────┬───────────────────────────────┬─────────┘
       │ 命令通道（agent_send/黑板事件/HTTP）          │
┌──────▼──────────┐        ┌───────────▼──────────┐
│ 跨设备黑板 :8792 │◄──────►│ 节点执行器（各节点）      │
│ nodes/ 状态中枢  │ 心跳    │ i9: Ollama/Docker 启停 │
│ tasks/ 任务状态  │ 状态    │ mac-mini: 8790 服务    │
└─────────────────┘ 上报    │ MBP: 本机 agent        │
                           └──────────────────────┘
```

## 三、核心组件

### 1. 节点执行器（node-agent，每节点一个）

| 能力 | 说明 |
|---|---|
| 注册 | 启动时向黑板 PUT nodes/<id> {capabilities, resources, addr} |
| 心跳 | 每 60s PUT nodes/<id>/heartbeat {ts, load, health} |
| 命令轮询/接收 | 收总线命令（HTTP 回调或轮询）：start/stop/status/pull 服务 |
| 执行回报 | 命令结果写 tasks/<id>（成功/失败/输出摘要） |
| 本地探针 | Docker ps / ollama list / 端口健康（i9 专属） |

### 2. 总线调度器（bus-scheduler）

| 功能 | 规则 |
|---|---|
| 任务→节点匹配 | 按 capabilities 匹配 + 负载最低优先 + 互斥检查（node:i9 锁） |
| 命令分发 | agent_send（agent 场景）/ HTTP（脚本场景）双通道 |
| 健康裁决 | 心跳超时 3× → 标记 offline → 告警（risk.detected 事件） |
| 互斥 | 节点级红绿灯：同一节点同时只允许一个写类任务（J35 落地） |
| 重试 | 命令失败重试 2 次 + 回报错误原因（不无限重试） |

### 3. 任务协议（task 卡）

```json
{ "task_id": "t-xxx", "node": "i9", "action": "pull-model", "params": {"model": "qwen2.5-vl:7b"}, "status": "queued|running|done|failed", "result": "..." }
```

## 四、首个用例：i9 视觉节点部署（总线调度）

1. i9 执行器注册（capabilities: ollama/docker/gpu-cuda）→ 黑板 nodes/i9
2. 总线命令：`pull-model qwen2.5-vl:7b` → i9 执行器拉取（10-30min）→ tasks 状态
3. 总线命令：`start-ollama` / `verify-vision` → 验证截图识别 → 结果写黑板
4. 视觉通道打通后：差评走查截图→ i9 本地视觉（M4 兜底解除）
5. 全程黑板可见：GET nodes/i9 实时状态（用户/设备协调随时看）

## 五、与现有体系衔接

| 现有 | 衔接 |
|---|---|
| 跨设备黑板 :8792 | 节点总线状态中枢（nodes/tasks 域） |
| bus-bridge 8791 | 命令通道之一（脚本→节点） |
| 8790 external-link | 推送出口（告警/结果可推企微） |
| 设备协调 5a5368af | 总线调度器逻辑承载者之一（设备域） |
| 事件总线 event-bus | 节点离线/任务完成 → risk.detected/task.completed 事件 |
| 审批分级 J45 | 节点命令按档（启停服务=L1，破坏性 Reset=L3 用户确认） |

## 六、风险与护栏（J39 穷举）

| 风险 | 护栏 |
|---|---|
| 节点离线/心跳丢失 | 3× 超时标记 offline + 告警；任务转 M4 兜底 |
| 命令执行失败 | 重试 2 次 + 错误回报 + 不自动升级重试 |
| 节点互斥冲突 | node: 级红绿灯锁（同节点单写任务） |
| 破坏性命令（Reset） | J45 硬性升级 L3：必须用户确认才下发 |
| 调度器单点 | 控制器逻辑可在协调者/HR/设备协调任一会话运行（黑板为事实源） |

## 七、成本与部署

- 零 LLM：node-agent（node/python 脚本）+ HTTP + 黑板文件
- i9 执行器：Windows node 脚本（nssm 或计划任务常驻）
- mac-mini/MBP：同脚本（python 版）
