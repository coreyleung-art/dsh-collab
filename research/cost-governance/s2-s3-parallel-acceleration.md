# S2/S3 并轨正式化方案 · 边用边迭代（Accelerated Parallel Path）

> 起草：2026-08-19 · HR · 用户问询：直接进 S2+S3 正式化，用每日监察+每日回放自动验证，边用边迭代？
> 结论：**可以**——监察体系已自动化（每日回放/日审/quota/熔断），兜底能力 ≥ 传统试点缓冲；「试点→验收→切换」的保守节奏可替换为「渐进放量+监察阈值」的持续交付节奏

---

## 一、为什么可以（监察三层兜底）

| 监察层 | 机制 | 能力 |
|---|---|---|
| 成本层 | 每日回放（launchd 已 load）+ token-roi-review 日审 | 逐日成本可见、异常 🔴>2x 标红 |
| 上限层 | gov quota 500M/日 + 熔断规则（日成本 >¥100 回退） | 硬上限防失控 |
| 质量层 | 5% 云端抽查（A4 PoC 设计）+ 复核门控 | 本地路由质量可监控 |

**关键差异**：我们的"生产"是内部运营（差评草稿/日报/监控告警），不是外部客户服务——错误成本低（草稿错可重写、告警误报可忽略），监察自动化后**试错成本≈0，兜底速度>试点周期**。

## 二、并轨方案（三轨同时启动）

| 轨 | 内容 | 启动即 | 渐进项 |
|---|---|---|---|
| S2a 监控事件化 | 11 店告警 EVENT→黑板/事件总线 | 核心店（初蘅天河）先行 | 全 11 店+类型扩展+阈值下调 |
| S2b A4 本地路由 | qwen3.5-2b 置信度门控 | 场景 1-2（分类/关键词） | 场景 3-5+阈值调优 |
| S3a 差评/日报恢复 | 差评草稿+经营日报 | 低阈值先跑 | 全量+错峰 |

## 三、迭代节奏（每日监察→周调整）

```
每日：回放趋势（¥）+ 日审（🔴异常）→ 成本/质量自动可见
周调整：阈值（T_high/T_mid）/ 场景范围 / 配额校准 / 事件化覆盖
熔断：日成本 >¥100 → 自动回退（FUSED→HALT）；本地抽查 <95% → 暂停对应场景
```

## 四、监察阈值（替代阶段验收）

| 阈值 | 动作 |
|---|---|
| 日成本 <¥100 | 保持并轨（目标 ¥30-60） |
| 日成本 >¥100 | FUSED：仅 p2p TASK + 黑板读；观察 24h |
| 再次超限 | HALT：全员被动，人工恢复 |
| 本地抽查 <95% | 暂停对应本地场景，升级云端 |
| 事件化误报率高 | 阈值回调（medium→high） |

## 五、与 S1 的关系（并行不冲突）

- S1 协议试点（回执黑板化）=行为层，与 S2/S3 基础设施/业务恢复正交
- 三轨并行：S1 改通信结构、S2a 改监控模式、S2b 改推理路由、S3a 恢复业务——互不阻塞

## 八、自动迭代闭环与用户介入点（2026-08-19 补充）

**迭代全自动，用户无需每天激活**——只需：一次性批准启动 + 异常/周期节点被唤醒。

| 层 | 自动化状态 | 机制 |
|---|---|---|
| 执行层 | ✅ 自动（恢复后） | agent 被动+事件驱动自动跑监控/路由/日报；高险动作仍门控确认 |
| 监察层 | ✅ 已 launchd | 每日回放（com.dsh.hr.cahac-replay.daily 已 load）+ token-roi-review |
| 熔断层 | ✅ 增强（本轮） | 每日回放自动检测：日成本 >¥100 → FUSED 标记 / >¥200 → HALT 标记 |
| 告警层 | 🔄 需实现 | 异常/周报定向通知用户（不每日打扰；仅异常与每周汇总） |

**用户介入点（极少）**：
1. **启动批准**（一次性）：并轨启动确认
2. **熔断恢复**：HALT 后人工评估是否继续/调整（周级内偶发）
3. **周报审阅**：每周自动汇总（成本/质量/命中率）供快速浏览
4. **月度复盘**：配额校准/规则升级/ROI 坐标更新

**告警规则**：仅三类打扰用户——① FUSED/HALT 熔断 ② 本地质量抽查 <95% ③ 每周汇总（可订阅关闭）。其余全部静默自动。
- 监察统一：每日回放/日审覆盖全部轨
