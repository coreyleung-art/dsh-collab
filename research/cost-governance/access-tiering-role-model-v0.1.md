# 接入分级与角色权限模型 · v0.1

> 设计：2026-08-22 · HR · 用户提出（接入时区分节点角色和权限：Tailscale=自有设备 / 公网=门店 / 付费订阅）· 衔接 node.bootstrap 自举 + 云 MCP 网关 + 多租户升级路径

## 一、核心原则：接入即分级（连接时确定身份→角色→权限）

```
接入来源（网络层） × 认证身份（凭据层） → 角色 → 权限集 + 租户边界
```

## 二、接入来源分层（网络识别）

| 接入层 | 来源 | 信任度 | 认证要求 |
|---|---|---|---|
| 内部 | Tailscale 网段（100.x） | 高（自有设备） | 内部 token（SSE_TOKEN）+ 网络白名单 |
| 公网-门店 | 云网关公网 → 门店身份 | 中（商户合同） | 门店凭据（企微身份/门店账号） |
| 公网-订阅 | 云网关公网 → 订阅用户 | 低（付费客户） | 订阅 API key（作用域） |

## 三、角色矩阵（角色 → 权限集 + 租户边界）

| 角色 | 数据边界 | 工具集（示例） | 审批 |
|---|---|---|---|
| **内部设备**（Tailscale） | 全网络（nodes/data/registry 全量） | 监察/审批/运营/黑板/总线（全工具） | 内部 J45 分级 |
| **门店**（公网） | 本店 data/<门店>/*（隔离） | 本店只读（订单/评价/报表）+ 受限操作（回复草稿） | 改价/上下架 → 自动升级店长/总部确认 |
| **订阅用户**（公网） | 订阅租户 data/<subscriber>/* | 只读聚合（简报/报告/知识检索） | 无写操作（网关层硬过滤） |

## 五、安全边界（公网必须）

| 层 | 要求 | 论文支撑 |
|---|---|---|
| 传输 | HTTPS（TLS） | — |
| 认证 | 门店=企微身份/账号；订阅=作用域 API key | 2605.30998（x402 作用域凭据） |
| 授权 | 云网关 ABAC 强制（工具发现+调用双重拦截） | 2605.18414（0% 越权） |
| 隔离 | 租户命名空间 data/<tenant>/* + 权限过滤 | 2508.03095（Agent Registry 方案权衡） |
| 审计 | 全量（谁/何时/什么工具/什么租户） | 监察体系扩展 |

## 六、与现有体系衔接

1. **node.bootstrap**（external-link-mcp 新工具）：连接后返回入职包（按角色）
2. **云 MCP 网关**：公网入口 → 网关层先判定来源+认证 → 决定角色 → 转发或拒绝
3. **黑板租户命名空间**：data/<门店>/*、data/<sub>/*（内部 nodes/* 不受影响）
4. **J45 审批联动**：门店写操作自动升级（改价=店长/总部）；订阅用户无写权
5. **注册表**：nodes/ 记录角色+租户（2508.03095 五种注册方案参考）

## 七、落地顺序（建议）

1. v0.1 内网：node.bootstrap 实现（internal 角色）——i9 接入即注册（当前痛点）
2. v0.2 门店：云网关 + 门店认证 + 租户隔离（投放时）
3. v0.3 订阅：订阅 API key + 只读聚合 + 计费（商业化时）
