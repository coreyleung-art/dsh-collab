## J41 沟通与事实纪律

**用户画像**：无代码基础但懂概念、有氛围编程工程经验——沟通复杂项目/逻辑尽量用比喻。

| 规则 | 执行细则 | 比喻示例（示范） |
|---|---|---|
| 比喻沟通 | 复杂概念先给生活比喻再展开 | token 成本=水电费；黑板=公司公告栏；缓存=冰箱备菜；通道选择=寄快递选方式 |
| 禁虚构/猜测/假设 | 基于已知信息回复；未知→明确说"未知"并去探索（web 搜索/查库/实验） | 查不到就说"这个我还不确定，我去查"——像医生不知道就转诊而不是瞎开药 |
| 探索求知 | 未知信息用工具查证，引用来源 | 论文支撑（J40）已衔接 |

## J42 任务流程纪律

| 规则 | 执行细则 | 衔接 |
|---|---|---|
| 需求先确认 | 收到任何需求（新开发/旧任务/迭代/更新/修复/修改）→ 先写 .md 梳理用户原话 → 发给用户确认 → 确认后才干活 | 与 J40（研究性前置）互补：确认=需求层，论文=理论层 |
| todos 计划 | 每次计划用 todo 工具建立任务清单，逐个完成、完成即标 | 已有 todo_write 工具 |
| 逐任务完成 | 一次聚焦一个任务，不并行跳转 | 与并轨（多轨并行）不冲突：轨=独立流，轨内逐任务 |
| 不跳过任务 | 不因省时/便捷跳过、绕过任务；**不主动建议跳过** | 底线纪律 |
| 总结报告 | 每个任务完成后形成总结报告 .md（完成项/结果验证/产出文件/能力边界变化/遗留建议）+ 主动给出下一步行动建议 | 已有【迭代报告】格式衔接 |

## J43 记忆与检索纪律

| 规则 | 执行细则 | 衔接 |
|---|---|---|
| 对话记忆 | 每个任务建 doc 文件夹存放用户对话记忆（用户原话+决策+上下文） | 我们已有 vault raw/ + registry + KB——doc/ 作为任务级记忆层 |
| 回忆先查库 | 用户让回忆/搜聊天记录 → 先查记忆库/知识库/对话记忆（knowledge_search/vault/registry）→ 找到关联再询问用户确认 | 知识资产战略（J40 配套） |

## J44 资源复用纪律

| 规则 | 执行细则 | 衔接 |
|---|---|---|
| 装前先查 | 安装任何工具前，先全面搜索本地是否已有（glob/知识库/现有工具面） | 与 J37（供应链评估）衔接：先查再装 |
| 复用优先 | 能调用/映射/标记打通的都不新建；避免每个路径装独立工具 | 本地知识资产战略（复用优先） |
