# 风险穷举方法论 · 模板与规范（J39）

> 建立：2026-08-19 · HR · 工具：scripts/risk-enumeration.py · 用途：任何新架构/新调研/新工具立项前的风险穷举
> 沉淀位置：底层知识库（DSH ops-science-research）+ 规则集（resource-conflict-policy.md J39）

## 一、方法步骤（5 步）

1. **回溯**：收集相关记录（registry 变更/研究文档/实测数据/会话历史）
2. **穷举**：按 7 类分类逐类列风险（架构/通信/成本/治理/实施/学术/外部——可扩展）
3. **定级**：每项标 概率（高/中/低）× 影响（高/中/低）
4. **对策**：高×高 与 中×高 必须有防线（已就绪/需补）
5. **结论**：架构可行性判断 + 必防清单 + 试点建议

## 二、分类框架（可扩展）

| 类 | 关注 | 示例 |
|---|---|---|
| architecture | 架构单点/竞争/损坏 | 黑板故障、选择器误判 |
| communication | 通信纪律/丢失/膨胀 | ack 复发、线程膨胀 |
| cost | 成本反弹/计量/配额 | 恢复失控、缓存失效 |
| governance | 治理疲劳/节奏/落地 | 日审麻木、协议阻力 |
| implementation | 试点/宿主兼容/数据 | 黑板化失败、实验不完整 |
| academic | 新颖性/泛化/脱敏 | n=1 质疑、数据敏感 |
| external | 供应商/安全/平台 | 调价、prompt 注入、风控 |

## 三、定级与对策规则

- 高×高：必防（防线必须「已就绪」或列入最高优先级「需补」）
- 中×高：重点防（防线入实施计划）
- 低×高：预案（低成本防线：默认安全/审计）
- 高×中：流程化（制度/检查单）
- 低×低：接受（记录即可）

## 四、产物规范

每次风险穷举产出：① 风险清单（7 类表格）② 概率×影响矩阵 ③ TOP N 必防表 ④ 结论。
命名：research/cost-governance/risk-<topic>.md；登记 registry；入库 ops-science-research。
