# 06 · 本机唯一共用读者机制：设计要点 · 必须避免的坑 · 失效条件

> R2-重派 · 2026-10-12 · ★ 回答题面第 6 问。
> ★ 本文是**设计建议**，不是已实现物。★ 凡引用本机事实处均标明现测时刻与证据位置。

## 〇、先回答「业界建议什么形态」

把 01–04 篇的结论压成一句：

★★★ **一个共用读者 = 【一张在创建时填的登记表】+【一个只读这张表的判定器】+【判定器自己的心跳】+【一个在系统之外的缺席接收方】。**
★ 四件里，**本机只有第三件的一半**（`data/ops/drift-heartbeat/current` 存在，但没人看它）；**第一件完全没有**；**第四件在结构上不存在**（04 篇 §三）。

★ 因此本报告的建议形态**不是**「再加一个扫描脚本」，而是**先有登记表**。理由（02 篇逐字）：

> **One field per artefact, filled at creation, not at audit time: `consumer:`**
> **Empty consumer field = the audit result. No investigation required; the answer was available on day one and every retrofit costs more than the original answer would have.**
> **"opened" is not consumption. Applied, closed, recorded, forwarded, decided are.**

## 一、设计要点（7 条）

### 要点 1 · **登记表是单一真源，读者只读登记表**

形态：`data/registry/ops-alert-registry.json`（或本仓既有登记表风格），每段一条：

```json
{
  "seg": "data/ops/drift-alert",
  "semantics": "A",                       // A 异常才写 / B 定期累积 / C 状态流 / D 台账 / E 测试夹具
  "consumer": "session:e317d6ab | tools/alert-reader.py",   // ★ 具名读者，创建时填
  "owner": "mac-mini-协调者",              // ★ 具名 owner（01 篇 RavenClaude 判据）
  "expect_when_normal": "empty",           // A: empty | B: latest_fresh | C: fresh | D/E: n/a
  "max_age_s": 21600,                      // B/C 类用
  "exclude": ["value.plugin == 'probe'"],  // ★ 过滤负控产物（见坑④）
  "claimed_since": "2026-10-12T20:00:00+08:00"
}
```

★★ **判据**：**`consumer` 为空字符串 ⇒ 该段就是「无读者」，且这本身就是审计结果**（不必再去代码里搜字符串）。
★ 本机今天之所以要「扫 1293 个代码文件去猜谁读它」，**根因就是这张表不存在**（05 篇 §五全部是**事后考古**）。

### 要点 2 · **读者必须同时枚举「板上段」与「登记表」——未登记的段报【黄】，不报【绿】**

现测：`data/ops` 第三段 **265 个**，登记表（今天）**0 条**。若读者只读登记表，**265 段全部隐形**；若只读板，**分不出语义**（05 篇 §二）。
⇒ **两条都要读，做差集。**

★★★ **这条是本设计最关键的一条**：**「未登记」必须是一个会显示的中间态。** 否则「新写一个告警段」会静默地不被覆盖 —— 那正是本机 9 个自读段的成因。

### 要点 3 · **三态判决，缺一不可：绿 / 红 / 不可判**

- **读不到**（网络失败、404、解析失败）⇒ **不可判**，**不冒充绿**。
  ★ **本机已有正确先例**：`beacon-check.py:207` 逐字 `return "undecidable", f"调用失败 {type(e).__name__} ⇒ ★ 读不到 ≠ 不存在"`。
  ★ **要保持**，不要「简化」成 `except: pass`。
- **不可判也必须计入汇总行**（★ 否则「全绿」会掩盖「有 N 条根本没看」。本仓 `tools/beacon-check.py` 已有 `SKIP` 单列的先例，逐字注释：`未抽检必须与"通过"长得不一样`）。

### 要点 4 · **读者自己必须留【运行痕迹】，且是一个覆盖写心跳**

形态：每次运行**单键覆盖写** `data/ops/alert-reader/heartbeat`（仿现有 `data/ops/drift-heartbeat/current`，现测 `version=43` 证明该键是覆盖写）。
**判据方看它的 staleness，不看内容。**

★★ 理由（03 篇 §一.5）：**手工/定时读者「没跑」与「没有告警」在输出上完全同形** —— 只有「上次运行时刻」能把它们分开。
★ 本机现状：`tools/beacon-check.py` **不在 launchd**（现测无命中；正控 103）⇒ **它今天完全符合「不知道跑没跑」**。

### 要点 5 · **读者只读不写被读对象**

★ 若读者把 `_read_at` 写回被读的卡，则：① 需要写权限；② **污染被读对象**；③ **下一次读到的不是同一份东西**（项目纪律「只读取证不得与写事务同一次调用」的变体）。
⇒ **认领/已读记录写到【独立命名空间】**（如 `data/ops-acked/<seg>/<id>`）。

### 要点 6 · **输出必须带 `as_of` 时刻**

★ 项目纪律「凡读状态必问『这是哪个时刻的』」。
★ **本机实证它是硬需求**：同一段 `pollution`，19:46 基线记 **1456**、本报告 20:32 现测 **1457** —— **今天一天内就动了**。
⇒ 任何不带时刻的告警读数**不可被引用**。

### 要点 7 · **读者的判据必须能被造红（负控）**

★ 项目纪律「一个断言若从未红过，它就不是判据」。
★★ **且负控要覆盖【每一条判决分支】**：绿 / 红 / 不可判 / **未登记（黄）**。
★ **本机现状（现测，见 07 篇）**：`beacon-check.py --selftest` **全绿**，但它的 14 个 case 里**没有一条**覆盖「告警卡有读者」（`grep -n "case("` 只有版本/证据指针/dod/updated_at/waves 与心跳四态）。
⇒ **该判据的红支在 selftest 里【未被覆盖】**。本报告用**假板负控**把它补上了（`evidence/negctl-alert-reader.py`，4/4 分支可达）。

## 二、★★ 必须避免的坑（8 条，每条都有本机实证）

| # | 坑 | ★ 本机实证 | 正确做法 |
|---|---|---|---|
| **①** | **用「目录非空」判所有段** | `gate-weekly-audit-*` 现测**非空**（1 键，20260907）但**已 35 天无新期**；`resource-gate` 现测 **11762 条**全部正常 | ★ 判据必须**按语义分类**（05 篇 §二五类） |
| **②** | **用「归档」代替「处理」** | `drift-delivery-failure` 7 条在 **19:23:08** 被加 `_archived_at`；★ 负控③实测：**同一板态**，不带过滤 **n=7 ⇒ 红**，带过滤 **n=0 ⇒ 绿** | ★ 归档必须带**理由 + 关联的处理记录**；★ **归档本身不得被算作「已处理」**（clawrush 判据：归档 ≠ applied/closed） |
| **③** | **读者只复述「计数」** | `drift-alert` 已有 1 个计数读者（`bb-blueprint-gallery.py:3672` 读 `n` 与 `latest`）；**内容字段 `drifts[].check` 现测全仓引用 = 1（写者自己）** | ★ 读者的**增量价值在内容与语义状态**，不在再数一遍 |
| **④** | **负控产物与真告警同命名空间** | `plugin-selfcheck` 75 条中 **72 条 `plugin='probe'`**（`missing: ["peer:@deepseek-ai/__NO_SUCH_PACKAGE__"]`，是**故意造的假依赖**） | ★ 读者必须带**过滤器**；★ 负控产物应写**独立命名空间** |
| **⑤** | **「读者没跑」被读成「绿」** | `beacon-check.py` **不在 launchd**（现测无命中/正控 103）；它不跑时**没有任何输出** | ★ 要点 4 的心跳 |
| **⑥** | **再造一层自读** | 现测 `pollution` / `channel-gate-weekly` / `resource-gate` / `queue-condense` / `pitfalls` 的字符串引用**全部落在写者自己文件里** | ★ 读者的判定方**必须在读者之外**（否则是把 9 个自读换成 10 个自读）；★ **其终点只能是「用户 / 对端设备」（04 篇 §三）** |
| **⑦** | **把「读不到」当「绿」** | ★ 本机已有**反面先例被修正**的记录：`beacon-check.py` 的 `skip()` docstring 逐字 `本台已 N 次栽在"跳过看起来和通过一模一样"上` | ★ 不可判单列 |
| **⑧** | **把「字符串扫描 0 命中」当「无读者」** | ★ `data/ops/drift-heartbeat` 字符串面 **1 处**（写者常量），**但确有读者**（`beacon-check` 经 `drift-scan-cron.py --status` 间接读） | ★ 读者必须**登记**（要点 1），不得靠**反查字符串** |
| **⑨** | ★★★ **把【段不存在】读成【空=绿】** | ★ 现测负控（`RAW-OUTPUT-blindspot-RERUN.txt`，20:38:47）：不存在的段名 ⇒ 读者报 `(0,'')` ⇒ **GREEN**。★★ 二次核验（20:41）：**键形 404 也【不能】区分** —— `data/ops/drift-alert`（前缀段，实际 352 条）键形**也是 404**；`data/ops/pitfalls/`（存在的单键段）段形 **total=0** | ★★ **本机黑板是纯 KV（键即命名空间），没有「段存在」原语** ⇒ **「空=绿」在原理上不可靠**。★ 唯一出路 = **板外的段登记表**（要点 1）提供「该段应当存在」，§ 板上「段里有没有键」交叉；**无登记表时，读者的「绿」只能降级为「不可判」** |

## 三、★★ 失效条件（★ 必须给，且不得含糊）

| # | 失效条件 | 后果 | 能否被本机制自己发现 |
|---|---|---|---|
| **F1** | **读者不在任何调度里** | 整条链退回「有人记得」 | ★ **不能**（除非心跳被**另一个**实体读，见 F5） |
| **F2** | **登记表与板漂移**（新段写了没登记） | 新告警段再次**隐形** | ✅ **能**（要点 2 的差集报「未登记=黄」）—— ★ **这正是要点 2 存在的唯一理由** |
| **F2b** | ★★ **板本身无法表达「段存在」**（纯 KV） | **段名打错 / 写者改名 / 段被删** ⇒ 读者**永远报绿** | ❌ **板不能**；★ **只有登记表能**（F2 的同一机制）⇒ ★★ **这是登记表【不可被省掉】的硬理由** |
| **F3** | **登记表被填成「自读」**（写者把自己填为 consumer） | 自读病**在登记表里合法化** | ⚠️ 部分能（可校验 `consumer` 是否等于写者文件名）；★ **但无法防止「写者改个名」** |
| **F4** | **被判对象是移动靶** | 读数不可比 | ✅ 能（要点 6 的 `as_of`） |
| **F5** | **读者的读者缺失** | 递归终止在「用户/对端」 | ❌ **不能** —— ★ **本机不存在「组织外部」**（04 篇 §三） |
| **F6** | **黑板本身不可达** | 全部段同时「不可判」 | ✅ 能（不可判态）—— ★ **但「全部不可判」与「真的全坏」需人判**，本机制不判 |
| **F7** | **读者自己有 bug（如只读第一个段就退出）** | 部分覆盖被读成全部覆盖 | ⚠️ **只有负控能发现**（要点 7 要求**每分支**负控，含「段数守恒」：读到的段数必须 == 板上段数） |
| **F8** | **登记者与被读者是同一主体**（自审） | ★ **结构上不带信息**（项目纪律「自审在结构上不带信息」） | ❌ **不能** —— 必须由**另一个会话/角色**审 |

★★★ **⇒ 本设计【不能】解决 F1 / F3 / F5 / F8。**
★ 其中 **F5（终端在系统之外）在本机结构上无解**，只能**如实登记为限制**（01 篇 §四、04 篇 §三）。
★ **任何声称「装了共用读者 = 告警一定有人看」的表述，都落在 02 篇 `security theater` 的定义里。**

## 四、★ 最小可行集（如果只能做一件）

★★★ **先做【要点 1 的登记表】，哪怕只登记现测的那 13 个段。**
理由链：
1. 现测 **265 个段**里，能回答「谁读它」的 **≤ 2**（05 篇 §五，且受盲区限制）；
2. 没有登记表，**读者只能靠反查字符串**（事后考古）——★ 而字符串反查**已被现测证明有系统性盲区**（坑⑧）；
3. ★ **登记表的 `consumer` 字段是【唯一一个在创建时刻就能回答「谁会读」的位置】**（02 篇逐字依据）；
4. ★ **它的最大单项收益不是「多抓到告警」，而是「让『未登记』变成一个显示出来的黄」**（要点 2）—— 这把「系统性无读者」从**默认静默**变成**默认显式**。

★ **成本估计**：登记表 13 条 + 读者脚本（复用 `beacon-check.py` 的 `read_alert_cards` + 三态框架）⇒ **半天级**。
★ **不建议做的**：把 265 段一次登记完（**分母不清且大量是 D/E 类**，会得到一个没人维护的大表 —— 那是 02 篇的 `checkbox compliance`）。
