## ★★ 最重要的五条发现（全部现测，非引用）

### ① 现役唯一读者的「绿」有【两个互相不可区分的成因】——「空 ≠ 无」的逐字违反

把 `read_alert_cards()` 的目录名换成**绝不存在**的名字，读者报 **`(0,'')` ⇒ GREEN**（负控，20:38:47）。
二次核验（20:41）发现**更坏**：黑板是**纯 KV（键即命名空间）**，**没有「段存在」这个原语** ——
- `data/ops/drift-alert/`（前缀段，确有 352 条）⇒ 键形 **404**
- `data/ops/pitfalls/`（存在的单键段）⇒ 段形 **`total=0`**
- `data/ops/zzz-nope-xyz/`（不存在）⇒ 段形 **`total=0`**

★★★ **⇒ 「段名打错 / 写者被改名 / 段被删」与「真的没有告警」在读者输出上**完全同形**。
⇒ 按纪律，**`data/ops/bus-expired-alert` 此刻的 `(0,'')` 是「不可判」，不是「绿」。**
★ 出路只能是**板外的段登记**（06 篇要点 1）——**这不是实现细节，是原理缺陷。**

### ② 「归档」把红变绿，但 7 条告警【一条都没被处理】

`data/ops/drift-delivery-failure` 7 条在 **19:23:08** 被加 `_archived_at`。
同一板态负控：**不带过滤 n=7 ⇒ 红；带过滤 n=0 ⇒ 绿**（`RAW-OUTPUT-negctl-alert-reader.txt`）。
⇒ ★ 对照业界：归档 **不是** `applied / closed / recorded / forwarded / decided` 中的任何一个（02 篇逐字判据「`opened` is not consumption」）。
⇒ **这是「silence 当 ack 用」的本机形态；且本机的 silence 没有到期时间。**

### ③ 写者报「完成」，盘上没写进去，35 天无人知

`com.dsh.gate-weekly-audit` 现测 **loaded**、周一 09:30；**今天正是周一**；日志有 `09:30 周度巡检开始` 与 `[gate-weekly] 完成`；
★ **但 stderr 是 `SyntaxError: EOL while scanning string literal`**（`python3 -c` 拼 `$SUMMARY` 时引号未转义）。
★ 板上该段**只有 1 个键：`gate-weekly-audit-20260907`**（2026-09-07）⇒ **35 天无新期**。
⇒ ★ 这一段是 **B 类（每期新键）**：任何「空=绿」或「非空=红」的判据**都答不出「最新一期在哪」**。

### ④ 读告警的读者【不在任何调度里】

`grep -rl beacon-check ~/Library/LaunchAgents/` **0 命中**，同期阳性对照 `grep -rl dsh ~/Library/LaunchAgents/ | wc -l` = **103** ⇒ **负结果可信**（本报告少数带完好对照的 0）。
★ 且 `--selftest` 现测**全绿 22 条**，★★ **但没有一条覆盖「告警卡有读者」**（心跳那一条有 4 条负控，这一条 **0 条**）。
⇒ ★ 该判据的**红支在自证里不可复现**；本报告用假板负控补上（4/4 分支可达）。

### ⑤ 告警面的最大两块不在任何清单上；「11 个目录」是【代码字符串清点】不是【板普查】

现测 `data/ops` 下第三段 **265 个**；条数 ≥2 的只有 **7 个**，其中 **`resource-gate` 11762 条**（含 **verdict=red 670 条**）与 **`queue-condense` 2243 条** ★★ **从未出现在任何告警清单里**。
★ 而题面 11 个里的 `auth-probe` / `probe` / `gate-weekly-audit-` **在板上根本不是段名**（是脚本里的 PUT 目标字符串）。
★★★ **⇒ 若以「代码字符串」当分母，会同时【漏掉 11762 条的那个段】和【误登记 3 个测试夹具】。**

## ★ 本报告的方法学弱点（★ 主动登记，供审）

1. ★ **读者扫描是字符串匹配**：对**经常量 / 配置 / 函数间接寻址的读者**有系统性盲区（已用 `drift-heartbeat` 实测坐实）。
   ⇒ 全文「0 外部引用」**一律限定为「字符串扫描面内 0 引用」**。
2. ★ **`data/ops` 是移动靶**：任何读数都只在标注时刻成立。
3. ★ **本报告自身的探针踩过 3 次事故**（前缀重复拼接 / 段长判据错 / 阳性对照选错），已全部更正并登记在 07 篇 §十。
   ★ 其中第 3 次恰好证明：**「没有对照的 0」与「对照坏了的 0」长得一模一样** —— 与本报告指控的病同构。
4. ★ **前一次尝试留下的一条「对照」结论经二次核验是错的**（「键形 404 可区分空与不存在」只在单键段成立），已在 05 篇 §五之二 当场更正。
   ⇒ **对照本身也必须被对照。**
5. ★ **未做**：告警**精度/召回**的量化（需要人工标注「哪些告警是真的」）⇒ 本报告**不报任何 precision/recall 数字**。
