## 二、★★ 四类语义（★ 本文的核心产物）

★ 判据不是「它叫什么名字」，而是**写者的写条件**（读源码可机械判定）+ **键的形态**。

| 类 | 语义 | 判据（机械） | 「正常」长什么样 | 「红」长什么样 | 该段的读者该读什么 |
|---|---|---|---|---|---|
| **A · 异常才写** | 事件驱动告警 | 源码里写入被 `if <异常>:` 包裹 | **空** | **非空** | 键的**存在性**（空=绿） |
| **B · 定期累积** | 周报/月报 | 写入**无条件**，键含时间戳 | **最新一期存在且新鲜** | **最新一期缺失/陈旧** | **latest 的 ts**（missing=红） |
| **C · 状态流 / 覆盖写** | 心跳、体检 | 键名固定（`current`）或 `status-<ts>`，**`version` 递增** | **新鲜** | **陈旧** | **staleness** |
| **D · 单键台账** | 知识台账 | 单键，内容为**数组**（`items[]`） | **有内容** | ★ **不适用**（不是告警） | 无（是文档） |
| **E · 测试目标** | 探针端点 | 板上无键或一次性键 | ★ **不适用** | ★ **不适用** | 无（是测试夹具） |

★★★ **⇒ 一句话：A 类「空=绿」，B/C 类「空/陈旧=红」，D/E 类根本不是告警。**
**把 A 与 B 用同一个读者读，是本次最要避免的错误。**

## 五之二、★★★ 决定性发现：**本机唯一读者的「绿」，把【不存在的段】与【空的段】读成同一个东西**

★ **本节是本报告最重要的一条负面发现。** 复跑命令与未编辑原始输出见 `evidence/RAW-OUTPUT-blindspot-RERUN.txt`（现测 2026-10-12T20:38:47+0800）。

**做法（负控）**：把 `read_alert_cards()` 的目录名换成**绝不存在**的名字，看它报什么。

```

  data/ops/drift-delivery-failure        -> (0, '★ 共 7 条、其中 7 条已归档；')
  data/ops/bus-expired-alert             -> (0, '')

== 负控：把目录名改成【绝不存在】的名字，看读者报什么 ==
  data/ops/zzz-audit-does-not-exist-xyz  -> (0, '')   => GREEN(0条)
  data/ops/another-bogus-ns              -> (0, '')   => GREEN(0条)

== 对照：用【键形】(无尾斜杠) 探测同一批不存在的名字 ==
  data/ops/zzz-audit-does-not-exist-xyz  HTTP=404 (键形) <-- 可与「空」区分
  data/ops/another-bogus-ns              HTTP=404 (键形) <-- 可与「空」区分
  data/ops/bus-expired-alert             HTTP=404 (键形) <-- 可与「空」区分
```

★ **本报告独立补测黑板列举语义**（20:39，同一文件）：
```
data/ops/                            total= 16169
data/ops/drift-alert/                total= 352
data/ops/zzz-nonexistent-xyz/        total= 0     <-- ★ 不存在的段：200 + 空 list
```
⇒ ★★ 前缀列举**确实按前缀过滤**；**但「段不存在」与「段存在且为空」都返回 `total=0 / 空 list`。**

★★★ **后果（这就是本项目的「空 ≠ 无」逐字违反）**：

| 情形 | 读者输出 | 读者判决 |
|---|---|---|
| 段存在，无告警（真绿） | `(0, '')` | **GREEN** |
| ★ **段名字打错 / 写者被改名 / 段被删** | `(0, '')` | ★★ **GREEN（假绿）** |
| 段存在，有未处理告警 | `(n>0, ...)` | 红 |
| 段存在，有告警但全部归档 | `(0, '★ 共 N 条、其中 N 条已归档；')` | GREEN（★ 见坑②） |
| 板不可达 | `None` | ★ **不可判**（✅ 做对了） |

★★ **⇒ 「读者绿」这件事有【两个】互相不可区分的成因**：真无告警，**或**读者根本没读到对的地方。
⇒ ★ 而 `data/ops/bus-expired-alert` 现测**就是 `(0, '')`** ⇒ **它此刻到底是「绿」还是「段名不对」，从读者输出上【无法区分】** ⇒ 按纪律：**它在读者眼里是「不可判」，而不是「绿」。**

★★★ **★ 二次核验（本报告现测 20:41）：上述「用键形 404 即可区分」的结论【是错的】，必须当场改正。**

```
data/ops/pitfalls                          http=200        <- 单键段：键形命中
data/ops/drift-alert                       http=404        <- ★ 前缀段：键形【也 404】，但该段确实存在（352 条）
data/ops/drift-alert/1791790395076         http=200        <- 其具体键命中
data/ops/zzz-nope-xyz                      http=404
--- 段形 ---
data/ops/pitfalls/      http=200 total= 0      <- ★ 存在（单键）却 total=0
data/ops/drift-alert/   http=200 total= 352
data/ops/zzz-nope-xyz/  http=200 total= 0      <- ★ 不存在
```

★★ **⇒ 键形 200 只在【单键段】成立；对【前缀段】（本机的多数）键形一律 404，与其存在与否无关。**
★★★ **⇒ 真正的结论更强，也更坏**：

> **本机黑板是一个纯 KV：【键即命名空间】，没有「段存在」这个原语。**
> ⇒ **「段存在但为空」与「段不存在」在【存储层】就是同一个状态**（段形皆 200+`total=0`；键形皆 404）。

★★★ **⇒ 因此「空 = 绿」在本机黑板上【在原理上不可靠】，不是实现细节问题。**
★ 唯一的出路是**板外信息**：**一张独立的段登记表**（06 篇要点 1）回答「**这一段应当存在**」，再与板上「段里有没有键」交叉。
★ **没有登记表时，读者的绿只能报「不可判」。**

★★ **（附带纪律教训）** 前一次尝试给出的「键形 404 可与空区分」这一**对照本身没有被对照** —— 它只在单键段上成立，却被写成了通则。
⇒ ★ **对照组也必须被本项目的纪律审查：一个只在部分样本上成立的对照，不是一个对照。**

## 六、★ 「不可判」清单（★ 空 ≠ 无）

| 项 | 为什么不可判 |
|---|---|
| `bus-expired-alert` 的 0 条 | 该段**板上无键** + 写者 `if (过期) {写}` ⇒ **「没有过期消息」与「写者从未被触发」在读数上完全同形** ⇒ ★ **不是「0 个过期消息」，是「不可判」** |
| `auth-probe` / `probe` 的 0 | ★ **不是「0 条告警」，是「板上根本没有这个段」**（它们是脚本里的 PUT 目标字符串） |
| 各段「0 外部引用」 | ★ 受**间接寻址盲区**限制（见 §五），**只能报「字符串面 0」，不能报「无读者」** |
| ★ `bus-expired-alert` 读者的 `(0,'')` | ★★ **「真无告警」与「段名不对/段不存在」在读者输出上不可区分**（§五之二）⇒ **不可判**，**不得报绿** |
| ★ 任何段的「绿」 | ★ 同上：**在本机黑板（纯 KV，无「段存在」原语）上，「绿」在没有【板外段登记】时不可成立** ⇒ 只能报「不可判」 |
| `plugin-selfcheck` 的「75 条」 | ★ 96% 是负控产物 ⇒ **不能报「75 个插件故障」** |
| `resource-gate` 的 670 条 red | ★ 是**采样流** ⇒ **不能报「670 次故障」**（未去重、无持续时长口径）；按纪律：**不可判** |
