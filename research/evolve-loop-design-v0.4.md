## 二、dsh-self-improved 共性/差异评估（用户裁决依据）

### 2.1 dsh-self-improved 实际能力（已调研）
- L0 capture（原始捕获）→ L1 memory extraction（记忆抽取）→ L2 scene grouping（场景分组）→ L3 user persona（用户画像）
- auto recall（自动召回注入）+ skill synthesis（技能合成）+ 全本地

### 2.2 共性（可借鉴部分）

| 共性 | 说明 |
|---|---|
| 记忆分层 | L0-L3 分级（捕获→抽取→分组→画像）——技能沉淀的分层思路可借鉴 |
| auto recall | 自动召回——技能库检索复用的思路一致 |
| 全本地 | 本地优先——与我们的零订阅原则一致 |
| skill synthesis | 技能合成——与「造牌」方向相关 |

### 2.3 差异（Evolve Loop 独有，dsh-self-improved 无）

| 差异 | dsh-self-improved | Evolve Loop | 重要性 |
|---|---|---|---|
| 目标锚定 | ❌ 无（纯记忆） | ✅ 蓝图消费（blueprint:<id> 锚定） | 核心 |
| 执行反思 | ❌ 无 | ✅ Reflexion（失败→反思→重试） | 核心 |
| 短板评估 | ❌ 无 | ✅ 短板评估器（能力 vs 蓝图差距） | 核心 |
| 课程推进 | ❌ 无 | ✅ 自动选题（Voyager 课程） | 核心 |
| gate 校验 | ❌ 无 | ✅ 蓝图 gate（ROI_eff>1） | 核心 |
| 工具造牌 | 仅 skill 合成 | 完整造牌（选型→开发→R006→登记） | 核心 |
| 用户对话 | ❌ 无 | ✅ blueprint-dialog（沟通工具化） | 核心 |
| 版本迭代 | ❌ 无 | ✅ blueprint-refine（版本 bump） | 核心 |

### 2.4 结论：差异 >> 共性 → **自研**

共性仅「记忆分层/召回」两点，差异覆盖 8 项核心能力（目标/反思/短板/课程/gate/造牌/对话/迭代）。dsh-self-improved 是「记忆型」插件，Evolve Loop 是「目标驱动执行型」——定位完全不同。扩展它 = 重写 80% + 背负其设计包袱；自研 = 干净架构 + 完整覆盖需求。**裁决：全新自研 dsh-plugin-evolve。**

## 三、专利/知识产权进取性评估（用户：进取性价值大于一切）

### 3.1 潜在专利点（Evolve Loop 组合创新）

| 潜在专利点 | 创新组合 | 进取性 |
|---|---|---|
| 蓝图-循环解耦架构 | blueprint platform + evolve loop 双层 | 高（无现成） |
| BP-9 蓝图元数据契约 | 9 字段 + 引用/标注语法 | 中高（标准化可主张） |
| 短板评估-课程联动 | 能力差距→自动选题→造牌 | 高（组合创新） |
| 反馈回流版本迭代 | 执行反馈→蓝图 bump | 中高 |
| 资源预算并行度 | 成本门禁内多实例调度 | 中 |

### 3.2 知识产权策略建议

1. **专利优先**：核心组合创新（蓝图-循环解耦 + 短板-课程联动）有申请价值——先记录技术交底（design doc 即证据），评估 PCT/国内申请
2. **防御性公开**：未申请前先留时间戳（设计文档 + KB 入库即公开记录，防他人抢先）
3. **开源策略**：若走开源（dsh-plugin 生态），用 LICENSE 声明（AGPL 类防闭源利用），核心专利点可保持专有
4. **进取性 = 技术主张权**：即使不申请专利，「我们是原创者」的记录（时间戳+文档+代码）就是知识产权基础——设计文档已落盘（v0.2/v0.3/v0.4 版本链可追溯）

### 3.3 用户裁决执行：自研（干净架构）+ 专利进取性优先（技术交底记录）

## 四、preset 设计（evolve 模式，先用后启）

evolve preset（~/.dsh/.agent-presets/evolve/）：
- 工具面：收窄到循环相关（goal/沉淀链/选型评估/registry/蓝图 API）
- persona：注入循环纪律（目标锚定/反思先行/造牌优先复用/用户确认制）
- 资源：登记蓝图平台资源（blueprint:<id> 读权）
- 启用：插件 v1.0 发布后激活（先用后启）

## 五、资源预算并行度评估器（用户裁决：看预算跟用户确认）

### 5.1 评估维度
- 成本预算：approval-config cost_gate（单任务 L0-L3 + 日熔断 ¥100/200）
- 可用 token：日预算剩余（token-ledger 实时）
- 资源占用：常驻服务内存/CPU（i9 GPU 约束）
- 依赖冲突：多循环共享资源（红绿灯锁）

### 5.2 流程

启动前 → 评估器计算建议并行数（预算内 N 实例）→ 与用户确认（同意/调整/单线程）→ 执行
