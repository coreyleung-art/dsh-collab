## 二、评估集（4 类任务 × 20 例）

| 类别 | 任务形态 | 示例 | 指标侧重 |
|---|---|---|---|
| 摘要 | 长文本→结构化摘要 | 周报/会议纪要 | 信息保真度、压缩比 |
| 抽取 | 非结构化→结构化字段 | 订单/评价关键信息 | 字段准确率（pass/fail） |
| 分类 | 文本→标签 | 意图/情感/风险分级 | 分类准确率 |
| 工具调用 | 自然语言→工具参数 JSON | 查询/动作参数生成 | JSON 合法率、参数正确率 |

每个样本含：输入（≤2k tokens）、参考答案、难度标记。judge 方案：规则可判的用规则（JSON/字段），主观的用 LLM-judge（同一模型打分，注明 judge 模型避免自评偏差）。

## 三、指标与统一成本口径

1. **质量**：准确率 / 1–5 分（按类别）
2. **性能**：tokens/s、首 token 延迟（TTFT）、显存峰值
3. **统一成本口径**：每万 token 处理耗时（秒）= 10000 / tokens/s；跨设备对比用「每万 token 耗时」而非绝对算力，便于换算调度价值
4. 记录模板：模型+量化档位 / 设备 / 类别得分 / tokens/s / 峰值显存 / 备注

## 四、执行流程

1. mac-mini 先跑通评估脚本（LM Studio 或 Ollama 任选，统一 OpenAI 兼容接口）→ 产出基线
2. 同一脚本+模型清单分派 PC-i9（协调侧已就绪，可直接调度）
3. 汇总成路由表：每类别选「达标前提下的最低成本/最快设备」模型组合
4. 路由规则回写 DSH agent preset 与设备分派协议
