## 最重要的三条发现

### ① `bus-8791` 是「绿而无效」的活样本（05 篇 §六 / 06 篇）

`lib/channel-matrix.json` 里 `bus-8791` 的唯一判据是 `expectBodyContains: "ok"`（**无 `expectStatus`**），而 `core.js:85` 用 `body.includes("ok")`。

实测判决表：

| 输入 | 语义 | 判决 |
|---|---|---|
| `200 {"ok":true,"task":null}` | 正常 | 绿 |
| `401 {"ok":false,"errmsg":"unauthorized"}` | 鉴权失败 | **绿** |
| `403 {"ok":false}` | 被拒 | **绿** |
| `500 {"error":"internal","ok":false}` | 服务端错 | **绿** |
| 不可达 | 服务死 | 红 |

⇒ `"ok"` 作为**键**出现在**失败**响应体里 ⇒ `includes("ok")` **无法区分「服务说它好」与「服务说它不好」**。
⇒ 这正是本项目纪律「**负控须验【被消费的值】而非【取数成功】」的逐字实例** —— 取数成功了，值读错了。

### ② 「12 项全绿」是状态量，且**日志无法回答「哪一项红过」**（05 篇 §二 / §四）

```bash
$ grep -c '"check"' ~/dsh-collab/logs/drift-scan.log
0            # 逐项记录根本不存在
$ grep -o '"result":"[A-Z]*"' ~/dsh-collab/logs/drift-scan.log | sort | uniq -c
    156 "result":"CLEAN"
    397 "result":"DRIFT"
```
⇒ **记录了 397 次「有东西红了」，却无法回答「哪一项红过」——而那正是本题唯一要问的问题。**
⇒ 按本项目纪律，**12 项的 B 类（曾否触发）状态 = 「不可判」，不是「0 项」，也不是「12 项」。**

### ③ 12/12 的比较器都能红 —— **但这只证明了「仪器在算」，没证明「仪器看对了」**（03 篇 §四 / 05 篇 §五）

影子副本 + 扰动期望矩阵 ⇒ **12/12 项在注入坏输入后能红**（无 A 类恒真）。
⇒ ★ **这否证了「12 项一个负控都没有 ⇒ 必有恒真项」这一推论**，同时也**精确了真正的缺口**：
> **缺的不是「比较器有没有判别力」，而是「观测通道读到的是不是真值」。**
> `bus-8791` 恰好是**比较器能红、而真值读错**的那一个 ⇒ **03 篇的边界是真边界，不是免责条款。**
