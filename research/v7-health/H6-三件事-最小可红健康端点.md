| 项 | 内容 |
|---|---|
| **做什么** | 把 `/health` 的读数接进 `tools/beacon-check.py`（`--net` 模式），与 v7 计划 §一.C 把信封尺接进 `beacon-check` 是**同一手法** |

## 第 1 件 ★★★：**定契约** —— 三态 + 逐项 + **总判必须独立**，且**不可判必须是 503**

### 依据（全部已读原文）

| 规范 | 逐字依据 | 它要求什么 |
|---|---|---|
| **Healthchecks.io** | "**New**. A newly created check that has not received any pings yet." | ★ **「一条都没收到」是独立态，绝不是 `Up`** |
| **Prometheus** | `absent()` "returns ... **1 if the vector passed to it has no elements**. This is useful for alerting on when **no time series exist**" | ★ **「没有数据」必须能被单独表达** |
| **gRPC** | "**If the service name is not registered, the server returns a `NOT_FOUND`** GRPC status." | ★ **「我查的东西不在」不是 OK** |
| **AWS ALB** | "the load balancer **fails open**" | ★ **「一个健康的都没有」是**被命名的**第三种裁决** |
| **K8s apiserver** | `[+]etcd **excluded**: ok` | ★ **「没查」≠「查了通过」** |
| **NATS `/healthz`** | schema：`status` **required** + `errors object[]` | ★★ **总判是独立必填字段，不得从明细反推** |

### 具体做法

```jsonc
// GET /health  的响应契约（建议形态）
{
  "verdict": "pass" | "fail" | "undecidable",   // ★ 独立总判，必填
  "checked": 6,                                  // ★ 分母
  "observed_at": "2026-10-12T20:1x:xx+08:00",   // ★ 观测时刻（读时用它判陈旧）
  "items": [
    {"channel":"board-local", "verdict":"pass", "layer":"identity",
     "detail":"hb-mac-mini node=mac-mini age=18.7s", "observed_at":"…"},
    {"channel":"sse-8803",    "verdict":"undecidable", "layer":"protocol",
     "reason":"observed < 60s, 0 change events while board moved"},
    {"channel":"bus-8791",    "verdict":"pass", "layer":"identity", "detail":"roundtrip ok"},
    {"channel":"tailscale-direct","verdict":"fail","layer":"reachability",
     "detail":"peer macbook-pro-2: offline, last seen 2m ago"}
  ]
}
```

★★★ **四条硬约束（每条都对应一份已读规范）**：

| # | 约束 | 依据 | 若违反会怎样 |
|---|---|---|---|
| 1 | **`verdict` 是独立字段** | NATS `/healthz` 的 `status` 是 `required` | ★ **下游只能拿 `total:0` 或 `errors` 为空反推总判** ⇒ 就是当下的病 |
| 2 | **分母 = 0 ⇒ `undecidable`，且 HTTP **503**** | Healthchecks.io `New` · AWS fail-open 是**显式的第三种** | ★ **0 条被读作通过**（当下的病） |
| 3 | **`undecidable` 不得写成 `pass`，也不得写成 `fail`** | AWS：摘掉 ↔ 不健康是**两个计数** | ★ 空被并进任一侧，都丢失信息 |
| 4 | **`observed_at` 必填，陈旧在【读时】判** | Healthchecks.io `Late`/`Down` 两态；Prometheus 靠 `absent()` 接缺失 | ★★ H5 §5 实测：**过期 1.54 倍仍写着 PASS** |

★ **关于 `undecidable` 该回 200 还是 503 —— 这是一个【待裁】项**：
- **AWS 选 fail open**（继续发流量）
- ★ **本文件倾向 fail closed（503）**，理由：本机通道是**协作基础设施**而非用户流量入口，
  且本机已有「报红由人裁」的既有形态（`drift-scan` `EXIT=1` + 告警卡）。
- ⇒ ★ **我判「必须有一个显式的第三种裁决」，不判「它该是 200 还是 503」。**

### 反例（必须跑，且必须能红）

```bash
# 反例 1：0 通道（分母为 0）
#   造法：临时把 item 源指向一个空的注册卡（不动生产数据 ⇒ 用副本/参数注入）
#   期望：verdict=undecidable · HTTP 503 · ★ 不得 200 · 不得 pass
# 反例 2：全部通道读不到
#   期望：verdict=undecidable · reason=unreachable · ★ 不得沿用上次的 pass
# 反例 3：单项「没查」（excluded）
#   期望：该项 verdict=excluded · ★ 不得写 ok
```

★ **本件的失效条件（纪律要求）**：
**当「分母」本身是软的**（即 `items` 的长度由实现方决定而非由一份**冻结的通道清单**决定）时，
「分母为 0 ⇒ 不可判」会被**加一行空 item** 绕过。
⇒ ★ **分母必须来自 `~/dsh-plugin-drift-scan/lib/channel-matrix.json` 这类单一来源清单**（本机已有此形态），
**不得由 `/health` 的实现自己 enumerate**。

## 第 2 件 ★★：**用已有的真数据 + 加身份断言**（不新造数据）

### 依据

| 规范 | 逐字依据 | 要求 |
|---|---|---|
| **Envoy · L3/L4** | "It expects the **byte buffer to be echoed** in the response if the host is to be considered healthy." | ★ **「通」= 我发的东西原样回来了，不是「有人回了 200」** |
| **dev.to 深探针** | "you must **monitor the content, not just the connection**"; 四条断言（Response Time / Content-Type / JSON Schema / Business Logic） | ★ **验证契约，不是状态码** |
| **NATS `/varz`** | 返回**小 JSON 快照**，不是全量数据 | ★ **健康面要有独立的便宜读路径** |
| **NATS `slow_consumers`** | "the number of clients the server has **disconnected for not keeping up**" | ★ **背压/队列深度是健康指标** |

### 具体做法（★ 数据源全部本机已有，见 H5 §6）

★ **H5 §6 实测**：`data/health/hb-mac-mini` age **18.7 s**、`hb-mbp` age **73.6 s**，
字段含 `node` / `app_pid` / `boot_iso` / `dsh_port`。
⇒ ★★ **真数据是新的、够用的、已经在板上** —— **缺的只是「读 + 判 + 表达」。**

| 通道 | 建议的真检查（**不是 200**） | 反例（必须能红） |
|---|---|---|
| `board-local` | GET `data/health/hb-mac-mini`，断言 **`value.node == "mac-mini"`** 且 **`now - value.ts < 120`** | ★ **H4 负控 B 已证**：指向冒牌 always-200 服务 ⇒ 现在报绿 ⇒ 加 `node` 断言后**必须红** |
| `board-central` | 同上 + 断言**两端 `ts` 差 < N** | 中央板返回**别的节点的卡** ⇒ **红** |
| `sse-8803` | 收 `hello` **且** T 秒内 ≥1 条 `change`（板在动就必有 `change`，H5 §7 实测 `id: 498036`） | 只收 hello、T 秒无 change **而板在动** ⇒ **红** |
| `bus-8791` | 带 token **往返**：发探针消息并读回**同一条** | token 过期/轮换 ⇒ **红** |
| `tailscale-direct` | ★ **H5 §4 的活反例即此处必须修**：判据**不得**是同名+`active` 子串匹配 | ★ **对端 `offline` 时必须红**（当下报绿） |
| 心跳 | 读时判 `now - ts > stale_threshold` | ★ **H5 §5 实测**：`sedimentation` 过期 1.54× 仍写 PASS ⇒ **必须红** |

★ **顺带解决的一个成本问题**（H5 §7 实测）：
当前 `board-local` 的 `probe.path` 是 `/notes` ⇒ 每次「查板活不活」下载 **32,510,382 bytes（31 MB）**。
⇒ **新的探针路径应是一个小键的直读**（如 `data/health/hb-mac-mini`，实测 ~300 bytes 级），
**把健康检查从「全量快照」搬到「增量/定点读」** ——
★ 这与既有调研 `research/agent-comm-paths/G0-源头架构统一诊断.md` 逐字的结论同源：

> **系统只有「取全量状态快照」这一个读原语，没有「给我上次读之后的增量」这个原语。**

### 反例

```bash
# 反例 A：身份置换（H4 负控 B 的正式化）
#   把 board-local 的探针指向一个对任何路径都回 200 的冒牌服务
#   期望（修后）：verdict=fail（因为 node 字段不对）· ★ 现状：pass  ← 已实测，见 H4 §4.4
# 反例 B：内容置换（同名返回但内容不是那个东西）
#   期望：fail
# 反例 C：陈旧（把心跳键的 ts 改成 10 分钟前）
#   期望：fail 或 undecidable · ★ 不得沿用 pass
```

★ **本件的失效条件**：
**当「被检查对象」与「检查者」是同源写者时，身份断言会被同源伪造。**
★ 本机实例已存在：`drift-scan` 的矩阵与检查器同仓、`/health` 若读板键而板键由本机进程写 ⇒
**「node == mac-mini」能挡住冒牌服务，但挡不住「本机进程自己写了个错值」**。
⇒ ★ **须补一条**：断言至少有一项**来自不由被检查者产生的外部信号**（本仓纪律「信号免疫」的 ② 半边）。

## 第 3 件 ★★：**给每条判据装一个能红的反例，且把「恒红（刷屏）」也当失效**

★★★ **这一件是本文件最重的，因为 H5 §3.3 的实测结果彻底改变了问题的形状：**

```
总扫描次数 N = 573
CLEAN = 167  DRIFT = 406  ⇒ 红率 = 70.9%
2026-10-06 → 10-10：连续 5 天 100% 红
data/ops/drift-alert/ 卡面总数 = 352
抽样 40 张：funnel-public 出现在 35 张（≈87.5%）
```

### ★★★ 诊断（比「零负控」更准确的一句话）

> **问题不是「判据从来没红过」，而是：**
> **① 至少 1 项【该红时不红】（`tailscale-direct` 在对端 `no reply` 时报绿 —— H5 §4 活反例）；**
> **② 红的压倒性多数来自 2 个网络检查的抖动 ⇒ 近乎恒红；**
> **③ 352 张卡里写了「哪条通道漂了」，而那个字段（`drifts[].check`）的读者 = 0（H5 §3.4b）**
> —— ★ **卡只被【计数】，从未被【读内容】。**
>
> ⇒ ★★ **这是同一条律的三端：**
> **恒绿、恒红、以及「红了但没人读内容」，都把判据的信息量降到 0。**
> **一个判据的信息量 = 它区分「好」与「坏」的能力，且该区分必须**落到某个读者**上。**

### 依据

| 规范 | 逐字依据 | 要求 |
|---|---|---|
| **AWS ALB** | "**UnhealthyThresholdCount** … **HealthyThresholdCount** …" (2–10) | ★ **连续计数 + 迟滞** |
| **GCP LB** | "Based on a configurable number of **sequential** successful or failed probes" | ★ 同上 |
| **Envoy** | "**failures required** before marking a host unhealthy, **successes required** before marking a host healthy" | ★ 同上 |
| ★ **本机已有** | `beacon-check.py --selftest` 逐字：`PASS 反例可红：…` / `PASS 正控：…（判据非恒红）` | ★★ **本机已有成熟范式，只是没用到 `drift-scan` 上** |

### 具体做法

| 动作 | 内容 |
|---|---|
| **A. 每项配一个可执行的负控** | 照 `beacon-check.py --selftest` 的形态：对 12 项各造一次「必然坏」的夹具，**证明它变红**。★ **必须能在不改生产环境的前提下跑**（本调查员的 H4 实验就是「复制到 /tmp 改副本」的模板） |
| **B. 加迟滞（连续计数）** | 单次读数**不得**改判。★ **H5 §3.2 实测**：同一未改系统 4 次连跑得 `0/0/1/0` ⇒ **单次判定必然抖动** |
| **C. 把「刷屏」也当失效** | 若某检查在窗口内红率 > 阈值（如 90%），**它必须被标为「判据失效」而不是「通道失效」** —— 因为**读者已经不看了** |
| **D. 修 `tailscale-direct` 的判据形态** | ★ 从「同行含 peer 且含 `active`」改为**显式否定匹配**（含 `offline` ⇒ 红），或更好：用 `tailscale ping` 的**输出**（★ 注意其 `rc=0` 不可用，见 H5 §9） |

### 反例（每一条判据都要问「什么条件下它会失效」）

| 判据 | 它在什么条件下失效 | 本机已实证？ |
|---|---|---|
| `tailscale-direct` | ★ **对端行同时含 `active` 与 `offline` 时**（信号与失效**不同路**） | ★★ **已实证（H5 §4 · 本调查员）** |
| `bus-8791` | ★ **消费的是 `body.includes("ok")`，而失败响应体 `{"ok":false}` 也含 `"ok"`** ⇒ 在 `401/403/500` 上**全绿** | ★★ **已实证（`research/v7-negctl/06-绿而无效-负控须验被消费的值.md` · 代理 R3）** |
| `board-local`（`expectStatus:200`） | ★ **失效形态也回 200 时**（探针指向不存在路径 / 冒牌服务） | ★★ **已实证（H4 负控 A/B/C · 本调查员）** |
| `hb-fwd`（`launchd-loaded`） | ★ **job 加载但反复崩溃时**（`launchctl list` 仍列出） | ★ **未实测**（需改 launchd，越权） |
| `sync-from-central` / `device-daemon`（`process-alive`） | ★ **进程存在但空转时**（这正是 `research/agent-comm-paths/G3-进度与活性分离-四十年工程史的同一个答案.md` 的整篇主题） | ★ **未实测** |
| 全部 endpoint 类 | ★ **单次采样时**（抖动） | ★★ **已实证（H5 §3.2）** |

★★ **合并结论（本调查员 + 代理 R3 两方证据）**：
**12 项的比较器都活着**（R3 `03` 篇已证「扰动期望 ⇒ 12/12 能红」），
**但其中至少 3 项对「真失效」零判别力**：`tailscale-direct`（信号不同路）·
`bus-8791`（消费的值错）· **全部 endpoint 类**（失效形态也回 200 ⇒ 恒绿）。
⇒ ★ **「能红」与「该红时不红」是两个不同的性质，必须分别验证。**

★ **本件的失效条件**：
**「负控」自身也可能是空转的。** ★ 本仓已有这条教训（`notes/xdom/log/20261012T040036-...` 逐字）：

> ★ **「写进控了」不等于「控是活的」** …… ★ **控还必须【复刻活板形态】**。
> ★ 我的控复刻了**值**，没复刻**形态**。

⇒ ★★ **故 A 项的验收标准不是「有负控」，而是「负控复刻的是**活板上那个失效形态**」** ——
★ 本调查员 H4 的负控 B **正是**照这个标准做的（它复刻的是「一个返回 200 但不是黑板的东西」，
**不是**「一个返回 500 的东西」）。

## 一、三件事的优先级与理由（含「为什么不是别的」）

| 序 | 事 | 为什么排这个位置 | 代价 | 立刻可见的读数变化 |
|---|---|---|---|---|
| **0** | 指定第一个读者（接入 `beacon-check`） | ★ 读者 = 0（H5 §2）⇒ **不先做这件，1–3 全是「做了没人看」** | 小 | `beacon-check --net` 多一项 |
| **1** | 定契约（三态 + 逐项 + 独立总判 + 不可判=503） | ★★★ **这是「不再是空壳」的定义本身**；且**先定契约才能定探针**（H4 §4.3 实测：先接探针会把假绿固化进矩阵） | 小 | `/health` 由 45 bytes 变为含 `verdict`/`items` 的结构 |
| **2** | 用已有心跳 + 加身份断言 | ★ 数据**已存在且新鲜**（H5 §6：18.7 s / 73.6 s）⇒ **边际成本最低**；且**顺手解掉 31 MB/次 的探针代价** | 中 | 至少 1 项由「HTTP 200」变为「node 断言 + 新鲜度」 |
| **3** | 每项装能红的反例 + 迟滞 + 刷屏判失效 | ★★ **不装，1 与 2 的读数都不可信**（H4 §4 已实证假绿位） | 中 | ★ 修后 `tailscale-direct` 应**当场变红**（对端现在 `no reply`） |

★★ **为什么【不】把「拆单点（8803 与 8792 同进程）」放进三件事**：
★ H5 §7 实测二者同进程 `pid 1221` ⇒ 这是**真实的结构缺陷**，
但它是**架构手术**（v7 计划 §二 已裁定「不在本阶段」），且**不影响 `/health` 是否能不再空壳**
—— ★ **它只要求 `/health`【如实表达同命】**（H3 §1），而那属于第 1 件的契约之内。

★ **为什么【不】把「dead man's switch（外部看门狗）」放进三件事**：

## 三、三件事的**失效条件**汇总（纪律：凡断言要能说清何时失效）

| 事 | 它在什么条件下会失效 |
|---|---|
| 0 指定读者 | ★ 读者自己不跑（`beacon-check` 无到场判据）⇒ 退化为「又一个 0 读者判据」 |
| 1 定契约 | ★ **分母由实现方自己 enumerate** ⇒ 「0 ⇒ 不可判」被「加一行空 item」绕过。**分母必须来自冻结清单** |
| 1 定契约 | ★ 若 `undecidable` 被判成 `fail`，则**「没查」与「坏」不可分** ⇒ 与 AWS 的双计数原则相悖 |
| 2 真数据 + 身份断言 | ★ **被检查者与检查者同源**时，身份断言被同源伪造 ⇒ 须有一项来自**污染者不产生的信号** |
| 2 真数据 + 身份断言 | ★ `tailscale ping` **打印 `no reply` 却 `rc=0`**（H5 §9 实测）⇒ **若用退出码当判据，必然恒绿** |
| 3 反例 | ★ **负控自己空转**（复刻了值、没复刻形态）—— 本仓已有此教训 |
| 3 迟滞 | ★ 迟滞会**推迟发现真故障** ⇒ 阈值是**待裁**项（AWS 默认「坏 2 次 / 好 5 次」可作起点） |
| 3 刷屏判失效 | ★ 阈值取值是**待裁**项；★ 若定得太低，**真故障也会被误判成「判据失效」而放过** |
