# 概念字典泛化研究 · 2026-08-30

> 研究：HR 司库 · 对象：concept-dict.py（R019 落地载体，registry v1.0.368）
> 方向：① 泛化到其他角色 ② 泛化到端侧（i9/MBP）③ 反向吸收（其他角色资产→字典）

## 一、泛化需求信号（实证）

| 信号 | 数据 |
|---|---|
| 角色知识/术语管理职责 | 19/52 档案有知识/概念/术语/标准职责（文汇/守灯塔/知了/明鉴/司库等） |
| 黑板已有字典资产 | 无（concept-dict 为首个）——空白即机会 |
| 端侧能力 | i9 capabilities 含 python3（可跑工具）；MBP 标准 DSH |
| R019 适用范围 | all-bus-devices（规则本就全网络） |

## 二、泛化方向评估

### 2.1 泛化到其他角色（横向）

| 角色 | 字典用途 | 价值 |
|---|---|---|
| 明鉴（蓝图主编） | BP-9 蓝图概念登记（flowernet 术语） | 高——蓝图概念是网络级共享术语 |
| 文汇（摄取） | 文档摄取术语标准化（raw/wiki 命名） | 高——摄取一致性 |
| 守灯塔（知识库） | 知识库概念统一 | 高——KB 检索准确度 |
| 知了（学习） | 学习数据概念（order_sales/返图特征） | 中——数据字段术语 |
| 守链（供应链） | 供应链术语 | 中 |
| 老登（运营） | 运营术语（活动/折扣/商品） | 中 |

结论：横向泛化价值高——19 个角色有术语管理需求，字典从 HR 工具升级为网络级共享概念库。

### 2.2 泛化到端侧（i9/MBP）

| 端 | 可行性 | 方式 |
|---|---|---|
| i9 | python3 已具备 | 拷贝 scripts/concept-dict.py + 数据文件同步（黑板/共享盘） |
| MBP | 标准 DSH | 同 i9 |
| 同步 | 黑板 data/registry/concept-dict/ 为主 | 端侧本地缓存 + 黑板增量同步（类似 bb-sub） |

结论：端侧泛化可行（python3 现成 + 黑板同步基建）。注意：字典是读多写少（查证频繁/登记低频）——端侧只读缓存 + 中枢权威写，避免多写冲突。

### 2.3 反向吸收（其他角色资产 → 字典）

| 源资产 | 内容 | 吸收方式 |
|---|---|---|
| 明鉴 BP-9 蓝图 | flowernet 术语（阶段/任务/校准点） | suggest 扫描蓝图 master → 待登记 → 主编确认 |
| 文汇摄取 raw/wiki | 文档命名概念 | suggest 扫描 vault |
| 知了学习数据 | 数据字段/特征概念 | suggest 扫描 docs + 数据表头 |
| 守灯塔 KB | 知识库概念 | suggest 扫描 KB 文档 |
| registry 术语 | 资源类型（file:/store:/chroma:） | 预置登记（权威定义在 registry） |

结论：反向吸收是高价值自动路径——suggest 已是提取器，扩展扫描源即可自动吸收各角色资产中的高频概念（人工确认后 add）。

## 三、泛化设计（三层）

权威层（中枢 mac-mini）：concept-dictionary.json（写权威）· add 登记走 HR/主编确认（R019-5）· suggest 每日提取（launchd 9:30）
  → 黑板 data/registry/concept-dict/ 同步 →
消费层（所有角色 mac + 端侧 i9/MBP）：query/check 只读（本地缓存）· 端侧只读避免多写冲突

### 3.1 泛化落地步骤

| 步 | 动作 | 负责 |
|---|---|---|
| 1 | suggest 扫描源扩展（蓝图 master/vault/KB/registry 预置） | HR |
| 2 | 消费层接入：各角色在 registry/蓝图相关场景调 query/check | 各角色 |
| 3 | 端侧同步：i9/MBP 拷贝工具+黑板增量同步（读缓存） | HR+端侧 |
| 4 | 反向吸收试点：明鉴蓝图概念 → suggest → 确认 → add | 明鉴+HR |
| 5 | 字典命名空间规范（data/registry/concept-dict/<domain>/） | HR |

## 四、风险与护栏

| 风险 | 护栏 |
|---|---|
| 多写冲突（端侧也 add） | 端侧只读缓存，中枢唯一写权威 |
| 概念膨胀（suggest 噪音） | 阈值 c>=3 + 人工确认制（R019-5） |
| 权威定义漂移 | 来源必填（可追溯）+ audit 定期健康 |
| 与 registry/KB 术语冲突 | 预置 registry 权威术语，字典引用不重复定义 |
| 端侧版本漂移 | 黑板同步 + version 字段对比 |

## 五、结论

三向泛化全部可行且有价值：
1. 横向（角色）：19 角色有术语需求 → 字典升级为网络级共享概念库（高价值）
2. 端侧（i9/MBP）：python3 现成 + 黑板同步基建 → 只读缓存消费（可行）
3. 反向吸收：suggest 扫描源扩展 → 自动提取各角色资产高频概念 → 人工确认登记（高价值自动路径）

建议落地优先级：反向吸收（suggest 源扩展）→ 横向接入（明鉴/文汇/守灯塔试点）→ 端侧同步（i9/MBP 只读缓存）。
