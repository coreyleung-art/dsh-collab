## 四、★★ C7 · `run-14.sh` 的 rc 捕获 —— 机制对，但 4 条结构性恒 0

### 4.1 先给**阳性对照**（★ 不先证机制，就不能下结论）

`run-14.sh` 第 14–29 行的 `run()` 把命令包在 `{ ... } | tee` 里，`rc` 在**子 shell 内、管道之前**取。**我把这个形态抽出来跑正控**：

```bash
run() { local id="$1"; local title="$2"; shift 2
  { echo "# $id"; "$@" 2>&1; local rc=$?; echo "# --- end ---"; echo "$rc" > "$OUT/$id.rc"; return $rc
  } | tee "$OUT/$id.txt" >/dev/null; }
run T1 "test exit 7"    bash -c 'echo hi; exit 7'
run T4 "python exit 3"  python3 -c 'print("x"); raise SystemExit(3)'
```

**未编辑原始输出**：

```
rcs: T1=7 T2=7 T3=0 T4=3
```

★★ **⇒ T1=7、T4=3 ⇒ `tee` 管道【没有】吃掉命令本体退出码。**
⇒ **`slo/01` §〇·一 与 `run-14.sh:5` 的自述「取自命令本体，不取管道末端」在【框架层】成立。**
★ （`T3=0` 是我自己造的 `bash -c 'echo hi; exit 7 | cat'` —— 其最后一条命令是管道 `exit 7 | cat`，rc 取 `cat` ⇒ 0。**这是我的构造瑕疵，不是被审脚本的问题**，如实记。）

### 4.2 但 `S8/S9/S10/S14` 把**内层管道**写进了「命令本体」

```bash
S8)  run S8 "..." bash -c 'du -sh ~/.dsh/sessions | awk "{print \$1}" | sed "s/^/会话目录: /"' ;;
S9)  run S9 "..." bash -c 'printf "文件数: "; ls ~/.dsh/inbox | wc -l; printf "体积: "; du -sh ~/.dsh/inbox | awk "{print \$1}"' ;;
S10) run S10 "..." bash -c 'ls -l ~/.dsh/agent-bus.json | awk "{printf ...}"' ;;
S14) run S14 "..." bash -c 'lsof -nP -iTCP -sTCP:LISTEN 2>/dev/null | awk "NR>1{print \$1, \$9}" | sort -u' ;;
```

⇒ `bash -c` 的 rc = **其内最后一条命令**的 rc（`sed` / `awk` / `sort`），**不是** `du` / `ls` / `lsof` 的。
**★ 我用同一形态造了 4 个正控（数据源故意坏掉）**：

```bash
bash -c 'false | awk "{print}" | sed "s/^/x/"'          # rc=0  ← du 失败被掩盖
bash -c 'printf "文件数: "; ls /nonexistent_dir_xyz | wc -l'  # rc=0  ← ls 报错(2) 被 wc 掩盖
bash -c 'ls -l /nonexistent_file_xyz | awk "{print \$5}"'     # rc=0
bash -c 'nosuchcmd_xyz 2>/dev/null | awk "{print}" | sort -u' # rc=0
```

**未编辑原始输出**：

```
S8 形态 du|awk|sed 全成功: rc=0
S8 形态 若 du 失败(simulate) : rc=0  <-- du 失败被 awk/sed 的成功掩盖
S9 形态 ls|wc -l 当目录不存在: rc=0  <-- ls 报错(2)，wc 成功(0) ⇒ 0
S10 形态 ls -l|awk 当文件不存在: rc=0
S14 形态 lsof|awk|sort -u 当 lsof 缺失: rc=0
```

★★★ **⇒ `out/S8.rc` `S9.rc` `S10.rc` `S14.rc` 的 `0` 是【结构性的 0】：无论被测对象是否可读，恒为 0。**
⇒ 依项目纪律「**一个断言若从未红过，它就不是判据**」：
**这 4 条 rc 不是判据**（它们的文本读数仍可用，**rc 不可用作门**）。
⇒ ★★★ **而 `run-14.sh:5` 的注释逐字写的就是这个失效模式的处方**：
「★ 退出码取自【命令本体】(**PIPESTATUS[0]**/直跑)，**不取管道末端**」
—— **它引用了正确的处方，然后在 4 条上开了同一张错方。**
