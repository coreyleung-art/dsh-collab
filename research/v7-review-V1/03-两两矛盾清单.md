## 矛盾 3 ★★★ `bus-8791`「整片失败域零判别力」——与 R3 自己的原始输出冲突，且被我构造反例证伪

| 方 | 逐字 |
|---|---|
| **R3 `05` §6.6 / `00-INDEX` ①** | 「⇒ 该判据对『服务坏了』**这一整类失败**（401/403/500）**零判别力**」·「在 401/403/500 上**全部判绿**；对『活着但坏了』**整片失败域零判别力**」 |
| **R3 `06` §2.2** | 「**中间整片「活着但坏了」的失败域，它一个都抓不住。**」 |

**★ 反例 1（来自 R3 自己的 Sample 4 原始输出）**：

```
红(拦截)  <=  真实不可达 HTML 404      ← R3 05 §6.4 自己跑出来的「活着但坏了」却被抓住
```
★ R3 把这行标注为「**真实不可达**」——但 **HTML 404 是「服务器答了、答的是坏东西」，不是「不可达」**。
⇒ ★ **正是这个误标，让「零判别力」这个过强的结论得以成立。**

**★ 反例 2（我构造：把 `bus-8791` 指向活的坏目标，跑真实扫描）**

★ 方法：`cp` 副本到 `/tmp`，**`HOME=/tmp/v7rev/home` 隔离**（生产日志 579 行 → 实验后仍 **579** 行，零写入）。

```
输入语义: 403 但失败体【不含 ok 子串】  {"errmsg":"forbidden","code":"FORBIDDEN"}
🔴 bus-8791   期望=...:18896/bus/receive 实际=HTTP 403 (body不含期望串)

输入语义: 502 HTML 错误页（不含 ok）  <html><body>Bad Gateway</body></html>
🔴 bus-8791   期望=...:18895/bus/receive 实际=HTTP 502 (body不含期望串)

输入语义: 不可达（无人监听）
🔴 bus-8791   期望=...:18999/bus/receive 实际=HTTP 0 (body不含期望串)
```

⇒ ★★★ **「活着但坏了」的 403 / 502 都被判红。** 「整片失败域零判别力」**不成立**。

**★ 同时我复现了 R3 为真的那一半**（三条全绿，逐字）：

```
401 {"ok":false,"errmsg":"unauthorized"}  → 🟢 实际=HTTP 401 (body含期望串)
500 {"error":"internal","ok":false}       → 🟢 实际=HTTP 500 (body含期望串)
200 {"ok":true,"task":null}               → 🟢 实际=HTTP 200 (body含期望串)
```

**判定**：
- ★ **R3 的核心发现成立且我已独立复现**：`body.includes("ok")` **无法区分「服务说它好」与「服务说它不好」**，
  在「失败响应体仍含子串 `ok`」的输入上恒绿。**这是一条真缺陷。**
- ★★ **但它的边界被写宽了。** 正确表述应为：
  > **对「失败响应体仍含子串 `ok`」的那一片失败域零判别力**（本机 8791 的失败体恒含 `ok` 键 ⇒ 实践上覆盖其全部失败体）。
  > **对不含 `ok` 的失败体（其他 4xx/5xx、HTML 错误页、代理层 502）它照常判红。**
- ★ **R3 的 `05` §6.6 还写「只在『完全不可达』时才红」——被我的 403/502 两例直接证伪。**
- ★★ **传播影响**：R1 的 `H4:61` 接受了「订正后深探针四格**全部**为 ❌」，并据「零判别力」把
  `bus-8791` 的 JSON-Schema 一格由 ⚠️ 改 ❌ ⇒ **R3 的过度一般化已经污染了 R1 的结论表**。
