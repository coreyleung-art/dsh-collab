### 1.1 ★★ 两条**假阴性**（探针坏 → 把「我读不到」记成了「不存在」）

#### ✗ N-1 Datadog 官方 alert testing 文档「未命中」—— **文档存在**

**文档原话**
```
v7-negctl/00-INDEX  §A 未取到的一手文档:  Datadog alert testing 官方文档 | 未命中
v7-negctl/02 §六     `testing that alerts fire alert unit testing Grafana Datadog` | 未命中 Datadog 官方 alert testing 文档
```

**我的实测（含阳性对照与反面对照）**
```
$ curl -s "https://docs.datadoghq.com/monitors/notify.md"
HTTP=200  bytes=19986   rc=0

★ 阳性对照（同一文件内搜必存在的串）:
234:## Test notifications{% #test-notifications %}
236:After defining your monitor, test the notifications with the Test Notifications button …

★ 反面对照（同一次 grep 搜不该存在的串）: grep -c 'ZZZ-not-present-xyz' → 0  rc=1
```

**⇒ ★★ 判定：这是一条假阴性。** Datadog 官方**有**专门的 `## Test notifications` 一节，**一手文档、可取到**。
★ **失效原因**：Datadog 文档站是 **JS 渲染**，`read_url` 的 text 模式取不到正文
（核查子代理独立复现：网页 HTML grep「test」无实质命中；须走 **`.md` 别名**或 curl 抓 HTML）。
★★ **R3 把「抓取器读不到」记成了「未命中」** —— 这正是本任务书点名的失效模式
（「某代理用本机不存在的 `timeout` 命令，一批『0 命中』其实是探针坏了」）的**同族**：探针坏在**抓取方式**上。
★ **R3 的诚实部分**：它加了「★ 未搜到 ≠ 不存在。特别是 Datadog 的 alert testing 与 Grafana 新版文档，本轮未取到，不代表没有。」
⇒ ★ **但归因错了**：它归因为「未命中」，而正确归因是「**我的取数方式对该站失效**」。

#### ✗ N-2 「plumbline 的 GitHub API 提交历史请求返回空」—— **API 正常返回**

**文档原话（`v7-negctl/06` §七.4）**
> `plumbline` 仓库真实性已核（GitHub API `"private": false`），但**未核其提交历史与维护状态**（**API 提交历史请求返回空**）。

**我的实测**
```
$ curl -s "https://api.github.com/repos/ChelseaKR/plumbline/commits?per_page=3"     ← 不带 UA
HTTP=200   → [{"sha":"eadf16391c13e94d35fa622f09efefb34118bd0c", …

```

**⇒ ★★ 判定：这是一条假阴性。** API **HTTP 200 且返回完整提交数据**（带/不带 UA 皆然）。
★ **后果比 N-1 更重**：R3 **用这个假阴性豁免了一项检查**（「未核其维护状态」）——
★★ **而这项检查恰恰会揭示该来源的权重**：**1 star · 1 fork · 2026-08-15 建 · 最后 push 10-07**，
即一个**约两个月大的个人仓库**。
★ **而 R3 的 `05` §7.2「最小可执行方案」的依据正是这个仓库的措辞**
（逐字引其「Coverage says a line ran. It says nothing about…」），并把它称作「规程」。
⇒ ★ **它标了「社区来源，非标准组织」（诚实）**，**但没标「1 star、两个月新」** ⇒
**v7 若据此方案立项，会高估该来源的实践成熟度。**

### 1.2 ★ 一条**探针未验证**的阴性（结论真、证据无效）

#### ⚠️ N-3 `which promtool` → 退出码 1 ⇒「本机无 promtool」

```
文档（v7-negctl/05 §八 · 02 §二）:  `which promtool` | 退出码 1，本机无 promtool

我的实测:
  which promtool        → rc=1
  which node            → rc=1     ← ★ node 确存在于 /opt/homebrew/bin/node（本文件通篇用它）
  command -v node       → rc=1
  PATH = /usr/bin:/bin:/usr/sbin:/sbin      ← ★ 不含 /opt/homebrew/bin
```

**⇒ ★ `which` 在本环境会对**确实存在**的命令返回 1 ⇒ 它是一个会产生假阴性的探针。**
**⇒ 该行无阳性对照 ⇒ 只能报「探针未验证」，不得报「本机无 promtool」。**
★ **我另用三法交叉复核**（`command -v` · `ls /opt/homebrew/bin | grep ^prom` · `ls /usr/local/bin` ·
`find /opt/homebrew -name promtool -maxdepth 6` · `ls /opt/homebrew/Cellar | grep -i prom`）
⇒ **结论「本机无 promtool」本身是真的**；**但 R3 给出的证据不足以支持它**。
