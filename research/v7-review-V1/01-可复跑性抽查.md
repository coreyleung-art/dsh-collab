### Sample 2 — 全史红率 ⚠️ 不一致

```bash

print('N=',n,'CLEAN=',c[0],'DRIFT=',red,'红率=%.1f%%'%(red/n*100))
```

**文档声称的「未编辑的原始输出」（H5 第 205–209 行）**：


**我的实跑（同一条命令，逐字）**：

```

result 分布 = {'DRIFT': 406, 'CLEAN': 175}
CLEAN = 175  DRIFT = 406  ⇒ 红率 = 69.9%
EXIT=0
```

**★ 两处不一致，性质不同**：

**(a) 数值漂移（可解释，但复跑块不可对齐）**
`logs/drift-scan.log` 是 **append-only**（`core.js:27` `fs.appendFileSync`），已被我核为**按 `at` 严格单调**（非单调位置数 = 0）。
文档测时 N=573（末行 `at = 2026-10-12T12:01:09.389Z`），我测时 N=581 —— 期间新增 8 行 CLEAN。
⇒ **`DRIFT = 406` 稳定不变；漂移的只有分母与 `CLEAN`。**
★ **但两份文档的复跑块都把 N 与红率写成固定值（`N= 573` · `红率=70.9%`），未标截止时刻** ⇒
**复跑者必然拿到不同的数**，而这正是「未编辑原始输出」这一承诺最容易失守的地方。

**(b) ★ 输出块里有两条该命令**不可能**打印的行**
`含 driftCount 的记录数 = 573` 与 `driftCount 分布 = {...}` ——
**所示命令的 `print` 只有三个，都不会产出这两行**。
★ 我按 573 行的**实际分布**验证：`{0:167, 1:226, 2:157, 3:2, 4:17, 5:4}` 与文档**完全吻合**
⇒ ★ **这两行不是编造，是真实读数**；但**它们来自另一条（未展示的）命令**。
⇒ ★ **判定：「复跑命令」与「未编辑的原始输出」不是同一次执行的配对。** 严重度：**中**（数据真、配对假）。

**★ 阳/阴双对照（证明这个退出码是有效信号，不是探针坏）**：


⇒ ★★ **`tailscale ping` 在 `no reply` 时退出码为 1，三次全为 1，且成功时为 0、解析失败时为 1。**
⇒ **该退出码是可用信号，不是「必然恒绿」。**

**★ 被证伪的三处原文**（同一错误在三个文件里各写了一遍）：

### Sample 6（追加）— `which promtool` ⚠️ 结论或真 · 证据无效

```
which_promtool_EXIT=1
which_node_EXIT=1        ← ★ node 确实存在于 /opt/homebrew/bin/node
command_v_node_EXIT=1
PATH=/usr/bin:/bin:/usr/sbin:/sbin
```

⇒ ★★★ **本 harness shell 的 PATH 不含 `/opt/homebrew/bin`**，而两份文档**通篇用 `/opt/homebrew/bin/node` 调用 node**。
⇒ **`which node` 对一个确实存在的命令返回 1** ⇒ **`which` 在本环境是一个会产生假阴性的探针。**
⇒ R3 `05` §八 与 `02` §二 用 `which promtool` 退出码 1 推出「**本机无 promtool**」——
★ **该阴性没有阳性对照，且其探针经实测会误判。**

**我另用三法交叉复核（这才是有效证据）**：

```
command -v promtool                 → rc=1
ls /opt/homebrew/bin/ | grep -i ^prom   → 无
ls /usr/local/bin/ | grep -i promtool   → 无
find /opt/homebrew -name promtool -maxdepth 6 → 无
ls -d /opt/homebrew/Cellar/* | grep -i prom   → 无
```

⇒ ★ **「本机无 promtool」这个结论是真的**；★ **但 R3 给出的证据（`which` 退出码）不足以支持它。**
⇒ 按本次审查的硬性约束：**R3 该行应报「探针未验证」，而不是「本机无 promtool」。**
