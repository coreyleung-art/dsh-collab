## 二、原则 2 · 通道自举 ⇐ 「新版本必须经旧通道投递，端侧验证才切换」

### 2.1 现测：升级脚本的时序

`scripts/bb-upgrade.py` 是**黑板自身**的升级流水线。读其第 7 步（`:199-210`）：

```
$ sed -n '190,215p' scripts/bb-upgrade.py
                  % (REUSE, args.what, args.deps, args.hub_dep, args.node_side))
    grade_line = [l for l in out.split("\n") if '"grade"' in l]
    grade = grade_line[0].split(":")[-1].strip().strip('",') if grade_line else "?"
    print("  复用分级: %s" % grade)

    # 7. 落链登记
    print("[7/7] 落链登记...")
    body = json.dumps({
        "item": "blackboard-%s（升级流水线）" % args.vto,
        "what": args.what,
        "reuse_grade": grade,
        "verify": "冒烟全过 + 生产验证",
        "rollback": "plist 指回 blackboard-server-%s.py" % args.vfrom,

    }).encode()
    req = urllib.request.Request(BB + "/data/iterations/upgrade-%s" % args.vto, data=body, method="PUT",
                                 headers={"Content-Type": "application/json", "Content-Length": str(len(body))})
    with urllib.request.urlopen(req, timeout=5) as r:
        print("  ✅ 落链: %s" % r.read().decode()[:60])

```

**⇒ 三条硬事实**：

1. ★★ **时序是「先升级、后落链」**：落链在 **`[7/7]`**（最后一步），且其后的打印是 **「✅ 升级完成」** ⇒ ★ **登记发生在升级之后，不是投递在切换之前。**
2. ★★ **落链走的通道 `BB` 就是被升级的那个黑板本身**（`BB + "/data/iterations/upgrade-<vto>"`）⇒ ★ **这不是「旧通道投递」，这是「新通道自证」。**
3. ★ **`"verify": "冒烟全过 + 生产验证"` 是一个【字符串字面量】** —— ★ 它**没有携带任何实测输出、时刻或退出码** ⇒ ★ **按本项目纪律「一个断言若从未红过，它就不是判据」：这个 `verify` 字段是不可红的。**
