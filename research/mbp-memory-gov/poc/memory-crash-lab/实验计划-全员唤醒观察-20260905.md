# 实验计划：Mac Mini 全员会话唤醒 · 持续观察

> 提议：mbp-ops · 2026-09-05 · 待用户执行触发
> 目的：验证 v0.6.0 + P2-3（cacheSize 2）后，唤醒大量会话时的 CLD 内存/稳定性真实表现
> 背景：黑箱实验室模拟 6 会话 512MB 顶 SIGABRT；本次在真实生产验证治理后表现

---

## 一、实验目标（可验证假设）

| # | 假设 | 验证方式 |
|---|---|---|
| H1 | 全员唤醒后 CLD 不崩溃、不 OOM（P1 重启 + P2-3 后应稳）| 观察 crashToday / 进程存活 |
| H2 | RSS 峰值有界（唤醒瞬时冲高后回落，不逼近 4GB OOM 区）| 高频 RSS 采样曲线 |
| H3 | 唤醒 N 会话的驻留增量可控（对比基线 280MB）| 峰值 vs 基线差 |
| H4 | 孤儿 tool_calls 修复生效（无会话续跑卡死）| 会话尾部无 400 错误 |

## 二、方法（只读观测，不碰生产）

1. **基线**：唤醒前采集（RSS/进程/崩溃数/会话数）——已得 280MB/0 崩溃
2. **触发**（用户执行）：唤醒 macmini 会话（方式由用户定：重启后恢复 / 黑板广播 / 手动打开）
3. **持续观察**（我执行，SSH 只读）：
   - 高频 RSS 采样（每 5s × 2min → 每 30s × 10min）
   - 崩溃监控（DiagnosticReports 新 ips）
   - 进程存活 / 心跳
   - stability-watch 卡循环
4. **终止条件**（安全阀）：RSS 超 2GB 或崩溃 → 立即报告，用户可决定是否干预
