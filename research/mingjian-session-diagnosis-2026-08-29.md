# 明鉴会话死亡诊断 · 修复风险评估（2026-08-29）

> 诊断：HR 司库（资源管理者）· 症状：Messages with role 'tool' must be a response to a preceding message with 'tool_calls' / INVALID_REQUEST

---

## 一、诊断结论：磁盘存档健康，损坏在活动会话内存态

### 1.1 实测证据

| 检查项 | 结果 |
|---|---|
| 会话文件存在 | ✅ session.jsonl.zstd（2.2MB）+ 备份 4 个 |
| zstd 解压 | ✅ 成功，14414 行 |
| tool/call vs tool/result 配对 | ✅ 478 对全配对，0 孤立 |
| 角色分布 | ✅ 正常（tool/call 478 = tool/result 478） |
| 最后活跃 | 2026-08-17（13.5 天前） |

### 1.2 错误根因分析

错误「tool 消息必须回应前序 tool_calls」= 会话历史中出现了**无前序的 tool 角色消息**。但磁盘存档配对完整——说明：
- 场景 A：活动会话在内存中损坏（重启/恢复时消息拼接错位）
- 场景 B：agent_wake 恢复时 splice 逻辑把消息序列弄断
- 场景 C：某次中断后（13.5 天前 8/17）恢复不完整，之后每次唤醒都报错

### 1.3 CLD 崩溃风险评估

| 风险项 | 评估 |
|---|---|
| 修明鉴会话 | **低风险**——会话文件是 zstd 存档，修改/重建不影响宿主进程 |
| 触发 CLD 崩溃 | **不会**——本错误是 API 层 INVALID_REQUEST，非进程级崩溃（与 cordis-crash-audit 审查的插件崩溃不同类） |
| 影响其他会话 | **不会**——会话隔离，明鉴损坏不影响其他 agent |
| 影响宿主 | **不会**——CLD 本体/插件 bundle 均未动 |

## 二、修复 vs 重建决策

| 方案 | 优点 | 缺点 | 成本 |
|---|---|---|---|
| A. 修复（清历史重来） | 保留档案/画像/认知（KB 侧） | 会话内记忆丢失（但档案在 agent-bus.json + KB） | 低 |
| B. 重建新会话 | 干净起点 | 需重新任命/接驳/登记（档案迁移） | 中 |
| C. 归档 + 新建明鉴 v2 | 借机升级（蓝图规划师扩展） | 需完整迁移档案/能力/资源 | 中高 |

### 2.1 关键事实：明鉴的「认知」不依赖会话内存

明鉴的核心资产（画像/生意认知/商业模式画布）都沉淀在：
- agent-bus.json 档案（role/abilities/resources 完整）
- user-profile.md（画像专属写）
- KB ops-science-research（洞察产出）
- Notion 只读通道（画像库/花材日报）

**会话内存 = 一次性对话记录，丢了不影响长期认知。**

### 2.2 裁决建议：方案 C（归档 + 新建明鉴 v2，顺势升级蓝图规划师）

理由：
1. 明鉴本来就要扩展为蓝图规划师（v2.0 评估已出）——正好借重建落地扩展
2. 会话内存无长期价值（认知都在 KB/档案）
3. 重建成本低（档案迁移 + 接驳登记，我负责）
4. 避免修一个「可能反复坏」的会话（死 13.5 天说明恢复路径有 bug，重建最干净）

## 四、结论

**修复无 CLD 崩溃风险**（API 层错误非进程崩溃，会话隔离不影响宿主）。
**建议重建而非修**——但重建要顺势升级：归档旧明鉴 → 新建明鉴 v2（含蓝图规划师扩展）→ 档案迁移 → 验证。
