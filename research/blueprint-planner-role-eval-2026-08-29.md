# 蓝图规划师角色评估（2026-08-29）

> 评估：HR 司库（资源管理者）· 需求：协助用户梳理制定蓝图目标、有计划有规范沟通、输出完整蓝图、拆解实施要素、主动判断缺陷

---

## 一、需求拆解（蓝图规划师 5 项核心职责）

| 职责 | 内容 | 对应 Blueprint Platform 工具 |
|---|---|---|
| ① 有计划有规范的沟通 | 引导用户结构化定义蓝图（目标/阶段/里程碑/验收） | blueprint-dialog（v0.3 已设计） |
| ② 输出完整项目蓝图 | 生成 BP-9 标准蓝图文档（9 字段契约） | blueprint-create |
| ③ 拆解实施要素 | 蓝图→子阶段→works（谁执行/依赖/顺序） | BP-9 stages/works 字段 |
| ④ 主动判断缺陷 | 评估蓝图缺口（能力/依赖/风险） | 短板评估器（Evolve Loop 组件） |
| ⑤ 版本迭代 | 执行反馈→主动找用户→bump 版本 | blueprint-refine |

## 三、评估结论：扩展明鉴（非新建）

### 3.1 核心理由
1. **职能天然重叠**：明鉴已在做「商业模式画布维护（SWOT/假设验证/迭代报告）」——这正是蓝图规划的雏形！商业模式画布 ≈ 蓝图的业务层
2. **已有生意认知**：明鉴读 8787 面板/Notion 画像/品牌理念库——制定蓝图需要理解生意全景，明鉴已具备，新建角色要重新学习
3. **用户私人参谋定位**：蓝图是用户意图的具象化，明鉴本就是「用户私人的经营参谋」——沟通用户定义蓝图是自然延伸
4. **资源预算**：扩展现有角色（加 3-4 项能力+工具面）比新建（新档案/新 preset/新学习周期）省成本

### 3.2 扩展内容（明鉴 v2.0）

| 新增 | 说明 |
|---|---|
| 能力：蓝图规划 | 引导沟通（blueprint-dialog）→ 输出 BP-9 蓝图 → 拆解 works → 缺陷评估 → 版本迭代 |
| 能力：BP-9 标准 | 9 字段契约认知 + blueprint:<id> 引用/标注语法 |
| 资源：data/blueprint/ 读权 | 读取蓝图库（stages/works/gate） |
| 工具：blueprint-* 三工具 | dialog（沟通）/ create（制定）/ refine（迭代）——属 Blueprint Platform |
| preset：蓝图规划模式（可选） | 工具面收窄（沟通+蓝图+洞察）+ persona（有计划规范沟通/缺陷主动判断） |

### 3.3 与 Evolve Loop 关系
- 明鉴 = 蓝图规划师（制定/迭代蓝图）——Blueprint Platform 的「主编」
- Evolve Loop = 蓝图执行者（消费蓝图推进）——Blueprint Platform 的「执行层」
- HR（司库）= 蓝图库登记维护 + 资源仲裁
- 星桥 = 协调（不直接制定，仅 FlowerNet 蓝图既有维护者，逐步移交明鉴）
