## 结论先行（适配要点）

1. **分发层（B1）**：首期只有公众号+知乎两个主平台，多平台矩阵工具的边际价值小。**OpenWrite（免费、Markdown 原生、程序员向）适配最高**，作为"一次写、双平台发"的轻量管道；蚁小二/易媒免费档可做备选，但注意第三方授权登录的账号风控风险，且矩阵功能首期用不满。
2. **定时层（B2）**：公众号用**官方自带定时群发**（P0，零成本零风险）；知乎无官方定时，靠 OpenWrite/手动按点发。最佳时段采用"经验值 + 自测校准"：公众号晚 20-22、知乎午 12-13 与晚 20-23（与管线 v1 用户决策一致），其余平台为二期参考。
3. **数据层（B3）**：公众号/知乎/小红书**均无面向个人创作者的开箱导出 API**（公众号数据统计接口需认证开发者权限，个人订阅号拿不到）。首期 P0 = 官方后台手动周度回收 + `reports/metrics-log.md` 台账；新榜/灰豚/Apify 等付费数据服务 P1-P2 再评估。
4. **内容管理层（B4）**：**本地 Markdown + Git（管线现有 drafts/ 结构）+ Notion/飞书知识库作展示与检索层** 最贴合 AI 一人工作流；公众号编辑器只作最终排版位；WordPress/Ghost 等开源 CMS 对"公众号+知乎图文"场景偏重，P2。

### B1.2 关键判断

- **是否原生发布**：多数一键分发工具走"自动填充编辑器+点击发布"（非原生接口），微信对非官方自动化发布风控趋严；公众号文案排版（特殊样式/封面）常需回官方编辑器二次确认。**结论：一键分发适合"正文基础分发"，公众号最终排版仍回官方编辑器**（与管线 v1"用户审核+外链发布"流程兼容）。
- **账号安全**：第三方工具需扫码/登录授权，存在撞库/封号/数据泄露风险；优先选择有官方背景（如新榜系）或开源可审计方案；不把主账号密码交给无来源小工具。
- **与"AI 一人运营"适配**：首期双平台手动或 OpenWrite 分发即可；自动化收益最大点在**内容生产**（A 类）而非分发环节，避免在 B1 过度投入。

- **错峰原则**（管线 v1 4.2）：稿件批量生产放 12-14/18-09 低峰时段，与发布时段解耦。

### B3.2 推荐落地（P0）

1. **每周一次**：公众号后台 + 知乎创作中心手动抄录到 `reports/metrics-log.md`（管线 v1 已规划该台账），字段：日期/平台/标题/阅读/互动/涨粉/转化线索。
2. 首月**不买任何数据服务**；2-4 周后若需竞品对标再评估新榜/灰豚月付档。
3. 数据口径以官方后台为准，第三方数字仅作趋势参考（来源不一，避免误判）。

| **WordPress** | 开源建站 CMS，插件生态大 | 中（域名/主机/维护） | 低：面向独立站，与公众号/知乎图文场景错配 | P2 | 开源 CMS 生态（官方/评测） |

| **静态站点生成器（Astro/Hugo）+ Git** | Markdown 源文件→静态站，版本管理强 | 免费（需技术） | 中：与我们管线契合但增加维护面，二期可做个人站点 | P1-P2 | 技术社区评测（评测） |

### B4.2 推荐架构（AI 一人运营版）

```
drafts/ + templates/（管线已有，Git 版本管理）   ← 生产主干（P0）
        ↓ 审核通过
Notion / 飞书知识库（稿件台账+选题+素材索引）      ← 展示/检索层（P0）
        ↓ 定稿
公众号官方编辑器（排版+定时） + 知乎（发布）       ← 发布位（P0）
```

- **为什么不用开源 CMS 当主干**：公众号+知乎图文不产生自有网站流量收益，多维护一个 CMS 增加成本；本地 Markdown + Git 已覆盖版本管理，Notion/飞书覆盖检索与协作，二者组合零服务器成本。
- **学习曲线**：Notion/飞书均低；Git 对 AI 助手透明（管线自动维护）；全员符合"AI 一人运营、自动化优先"。
