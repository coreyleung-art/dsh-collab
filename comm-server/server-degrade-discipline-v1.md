# 服务器故障降级纪律（防「乱来乱尝试」）v1 · 2026-09-09 星桥
> 用户指出：服务器暂错时各 agent 会乱来乱尝试（各自重试/换通道/绕过守护）
> 目标：服务器故障时设备行为有唯一约束，禁多路径乱试，防重试风暴与动作冲突

## 一、问题定性（实测观察）

| 乱象 | 成因 | 后果 |
|---|---|---|
| agent 各自重试 | 发送失败后无统一策略，每个会话自己重发 | 重试风暴、双倍 token |
| 换通道乱试 | 总线不通就试黑板/Tailscale/Funnel | 多路径重复、冲突 |
| 绕过守护直发 | agent 认为守护不可靠自己另走 | 双收、无法审计 |
| 守护与 agent 双重重试 | 守护断线重连 + agent 自己重发 | 同消息处理多次 |

根因：**无「服务器故障 → 设备行为」的单一权威规则**——每个 agent 各自猜测。

## 二、降级纪律（设备侧强制）

### 2.1 服务器状态机（设备守护维护）
```
探照灯态   判定(守护持续探测)                   设备行为
─────────────────────────────────────────────────────
绿灯       服务器 send/status 正常(<5s)        正常走总线
黄灯       服务器超时/5xx 但黑板域可用          禁总线新发 → 转黑板域留痕
红灯       服务器完全不可达(连续3次探测失败)     全停 → 本地缓存 + 只读
恢复       守护探测成功                        守护统一补投(agent 禁自发)
```

### 2.2 硬约束（防乱来——违反=Gate FAIL 关联 incident 门）

1. **agent 禁自发重试**：发送失败 = 交给守护层；agent 层不得循环重发（最多 1 次由守护统一做）
2. **禁多路径乱试**：黄灯 = 唯一降级路径「黑板域 notes/<node>/」留痕；红灯 = 停发本地缓存
   禁止 agent 自行尝试 Tailscale 直连/Funnel/其它通道当备胎
3. **守护是唯一发送代理**：所有跨设备发送经守护（agent 无独立通道）；守护负责
   状态判定+降级+恢复补投——单一权威，agent 不猜
4. **降级期间动作收敛**：黄/红灯期间，agent 只做「本地可完成」的事；
   跨设备协作类任务挂起等绿灯，不自行改走黑板上报"完成"（R030 防假完成）
5. **审计留痕**：守护记录每次降级/恢复/补投 → data/ops/server-degrade/<date>
   防"谁在故障期乱动"无法追溯

### 2.3 恢复补投（唯一补投者 = 守护）
- 绿灯恢复后，守护按序补投黄灯期黑板域留痕 + 红灯期缓存
- agent 收到补投即处理，不重复确认（hash 去重 G-C15 兜底）

## 五、最终兜底：人类求救通道（用户 2026-09-09 补充）

自动化全失效时（红灯持续 / 守护自身异常 / 本地也异常），设备生成**标准求救提示词**，
人类复制粘贴给管理员/协调者（人工介入）。这是降级分层的最后一层：

### 5.1 降级分层（自低到高）
```
L1 自动化降级: 探照灯黄/红灯 → 黑板域留痕/本地缓存（守护自动）
L2 守护兜底:   守护断线重连 + 补投 + 审计（守护自动）
L3 人类求救:   L1/L2 都失效 → 生成求救提示词给人类转管理员（本文）
```

### 5.2 求救提示词标准格式（agent 或守护生成）

设备故障时输出以下格式（人类可直接复制给管理员）：

```
🚨 [节点求救] <设备名> <时间戳>
症状: <具体现象: 服务器不可达N分钟/守护崩溃/消息滞留X条/黑板写入失败>
已自动尝试: <守护重连N次/黑板域留痕X条/本地缓存Y条——简述>
仍失败原因: <如有判断>
本地数据: <关键文件路径/黑板键/日志路径——供管理员取证>
请求: <期望管理员动作: 重启服务器/检查xingqiao/恢复黑板/人工转发N条消息>
建议: <可选, 管理员可执行的下一步>
```

### 5.3 人类求救的触发条件（agent 判断）
1. 守护红灯 >10 分钟且本地缓存 >20 条未投
2. 守护进程自身崩溃且无法自启（launchd 失效）
3. 本地黑板写入持续失败（>5 次）——可能本地也异常
4. 跨设备消息滞留 >30 分钟无法自愈
满足任一 → 生成求救提示词，写到: 
  - 人类可见处: ~/Desktop/<node>-SOS-<ts>.txt（GUI 用户可见）
  - 黑板 data/ops/sos/<node>-<ts>（管理员 agent 可读）

### 5.4 纪律
- 求救是**最后手段**：L1/L2 应先充分尝试（不跳过自动降级直接求救）
- 求救提示词**结构化可执行**：管理员拿到能直接定位/操作，非模糊抱怨
- 生成求救后 agent 停止一切自动动作（等人工），防"边求救边乱试"
