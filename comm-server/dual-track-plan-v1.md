# Comm-Server 双轨制接入方案 v1（cs3 · 用户选定）

> 2026-09-06 星桥 · 服务器 xingqiao.meetfunbp.com 已公网就绪
> 架构：**本机黑板主（8ms 低延迟）+ 中枢跨设备（40-180ms 公网）**

## 一、为什么双轨（延迟实测）
| 黑板 | 延迟 | 定位 |
|---|---|---|
| 本机 :8792 | 8ms | 本地低延迟主：central-inbox 注入/星台轮询/本机会话 |
| 中枢 :8792 | 40-180ms | 跨设备事实源：i9/MBP 互通、容灾备份 |

## 二、架构
```
        ┌──────── 中枢 xingqiao.meetfunbp.com ────────┐
        │  rust-blackboard（跨设备单一事实源/备份）     │
        └───────┬──────────────┬──────────────┬──────┘
            同步层          同步层           直连
        mac-mini 本机黑板  MBP 黑板         i9
        (:8792 本地主)     (心跳/任务走中枢)
            │
    central-inbox/桥/星台（低延迟 8ms）
```

## 三、同步层设计（本机 ↔ 中枢）
```
方向1 上行（本机→中枢）：本机关键域定期/实时推中枢
  notes/collab/, notes/mac-mini/（跨设备相关）, tasks/central/queue/, data/asset-inventory/
方向2 下行（中枢→本机）：i9/MBP 写中枢的 notes/i9/, notes/mbp/ 增量 → 同步到本机读侧
```

### 同步工具（mac-mini 侧 daemon）
```
sync-to-central.py    # 上行：本机新键 → 推中枢（SSE 订阅本机 8803 触发）
sync-from-central.py  # 下行：中枢 notes/i9/+notes/mbp/ 新键 → 镜像本机
```

## 四、各端角色（双轨下）
| 端 | 主黑板 | 中枢角色 |
|---|---|---|
| mac-mini | 本机 :8792（低延迟主） | 上行推关键域 + 下行拉 i9/MBP |
| MBP | 中枢（跨设备） | 心跳/任务直接中枢 |
| i9 | 中枢（跨设备） | 心跳/任务直接中枢（notes/i9/ 域） |
| 星台 | 本机（桥接） | 不变（低延迟优先） |

## 五、数据一致性（Lean4 I1 不变量）
- 本机为主、中枢为镜像：以本机时间戳为准（写入先本机后推中枢）
- 冲突：中枢仅接受本机推送（单写者），i9/MBP 只读或经任务卡
- 断连恢复：同步层补偿（拉取断连期间中枢新键）

## 七、风险与门
- 延迟 180ms 峰值：同步层异步（不阻塞本地操作）
- 中枢挂了：本机黑板独立可跑（双轨的天然容灾）
- 数据不一致：单写者 + 时间戳比对 + 补偿同步
- 门：每步验证通过才进下一步（R030 无验证成功=未成功）
