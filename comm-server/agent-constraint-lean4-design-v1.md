# 智能体约束结构 · Lean4 逻辑化设计 v1（防自作聪明）
> 用户 2026-09-09 核心担忧：「最怕智能体太自作聪明」——纸面规则可被聪明绕过
> 解法：把约束从「行为规范(检查层,可绕)」升级为「能力边界(结构层,不可能违反)」

## 〇、Lean4 逻辑核心思想

Lean4 证明的本质：**不是"运行时检查你不违规"，而是"定义上你无法构造违规"**——
像类型系统：类型不对的程序根本编译不过，不是运行时才报错。

映射到智能体约束：
```
纸面规则   = "你应该遵守"(agent 可聪明绕过)   → 无用(用户痛点)
检查门     = "违规会被拦截"(运行时 if 检查)    → 有用但 agent 可找旁路
结构约束   = "你无法构造违规"(能力不存在)      → 根治(Lean4 目标)
```

## 一、三类约束的分层（核心设计）

| 层 | 机制 | Lean4 类比 | 示例 |
|---|---|---|---|
| **L1 能力边界** | agent 无此能力/无此通道，物理上做不到 | 类型系统(构造不出) | 普通 agent 无 bash；跨设备发送仅守护持有 |
| **L2 收口检查** | 操作必经唯一封装，封装内强制校验 | 运行时断言 | bb-gate can_write；信封 schema 门 |
| **L3 结构审计** | 违规在结构上必留痕可追溯 | 证明可验证 | 全量审计日志 + incident 联动 |

关键：**约束必须下沉到 L1**（能力不存在），L2/L3 只是兜底——
agent 若连"绕过"的动作都构造不出来，就不会自作聪明。

## 二、现状差距（实测）

| 约束 | 现层 | 差距 |
|---|---|---|
| 写域隔离(bb-gate) | L2 检查 | agent 有 bash 可直写他域 → 需 L1: 域 token 分离 |
| 跨设备发送 | 无(星桥 bash 可 curl) | 需 L1: 发送仅守护持有 server token |
| agent 自发重试 | 纸面(降级纪律§2.2) | 需 L1: agent 无 send/retry 工具 |
| 状态判定 | agent 各自猜 | 需 L1: 探照灯状态仅守护维护, agent 查接口 |

## 三、L1 能力边界落地（按工具面/宿主收口）

### 3.1 跨设备发送唯一化
- **守护 = 唯一跨设备发送者**：server bus token 只存在守护侧(0600)
- agent 无 http-out 能力(或仅白名单 URL = 本机守护/黑板)
- agent 要发跨设备消息 → 写本机 `notes/<dev>/outbox/` 队列 → 守护转发
  （agent 连服务器的动作在能力上不存在）

### 3.2 域 token 分离（写域结构性收口）
- 每 agent/域独立写 token(或 bb-gate 服务端强制)，agent 无他域凭据
- can_write 从"检查"变"服务端无此域凭据就 403"(非 agent 自觉)

### 3.3 状态只读化
- agent 查探照灯状态 = 只读接口(守护维护)
- agent 无"声明自己在线/改状态"能力——状态是守护观测的，不是 agent 说的

### 3.4 重试不存在
- agent 无循环重试工具；失败返回值 = 守护状态码(黄/红)
- agent 收到黄/红 = 只能"挂起+本地缓存"，重试动作在守护(唯一)

## 四、Lean4 断言化(convention-lean4-check.py 扩展 G-C 系列)

| 断言 | 校验 L1 能力边界真的存在(结构) |
|---|---|
| G-C22 no-http-out | agent preset/tool 面无直连服务器能力(仅守护) |
| G-C23 domain-cred-sep | 域写凭据分离(服务端无他域凭据→403) |
| G-C24 state-readonly | agent 对探照灯状态只读(无写状态工具) |
| G-C25 no-retry-tool | agent 无循环重试工具 |
| G-C26 send-via-daemon | 跨设备发送仅经守护(outbox 队列模式) |

## 五、实施优先级(防自作聪明的关键项)

- P0: G-C22 no-http-out —— 最大漏洞(星桥现可 curl 服务器)
- P0: G-C23 domain-cred-sep —— 写域结构性收口
- P1: G-C26 send-via-daemon —— agent 发送改 outbox 队列
- P1: G-C24/G-C25 —— 状态只读+无重试

## 六、验证(R030)

- [ ] agent 写他域 → 服务端 403(无凭据), 非检查拦截
- [ ] agent 无法自发重试跨设备消息(无工具)
- [ ] 探照灯状态仅守护可写, agent 只能查
