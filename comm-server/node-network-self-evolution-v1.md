> 关联：公约 §十(convention-PR) / G-C 断言族 / 系统架构管理器(SystemGraph)

## 一、自进化定义

**节点网络自进化 = 约束(公约)由被约束方(端侧设备/角色)共同维护的负反馈闭环**：
```
端侧实测 → 发现约束缺口 → 提案(CP) → 中枢验证+评审 → 合并入公约
  → 广播全节点 + 转 Lean4 断言 → 端侧被新约束约束 → 新场景再实测 → 再发现缺口
```

非中心化设计：mac-mini 不是"规则制定者"而是"治理执行者"——所有接入节点都有提案权，
共识驱动规则演进（类比：开源项目 = 维护者合并社区 PR；此处 = 协调者合并端侧 CP）。

## 二、自进化闭环架构（五环节）

```
┌─ 感知: 端侧实测(扫描/亲历痛点) → 发现「约束 vs 现实」缺口
├─ 提案: convention-propose 信封 / convention-pr.py submit(带理由+建议文本)
├─ 治理: 中枢验证(漏洞复现) + 评审(相关方3日) + 裁决(merge/reject带理由)
├─ 固化: 并入公约 + 版本bump + 转 Lean4 断言(G-C) + notify-nodes 广播全节点
└─ 回归: 端侧被新断言约束 → 行为符合新规则 → 新场景触发再感知
```

### 关键不变量(Lean4)
1. 提案须带实测理由(R030: 无验证不陈述)——杜绝纸面拍脑袋改规则
2. 合并即转 G-C 断言(结构门)——规则不是文档是机器强制
3. 端侧提案优先响应(被约束方最懂落地痛点)——MBP CP-003/004 实证
4. 广播全节点(§9.2)——规则变更无信息孤岛
